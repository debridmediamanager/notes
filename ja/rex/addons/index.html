rex アドオンの作り方

rex は、ソースが伝えてくれた情報をもとに中身を表示します。ソースは feed API を通して rex に持っているものを伝え、rex が要求したときにファイルを配信します。rex はどのソースも同じように扱います。アドオンは、ホームビデオ、録画、Stremio のカタログ、音楽、ライブチャンネルなどのために自分で書くソースです。

このページでは、rex がアドオンに必要とするもの、項目の名前の付け方、そして重要なルールを説明します。最後に、1ファイルの例として rex-stremio を紹介します。

アドオンがやることは3つです。

  • バイトを配信する。 再生ボタンが押されると、rex はアドオンから HTTP ですべてのバイトを取得します。ファイルの場合もあれば、rex がリダイレクトされるストリームの場合もあります。
  • 持っているものを rex に伝える。 feed API を通じて、一覧を rex に送ります。その後に起きた変更もすべて送ります。rex は自分でスキャンすることはありません。
  • 持ち込むものに名前を付ける。 どのエージェントも知らないものについては、タイトル、あらすじ、日付、アートワークをアドオン自身が送ります。Plex のアプリは、それらを他のライブラリと同じように表示します。

持ち込みたいものが、Plex がすでに知っている映画やシリーズ（IMDb や TMDB の ID がわかっているもの）の場合は、代わりに 独自のアプリでの rex を使ってください。そうすれば Plex がすべての名前と説明を用意してくれます。

Stremio アドオンのカタログを rex に取り込みたいだけなら、書くものは何もありません。rex-stremio がすでに用意されています。設定ページにアドオンのリンクを貼り付けて、使いたいカタログにチェックを入れるだけです。

サーバーを書いて動かすのは避けたい場合は、代わりに rex-addons の JavaScript アドオンを使えます。manifest.json と main.js の2つのファイルで、git リポジトリを通して共有します。zurg+rex Android アプリでも動きます。アドオンはサンドボックスの中で動き、一覧に載っているウェブサイトにしか接続できず、ディスク上のファイルも読めません。そのため、ディスク上のフォルダーではなく、インターネット上のものに向いています。書き方は アドオンの書き方 を見てください。このページのアドオンはどの言語でも書けて、自分のファイルを配信し、必要なことを何でもできます。

すぐ動くコードから始めたいですか？ 3つのチュートリアルでは、それぞれ標準ライブラリだけを使った1つの Python ファイルで完全なアドオンを作ります。各部分が何をしているかも説明しています。

チュートリアル rex に取り込むもの
ホームビデオ 自分の動画のフォルダー。動画から切り出したタイトル、日付、ポスター付きのライブラリとして取り込みます
音楽 アルバムのフォルダー。MusicBrainz を通じて Plex が名前を付け、歌詞も付きます
IPTV M3U プレイリストと、その XMLTV ガイド。ガイド付きの Live TV チャンネルとして取り込みます

このページでは、これらのチュートリアルが行うすべての手順を説明しています。アドオンからさらにでは、字幕、予告編、チャプター、コレクション、プレイリストなどを追加します。

始める前に

必要なもの 理由
rex を 独自アプリで rex を使う の手順 (手順 1 から 3) どおりにセットアップしておく アドオンのライブラリがここに表示されます
2026.10.25 以降の rex nightly、Music と Live TV を使うなら 2026.11.02 以降 このページはそのバージョン向けに書かれています
アドオンがストリームを配信する場合は、rex を動かす場所に FFmpeg rex はストリームを変換 (コピーなので負荷は小さめ) して再生します。rex は FFmpeg を自動で見つけます。動画の変換 を参照してください
アドオンを rex と同じマシン、または自宅のネットワーク上に置く rex のフィードは、この範囲からの接続にだけ応答します。ポートを非公開にする を参照してください

このページでは、rex のアドレスを 192.168.1.20:32400、アドオンのアドレスを 127.0.0.1:9981 と書いています。お使いの環境の値に読み替えてください。rex の API の全体像は docs/feed-api.md にあります。

手順 1. ファイルを配信する

何をするか。 rex が読み取れるURLを、すべての動画に用意します。

なぜ重要か。 rex はメディアを保存しません。誰かが再生ボタンを押すたびに、rex があなたのアドオンから動画を読み込みます。

アドオンは HTTP サーバーです。動画は <your address>/<path> にあり、path は好きに決めてかまいません。種類は2つあります。

配信するもの 方法 rex の動作
ファイル (.mkv, .mp4, ...) GET にファイルで応答します。Range リクエスト (206) に応答すると、シークが速くなります。応答しないと、シークのたびに rex は最初から読み直します Plex アプリは可能であれば直接再生します。できない場合は rex が変換します
ストリーム (HLS, .m3u8) GET にプレイリストで応答するか、そこへのリダイレクトを返します。リダイレクトは追跡され、ログイン情報が別のホストに送られることはありません rex は必ず変換します。映像と音声のコピーを、アプリが再生できる形にします。ファイルを直接読むアプリも、この変換に回されます

必須ではありませんが、設定しておくと良いものがあります。

  • ログイン。 Basic 認証 (user, password) またはベアラートークンを使えます。rex はアドオン自身のアドレスにだけ送ります。
  • 削除。 Plex アプリでタイトルを削除すると、rex は最初にそのパスに対して WebDAV の DELETE をアドオンに送ります。2xx（削除済み）または 404（すでにない）で応答すると、rex はタイトルを削除します。それ以外の応答だと、Plex アプリは削除できなかったと表示します。

手順 2. rex に登録する

何をするか。 rex にアドオンの名前、バイトの場所、そしてそれが埋めるライブラリを伝えるよ。

なぜ大事か。 rex は、知らないソースからは何も読み込まない。もう一度登録しても何も変わらないので、アドオンが起動するたびに毎回実行しよう。

curl -X PUT http://192.168.1.20:32400/rex/sources/myaddon \
  -H 'Content-Type: application/json' \
  -d '{"url": "http://127.0.0.1:9981",
       "directories": [{"name": "kids", "shows": "Kids"}]}'
 
Invoke-RestMethod -Method Put http://192.168.1.20:32400/rex/sources/myaddon -ContentType application/json `
  -Body '{"url": "http://127.0.0.1:9981", "directories": [{"name": "kids", "shows": "Kids"}]}'
項目 意味
url バイトがある場所。動画のバイトは GET <url>/<path> で取得される
user と password、または bearer アドオンのログイン情報（あれば）。url の中には絶対に入れないこと
directories アドオンが埋めるライブラリ。各エントリは最初のパスセグメント（name）とライブラリのタイトルで、shows（TV ライブラリ）、movies（映画ライブラリ）、music（音楽ライブラリ）のいずれか、または複数指定できる。rex は初回にライブラリを作成する。Plex で名前を変えても、その変更はそのまま残る
trash false にすると、アドオンが削除したもの（スナップショットから外れたものや DELETE されたもの）を rex のゴミ箱に入れず、そのまま完全に削除する

最初のパスセグメントで、どのライブラリに入るかが決まる。上の例では kids/ で始まるパスはすべて Kids に入る。ライブラリごとに、違う最初のセグメントを使ってね。

見えるはずのもの。 rex はソースを返す。rex のログには SOURCES myaddon registered at http://127.0.0.1:9981 と出る。初回だけ SECTION create Kids (show) for myaddon's kids も出る。ライブラリは 1 秒以内に、Plex のアプリの More の下に表示される。

手順 3. 各動画を説明する

何をするか。 rex が動画ごとに保持するレコードを作ります。動画の場所、種類、見た目の情報です。

なぜ重要か。 このレコードが rex にとってのすべてです。プローブの欠落や id の変更が、アドオンのバグの大半の原因になります。

{
  "id": "home-2026-07-22-beach",
  "path": "kids/summer-2026/beach.mp4",
  "kind": "episode", "season": 1, "episode": 3,
  "name": "Summer 2026",
  "media_info": { "...": "ffprobe's output, whole" },
  "display": {
    "title": "First day at the beach",
    "summary": "...",
    "date": "2026-07-22",
    "thumb": "http://127.0.0.1:9981/kids/summer-2026/beach.jpg",
    "show": {"title": "Summer 2026", "summary": "...", "poster": "https://...", "art": "https://..."},
    "season": {"poster": "https://..."}
  }
}
Field Required Meaning
id はい 動画ごとのキーです。ずっと変えないでください。rex は視聴履歴をこの id に紐づけます
path はい url の下にある動画データの場所です。最初のセグメントでライブラリが決まります
media_info 実際には必須 動画の ffprobe の -show_format -show_streams JSON です（ストリームの場合は、その URL に対してプローブします）。これがないと、ファイルは保留になります。保存はされますが表示されません。Plex アプリは中身が分からない動画を再生しないためです。.m3u8 のストリームにこれがないと not a video file で拒否されるので、プローブしてからストリームを送ってください
kind 番組の場合 episode または movie です。これがないと動画の配置先が決まりません。テレビライブラリでは name という名前の番組のエピソードとして、ファイルの順番で番号が振られます。映画ライブラリではファイル名をタイトルにした映画として扱われます
season, episode エピソードの場合 配置先です。エピソードに番号を振るときは、新しいエピソードを追加しても他の番号がずれないようにしてください
name いいえ 番組の名前で、そのエピソードをまとめる単位にもなります。デフォルトはフォルダー名です（フォルダーがないパスの場合はファイル名）
release いいえ 一緒に扱うべき動画をまとめます。デフォルトは動画のフォルダーです
display 既存のエージェントが知らない場合 タイトル、概要、日付、アートワークです。ステップ4を参照してください

ストリームの path は .m3u8 で終わり、その media_info には "format_name": "hls" と書かれている必要があります。rex はこの両方がそろっている場合にのみ受け付けます。それ以外のファイルは、動画の拡張子を持っている必要があります。

手順 4. 名前と見た目を整える

何をするか。 Plex のエージェントが知らないものについて、Plex アプリにタイトル、あらすじ、日付、画像を表示します。

なぜ重要か。 display がないと、エピソードは空のタイルに「Episode 3」と表示され、シリーズにはポスターがありません。

フィールド 表示される場所
title, summary 動画のタイトルとあらすじです。送ったとおりに表示されます
date 公開日 (YYYY-MM-DD) と、そこから取った年です。年しかわからないもの（古い映画など）は、年だけ (YYYY) を指定できます。その場合、Plex アプリは年だけを表示し、公開日は表示しません
thumb 映画のポスター、またはエピソードのスチルです
art 映画の背景です
show.title, show.summary, show.poster, show.art エピソードのシリーズです
season.summary, season.poster エピソードのシーズンです（ない場合はシリーズのポスターを使います）

どのフィールドも任意です。画像は http:// または https:// の URL にしてください。rex が画像を自分で取得します。取得元は、公開インターネットか、登録した url（アドオン自身のアドレス）です。後者の場合は、そのアドオンのログインを使います。ホームネットワーク上のそれ以外のアドレスは拒否されます。そのため、アドオンが自分の画像を配信することもできます。たとえばホームビデオの各フレームを使えます。ポスターには 2:3 の画像が最適で、スチルと背景には 16:9 の画像が最適です。

rex の動作は次のとおりです。

  • 何も指定されていないものだけ。 kind と、Plex が知っている ids で送られた動画は、Plex の説明どおりに表示されます。そのときは display を無視します。
  • 後から送ると更新されます。 新しい display を付けて動画をもう一度送ると、その行、シリーズ、シーズンがその場で変わります。アプリには新しい画像が表示されます。シリーズは、最初に作られたときのタイトルを保ちます。
  • ユーザーの設定が優先されます。 誰かが Plex アプリで編集してロックしたフィールドは、その値が保たれます。アップロードされたポスターもそのまま残ります。
  • 内容はチェックされます。 http(s) で始まらない URL の画像や、別の形式の日付があると、その動画は拒否されます。どのフィールドが原因かも表示されます。

手順 5. 送信する

やること。 動画をrexに送ります。最初に全部送り、その後は変更があるたびに送ります。

なぜ大事か。 rexは、最後に送った内容を正確に表示します。

目的 送るもの rexの返答
動画を追加・変更する POST /rex/feed/myaddon/items と {"items": [...]} created、updated、held、unchanged の数と、拒否された動画ごとの rejected と理由
動画を削除する DELETE /rex/feed/myaddon/items と {"ids": [...]} trashed、deleted、released（保留中だったものは忘れられます）、unknown の数
全部送る PUT /rex/feed/myaddon/snapshot と {"items": [...]}。分割する場合は "session"（任意のテキスト）、0から始まる "part"、最後のパートに "complete": true 同じ数に加えて、removed（スナップショットに含まれなかったあなたの動画すべて）

1回のリクエストには数百本程度の動画を送ってください。何も含まないスナップショットでは何も削除されません。動画の半分より多くを削除するスナップショットは、最後のパートに "force": true を付けない限り拒否されます。これは、状態を見失ったアドオンがうっかりライブラリを空にしてしまうのを防ぐためです。

表示される内容。

curl -s http://192.168.1.20:32400/rex/feed/myaddon/items | head -c 400   # what rex shows, with each ratingKey
curl -s http://192.168.1.20:32400/rex/feed/myaddon/held                  # what waits for a probe
 
curl.exe -s http://192.168.1.20:32400/rex/feed/myaddon/items   # what rex shows, with each ratingKey
curl.exe -s http://192.168.1.20:32400/rex/feed/myaddon/held    # what waits for a probe

rexのログには、拒否された動画ごとに理由が表示されます。形式は FEED myaddon rejected <id>: <reason> です。

音楽

何をするか。 アルバムを音楽ライブラリに取り込みます。取り込んだアルバムは Plexamp、Plex Web、Plex for Android で再生できます。

なぜ重要か。 Plex は音楽を MusicBrainz のリリースで識別します。そのリリース ID を送ると、Plex がタイトル、カバー、アーティスト写真、経歴をすべて自分で埋めてくれます。

音声ファイルはそれぞれトラックとして送ります:

{
  "id": "albums/in-rainbows/01",
  "path": "music/Radiohead/In Rainbows/01 - 15 Step.flac",
  "kind": "track",
  "ids": {"mbid": "3b408cb5-7d51-4188-b07c-fabcf308cda3"},
  "disc": 1, "track": 1,
  "media_info": { "...": "ffprobe's output, whole" }
}
フィールド 意味
kind track
path 音声ファイル。.flac、.mp3、.m4a、.aac、.ogg、.oga、.opus、.wav、.alac、.aif、.aiff、.wma、.ape、.wv、.dsf、.mka のいずれか
ids.mbid トラックのアルバムの MusicBrainz リリース ID。musicbrainz.org/release/<id> リンクの ID を使います。リリースグループや録音の ID ではありません。または ids.plex（Plex 独自のアルバム GUID、plex://album/<id>）
disc、track そのリリースでのトラックの位置。その番号で Plex が表示するトラックが選ばれます
release トラックがどのアルバムのコピーに属するか。デフォルトはそのフォルダーです。Plex はコピーごとに別のアルバムとして表示するため、ディスクフォルダー（CD1/、CD2/）に入ったファイルは、1つのコピーにつき1つの release を送ってください
display Plex が知らない音楽用の情報。トラックの title、アーティストの artist（title、summary、poster、art）、アルバムの album（title、summary、poster、date）
lyrics アドオン上でそのファイルの隣にある歌詞ファイル。例: [{"path": "music/.../01 - 15 Step.lrc", "size": 147}]。時間付きの .lrc または .txt を、曲の歌詞として表示します
loudness アドオンが音量を測定している場合のみ。Plex の名前で gain、albumGain、peak、albumPeak、albumRange、loudness、lra、フェードの startRamp と endRamp、100 ms ごとの音量 levels を指定します。rex 自体は音量を測定しません
  • 先に音楽ライブラリが必要です。 ステップ 2 で宣言する（"directories": [{"name": "music", "music": "Music"}]）か、Plex アプリで音楽ライブラリを追加してください。どの音楽ライブラリも受け取らないトラックは拒否されます: no music library holds <file>。
  • リリース ID の探し方。 アルバムのタイトルとアーティストで MusicBrainz を検索し（https://musicbrainz.org/ws/2/release?query=release:%22In%20Rainbows%22%20AND%20artist:Radiohead&fmt=json）、トラック数が合う公式リリースを選びます。国ごとに複数一致することが多いですが、どれもアルバムを指しています。MusicBrainz は 1 つのアドレスからのリクエストを 1 秒に 1 回までしか受け付けず、それ以上は拒否します。また、アドオン名を含む User-Agent を求めています。アルバムごとに 1 回だけ問い合わせて、結果を保存しておいてください。
  • rex はタグを読みません。 タイトル、カバー、ジャンル、類似アーティストは Plex が提供します。Plex がリリースを知らないトラックは、指定した display の内容が、指定したアーティストとアルバムの下にまとめて表示されます。display がない場合は、[Unknown Artist] の下にファイル名で表示されます。
  • そのまま再生されます。 FFmpeg は不要です。ただし、アプリが元の品質より低い品質を求めた場合は、Plex と同じく rex が FFmpeg で変換します。
  • 含まれないもの。 Plexamp のラジオ、ミックス、ステーション、音響的に似たトラックには、rex が行わない解析が必要です。

表示される結果。 音楽ライブラリにアルバムが Plex のカバーとトラック名付きで表示され、アーティストには写真が付きます。Plexamp では、ライブラリとして rex の音楽ライブラリを選んでください。

ライブ TV

何をするか。 ライブ配信を、Plex Web と Plex for Android の Live TV のチャンネルにします。番組表、What's On、チャンネル番号が付きます。

なぜ大事か。 ライブ配信だけだと、ライブラリの中の1行にすぎません。channel を付けると、テレビと同じように、番組表から、今放送中の番組で見つけられます。

手順3のとおりに(.m3u8 と probe を付けて)ライブ配信を送り、さらに channel を付けます:

"channel": {
  "number": "100.1",
  "title": "Rex News",
  "guide": [
    {"start": "2026-11-01T18:00:00Z", "end": "2026-11-01T19:00:00Z",
     "title": "Evening News", "summary": "The day's headlines.", "categories": ["News"]},
    {"start": "2026-11-01T19:00:00Z", "end": "2026-11-01T19:45:00Z",
     "title": "The Pilot", "type": "episode", "show": "Rex Stories", "season": 1, "episode": 1,
     "categories": ["Drama"]}
  ]
}
Field Meaning
number 番組表でのチャンネル番号(100.1、704)。英字、数字、.、-、_ が使えます。他のアドオンのものと重ならない番号を選んでください。番号付きで最初に送られたチャンネルがその番号を保つ
title 番組表に出る名前。既定値はストリームの display タイトル
call_sign 短い名前。既定値は title
guide 放送内容。start と end(エポック秒、または Z かオフセット付きの ISO 8601)、title、そして任意で summary、categories、thumb、previously_shown(再放送なら true)。エピソードの場合は "type": "episode" と show、season、episode を追加します。番組表はそれを番組名ごとにまとめます
  • 番組表は、数時間前から、わかっている範囲で先まで送ってください(テレビ番組表のファイルと同じく、約1週間分)。番組が変わるたびに、もう一度送ってください。rex は番組が終わって3時間後まで番組を一覧に載せます。送信するたびに、そのチャンネルの番組表が置き換わります。channel を付けずに送ると番組表は残ります。"channel": null にするとチャンネルが終了します。
  • FFmpeg が必要です。ほかのストリームと同じく、rex は誰かが視聴しているあいだにチャンネルを変換します。
  • 録画はできません。 Plex Web と Plex for Android には Record ボタンがありません。
  • 終了するチャンネル。 手順2のとおり "trash": false を付けて登録してください。そうすると、削除したチャンネルは rex のゴミ箱に残らず、完全に削除されます。
  • カテゴリの効果。 Sports や News のエピソードは、What's On の Sports と News の棚に表示されます。type がない番組は、Plex が任意のテレビ番組表で行うのと同じく、映画として表示されます。

表示されるはずのもの。 Plex Web または Plex for Android のアプリのメニューに Live TV があり、番組表のその番号にチャンネルがあり、開くとストリームが再生されます。rex のログには、受け付けられなかったチャンネルと理由が出ます(例: channel.guide[3]: end must be after start)。

rex-live-sports は、ライブスポーツのサーバーのチャンネルについて、これらすべてを行います。グループごとに 100.1 から番号を振り、各チャンネルの番号を保ち、番組表を Pluto TV と epgshare01 の無料の XMLTV ファイルから取得します。

例: rex-stremio

rex-stremio は、Stremioアドオンのカタログをrexのライブラリに変換します。映画は映画ライブラリに、シリーズはTVライブラリに、ライブチャンネルは「Live TV」という名前のライブラリに入ります（Live TVガイドではありません）。Steps 1〜5を行い、標準ライブラリだけを使う1つのPythonファイルです。削除には対応していません。カタログのタイトルは、rex-stremioが削除できるものではないからです。

登録。 チェックしたカタログはそれぞれライブラリを指定します。名前を変えない限り、Stremio Films、Stremio Shows、またはLive TVになります。rex-stremioは stremio として登録し、ライブラリごとにディレクトリを1つ作ります。ディレクトリ名はライブラリ名にちなみ（例：stremio-films）、シリーズのカタログでは shows のタイトル、映画とライブTVのカタログでは movies のタイトルとしてそのライブラリを宣言します。

配信。 ストリームアドオンのリンクは期限切れになるため、rex-stremioはリンクを保存しません。タイトルごとにURLを1つ提供し、/<directory>/<catalog>/<id>.<ext> の形式でアクセスされると、その時点で新たに取得したリンクへリダイレクトします。

url = app.sync.resolve(vid)   # ask every stream addon, rank, take the first link that opens
self.send_response(302)
self.send_header("Location", url)

rex-stremioは、そのタイトルを提供する各アドオンに問い合わせます（/stream/<movie or series>/<id>.json）。そのうえで、普通の http(s) リンクだけを残します（torrentの infoHash はrexが読めるファイルではないため除外します）。解像度やサイズの上限を超えるものは捨て、残りを解像度の高い順に試します。開けたリンクは、期限の1時間前までキャッシュされます（リンクに期限が書かれていない場合は1時間）。rexはリダイレクトをたどり、シーク付きでリンクから直接ファイルを読みます。独自のヘッダーが必要なリンクはrex-stremioが自分で中継します。HLSのマスタープレイリストには、最も品質の高いバリアントだけを返します。

プローブ。 タイトルごとに一度、rex-stremioは自分のURLに対してffprobeを実行します。これにより media_info はrexが実際に読む内容と一致し、結果はキャッシュされます。同時に確認するタイトル数は probe_workers で決まります（未設定なら4）。それでも、各アドオンのホストには stream_interval_seconds ごとに最大1回しか問い合わせません。プローブに使ったストリームは覚えておき、再生のたびに最初に試します。そのため、実際に再生されるものは、rexに伝えた情報と同じになります。プローブのコンテナによって、パスの拡張子が決まります。.mkv、.mp4、.ts、.avi、またはHLSの場合は .m3u8 です。

保存済みプローブ。 DMMのAPIキー（dmm_api_key、または設定ページの DMM）を設定している場合、DMMがそのファイルのプローブをすでに保持していれば、torrentストリームはffprobeをスキップします。torrentのハッシュは、ストリームの infoHash、またはそのリンクから取得します（Torrentioのdebridリンクはパスにハッシュを含んでいます）。rex-stremioは、リンクに1バイトの Range を送った応答からファイルサイズを読み取り、DMMの POST /api/sponsor/mediainfo に最大100件のハッシュをまとめて問い合わせます。DMMのプローブを使うのは、そのリリースのファイルのうち、このサイズに一致するものがちょうど1つだけの場合に限ります。ストリームがファイル名を示している場合は、その名前も一致の確認に使います。それ以外は上記のとおりプローブし、その結果をDMMに送り返します（POST /api/sponsor/probes）。送るのは、torrentのハッシュ、ファイルサイズ、ストリームがファイル名を示している場合はその名前、そしてffprobeの出力です（読み取ったアドレスは含めません）。これにより、次に同じファイルに出会ったスポンサーはプローブをスキップできます。DMMは、ファイルごとに最初のプローブを保持し、zurg自身のスナップショットを優先して返します。share_probes: false を設定すると、プローブはrex-stremioの中だけに留まります。ただし、DMMのプローブは引き続き使われます。プレイリストのプローブは決して送信されません。

命名。 映画とエピソードはそれぞれ、kind とIMDb IDを ids に入れてrexに渡します。そのためPlexは、rex with your own app と同じ方法で名前を付けます。カタログ自体のタイトル、概要、日付、ポスターは display に入ります。これはPlexが名前を付けるまでの間だけ表示されます。ライブチャンネルや、アドオンだけが知っているタイトルにはIMDb IDがないため、display だけで名前が付けられます。

番号付け。 映画は映画のまま扱います。シリーズのシーズンとエピソードは、IMDbのIDを使うCinemetaから取得し、その番号をそのまま使います。そのため、新しいエピソードが追加されても、既存のエピソードの番号はずれません。rexは番号をTMDBの番号に合わせて配置するため、CinemetaとTMDBで番号が異なる場合、エピソードが誤った場所に入ってしまいます。

ID。 IDは、カタログ名とIMDb ID（およびシーズンとエピソード）を組み合わせたもので、例えば st-<catalog>-tt0111161 のようになります。IDは変わらないため、2つのカタログにある同じ映画は、2つの別のアイテムになります。Catalogs as collections をオンにすると、同じライブラリ内の複数のカタログに載っている映画やシリーズは、各カタログのコレクションの中で1つのタイトルとして扱われます。

送信。 6時間ごとと、設定を保存するたびに、次の処理を行います。まず登録します。次に、各タイトルを確認できた時点で送信します（POST .../items、一度に最大20件、または5秒ごとに準備できたもの）。最後に、各カタログのスナップショットを1つずつ、200件ずつに分けて送信します。保存後の最初のスナップショットには "force": true が付きます。カタログのチェックを外すと、半分以上が削除される可能性があるためです。カタログが空を返したり、一部しか返さなかったりした場合、その回ではスナップショットを送信しません。追加と更新は行いますが、何も削除しません。後の完全な回で、実際に消えたものだけが削除されます。
