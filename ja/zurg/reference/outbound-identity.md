# 送信リクエストのアイデンティティ {#outbound-request-identity}

`user_agent` は、debrid API と CDN 読み取り、Newznab 検索、NZB ダウンロード、OpenSubtitles、ffprobe のプローブ、メディアサーバー連携、依存関係のダウンロード、アップデート、そしてオプションの共有/ログエクスポートで使われる共通の HTTP User-Agent を制御します。
デフォルトは一般的なブラウザのエージェントです。空欄にするとこのデフォルトに戻ります。明示的に指定したカスタム値は、アプリケーションを識別する内容であっても入力したとおりに送信されます。
`omit_user_agent: true` にすると、Go の HTTP クライアントの User-Agent ヘッダーが送られなくなり、ffprobe にも空のエージェントが渡されます。設定した文字列より優先されます。サービスによっては、エージェントがないリクエストを拒否することがあります。GitHub はすべてのリクエストを 403 で拒否するため、GitHub へのリクエスト（`zurg update` と rclone および ffprobe のダウンロード）には、設定されたエージェントが付きます。設定がなければ一般的なブラウザのエージェントが使われます。

Plex、Jellyfin、Emby もクライアント/デバイスのメタデータを必要とします。設定は `outbound_client_name`、`outbound_client_id`、`outbound_client_version`、`outbound_device_name`、`outbound_device_id`、`outbound_platform` で行います。デフォルトはそれぞれ順に `Media Client`、`media-client`、`1.0`、`Media Client`、`media-client`、`Desktop` です。Plex は認証、スキャン、メタデータのリクエストにクライアント ID を使い、Jellyfin/Emby は認証メタデータにデバイス ID を使います。各フィールドは、プロトコルが対応している場合にのみ使われます。ID を変更すると、メディアサーバー上で別のクライアント/デバイスとして表示されることがあります。

これらの設定はすべて、ダッシュボードの Network & Connectivity にあります。ダッシュボードには、デフォルト値を解決したうえで保存済みの値が表示されます。再起動すると設定がまとめて適用されます。保存しただけでは、実行中の識別情報は変わりません。値は印字可能な ASCII 文字のみで、最大 2048 文字までです。クライアント/デバイスのフィールドには引用符とバックスラッシュを含められません。認証トークンとプロトコルのヘッダー名は変わりません。DMM が必要とする `X-Zurg-Token` の認証情報も含みます。

プロバイダー/インデクサーのクライアントは、リダイレクトを含め、リクエストを送る前に `Referer`、`Origin`、`X-Zurg*` のヘッダーを削除します。リダイレクトによって、直前の URL の非公開パスや API キーのクエリパラメーターが Referer 経由で漏れることはありません。認証、範囲リクエスト、プロバイダーの Cookie、リダイレクト回数の上限はそのまま残ります。これらのリクエストには、アプリケーションのクライアント/デバイス識別子は追加されません。

NNTP は必要に応じて `AUTHINFO USER`、`AUTHINFO PASS`、`BODY`、`STAT`、`DATE`、`QUIT` を送信します。ソフトウェアを識別するコマンドは送りません。設定できる NNTP のソフトウェア ID はありません。ユーザー名とパスワードは、各プロバイダーの NNTP 設定にそのまま保存されます。TLS と平文のトランスクリプトテストで、認証、記事へのアクセス、keep-alive、シャットダウンを確認しています。

この仕組みはアプリケーションの明示的な識別子を最小限にしますが、匿名性を提供するものではありません。リモートのサービスからは、認証情報、接続元 IP、リクエストされたコンテンツ、タイミングが依然として見えます。TLS/HTTP の挙動、カスタムの識別情報、アプリに登録された API キー、アクセスパターン（Real-Debrid のネットワークテスト用リンクを含む）によって、関連付けが可能になることがあります。外部から提供された URL、torrent のメタデータ、記事 ID、共有ペイロード、エクスポートしたログや設定の内容は書き換えられません。ソフトウェアのダウンロード URL は、要求されているソフトウェアを特定します。外部プレイヤーや別途起動されるツールは、それぞれ独自の設定を使います。

ソケットレベルの回帰テストで、デフォルト値、カスタムおよび省略されたエージェント、リダイレクト、維持される認証、メディアサーバーのメタデータを確認しています。設定/ダッシュボードのテストでは、バリデーション、YAML の往復変換、再起動時の設定適用を確認しています。
