# コマンドライン {#command-line}

zurg バイナリはサーバーと、いくつかのツールをまとめたものです。コマンドなしで実行するとサーバーが起動します。どのコマンドも `--help` に対応していて、このページの内容のもとになっているテキストを表示します。

コマンドは、インスタンスの作業ディレクトリで実行してください。`--config` を指定しない限り、zurg はそこにある `./config.yml` を読み込みます。データとログのフォルダも、同じディレクトリを基準にして決まります。

```
zurg [flags]
zurg [command]
```

## すべてのコマンドで使えるフラグ {#flags-every-command-takes}

| Flag | What it does |
|---|---|
| `-c`, `--config` | 読み込む設定ファイル。デフォルトは `./config.yml` です。 |
| `-v`, `--version` | ビルド情報を表示して終了します。出力は `zurg version` と同じです。 |
| `-h`, `--help` | zurg 全体、または特定のコマンドのヘルプを表示します。 |

## セットアップ {#setting-up}

### zurg setup

このコマンドは設定ファイルを作成し、rclone と ffprobe をダウンロードします。そのあと zurg が自動で起動するように登録します。足りない情報があれば、そのつど質問してきます。`--dry-run` を付けると、実行する内容を表示するだけで、何も変更しません。

キーやパスワードはファイルから読み込みます。こうすると、シェルの履歴に残りません。

| Flag | What it does |
|---|---|
| `--provider` | 設定するプロバイダーです。複数指定するときは繰り返します。realdebrid、torbox、alldebrid、nzb、premiumize、debridlink、offcloud、torbox_nzb のいずれかを指定します。torbox_nzb は、torbox と同じく `--torbox-token-file` または `TORBOX_TOKEN` からキーを読み込みます。 |
| `--realdebrid-token-file` | このファイルから Real-Debrid のトークンを読み込みます。同じフラグが `torbox`、`alldebrid`、`premiumize`、`debridlink`、`offcloud` にもあります。 |
| `--nntp-host` | `nzb` プロバイダー用のニュースサーバーです。 |
| `--nntp-port` | ニュースサーバーのポート番号です。TLS を使う場合は 563、使わない場合は 119 がデフォルトです。 |
| `--nntp-tls` | TLS を使います。デフォルトで有効です。 |
| `--nntp-username` | ニュースアカウントのユーザー名です。 |
| `--nntp-password-file` | このファイルからニュースアカウントのパスワードを読み込みます。 |
| `--nntp-connections` | ニュースアカウントで許可されている接続数です。デフォルトは 8 です。 |
| `--mount-path` | マウントを配置する場所です。デフォルトは、お使いのプラットフォームの慣習に従った場所です。 |
| `--port` | HTTP ポートです。省略した場合は、設定ファイルの値をそのまま残します。 |
| `--service-name` | サービスまたはスケジュールタスクの名前です。デフォルトは `zurg` です。 |
| `--service-scope` | `auto`、`user`、`system` のいずれかを指定します。デフォルトは `auto` です。 |
| `--service-user` | システムサービスを実行するユーザーです。 |
| `--no-service` | すべて設定しますが、自動起動は登録しません。 |
| `--no-start` | サービスは登録しますが、起動はしません。 |
| `--skip-downloads` | rclone と ffprobe をダウンロードしません。 |
| `--skip-prerequisites` | このプラットフォーム向けの FUSE チェックを省略します。 |
| `--non-interactive` | 足りない入力を求める代わりに、エラーで終了します。 |
| `--dry-run` | 実行する内容を表示するだけで、何も変更しません。 |

各プラットフォームには、それぞれ個別の手順があります。

- [Linux](../setup/linux.md)
- [macOS](../setup/macos.md)
- [Windows](../setup/windows.md)
- [Docker](../setup/docker.md)

### zurg doctor

スクリプトはセットアップで作られたものを確認します。設定を読み込み、rclone と ffprobe があるかを調べます。そのあとサービス、HTTP エンドポイント、マウントをチェックします。何かうまく動かないときは、まずこれを実行してください。

| Flag | What it does |
|---|---|
| `--working-dir` | インスタンスの作業ディレクトリです。デフォルトは現在のディレクトリです。 |
| `--service-name` | 確認するサービス名です。デフォルトは `zurg` です。 |
| `--service-scope` | `auto`、`user`、`system` のいずれかです。デフォルトは `auto` です。 |

### zurg service

自動起動を設定・管理します。セットアップのほかの部分は実行しません。

| Command | What it does |
|---|---|
| `zurg service install` | 自動起動を設定して、起動もします。`--start=false` を付けると、起動せずに設定だけします。 |
| `zurg service uninstall` | 自動起動を削除します。設定とデータはそのまま残ります。 |
| `zurg service start` | インストール済みのサービスを起動します。 |
| `zurg service stop` | サービスを停止します。 |
| `zurg service restart` | サービスを再起動します。 |
| `zurg service status` | 自動起動の状態を表示します。 |

どのコマンドも同じフラグを使えます。

| Flag | What it does |
|---|---|
| `--name` | サービスまたはスケジュールタスクの名前です。デフォルトは `zurg` です。 |
| `--scope` | `auto`、`user`、`system` のいずれかです。デフォルトは `auto` です。 |
| `--user` | システムサービスを実行するユーザーです。 |
| `--working-dir` | サービスが起動するときの作業ディレクトリです。 |
| `--executable` | サービスが実行する zurg のバイナリです。 |

### zurg download-requirements

rclone と ffprobe をフォルダにダウンロードし、そのパスを設定ファイルに書き込みます。`--skip-downloads` を指定しない限り、セットアップがこれを自動で行います。

| フラグ | 説明 |
|---|---|
| `--dir` | バイナリの保存先です。デフォルトは `bin` です。 |
| `--rclone-version` | rclone のリリースバージョン（例: `1.67.0`）です。デフォルトは `latest` です。 |
| `--ffprobe-version` | ffprobe のリリースバージョンです。デフォルトは `latest` です。 |

### zurg update

スポンサー向けの最新ナイトリービルドで、バイナリを置き換えます。使用する GitHub アカウントには、[gatekeeper](https://gatekeeper.debridmediamanager.com/) からスポンサーアクセスが必要です。コンテナの中では、次に再作成したときに新しいバイナリが消えてしまうため、更新を拒否します。代わりにそこで新しいイメージを pull してください。`--force` を付ければ、それでも更新されます。

GitHub へのサインインは GitHub CLI を通じて行います。使うのは PATH 上にあるものか、インストーラーが zurg の横の `bin` に置いたものです。GitHub CLI 本体がなくても、キーリングを使わずに保存されたサインインであれば動作します。`GITHUB_TOKEN` も使えます。どれも見つからない場合は、GitHub CLI を入れ直すためのインストーラーコマンドを表示します。

### zurg version

ビルド情報を表示します。`zurg --version` でも同じ内容が表示されます。

## ヘルプを求める {#getting-help}

### zurg サポート {#zurg-support}

ログと設定を DMM サポートに送信し、`K7QM-3XPD` のようなサポートコードを表示します。そのコードを Discord のサポートスレッドに投稿してください。コードは 7 日間保管され、DMM サポートだけが開くことができます。

送られる内容はダッシュボードの **Export Logs** と同じです。zurg が起動しない場合や、ダッシュボードにアクセスできない場合に使ってください。zurg の作業ディレクトリで実行します。そこにある `config.yml`（または `--config`）と `logs/zurg.log` を読み込みます。Docker の場合は `docker exec <container> /app/docker-entrypoint.sh support` を実行してください。適切なディレクトリは自動で選ばれます。コンテナが起動し続けない場合は、zurg 用にマウントしているフォルダと同じフォルダを使って `docker run --rm -v <your config folder>:/config ghcr.io/debridmediamanager/zurg:<tag> support` を実行してください。

送信前に、トークン、パスワード、ダウンロードリンク、そしてご自身のホスト名は削除されます。ダッシュボードと同じ方法で処理されます。読み込めない設定ファイルは送信されず、代わりにそのエラー内容が送られます。長すぎるログは、サイズに収まるように古い方の末尾から切り詰められ、そのことがバンドルに記載されます。

DMM のサポートサーバーに接続できない場合、またはアップロードが拒否された場合、zurg はその理由を表示し、代わりに 2 つのファイルを公開のペーストサイトに送信して、そのリンクを表示します。どこにも送信できない場合は、同じ方法で編集済みのファイルを `zurg-debug.tar.gz` に書き出すので、それをスレッドに添付してください。

## バックアップ {#backups}

### zurg backup

中身は、ほかでは再構築できないものだけを収めた `.zurgbackup` ファイルを書き出します。具体的には、トークン付きの設定と、タグやアカウントのリンクを含むすべての `data/*.zurgtorrent` です。加えて、`data/local/` 以下の `__magic__` ストアと、`nzbs/` 以下の元の NZB も含みます。キャッシュ、Plex のスナップショット、ログは含めません。そのためバックアップのサイズは、守っているデータ分だけに収まります。

インスタンスは起動している必要はありません。だからスケジュール実行しても安全です。このファイルは gzip 圧縮した tar で、中にトークンが入っています。パスワードと同じように保管してください。

| フラグ | 内容 |
|---|---|
| `-o`, `--out` | 書き出し先を指定します。省略時は、カレントディレクトリに `zurg-<timestamp>.zurgbackup` を作成します。 |
| `--include-caches` | 派生メタデータとキャッシュデータも一緒に含め、すぐに復元できるようにします。Plex のスナップショットとログは含めません。サイズが大きくなることがあります。 |

### zurg restore-backup

`.zurgbackup` を現在のディレクトリに展開します。各ファイルは元のパスに戻ります。先に zurg を止めてください。実行中のインスタンスが書き込んでいるファイルに対して復元が書き込みを行うためです。

```
zurg restore-backup my-backup.zurgbackup
```

ディレクトリに設定ファイルがすでにあれば、そのまま残します。このファイルには、ライブラリ全体が依存するトークンが入っているからです。上書きしたい場合は `--force-config` を付けて実行してください。

## 計測 {#measuring}

### zurg benchmark-my-setup

プレーヤーと同じように実際のバイトを読み込み、1つの数値ではなくばらつきを報告します。

3つのフェーズで実行されます。まずは各アカウントを単独で測定します。これがサービスの公称値と比べる基準になる数値です。次に全アカウントを同時に測定します。それぞれ単独では70 MiB/s、同時では25 MiB/sだったアカウントは、飽和した1本の回線を共有しています。最後にrcloneマウント経由で読み込みます。1つ目のフェーズとの差が、FUSEとVFSによるオーバーヘッドです。

サンプルはランダムなオフセットから読み込みます。下位のレイヤーはすべてキャッシュするため、同じオフセットを読み直すと、リンクではなくキャッシュを測ってしまうからです。

何も追加・削除はしません。ただし帯域は消費します。各アカウントは、サンプルサイズ×反復回数を2回読み込みます。マウントのフェーズはそれに加わります。

| フラグ | 説明 |
|---|---|
| `-n`, `--iterations` | アカウントごと、フェーズごとのサンプル数。デフォルトは 3 です。 |
| `--sample-mb` | サンプルごとに読み込む MiB 数。デフォルトは 128 です。持続的なマウント測定値を得るために rclone の read-chunk ramp を超えたい場合は 1024 を指定します。 |
| `--provider` | 指定した名前のアカウントだけをベンチマークします。繰り返し指定できます。 |
| `--skip-concurrent` | 全アカウントのフェーズをスキップします。 |
| `--skip-mount` | マウントのフェーズをスキップします。 |
| `--json` | レポートを JSON 形式で出力します。 |

### zurg network-test

ホストから各 Real-Debrid ダウンロードサーバーへの速度を、IPv4 と IPv6 のそれぞれで測定します。結果は `logs/network-test.log` に書き込まれ、サーバーがホストを選ぶときに読み取る `data/` にも保存されます。プロキシ経由でテストしたい場合は、環境変数で `PROXY` を設定してください。

| Flag | What it does |
|---|---|
| `-t`, `--test-url` | Real-Debrid 独自の速度テスト用ファイルの代わりに、すべてのサーバーからこのパスを取得する URL を指定します。 |

## Plex

これら3つは、このホスト上のPlexサーバーに対して動作します。まずPlexを設定してください。[Plex Integration](config.md#plex-integration)を参照してください。

### zurg plex-settings

Plex の設定のうち、マウントに影響するものを確認し、ポリシーで許可されている範囲で修正します。Plex のデフォルトはローカルディスクを前提にしています。そのうちのひとつは、スキャン中に一瞬でも問題が起きるとライブラリを削除してしまいます。ほかにも、Plex が持っているすべてのファイルをデコードさせてしまう設定があります。各設定の説明は [plex.md](../guides/plex.md#recommended-plex-settings) にあります。

| フラグ | 機能 |
|---|---|
| `-p`, `--policy` | このランで使うモードで、`off`、`warn`、`guard`、`enforce` のいずれかです。デフォルトは設定ファイルの `plex_settings_policy` です。より厳しいモードを指定すると、採用する前に変更内容をプレビューできます。 |

### zurg plex-drift

Plex のデータベースを読み取るだけで、書き込みはしません。そのデータベースが指しているファイルを、マウントの下で一つずつ確認します。消えているファイルがあれば報告します。ライブラリのスキャンを実行する前に使ってください。スキャンがそれらのファイルに出会うと、削除扱いになってしまうからです。先に件数がわかっていれば、スキャンは当てずっぽうではなく、判断して実行できます。

`plex_database_path` を設定し、Plex を同じホスト上で動かしておく必要があります。

### zurg plex-backups

zurg が保持している Plex データベースのスナップショットを、新しいものから順に一覧表示します。各行には、スナップショットが取られた日時、サイズ、そのときに各ライブラリに入っていたアイテム数が表示されます。件数はスナップショット自体から読み取ったものなので、この一覧を見ればそれぞれのスナップショットで実際に何を復元できるかがわかります。zurg がいつスナップショットを取るかは、[Plex Library Maintenance](config.md#plex-library-maintenance-same-host-only) に書いてあります。

## 共有 {#sharing}

### zurg export-torrents

ポータブルな `.zurgtorrent` ファイルを書き出します。このファイルにはアカウント情報は含まれません。認証情報は入らず、torrent ID、修復状態、CDNリンクも含みません。プロバイダーには接続しません。

`data/*.zurgtorrent` または古いダンプファイルを読み込みます。ファイルまたはフォルダーを指定すると、その分だけをエクスポートします。受け取る側は、ファイルを `torrents/<their-account>/` に置き、そのアカウントの `library.source: local` を設定します。受け取り側の手順は [portable-libraries.md](../guides/local-libraries.md) にあります。

| フラグ | 内容 |
|---|---|
| `--provider` | 設定済みのこのアカウントが保持しているリリースをエクスポートします。 |
| `--output` | ポータブルファイルの出力先です。 |
| `--replace` | 同じハッシュの既存のエクスポートを置き換えます。 |
| `--skip-invalid` | 一括エクスポート中に読み取れないエントリをスキップして、その件数を数えます。 |

### zurg nzb-share

公開できる NZB の共有セットを作成します。結果は、`manifest.json` と、リリースごとに 1 つずつ作られる `.nzb.gz` ファイル（名前はコンテンツハッシュ）が入ったフォルダです。すべての NZB は、まずクリーニングされます。コメント、DOCTYPE、透かし用のメタデータを削除します。元のファイル名も削除します。投稿者（poster）と日付も削除し、すべてのファイルに同じ固定のニュースグループを設定します。一部のインデクサーは、ダウンロードするたびにこの 3 つを変えてしまうためです。インデクサーが subject、title、パスワードに埋め込んでいるアカウントの印も取り除きます。公開されるのはリリース名だけで、そのリリースをダウンロードしたアカウントは含まれません。ただし、実際のアーカイブパスワードは残します。受け取った人がリリースを読むために必要だからです。

フォルダは、静的なホスティングならどこにでも公開できます。git リポジトリ、Pages サイト、`rclone serve` などが使えます。何を削除したかの監査ログはあなたのマシン上に残り、ここに表示されます。ただし、そのログには、このクリーニングで取り除くための識別子そのものが含まれています。

| フラグ | 動作 |
|---|---|
| `--from` | 共有するウォッチフォルダ。再帰的にたどります。デフォルトは `nzbs`。 |
| `--out` | 出力先フォルダ。デフォルトは `nzb-share-<timestamp>`。 |
| `--title` | manifest に記録されるタイトル。 |
| `--filter` | この正規表現にマッチするソースパスだけを共有します。 |

ダッシュボードからも共有を配信できます。詳しくは [公開 NZB 共有](config.md#public-nzb-sharing) を参照してください。

### zurg nzb-sync

共有ライブラリをウォッチフォルダに取り込みます。共有の`manifest.json`を、URLまたはローカルパスから読み取ります。各NZBは、書き込む前にmanifestのハッシュと照合されます。実際のデータは、自分のニュースアカウントで取得します。

```
zurg nzb-sync https://example.com/share/manifest.json
```

追加だけを行います。すでにあるエントリはスキップされ、共有によって削除されることはありません。同じリリースを含む2つの共有は、コンテンツハッシュで重複を除去されます。

| フラグ | 役割 |
|---|---|
| `--into` | 書き込み先のウォッチフォルダ。デフォルトは `nzbs`。 |
| `--dry-run` | 書き込む予定の内容を表示するだけで、何も書き込まない。 |

## Real-Debrid アカウントを初期化する {#clearing-a-real-debrid-account}

この2つのコマンドは、Real-Debrid アカウントから特定の種類のものをすべて削除します。削除は元に戻せません。動作するのは Real-Debrid のみです。

どちらのコマンドも、API トークンではなく、ログイン済みの Real-Debrid のブラウザセッションにある `auth` Cookie を求めます。そのCookieを表示する JavaScript の1行を出力します。それを real-debrid.com のブラウザのコンソールで実行し、結果を貼り付けてください。

| コマンド | 内容 |
|---|---|
| `zurg clear-torrents` | アカウント内のすべてのトレントを削除します。 |
| `zurg clear-downloads` | アカウント内のすべてのダウンロードを削除します。これらは制限解除済みのリンクです。 |

## シェル補完 {#shell-completion}

`zurg completion bash` は bash 用の補完スクリプトを出力します。`zsh`、`fish`、`powershell` でも同じように使えます。`zurg completion <shell> --help` で、どこに置けばよいかが分かります。
