# TorBox ニュースサーバー {#torbox-news-server}

TorBox Pro のサブスクリプションには Usenet アカウントが付属しています。これは本物の NNTP サーバーで、zurg は通常の `type: nzb` プロバイダーとして使えます。このページでは、そのサーバーがどういうもので、プロバイダー枠としてどれくらいの価値があるかをまとめています。以下の内容はすべて、別々のネットワークにある 2 台のホストから、2026-09-02 と 2026-09-03 に測定したものです。

## ワイヤー上で応答する内容 {#what-answers-on-the-wire}

`nntp.torbox.app:563` は、Let's Encrypt の証明書（`nntp.torbox.app` 向け）を使った TLS 1.3 上で NNTP を話します。挨拶は `200 Welcome to TorBox` です。機能一覧にはソフトウェア名が書かれています。

```
VERSION 2
IMPLEMENTATION nntpswitch2 (local-dev)
READER
LIST OVERVIEW.FMT ACTIVE ACTIVE.TIMES NEWSGROUPS DISTRIB.PATS HEADERS MOTD
OVER
HDR
XZVER
XZHDR
POST
```

その実装文字列は INN でも Diablo でもなく、一部のプロバイダが報告する `nntpd` でもありません。独自開発のソフトウェアで、名前がその役割を表しています。前段にスイッチがあり、その後ろに 1 つ以上の記事スプールが並んでいます。

40個の公開リーダーのホスト名に対して、その実装文字列を確認しました。32個がNNTPに応答し、そのうち6個が`nntpswitch2`と報告しました。この6個はすべて、同じ順序で同じ機能リストを返します。

残りはすべて違う応答を返しました。Omicronのブランド群、Eweka、Frugal、UsenetExpress、Giganews、Usenet.Farmなどがこれに含まれます。

アドレスを見れば残りもわかります。`94.232.112.0/21`はサンマリノのAbavia S.r.l.に登録されていて、記録上の連絡先は`abuse@abavia.com`です。`94.232.116.0/24`を逆引きすると、そのブロックだけで60を超えるリーダー名が見つかります。XS News、Easyusenet、Hitnews、UseNeXTはそこに、他の多くの小さなブランドと並んでいます。隣の`94.232.117.0/24`は、端から端までXS Newsのホスト命名になっています。

TorBoxはそのブロックにはありません。`news.cheapnews.eu`から7アドレス離れた、アムステルダムの範囲にあります。

**実測**できたのは、ソフトウェアのフィンガープリント、アドレスの所有者、そして隣接関係です。**推定**にとどまるのは商業的な取り決めのほうです。TorBoxは自社のUsenetを、複数のUsenetプロバイダーを組み合わせた高品質なものだと説明しており、切り替えソフトウェアもそれと矛盾しません。ですから安全に言えるのは、TorBoxがAbaviaやXS Newsのブランドと同じリーダー基盤の前に立っている、ということです。TorBoxが特定の一つのスプールを再販している、とは言えません。

認証情報は torbox.app の tools 内の View Usenet Connection Details から取得できます。ユーザー名はアカウントの auth id です。
パスワードは一度だけ表示されます。リセットすると以前のパスワードは無効になるため、リセットすると設定済みのすべてのクライアントが動かなくなります。

何か問題が起きたときに重要になる拒否メッセージは2つあります。
`482 too many connections for your user` は上限に達したことを示すもので、接続が返却された瞬間に解消されます。
`482 Invalid username or password` は本当に無効な認証情報を意味します。
どちらも約2秒かかってから失敗します。
認証に成功した場合はずっと速く、本番環境での接続試行1日分では 64 ms から 592 ms の間と計測されました。

## 記事番号の範囲は2週間分です {#the-article-number-window-is-two-weeks-wide}

`GROUP` で混み合っているバイナリグループを見ると、件数が high water mark（上限）から low water mark（下限）を引いた値と、ちょうど同じになります。実際のスプールには欠番があるので、この一致は記事番号が合成されたものだという証拠です。ウィンドウも短いです。

| グループ | 下限 | 上限 | ウィンドウ内の番号 |
|---|---|---|---|
| `alt.binaries.boneless` | 148068410000 | 150053594960 | 1,985,184,960 |
| `alt.binaries.teevee` | 2992135000 | 3392153099 | 400,018,099 |
| `alt.binaries.multimedia` | 31901685000 | 32301734812 | 400,049,812 |

`alt.binaries.boneless` の最も古い番号をサンプリングすると、2026-08-19 に投稿された記事が返ってきます。これは本書を書いた日の14日前です。それより古いものには、このサーバー上で番号がありません。

これは zurg には影響しません。NZB は message id で記事を指定し、message id の検索はウィンドウよりずっと古い記事にも届くからです。影響するのは記事番号をたどる処理です。このサーバーを対象にしたヘッダーダウンローダーやインデクサーには、ここ2週間分の Usenet しか見えず、それより前は何も見えません。

## リクエストを他のプロバイダーに中継しているか {#is-it-proxying-your-request-to-other-providers}

いいえ。3つの測定結果から、答えはプラットフォームがすでに保持しているスプールから来ていることがわかります。

**誰かに問い合わせるより速く拒否しています。** 世界に一度も存在したことのないメッセージID 25個を、3つのサーバーに問い合わせました。

| サーバー | ヒットしたときの `STAT` | 存在しないIDに対する `STAT` |
|---|---|---|
| `nntp.torbox.app` | 37 ms | **43 ms** |
| `news.eweka.nl` | 20 ms | 471 ms |
| `newshosting.tweaknews.eu` | 44 ms | 909 ms |

上流に問い合わせてから応答するサーバーは、答えが「いいえ」のときに最も遅くなります。すべての上流が先に返信しなければならないからです。このサーバーは「はい」を確認するのと同じ時間で「いいえ」と返しています。これは、ローカルのインデックスが答えていることを示しています。

**初回取得のペナルティはありません。** 2012年から2018年までの記事10本を、まずコールドで取得し、同じ接続ですぐにもう一度取得しました。

| サーバー | コールドの中央値 | ウォームの中央値 |
|---|---|---|
| `nntp.torbox.app` | 49.6 ms | 30.9 ms |
| `news.eweka.nl` | 98.0 ms | 78.1 ms |

コールドとウォームの比率は、ここでは1.6で、普通のスプールの1.25より大きくなっています。これはTCPとページキャッシュによるものです。初回リクエストで第三者から取得していたら、もっと大きなコストがかかり、そのコストはコールドの回にだけ現れたはずです。792 KBの記事がコールドで49〜73ミリ秒で届きました。これは約11〜16 MB/sで、別のプロバイダーへのラウンドトリップが入る余地はありません。

**ブレンドが、そのメンバーの部分集合になることはありえません。** これが決め手となる論点です。このサーバーが複数のバックボーンを統合していたなら、カバー範囲は各バックボーンの和集合になり、少なくとも1つのメンバーが持っていない記事を含むはずです。しかし、このサーバーは一つも持っていませんでした。Omicronアカウントの71.2%の厳密な部分集合です。プロバイダーを統合して、こうはなりません。

ソースを追跡しようとする人向けの関連する点がもう1つあります。ヘッダーは原文のままではなく、正規化されて返ってきます。フィールドの順序が変わり、大文字小文字が書き換えられるため、`X-Received-Body-CRC` は `X-Received-Body-Crc` に、`Message-ID` は `Message-Id` になります。`Path` は、確認したすべての記事で `not-for-mail` でした。普通のスプールなら実際の経路を保持できますが、上のサーバーの一つは、同じ記事に対して `news.tweak-news.eu!spooler.pl1!...!feed.tweaknews.nl!path-stripped` を返しています。つまり、ヘッダーは解析済みのフィールドから組み立て直されており、フィードの経路はそこからは復元できません。

## zurg での設定 {#configuring-it-in-zurg}

このアカウントは、通常の `type: nzb` サーバーエントリです。重要なキーは 2 つあります。

```yaml
providers:
  - type: nzb
    nntp:
      host: your-primary.example.com
      tls: true
      username: USERNAME
      password: PASSWORD
      connections: 40
      backbone: primary-backbone
      servers:
        - name: torbox-news
          host: nntp.torbox.app
          port: 563
          tls: true
          username: YOUR_TORBOX_AUTH_ID
          password: YOUR_TORBOX_NEWS_PASSWORD
          connections: 8
          backbone: torbox
          backup: true
```

`backup: true` を設定すると、ほかのすべてのアカウントがすでに記事を返せなかった場合にだけ、10 本の接続が記事の取得に使われます。
混雑している primary はそちらに振り分けられることはなく、本当の *no such article* が返ったときだけ使われます。
`backup` と `backbone` の動作について詳しくは、[プロバイダーのキー設定](../reference/config.md)を参照してください。

接続数は 10 ではなく 8 に設定してください。接続数の上限には、まだハンドシェイク中の接続も含まれるので、上限いっぱいまで開くプールはコールドスタート時に自分自身を拒否してしまいます。さらに 2 本空けておけば、本番に影響を与えずに手動でチェックを実行する余地も残ります。
同じ認証情報で 2 つ目のクライアントを接続させることは、絶対に避けてください。10 接続のアカウントを 2 つのクライアントで使うと互いに接続枠を奪い合い、サーバーは新しい方ではなく古い方の接続を切断してしまいます。

TorBox は、3つの有料バックボーンのどれよりもこのライブラリへの応答が少なかったです。

ただし、スロットを残す価値があるかどうかを決める数字は別にあります。**TorBox は、他のどこにもない記事を一つも持っていませんでした。** 531 件のうち、ゼロです。Omicron アカウントと比べると、完全な部分集合で、独自の記事は一つもありません。Frugal にないものが 9 件、Eweka にないものが 6 件ありましたが、そのどれも Omicron にもありました。一方で、Omicron アカウントだけが、他のどのバックボーンにもない記事を 61 件持っていました。

このサーバーでのミスは、混雑による誤った応答ではなく、本当に記事がないことを意味します。ミスした 153 件は、数分後に新しい接続で再度問い合わせましたが、どれも返ってきませんでした。同じ形式の以前の実行では、77 件のミスを再問い合わせして、返ってきたのは 1 件だけでした。つまり、否定的な応答のうち約 1 % がノイズで、残りは実際の不在です。

ヒットも本物です。4 つのサーバーすべてが持っていると答えた 20 件の記事を、`BODY` で全文取得しました。4 つすべてが 20 件中 20 件を返しました。このサーバーの `STAT` は、バイトが届くという意味として信頼できます。

単一接続のスループットも同じ実行で測定しましたが、安定していなかったため、ここでは報告しません。同じホストからの 3 回の測定では、TorBox は 1.6 から 7.4 MB/s の間に散らばり、他の 3 つもその範囲と重なり、一貫した順位はありませんでした。プールのサイズを決める場合は、自分のホストで測定してください。

表と一緒に、3 つの注意点があります。このサンプルは一人の運営者のライブラリなので、そのライブラリが集めたものを反映しているだけです。同じリリースから取った 3 つの記事は互いに独立していないため、年ごとのセルは実際には 36 件ではなく 12 件のリリースと考えるべきです。そして `STAT` の応答は、リリース全体の判定ではなく、1 件の記事についての主張にすぎません。

## スロットを使う価値はあるか {#is-it-worth-a-slot}

アカウントは Pro に含まれているので、追加料金はかかりません。これが一番の利点です。

ただし、これは保存期間を支える主力のバックボーンではありません。そのように設定するとがっかりすることになるでしょう。比較された有料アカウント3つと比べて、実際のライブラリのうち応えられた範囲は少なく、他のアカウントが既に断った記事を見つけることもありませんでした。すでに Omicron のアカウントを使っているスタックなら、これを追加しても何も得られません。

それでも正直に使える場面が2つあります。プロバイダーが1つだけの構成では、無料のセカンドオピニオンが手に入ります。そして、セカンドオピニオンは無いよりずっとましです。また、`backup: true` を指定すると、外れた推測のコストが小さく済みます。バックアップのアカウントは、すべてのプライマリが「そのような記事はない」と答えた後にだけ問い合わせられるからです。
