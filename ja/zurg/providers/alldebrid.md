# AllDebrid

`type: alldebrid`

[AllDebrid](https://alldebrid.com/?uid=1kk5i&lang=en) は、認証情報をローテーションさせるもう一つのバックエンドです。そのため、ここでは `download_tokens` と、別の `.strm` 用トークンの両方に意味があります。ファイル一覧は、マグネットリストからではなく、専用のエンドポイントから取得されます。そのため、大規模なライブラリの初回スキャンの体感が変わります。

## APIキーを取得する {#get-the-api-key}

サインインして、[alldebrid.com/apikeys](https://alldebrid.com/apikeys?uid=1kk5i) を開いてください。
キーを生成して、コピーしてください。

## 設定する {#configure-it}

```yaml
zurg: v1
providers:
  - type: alldebrid
    token: YOUR_ALLDEBRID_API_KEY
mount_path: "/zurg_mnt/zurg"
```

新しいコンテナに初めてインストールする場合は、セットアップに書き込んでもらいます。

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider alldebrid
```

すでに `config.yml` があるインストールでは、`http://localhost:9999/config/` の Dashboard で **Add provider** を使うか、ファイルを直接編集してください。どちらの場合も、最後に再起動してください。

```bash
docker compose restart zurg
```

`ALLDEBRID_TOKEN` は `zurg setup` で読み込まれ、実行中のデーモンでは読み込まれません。compose の `environment:` ブロックに書いてコンテナを起動しても、それだけでは何も起きません。

## このバックエンドが使う追加のキー {#extra-keys-this-backend-uses}

```yaml
providers:
  - type: alldebrid
    token: PRIMARY_AD_API_KEY
    strm_link_token: AD_KEY_FOR_STRM
    download_tokens:
      - SECOND_AD_API_KEY
```

`download_tokens` は、同じサービス上のバックアップ用のキーです。
アクティブなキーの帯域上限を使い切ると、これらが代わりに使われます。
このエントリーのカタログを使い、それぞれのライブラリはインポートされることはありません。

`strm_link_token` は、`/strm/` に届く読み取りリクエストを処理します。
そのため、`.strm` を開くプレーヤーが、ライブマウントのストリーミングに使っているキーを消費することはありません。
未設定の場合は `token` にフォールバックします。

## 最初のスキャンは少しずつ反映されます {#the-first-scan-fills-in-gradually}

AllDebrid v4.1 では、ファイルの詳細がマグネットのリストから別のエンドポイントに移されました。マグネットの一覧を取得しても、中身のファイルが何なのかは zurg には分かりません。そのため、リリースごとに1回ずつ詳細を取得する必要があります。

ただ、良いニュースもあります。それは **一度だけ** で済み、再起動のたびに毎回行う必要はありません。マグネットのファイルツリーは Ready になった時点で変わらなくなるので、zurg のディスク上の情報キャッシュは、そのマグネットについてずっと残ります。エンドポイントの手前にあるバッチャーが、最初のスキャンをまとめて処理します。初回起動時には大きなライブラリが少しずつ現れていきますが、その後は同じ処理が二度と繰り返されることはありません。

## 知っておきたい制限 {#limits-worth-knowing}

**アクティブな magnet の上限は公開されていません。** zurg が勝手に上限を作ることはありません。修復は、もともと不足していなかった空きを待つことはありません。

**1 つのキーで 1 分あたり 600 リクエスト。** これがドキュメントに書かれている上限です。zurg は、HTTP クライアントが独自に行うリトライによって一気にバーストが上限を超えないように、600 から 100 を引いた値でペースを調整しています。実際に一番効いてくる制約は同時接続数で、ドキュメントにある毎秒 12 リクエストに合わせて 12 に制限しています。

**1 つの配信サーバーへの 33 本目の接続は 429 になります。** 2026-08-23 に、500ms ごとに 1 本ずつ接続を開いて保持するテストで確認しました。AllDebrid はアンロックのたびに新しい配信ホスト名を発行します。そのため、複数の読み取りがたまたま同じホストを共有したときにだけ問題になります。zurg は 32 本を超えた分は接続を張らず、キューに入れて待たせます。

**ファイル単位の選択はできません。** magnet を追加するとすべて取得され、修復もリリース全体を丸ごと再追加します。

**コンテンツは自然に消えることがあります。** magnet はアカウントから時間とともに削除されることがあり、ホスターがリンクを落とすこともあります。消えたリリースは破損ではなく、想定される結果です。修復は、明示的に頼まれない限りそのままにしておきます。

**保存済みのリンクが古くなることはありません。** ファイルに紐づけられたロック済みリンクは、magnet の現在の状態から再生成されます。データがあるかどうかは magnet 自身のステータスがすでに教えてくれます。zurg は、ステータスを見ればわかることを確かめるためだけに、コールドスキャンのたびに torrent ごとにアンロックを消費するようなことはしません。

## 正しく動いたか確認する {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/alldebrid/test
ls /zurg_mnt/zurg/__all__/ | head
```

アカウントが1つだけだと、そのアカウント専用のフォルダーはマウントのルート一覧から除外されるため、同じファイルが `__all__` の下に表示されます。

## うまくいかないとき {#when-it-goes-wrong}

**`AllDebrid rejected the API key` がログに出ている。** キーが取り消されたか、再生成された可能性があります。[alldebrid.com/apikeys](https://alldebrid.com/apikeys?uid=1kk5i) で新しいキーを取得して、エントリを更新してください。

**キャッシュがない（cold）ライブラリの表示が遅い。** 想定どおりの動作です。上のセクションを参照してください。リリースごとに一度だけ検索が走り、それ以降は繰り返されません。

**リリースがマウント内の別の場所では再生できるのに、`__alldebrid__` の下では 404 になる。** 壊れているかどうかはアカウントごとに判断され、そのディレクトリは読み取りをこの1つのアカウントに固定します。別のアカウントに正常なコピーがあるのでしょう。
