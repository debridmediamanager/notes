# ローカルのデバリッドライブラリとポータブルな zurgtorrent {#local-debrid-libraries-and-portable-zurgtorrents}

ローカルライブラリは、ポータブルな `.zurgtorrent` ファイルからメンバーシップ情報を取得します。通常の WebDAV、HTTP、プロバイダーのディレクトリに表示されます。ファイルのインポート、一覧表示、カタログの更新を行っても、トレントが追加されたりダウンロードリンクが解決されたりすることはありません。再生時に、設定済みのアカウントを通じて要求されたファイルを解決します。

## ライブラリをエクスポートする {#export-a-library}

エクスポート元インスタンスの作業ディレクトリから:

+++ Linux and macOS
```sh
./zurg --config config.yml export-torrents data --provider realdebrid --output exported/realdebrid
```
+++ Windows
```powershell
.\zurg.exe --config config.yml export-torrents data --provider realdebrid --output exported/realdebrid
```
+++

`--provider` には設定済みのアカウント**名**を指定します（カスタム名も含みます）。省略すると、対応しているすべての debrid のコピーをエクスポートします。入力には、ランタイムのキャッシュファイル 1 つ、レガシーの `dump/` ディレクトリ、または既存のポータブルカタログも指定できます。
ローカルライブラリの場合は、そのソースディレクトリ（`torrents/<account>`）をエクスポートしてください。オプションの他プロバイダーへの参照もそのまま保持されます。

エクスポートはオフラインで動きます。書き込みを始める前に、すべての入力と出力先の衝突をチェックします。選択済みのファイルメタデータがないランタイムのエントリは報告してスキップし、リリースはハッシュごとにまとめて、`<hash>.zurgtorrent` を書き出します。同じ内容のエクスポートが既にあれば、何度繰り返しても安全です。不正なレガシーのキャッシュエントリを含む大量の移行では、`--skip-invalid` を付けると有効なエントリだけをエクスポートし、除外した件数を報告します。付けない場合は、最初の不正なエントリで中断され、何も書き込まれません。`--replace` を付けると、同じハッシュのポータブルエクスポートを置き換えられます。ただし、ランタイムのキャッシュを上書きする権限にはなりません。

共有を想定しているのはエクスポートされたファイルだけです。`data/*.zurgtorrent` はプライベートなランタイムの状態データのままです。`.zurgbackup` にはアカウントの認証情報も含まれるので、共有できるライブラリではなく、インスタンスのバックアップです。

## ライブラリを受け取る {#receive-a-library}

最初に、エクスポートしたファイルを `torrents/rd-local/` に置き、受け取り側のアカウントを設定します:

```yaml
providers:
  - name: rd-local
    type: realdebrid
    token: YOUR_OWN_TOKEN
    download_tokens: # Optional bandwidth fallback on another RD account.
      - SECOND_RD_TOKEN
    library:
      source: local
      # Optional; defaults to torrents/<account-name>.
      path: torrents/rd-local

  - name: tb-online
    type: torbox
    token: YOUR_OWN_TORBOX_TOKEN
    # Omitted library block means the provider owns this account's catalog.
```

Real-Debrid と AllDebrid では、`download_tokens` は、そのプロバイダー項目と同じローカルカタログを使います。上の 2 つ目の RD アカウントにはディレクトリが不要で、そのトレントライブラリはインポートされません。
これらは、現在のダウンロードトークンの帯域幅の上限に達したときに使われる予備の認証情報です。すべてのダウンロードを 2 つ目のアカウントに強制するものではありません。`providers` に 2 つ目の RD 項目を追加すると、代わりに、独自のディレクトリを持つ別のカタログが作られます。すべての認証情報は設定ファイルに残り、ポータブルなエクスポートからは除外されます。

TorBox も `download_tokens` を受け付けますが、そのトークンのローテーションでは、保存されたトレント/ファイル ID を別のアカウントの ID に対応づけられません。別々のアカウントには、それぞれ別の TorBox 項目を使い、それぞれに独自のローカルカタログを持たせてください。

Premiumize、Offcloud、Debrid-Link のアカウントにもローカルライブラリを持たせられます。いずれも、移植可能なファイル参照がありません。そのため、TorBox と同様に、各アカウントは初回再生時にそのアカウントへハッシュを追加し、パスとサイズでファイルを照合します。アカウントごとに 1 つのプロバイダー項目を使ってください。

アカウント設定を変更したら、再起動してください。ファイルの追加、置き換え、削除は、通常の更新ループで自動的に反映されます。各ディレクトリは 1 階層だけスキャンされます。パスは `torrents/` 配下の別々のディレクトリである必要があるため、通常のバックアップにも含まれます。読み取れないディレクトリや無効な置き換えファイルがあると、最後に有効だったメモリ上のエントリを保持し、問題をログに記録します。再起動後は、無効なファイルを修正しないとカタログに入りません。

同じマニフェストを、AllDebrid または TorBox アカウントのローカルディレクトリにコピーできます。マニフェストに含まれるのはコンテンツの識別情報で、プロバイダーのアカウント名は含まれません。複数のアカウントにまたがる同じハッシュは 1 回だけ表示され、複数のソースを持ちます。ソースの優先順位と フェイルオーバーの順序は、既存のアカウント優先設定に従います。1 つのディレクトリ内で同じハッシュのファイルが重複している場合は、ソート順で最初のファイル名が使われます。ハッシュごとに 1 つのマニフェストだけを置いてください。

ローカルカタログのメンバーシップは、プロバイダーのオンラインライブラリから削除されても残ります。名前の変更、タグ、IMDb ID、ファイルの削除は、マニフェストに保存されます。ローカルのリリースを削除すると、そのソースドキュメントが削除されますが、プロバイダーのトレントは削除されません。オンラインのコピーがあるリリースを削除すると、通常の一括削除と同様に、それらのオンラインコピーも削除されます。

ローカルアカウントは、ウォッチリスト、マグネットの追加、トレントファイルのアップロードの対象になりません。項目はマニフェストをインポートして追加してください。`add_torrents: false` を設定しても、RD/AD は既存の共有参照を引き換えられます。ただし、必要な場合に再生時にプロバイダー側の添付を作成することは防がれます。

## オンラインアカウントをローカルライブラリに移す {#offload-an-online-account-into-a-local-library}

AllDebrid はアカウントごとに最大 1000 個のマグネットしか受け付けず、Real-Debrid のアカウントもすぐにいっぱいになります。完了したリリースは、再生を続けるためにアカウント上にトレントを残しておく必要はありません。Real-Debrid の `/d/` リンクはトレントを削除した後も動き続けますし、AllDebrid のロック済み `/f/` リンクもマグネットを削除した後も動き続けます。オフロードはこの仕組みに頼っています。zurg は完了したリリースを同じサービス上のローカルライブラリに書き出し、その後オンラインアカウントからトレントを削除して枠を空けます。リリースはマウント内で同じフォルダーを保ち、保存済みのリンクから再生されます。

同じアカウントに対して 2 つのエントリを設定します。1 つはオンライン用、もう 1 つはローカル用です:

```yaml
providers:
  - name: ad
    type: alldebrid
    token: YOUR_AD_TOKEN
    library:
      offload_to: ad-local     # the local entry below
      offload_after_mins: 30   # optional, 30 is the default

  - name: ad-local
    type: alldebrid
    token: YOUR_AD_TOKEN       # the same token
    library:
      source: local            # manifests live in torrents/ad-local/
```

新しいリリースは引き続き `ad` に届きます。アカウントの一覧を完全に取得するたびに、また 5 分ごとに、zurg は条件を満たすリリースを 1 つずつ移動します。リリースは次の条件をすべて満たすと対象になります:

- アカウント上で完了状態になってから `offload_after_mins` が経過していること。経過時間は、この zurg プロセスが完了を初めて確認した時点から数えます。再起動すると待機は最初からやり直しになります。
- すべてのファイルに、別のアカウントで引き換え可能な有効なリンクがアカウント上にあること。1 つでもリンクがないファイルがあるリリースはオンラインに残ります。
- 正常な状態で、修復中ではなく、どのインスタンスもまだダウンロード中ではないこと。修復処理やダウンロードクライアントがそのトレントを保持していないこと。
- Sonarr や Radarr の qBittorrent ジョブがまだそのリリースを一覧に載せていないこと。*arr 側で Remove Completed Downloads を有効にしておくと、インポート後にジョブが削除されます。そうしないと、ジョブを手動で削除するまでリリースはオンラインに残ります。
- Acquisition によって 1 時間以内に追加されたものではないこと。
- 移動してもリリースが含まれるディレクトリが変わらず、フォルダー名も保たれること。オンラインアカウント名を指定した `provider:` フィルターを持つディレクトリでは、移動するとリリースが見えなくなるため、そのリリースはオンラインに残ります。

処理の順序は固定です。まずマニフェスト `<hash>.zurgtorrent` をローカルライブラリに書き込み、次にリリースをローカルライブラリに追加し、その後でオンラインアカウントからトレントを削除します。マニフェストを書き込めない場合は、何も削除されません。削除に失敗した場合は、オンライン側のコピーがローカル側と並んで残り、次回の更新でトレントがまだあるかどうかが表示されます。ローカルライブラリにそのリリースのマニフェストが既にある場合は、二重に書き込まずに既存のものを更新します。マニフェスト内のオンラインアカウントのリンクは更新され、名前や編集内容はマウントに表示されるとおりリリースに追従します。もう一方のサービスのリンクは残ります。

リリースは `__ad__` から消え、`__ad-local__` に表示されます。他のすべてのディレクトリ(`__all__` や自分のディレクトリを含む)では、同じ名前で引き続き表示されます。メディアサーバーのスキャンは開始されません。メディアサーバーがインデックスするものは何も変わっていないためです。Plex などのメディアサーバーは、アカウントごとのディレクトリではなく、これらのディレクトリを参照するように設定してください。

両方のエントリが同じトークンを使っている場合、ローカル再生によって同じアカウントにリリースが再び追加されることがあります(後述)。その場合、そのトレントはオンラインの一覧にも表示されます。zurg は、オンラインのトレントがそのような追加分であるリリースや、ローカル再生が追加中のリリースはオフロードしません。削除すると、ちょうど取得された再生が壊れてしまうためです。

オフロードできるのは Real-Debrid と AllDebrid だけです。TorBox、Premiumize、Offcloud、Debrid-Link にはトレントを削除した後も残るリンクがないため、ローカル再生ではトレントを追加し直すことになり、オフロードしても何も解放されません。zurg はこれらのアカウントでの `offload_to` を拒否します。

ダッシュボードでは、単一のリリースを移動することもできます。リリースのページにある Accounts テーブルでは、同じ種類のローカルライブラリが存在する場合、Real-Debrid または AllDebrid の各コピーの横に Move to local library が表示されます。これは `offload_to` を設定していなくても表示されます。リリースをまだ移動できない場合、ボタンは無効になり、その理由が表示されます。設定ページのアカウント設定にも同じ選択肢があり、zurg の起動以降に移動されたリリースの数と、最後のエラーが表示されます。

## ファイルに含まれるもの {#what-travels-in-the-file}

バージョン付き JSON 形式では、`format: "zurgtorrent"` と数値の `version: 1` を使います。
この形式には、infohash、リリース名、追加日時、名前変更、タグ、IMDb ID、選択されたファイルのパス、サイズ、任意の名前変更が含まれます。参照情報は任意です:

| プロバイダー | 持ち運び可能な参照 | 再生 |
|---|---|---|
| Real-Debrid | 正規の13文字の `https://real-debrid.com/d/...` | 受信者自身の認証情報とダウンロード IP で解決します。 |
| AllDebrid | ロック済みの `https://alldebrid.com/f/...` | 受信者の認証情報でロックを解除します。 |
| TorBox | ハッシュとファイルのパス/サイズ | 最初の再生時に、受信者側で新しいトレントを取得し、パスとサイズでファイルを照合します。 |
| Premiumize, Offcloud, Debrid-Link | ハッシュとファイルのパス/サイズ | 最初の再生時に、受信者のアカウントにハッシュを追加し、パスとサイズでファイルを照合します。 |

アカウント名、認証情報、プロバイダー側のトレント/ファイル ID、CDN URL、MediaInfo の入力 URL、Plex ID、修復状態、削除キューはエクスポートされません。インポーターは未知のフィールドや、認証情報を含む、または想定外の参照 URL を拒否します。マニフェストの検証中には URL を取得しません。Usenet は `.nzb` のソース形式を維持します。NZB のランタイムキャッシュは、ポータブルなトレントとしてエクスポートすることはできません。

## 再生と制限 {#playback-and-limits}

ローカルでのトラッキングが決めるのは、カタログの所有者だけです。プロバイダーがまだデータを持っていて配信できることは保証しません。アカウントへのアクセス、許可されたネットワークの場所、アクティブなスロット、クォータ、レート制限は、引き続き適用されます。

RD と AD は、共有のロック済み参照があればそれを使います。ハッシュだけのマニフェストや、API が存在しないと明確に報告した RD 参照では、受信者のアカウントにコンテンツを用意できます。TorBox は常にアカウントへの追加が必要で、まず受信者のアカウントにすでにある一致するトーレントを再利用します。追加はプロバイダーの既存のペースに従い、アカウントごとに順番に実行されます。アカウントがスロット数を報告した場合、または zurg がそれを把握している場合、満杯のアカウントへの追加は拒否され、1分後の次の再生リクエストで再試行されます。AllDebrid、Premiumize、Offcloud はスロット数を報告しないので、追加は実行されます。アカウントが満杯なら、そこで拒否されます。結果がはっきりしない追加は、30分間保留されてから再試行されます。準備中のトーレントは、再生が再度リクエストされたときにだけ確認されます。

受信者の ID と解決済みのネイティブファイルハンドルは、`data/local-torrents/` に非公開で保存されます。この記録は再起動後も残り、通常のバックアップにも含まれます。zurg はこれらのアタッチメントを自動では削除しません。冪等な追加では、受信者がすでに持っていたトーレントが返されている可能性があるためです。オフロードでもこれらには触れません。プロバイダーでエラーが起きても、ローカルのエントリは表示されたままになります。バックグラウンドで修復を始めたり、スキャンのたびに追加を繰り返したりはせず、少し時間を置いてから再試行します。

ローカルのアーカイブリリースは、ソースボリュームを一覧表示するだけです。自動展開やバックグラウンドでの検査は行いません。アーカイブ内の明示的なパスを指定した場合は、アーカイブリーダーが呼び出されることがあります。ローカルコピーがあるエントリでは、MediaInfo の自動プローブと次のファイルのプリフェッチは行われません。

## 古いダンプを移行する {#migrate-an-old-dump}

上のコマンドで `dump/` をエクスポートし、結果を受け取り側アカウントの `torrents/<name>/` ディレクトリに置いて、`library.source: local` を有効にしてください。移行が終わったら `load_dumped_torrents` をオフにします。古いオプトインの `__dump__` リーダーは互換性のために残っていますが、新しいローカルライブラリでは使いません。アカウントタイプがないランタイムキャッシュは、共有する前に、そのプロバイダーを認識しているインスタンスから再エクスポートする必要があります。

このビルドで書き出されたバックアップは、新しい永続ルートを含めるためにフォーマット 2 を使います。リストアコマンドは引き続きフォーマット 1 のバックアップを読み込めます。古いビルドはフォーマット 2 を拒否します。ローカルライブラリを黙って失うことがないようにするためです。
