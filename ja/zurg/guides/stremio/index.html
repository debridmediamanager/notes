Stremioアドオン

zurg は Stremio のアドオンとして応答できます。Stremio は IMDb id で問い合わせてきます。zurg は Newznab インデクサーを検索し、選んだリリースの NZB を Usenet バックエンドに取り込みます。その後は zurg の他のリリースと同じように再生・修復されます。 このやり方で再生したものはすべてライブラリにも追加され、Plex にも表示されます。

設定

このアドオンには NZB アカウントが必要です。データを実際に配信するのは、nzb または torbox_nzb のどちらかです。インデクサーも 1 つ以上必要です。torbox_nzb を使う場合、TorBox に既にあるリリースは、ほかに待機中の NZB 投稿がなければアドオンの待ち時間内に再生が始まります。ただ、キャッシュされていないリリースは先に TorBox 側で完了させる必要があり、プレイヤーが待てる時間より長くかかります。

stremio:
  enabled: true
  # token: ""            # generated and kept in data/stremio-token when empty
  indexers:
    - name: my-indexer
      url: https://indexer.example
      api_key: YOUR_KEY
    - name: second-indexer
      url: https://second-indexer.example
      api_key: YOUR_KEY
      api_path: /api/v1/api   # for an indexer that 404s the default /api

設定はすべて config ページの Stremio Addon にあります。スイッチ、インデクサーの一覧、結果の上限数などです。アドオンの URL もそこに表示され、コピーボタンで取得できます。この URL は、ダッシュボードを開いたアドレスから作られます。使うべきアドレスはこれです。詳しくは 別のデバイスへのインストール を見てください。

zurg は起動時にアドオンの URL をログに出力します:

<zurg>/stremio/<token>/manifest.json

それを Stremio に貼り付けてください (Addons → 検索ボックスに URL を入力できます)。パスに含まれるトークンが認証のすべてです。Stremio のクライアントは独自の認証を送らないため、SABnzbd エンドポイントと同じように、これらのルートは basic auth の外に置かれています。この URL はパスワードと同じように扱ってください。生成される再生リンクにはインデクサーの API キーが含まれており、URL を持つ人があなたのインデクサーの grab 回数やニュースサーバーの接続を使い切ってしまう可能性があります。

別のデバイスへのインストール

Stremioは、アドオンをプレーンなhttpで指定できるのは、Stremio本体が動いているコンピューター上だけです。つまり、zurgのマシン上でhttp://127.0.0.1またはhttp://localhostを使う場合に限られます。それ以外の場所ではhttpsが必要です。テレビやスマートフォン、別のコンピューターからhttp://のアドレスを指定すると、zurgにちゃんと届く場合でもfailed to load manifestと表示されます。LANのアドレスやTailscaleのアドレスでも同じです。設定ページで、そのようなアドレスをhttpで開いた場合は、アドレスURLの横にその旨が表示されます。

zurgはhttpsを直接提供しません。前段にhttpsに対応したものを置いてください。そのうえで、httpsのアドレスで設定ページを開き、そこからアドレスURLをコピーします。zurgは、リクエストが届いたアドレスをもとに、アドレスURLとすべての再生リンクを組み立てます。公開URLの設定はなく、base_urlもここでは使われません。1つのzurgで、LAN内のプレーヤーとリモートのプレーヤーを同時に使えます。

前段のものは、zurgに次の2つを伝える必要があります。ホスト名はHostヘッダーまたはX-Forwarded-Hostから取得されます。スキームはX-Forwarded-Proto: httpsから取得されます。このヘッダーがないと、アドオンは読み込めても再生リンクがhttp://で返ってきて、再生に失敗します。以下の各オプションは、どちらも両方のヘッダーを送るようになっています。

Stremioは2つのパスを使います。/stremio/はアドオンです。/strm/e/は、再生ボタンを押したときにプレーヤーを動画へ誘導する場所です。Stremioはパスワードを送れないため、どちらもzurgのパスワードなしで動作します。アドオンURLに含まれるトークンが、これらを保護しています。zurgをインターネットに公開する場合は、この2つのパスだけを公開してください。それ以外はダッシュボードとライブラリ用です。

Tailscale Serve

Stremio を動かすすべての機器で Tailscale が使えるなら、これが一番簡単な方法です。zurg はインターネットに公開されないままになります。

  1. Tailscale の管理コンソールで MagicDNS と HTTPS certificates をオンにします。

  2. zurg のマシンでこれを実行します。zurg が 9999 番ポートで動いていない場合は、自分のポート番号を使ってください。

    tailscale serve --bg 9999

    Windows では同じコマンドを PowerShell で実行してください。"access denied" と表示された場合は、管理者として開いた PowerShell で実行します。Linux では、sudo tailscale set --operator=$USER で自分を Tailscale の operator にしていない限り、先頭に sudo を付けてください。macOS で tailscale が見つからない場合は、Tailscale アプリに含まれているコマンドを使います。/Applications/Tailscale.app/Contents/MacOS/Tailscale です。

  3. https://<machine>.<tailnet>.ts.net/config/ を開き、Stremio Addon カードにあるアドオン URL をコピーしてください。

Tailscale が証明書を取得し、両方のヘッダーを送ります。tailscale serve reset を実行すると、元に戻せます。

Tailscale を動かせない機器では、代わりに Tailscale Funnel を使えます。これは同じアドレスをインターネットに公開します。Stremio に必要なものだけを公開してください。

tailscale funnel --bg --set-path /stremio http://127.0.0.1:9999/stremio
tailscale funnel --bg --set-path /strm/e http://127.0.0.1:9999/strm/e

設定ページはそのアドレスにはありません。いつも開いているとおりにページを開いてアドオン URL をコピーし、先頭部分を https://<machine>.<tailnet>.ts.net に置き換えてください。Tailscale は Funnel に使える帯域を制限しています。4K remux はカクつくかもしれません。

自分でのリバースプロキシ

すでにドメインと証明書を使ってリバースプロキシを動かしていますか？ それなら zurg を追加しましょう。 Caddy は Host ヘッダーを保持し、X-Forwarded-Proto も自動で送ってくれます。 これで Stremio 用の 2 つのパスだけが公開され、それ以外は公開されません。

zurg.example.com {
    handle /stremio/* {
        reverse_proxy 127.0.0.1:9999
    }
    handle /strm/e/* {
        reverse_proxy 127.0.0.1:9999
    }
    handle {
        respond 404
    }
}

nginx は、両方のヘッダーを指定しない限り、どちらも送りません。

location ~ ^/(stremio|strm/e)/ {
    proxy_pass http://127.0.0.1:9999;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
}

それを、証明書を使って 443 で待ち受けている既存の server ブロックの中に書いてください。proxy_buffering off を設定すると、動画ストリームが nginx のバッファを通らず、そのまま流れます。

Cloudflare Tunnel

名前付きトンネルを使うと、Cloudflare に登録しているドメインで zurg に https のアドレスを割り当てられます。ポートを開く必要はありません。Cloudflare が Host ヘッダーを保持し、X-Forwarded-Proto も自動で送ってくれます。トンネルの config.yml では、Stremio のパスだけをルーティングしてください。

ingress:
  - hostname: zurg.example.com
    path: ^/(stremio|strm/e)/
    service: http://127.0.0.1:9999
  - service: http_status:404

先に知っておいてほしいことが 2 つあります。Cloudflare は 100 秒を超えるリクエストを打ち切ります。リリースの最初の再生は、それより長くかかることがあります。そのときは、もう一度再生を押すと始まります。また、Cloudflare の利用規約では、有料プランを使わずに大量の動画を自社ネットワークに流すアカウントを制限することがあります。再生はすべてトンネルを通ります。

再生時の動作

ストリームを選ぶことは grab です。zurg はインデクサーから NZB をダウンロードし、 nzbs/ に配置します。このとき SABnzbd エンドポイントと同じ命名ルールを使うので、 同じリリースを 2 回 grab した場合や、*arr がすでに grab している場合は、 重複させずに既存のものを見つけます。その後ライブラリに一覧されるまで待ち、 プレイヤーを、すべての .strm ファイルがすでに再生に使っている、署名付きの /strm/e/ エンドポイントへリダイレクトします。 このエンドポイントでは、範囲読み取り、アカウントのフェイルオーバー、RAR/7z の内部読み取りに対応しています。

そのため、リリースを最初に再生するときは、debrid ストリームより時間がかかります。NZB の取得と解析、 そしてアーカイブ内部の読み取りが必要だからです。通常は数秒ですが、命名処理を実行する必要がある難読化された投稿では、1 分から 2 分かかることもあります。待ち時間内に再生が始まらない場合は、Retry-After 付きの 503 を返します。もう一度再生を押すと、高速パスに入ります。それ以降の再生はすぐに始まります。

リリースがライブラリに一覧されたものの、再生できるファイルが何もないとわかる場合があります。多くは、スプールから期限切れになったリリースや、ニュースサーバーのチェックですべてのファイルが壊れていると判定されたリリースです。それでもクリックが無駄になるわけではありません。再生 URL には、それを生成したときのリクエストが含まれているため、zurg はそのタイトルのリリースを再度ランク付けし、選んだ行の後ろにある行を順に試します。各行は同じ grab と一覧の流れを通ります。最初に再生できたリリースに、プレイヤーがリダイレクトされます。zurg は、リストに表示された行だけでなく、回答全体を順に試します。max_results は、人がスクロールする量を指定するものです。それで回復処理まで制限されると、検索で見つかっていた候補があっても、10 行目に表示されたタイトルは 9 行しか試せなくなってしまいます。選んだ行の後ろにある行は、同じ解像度か、より小さいサイズか、ひとつ下の解像度のリリースです。ユーザーが見送った、より大きなリリースが試されることはありません。フォールバック先がまだ取り込み中の場合も、同じ 503 を返します。そのリリースはすぐに拒否され、もう一度再生を押すと、フォールバック先が高速パスで見つかります。最後の拒否だけが次の行へ進みます。503 が返った場合は、次の行には進みません。各試行はインデクサーの grab を 1 回使い、ほかの grab と同じようにリリースをライブラリに残します。そのため、この連鎖には 25 秒の予算と、最大 6 回の試行という上限があります。予算が必要なのは、試行ごとのコストが同じではないからです。スプールから期限切れになったリリースは 1 秒未満で拒否されます。一方、取り込みを行い、アーカイブを開いてから何も再生できないとわかるリリースは、予算のほとんどを使い切ることがあります。試した行がすべて拒否されたら、従来どおり 404 を返します。各フォールバックは、拒否したリリースと次に試したリリースを、info レベルでログに記録します。

2026年9月7日に、Usenet を使う他の Stremio アドオン 3 つと比較して計測した結果です: stremio-addon-findings-2026-09-07.md。 要約すると、解像度ごとの上限は前回の調査で見つかった問題を修正しましたが、カバー率はそれでも半減していました。上限 5 件のバケットは、最初に再生可能なエントリがスプールから期限切れになったリリースである場合に行き場がないためです。上記のフォールバックは、その調査結果に対する最初の修正です。バケットは 5 件から 10 件に増えました。

検索の動作

  • 映画は t=movie、エピソードは season/ep を付けた t=tvsearch で検索します。どちらも imdbid で、数字だけの形式で送ります。tt 形式だと結果がゼロになるインデクサーがいくつかあるためです。
  • 各インデクサーには search_limit 件のリリースを求めます（デフォルトは100）。以下のすべての上限は、この要求された件数の中から選ぶので、回答の上限になります。
  • インデクサーには並列で問い合わせます。1つが拒否しても（バーストリミットや無効なキーなど）、失われるのはそのインデクサーの結果だけで、リスト全体は失われません。拒否はインデクサーごとにログに記録されます。
  • 結果はリリース名で重複を除き、解像度を優先し、次にサイズ順に並べ、解像度ごとに max_results（デフォルトは10）件で打ち切ります。上限を解像度ごとに数えるのは、並び順が2160pを先頭にするためです。人気のタイトルはどんな上限よりも多くのUHDリリースがサイズ上限内に入るので、リスト全体で数えると、他に何が見つかっていても、結果がremuxばかりになってしまいます。
  • 各解像度が残すのは、最大サイズの上位数件ではなく、サイズの幅です。最大のリリースから最小のリリースまで等間隔に選び、両端は必ず含めます。上位から残すと、5件の1080pは19〜30GBのremuxが5件になり、スマホやノートPCがそのまま再生できる4GBのエンコードは、上限によって必ず消えてしまいます。2026年9月7日時点で計測したところ、The Shawshank Redemption の zurg の15件中3件が6GB未満でした。同じインデクサーでは、そのような作品が40件ありました。解像度内のリストは、サイズの降順のままです。インデクサーがサイズを示さなかったリリースは、この軸に置く場所がないので、サイズのわかるリリースが残した余地を埋めるためだけに使われます。
  • 各ストリームの説明には、リリース名、サイズ、見つけたインデクサー、そして投稿されてからの経過時間（インデクサーが示した場合のみ、3d、126d、2y のように表示）が含まれます。ニュースサーバーでの保存期間切れは、2026年9月7日の試行で再生が失敗する最も多い原因でした。投稿日は、視聴者がそれを避けるための唯一の目安になります。
  • max_size_gb より大きいリリースは、ランク付けの前に除外されます。リミックスを再生できないプレーヤー向けです。デフォルトでは除外はありません。上記の幅によって、各解像度の最小のリリースがリミックスと並んで既に表示されているからです。インデクサーがサイズを示さなかったものは残します。この上限はリストを表示する時に適用されるので、上限を変えるとキャッシュ済みのタイトルにも反映されます。
  • 結果は data/stremio-cache/ にタイトルごとに1ファイルずつ、ディスクにキャッシュされます。そのため、タイトルを開き直してもインデクサーへの問い合わせはゼロです。インデクサーは1日のクォータ制限があることが多く、Treasure Maps は短時間に約6回連続で呼ぶと拒否するためです。回答の有効期間は、検索で見つかった数に応じて変わります。見つかった数が少ないのは、アップロードがまだ届いている途中か、インデクサーが停止していた証拠だからです。1件なら1時間、2件なら2時間、最大4件までは同様です。5件以上は確定した回答とみなし、cache_hours（デフォルトは24。設定可能なのはこの値だけ）の間有効です。空の回答はキャッシュしません。キャッシュされたストリームリストの最下部には、どれくらい古いかを示す refresh 項目があります。その項目を開くと（プレーヤーではなくブラウザで開きます）、そのタイトルのキャッシュが消去され、タイトルを開き直すと新しく検索されます。キャッシュは再起動後も残り、期限切れのエントリーは自動的に削除されます。
  • シーズン0（スペシャル）は、誤った方法で検索するのではなく、拒否されます。また、ID検索の対象範囲はインデクサー次第です。インデクサーがテキスト検索でしか見つけられないリリースは、表示されません。
