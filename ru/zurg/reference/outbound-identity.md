# Идентичность исходящего запроса {#outbound-request-identity}

`user_agent` задаёт общий HTTP User-Agent для API debrid-сервисов и чтения с CDN, поиска Newznab, загрузки NZB, OpenSubtitles, проверок ffprobe, интеграций с медиасерверами, загрузки зависимостей, обновлений и необязательных экспортов для обмена или логов. По умолчанию используется обычный агент браузера. Пустое значение возвращает этот вариант по умолчанию. Явно заданное пользовательское значение отправляется как введено, даже если оно указывает на приложение.

`omit_user_agent: true` отключает заголовок User-Agent в HTTP-клиентах Go и даёт ffprobe пустой агент, переопределяя заданную строку. Некоторые сервисы могут отклонять запросы без агента. GitHub отклоняет все такие запросы с ошибкой 403, поэтому запросы к GitHub (`zurg update`, а также загрузки rclone и ffprobe) всё равно отправляются с заданным агентом или с обычным агентом браузера, если он не задан.

Plex, Jellyfin и Emby также требуют метаданные клиента и устройства. Их можно настроить через `outbound_client_name`, `outbound_client_id`, `outbound_client_version`, `outbound_device_name`, `outbound_device_id` и `outbound_platform`. Значения по умолчанию: `Media Client`, `media-client`, `1.0`, `Media Client`, `media-client` и `Desktop` соответственно. Plex использует client ID для аутентификации, сканирования и запросов метаданных. Jellyfin и Emby используют device ID в метаданных аутентификации. Поля применяются только там, где их поддерживает протокол. Если изменить ID, медиасервер может показывать клиент или устройство под другим именем.

Все эти настройки доступны в разделе Network & Connectivity на дашборде. Дашборд показывает сохранённые значения с подставленными значениями по умолчанию. Перезапуск применяет настройки все вместе. Простое сохранение не меняет текущую идентичность в работе. Значения должны состоять из печатаемых ASCII-символов и быть не длиннее 2048 символов. Поля клиента и устройства не могут содержать кавычки или обратные слэши. Токены аутентификации и названия заголовков протокола не меняются, в том числе обязательный для DMM учётный токен `X-Zurg-Token`.

Клиенты провайдеров и индексаторов удаляют заголовки `Referer`, `Origin` и `X-Zurg*` перед отправкой запросов, включая редиректы. Так редиректы не могут через Referer раскрыть приватные пути предыдущих URL или query-параметры с API-ключами. Аутентификация, range-запросы, cookies провайдеров и лимиты редиректов остаются без изменений. В эти запросы не добавляются идентификаторы клиента или устройства приложения.

NNTP отправляет `AUTHINFO USER`, `AUTHINFO PASS`, `BODY`, `STAT`, `DATE` и `QUIT` по мере необходимости, без команды, которая определяет программное обеспечение. Настроить NNTP software ID нельзя, его просто нет. Имена пользователей и пароли остаются в NNTP-настройках каждого провайдера. Тесты TLS и открытого текста покрывают аутентификацию, доступ к статьям, keep-alive и завершение соединения.

Это минимизирует явные идентификаторы приложения, но не обеспечивает анонимность. Удалённые сервисы по-прежнему видят учётные данные, IP-адреса источника, запрошенный контент и время запросов. Поведение TLS/HTTP, пользовательские идентичности, API-ключи, зарегистрированные приложением, и шаблоны доступа (включая тестовые ссылки сети Real-Debrid) могут помочь в корреляции. Внешние URL, метаданные торрентов, ID статей, данные для обмена и содержимое экспортируемых логов и конфигов не переписываются. URL для загрузки программ указывают на запрошенное программное обеспечение. Внешние плееры и отдельно запускаемые инструменты используют свои собственные настройки.

Регрессионные тесты на уровне сокетов покрывают значения по умолчанию, пользовательские и отключённые агенты, редиректы, сохранение аутентификации и метаданные медиасервера. Тесты конфига и дашборда покрывают валидацию, YAML round trip и применение настроек при перезапуске.
