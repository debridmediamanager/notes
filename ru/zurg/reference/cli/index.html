Командная строка

Бинарник zurg — это сервер и набор утилит. Запустите его без команды, чтобы стартовал сервер. У каждой команды есть --help, который выводит текст, по которому написана эта страница.

Запускайте команды из рабочей папки экземпляра. zurg читает ./config.yml из неё, если вы не передали --config. Папки данных и логов тоже определяются относительно этой директории.

zurg [flags]
zurg [command]

Флаги, которые принимают все команды

Флаг Что делает
-c, --config Конфигурационный файл, который нужно прочитать. По умолчанию ./config.yml.
-v, --version Выводит версию сборки и завершает работу. Вывод совпадает с zurg version.
-h, --help Выводит справку по zurg или по одной команде.

Настройка

zurg setup

Записывает конфиг и скачивает rclone и ffprobe. Затем регистрирует zurg на автозапуск. Если чего-то не хватает, спрашивает. --dry-run выводит план и ничего не меняет.

Ключи и пароли читаются из файлов. Так они не попадают в историю шелла.

Флаг Что делает
--provider Провайдер для настройки. Повторите флаг, чтобы указать несколько. Один из realdebrid, torbox, alldebrid, nzb, premiumize, debridlink, offcloud, torbox_nzb. torbox_nzb берет ключ из --torbox-token-file или TORBOX_TOKEN, как и torbox.
--realdebrid-token-file Читает токен Real-Debrid из этого файла. Такой же флаг есть для torbox, alldebrid, premiumize, debridlink и offcloud.
--nntp-host Новостной сервер для провайдера nzb.
--nntp-port Его порт. По умолчанию 563 с TLS и 119 без него.
--nntp-tls Использовать TLS. Включено по умолчанию.
--nntp-username Имя пользователя новостного аккаунта.
--nntp-password-file Читает пароль новостного аккаунта из этого файла.
--nntp-connections Допустимое количество подключений для новостного аккаунта. По умолчанию 8.
--mount-path Где появится монтирование. По умолчанию используется принятое для вашей платформы место.
--port HTTP-порт. Если не указать, значение из конфига сохраняется.
--service-name Имя службы или запланированной задачи. По умолчанию zurg.
--service-scope auto, user или system. По умолчанию auto.
--service-user Пользователь, от имени которого работает системная служба.
--no-service Настраивает всё, но не регистрирует автозапуск.
--no-start Регистрирует службу, но не запускает её.
--skip-downloads Не скачивает rclone и ffprobe.
--skip-prerequisites Пропускает проверку FUSE для этой платформы.
--non-interactive Завершается с ошибкой вместо запроса недостающих данных.
--dry-run Выводит план и ничего не меняет.

Для каждой платформы есть своё пошаговое руководство.

  • Linux
  • macOS
  • Windows
  • Docker

zurg doctor

Проверяет, что настройка установки сделала. Он читает конфиг и ищет rclone и ffprobe. Потом проверяет сервис, HTTP-эндпоинт и монтирование. Если что-то не работает, запустите его первым делом.

Flag What it does
--working-dir Рабочая директория экземпляра. По умолчанию текущая.
--service-name Имя сервиса для проверки. По умолчанию zurg.
--service-scope auto, user или system. По умолчанию auto.

zurg service

Устанавливает и управляет автозапуском без запуска остальной настройки.

Command What it does
zurg service install Устанавливает автозапуск и запускает его. Передайте --start=false, чтобы установить без запуска.
zurg service uninstall Удаляет автозапуск. Конфиг и данные остаются.
zurg service start Запускает установленный сервис.
zurg service stop Останавливает его.
zurg service restart Перезапускает его.
zurg service status Показывает статус автозапуска.

Все они принимают одни и те же флаги.

Flag What it does
--name Имя сервиса или запланированной задачи. По умолчанию zurg.
--scope auto, user или system. По умолчанию auto.
--user Пользователь, от имени которого запускается системный сервис.
--working-dir Рабочая директория, в которой стартует сервис.
--executable Бинарный файл zurg, который запускает сервис.

zurg download-requirements

Скачивает rclone и ffprobe в папку и прописывает их пути в конфиг. Setup делает это за вас, если только не передать --skip-downloads.

Flag What it does
--dir Куда положить бинарники. По умолчанию bin.
--rclone-version Версия rclone, например 1.67.0. По умолчанию latest.
--ffprobe-version Версия ffprobe. По умолчанию latest.

zurg update

Заменяет бинарник на самую свежую ночную сборку для спонсоров. Аккаунт GitHub, который для этого используется, должен иметь доступ спонсора через gatekeeper. Внутри контейнера команда отказывается работать, потому что следующее пересоздание контейнера удалит новый бинарник. Вместо этого загрузите новый образ. --force обновит всё равно.

Вход в GitHub выполняется через GitHub CLI. Это либо та программа, что лежит в вашем PATH, либо та, которую установщики держат в bin рядом с zurg. Вход, сохранённый GitHub CLI без keyring, работает, даже если сам CLI уже удалён. GITHUB_TOKEN тоже подходит. Если ничего не найдено, команда выводит команду установщика, которая восстанавливает GitHub CLI.

zurg version

Выводит информацию о сборке. zurg --version выводит то же самое.

Где получить помощь

поддержка zurg

Отправляет твой лог и конфиг в поддержку DMM и выводит код поддержки, например K7QM-3XPD. Вставь этот код в свою тему поддержки в Discord. Он хранится 7 дней, и открыть его может только поддержка DMM.

Она отправляет то же самое, что и Export Logs на дашборде, так что используй её, когда zurg не запускается или до дашборда не достучаться. Запускай её из рабочей папки zurg: она читает там config.yml (или файл из --config) и logs/zurg.log. В Docker выполни docker exec <container> /app/docker-entrypoint.sh support, он сам выберет нужную папку. Если контейнер не держится запущенным, выполни docker run --rm -v <your config folder>:/config ghcr.io/debridmediamanager/zurg:<tag> support, указав ту же папку, что монтируешь для zurg.

Токены, пароли, ссылки на загрузку и твои собственные имена хостов сначала удаляются, так же как это делает дашборд. Конфиг, который не загружается, не отправляется: вместо него отправляется ошибка, которую он выдаёт. Длинный лог обрезается с самого старого конца, чтобы влезть, и в пакете об этом написано.

Если сервер поддержки DMM недоступен или отклоняет загрузку, zurg сообщает причину и вместо этого отправляет два файла на публичные сервисы для вставки текста, выводя их ссылки. Если отправить вообще ничего не получилось, он записывает те же очищенные файлы в zurg-debug.tar.gz, чтобы ты прикрепил его к своей теме.

Резервные копии

zurg backup

Создаёт файл .zurgbackup, в котором лежит всё, что нельзя восстановить из других источников. Это конфиг с токенами и каждый data/*.zurgtorrent со своими тегами и связками с аккаунтами. Также туда попадает хранилище __magic__ из data/local/ и исходные NZB из nzbs/. Кэши, снимки Plex и логи в архив не входят, чтобы бэкап был такого же размера, как то, что он защищает.

Инстанс для этого не нужно запускать. Поэтому бэкап можно спокойно ставить в расписание. Файл представляет собой gzip-архив tar с вашими токенами внутри. Храните его как пароль.

Флаг Что делает
-o, --out Куда записать файл. По умолчанию zurg-<timestamp>.zurgbackup в текущей директории.
--include-caches Дополнительно включает производные метаданные и закэшированные байты для быстрого «тёплого» восстановления. Снимки Plex и логи по-прежнему не включаются. Файл может получиться большим.

zurg restore-backup

Распаковывает .zurgbackup в текущую папку. Каждый файл возвращается по тому пути, откуда был взят. Сначала останови zurg. Восстановление пишет файлы, в которые одновременно пишет запущенный экземпляр.

zurg restore-backup my-backup.zurgbackup

Конфиг, уже лежащий в папке, не трогается. Этот файл хранит токены, на которых держится вся библиотека. Передай --force-config, чтобы перезаписать его.

Измерения

zurg benchmark-my-setup

Он читает реальные байты так, как это делал бы плеер, и показывает разброс, а не одно число. Работает в три этапа. Сначала каждый аккаунт отдельно. Это число и надо сравнивать с тем, что обещает сервис. Затем все аккаунты сразу. Если каждый аккаунт отдаёт 70 MiB/s в одиночку, а вместе они дают 25 MiB/s, значит, они делят один насыщенный канал. В конце он читает через rclone mount. Разница с первым этапом показывает, сколько съедают FUSE и VFS.

Образцы берутся по случайным смещениям. Все нижележащие слои кешируют данные, и если читать одно и то же смещение снова, вы измерите кеш, а не канал.

Он ничего не добавляет и не удаляет. Но он тратит ваш трафик. Каждый аккаунт читает размер образца, умноженный на количество итераций, дважды. Этап с mount идёт поверх этого.

Флаг Что делает
-n, --iterations Образцов на аккаунт на каждом этапе. По умолчанию 3.
--sample-mb MiB, которые читаются за один образец. По умолчанию 128. Используйте 1024, чтобы пройти рамп read-chunk в rclone и получить устойчивую цифру для mount.
--provider Тестирует только указанные аккаунты по имени. Можно повторять.
--skip-concurrent Пропускает этап со всеми аккаунтами сразу.
--skip-mount Пропускает этап с mount.
--json Выводит отчёт в формате JSON.

zurg network-test

Измеряет, насколько быстро этот хост достигает каждого сервера загрузки Real-Debrid по IPv4 и по IPv6. Результаты записываются в logs/network-test.log и в data/, откуда сервер их читает, чтобы выбрать хосты. Чтобы тестировать через прокси, задайте PROXY в окружении.

Flag What it does
-t, --test-url Файл по URL, путь которого запрашивается с каждого сервера вместо собственного тестового файла Real-Debrid для проверки скорости.

Plex

Эти три работают с Plex-сервером на этом хосте. Сначала настройте Plex. См. Plex Integration.

zurg plex-settings

Сообщает, какие настройки Plex важны для монтирования, и исправляет то, что допускает политика. Значения Plex по умолчанию рассчитаны на локальные диски. Одна из них удаляет библиотеку, если при сканировании случается сбой. Другие заставляют Plex декодировать каждый файл, который у него есть. plex.md объясняет каждую из них.

Flag What it does
-p, --policy off, warn, guard или enforce для этого запуска. По умолчанию используется plex_settings_policy из конфига. Если передать более строгую политику, можно сначала посмотреть, что она изменит, прежде чем её принять.

zurg plex-drift

Читает базу данных Plex, не записывая в неё, и проверяет каждый файл, на который она ссылается, в примонтированной папке. Выводит те, которых уже нет. Запускайте перед сканированием библиотеки. Если скан наткнётся на эти файлы, он превратит их в удаления. Зная количество заранее, вы принимаете решение осознанно, а не рискуете вслепую.

Нужны plex_database_path и Plex на том же хосте.

zurg plex-backups

Показывает снимки базы данных Plex, которые хранит zurg, от новых к старым. В каждой строке видно, когда снимок был сделан, его размер и сколько элементов было в каждой библиотеке на тот момент. Количество берётся из самих снимков, поэтому список показывает, что каждый из них реально может восстановить. Обслуживание библиотеки Plex рассказывает, когда zurg их создаёт.

Совместный доступ

zurg export-torrents

Записывает переносимые файлы .zurgtorrent, которые описывают ваши релизы без вашего аккаунта внутри. Учётные данные не попадают в файлы. Ни torrent id, ни состояние repair, ни ссылки CDN тоже. Провайдер не опрашивается.

Читает data/*.zurgtorrent или старый файл дампа. Передайте файл или папку, чтобы экспортировать только их. Получатель кладёт файлы в torrents/<their-account>/ и ставит для этого аккаунта library.source: local. portable-libraries.md описывает приёмную сторону.

Flag What it does
--provider Экспортирует релизы, которые хранятся на этом настроенном аккаунте.
--output Куда записываются переносимые файлы.
--replace Заменяет существующий экспорт с тем же hash.
--skip-invalid Пропускает и считает записи, которые не удаётся прочитать при массовом экспорте.

zurg nzb-share

Собирает из ваших NZB набор, который можно опубликовать. На выходе получается папка с manifest.json и одним .nzb.gz на каждый релиз. Имя файла — хеш содержимого.

Сначала каждый NZB очищается. Удаляются комментарии, DOCTYPE и метаданные водяных знаков. Также удаляются исходные имена файлов. Удаляются и постеры с датами, а каждому файлу ставится одна и та же фиксированная группа новостей. Дело в том, что некоторые индексаторы меняют все три при каждой загрузке. Отметки аккаунта, которые индексатор прячет в теме, заголовке или пароле, тоже вырезаются. В опубликованном наборе есть название релиза, но никогда не указывается аккаунт, который его скачал. Настоящие пароли к архивам остаются, потому что получателям они нужны, чтобы открыть релиз.

Публикуйте папку на любом статическом хостинге. Подойдёт git-репозиторий, сайт на Pages или rclone serve. Отчёт о том, что было вырезано, остаётся на вашем компьютере и выводится здесь. В нём как раз те идентификаторы, ради удаления которых и нужна очистка.

Флаг Что делает
--from Папка с наблюдением, которой нужно поделиться. Обходится рекурсивно. По умолчанию nzbs.
--out Папка для результата. По умолчанию nzb-share-<timestamp>.
--title Название, которое записывается в manifest.
--filter Делится только путями источников, которые подходят под это регулярное выражение.

Дашборд тоже может раздавать набор. См. Публичный обмен NZB.

zurg nzb-sync

Подтягивает общую библиотеку в вашу папку наблюдения. Он берёт manifest.json шары по URL или из локального пути. Перед записью каждый NZB проверяется по хешу из манифеста. Сами байты скачивают ваши собственные аккаунты новостных серверов.

zurg nzb-sync https://example.com/share/manifest.json

Он только добавляет. Записи, которые у вас уже есть, пропускаются, а шара ничего не удаляет. Две шары с одними и теми же релизами убирают дубликаты по хешу содержимого.

Flag What it does
--into Папка наблюдения, куда писать. По умолчанию nzbs.
--dry-run Показывает, что было бы записано, но ничего не пишет.

Очистка аккаунта Real-Debrid

Эти две команды удаляют всё одного типа из аккаунта Real-Debrid. Отменить это нельзя. Работают они только с Real-Debrid.

Обе просят cookie auth из залогиненной браузерной сессии Real-Debrid, а не ваш API-токен. Они выводят строку JavaScript, которая его показывает. Выполните её в консоли браузера на real-debrid.com и вставьте результат.

Команда Что делает
zurg clear-torrents Удаляет все торренты в аккаунте.
zurg clear-downloads Удаляет все загрузки в аккаунте. Это разблокированные ссылки.

Автодополнение в оболочке

zurg completion bash выводит скрипт автодополнения для bash. То же самое работает и для zsh, fish и powershell. zurg completion <shell> --help подскажет, куда его положить.
