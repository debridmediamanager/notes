# Эндпоинт MCP {#the-mcp-endpoint}

zurg может отвечать ИИ-агенту по протоколу [Model Context Protocol](https://modelcontextprotocol.io):
клиент спрашивает, какие инструменты есть, zurg их описывает, а агент вызывает их,
чтобы почитать библиотеку, понять, почему релиз не воспроизводится, починить его
или управлять медиасерверами. Это тот же набор операций, что доступен в панели и CLI,
только в виде типизированных инструментов со схемами, а не в виде HTML и редиректов 303.

Эндпоинт по умолчанию выключен. Он находится за той же базовой аутентификацией, что и панель,
и zurg вообще не запускает его, если не задано имя пользователя: при пустом значении
каждый маршрут на сервере открыт всем, а эти инструменты удаляют релизы.

## Конфигурация {#configuration}

```yaml
mcp:
  enabled: true
```

Это всё, что нужно для обычной установки. Остальное имеет значения по умолчанию, которые стоит знать:

```yaml
mcp:
  enabled: true
  toolsets: [library, releases, repair]   # the default; see below
  read_only: false                        # withhold every tool that changes anything
  allow_unauthenticated: false            # serve /mcp with no username set
  allow_lifecycle: false                  # admit the tools that stop zurg or its mount
  page_limit: 50                          # items a listing returns by default; 500 is the cap
  max_result_kb: 256                      # ceiling on one result; a page over it is trimmed
  session_timeout_mins: 30                # -1 keeps sessions for the life of the process
```

Как и другие блоки функций, это читается один раз при запуске: чтобы изменения вступили в силу, нужен перезапуск.

## Подключение {#connecting}

### По HTTP {#over-http}

Эндпоинт — `/mcp` на обычном порту zurg, работает по Streamable HTTP. Укажите клиенту адрес
`http://<host>:9999/mcp` и учётные данные от дашборда.

```bash
npx @modelcontextprotocol/inspector
# Transport:  Streamable HTTP
# URL:        http://localhost:9999/mcp
# Header:     Authorization: Basic <base64 of user:password>
```

### По stdio {#over-stdio}

Клиенты, которые понимают только stdio, используют подкоманду `zurg mcp`, которая связывает их с уже запущенным экземпляром:

```json
{
  "mcpServers": {
    "zurg": {
      "command": "/path/to/zurg",
      "args": ["mcp"],
      "cwd": "/path/to/your/zurg/directory"
    }
  }
}
```

`cwd` важен: все пути zurg вычисляются относительно рабочей директории, и именно оттуда `zurg mcp` читает `config.yml` с портом и учётными данными. С ними никаких аргументов не нужно. `--username` и `--password` переопределяют локальные учётные данные. Пользовательский `--url` никогда не берёт учётные данные из локального конфига. Передай оба флага с учётными данными явно, если этот эндпоинт их требует, чтобы локальный пароль случайно не ушёл на другой хост.

Он не запускает второй экземпляр. Второй zurg загрузил бы всю библиотеку, занял бы второй набор слотов у провайдера на аккаунтах, где их считают, и конкурировал бы с первым за монтирование. Поэтому команда работает как канал к демону и ничего не отдаёт, если демон не запущен. Её диагностика идёт в stderr, потому что stdout несёт протокол.

Одно ограничение: уведомление, которое сервер отправляет вне какого-либо вызова, через мост не проходит. Прогресс и строки логов, которые появляются *во время* вызова, приходят в его собственном ответе и доставляются нормально. Это охватывает всё, что шлёт zurg.

## Наборы инструментов {#toolsets}

Полный набор инструментов zurg насчитывает несколько сотен инструментов, и клиент с таким количеством плохо справляется. Начиная примерно с восьмидесяти, модель чаще выбирает не тот инструмент, а одни только схемы съедают десятки тысяч токенов. Поэтому `toolsets` выбирает группы, а по умолчанию включён рабочий поднабор, а не всё сразу.

| Набор инструментов | Есть по умолчанию | Что покрывает |
|---|:-:|---|
| `library` | да | Поиск, списки каталогов, количество тегов |
| `releases` | да | Один релиз подробно: файлы, копии по аккаунтам, что может отдавать каждый файл |
| `repair` | да | Что сломано, дойдёт ли до этого ремонт, принудительный запуск ремонта |
| `releases_write` | | Удаление, переименование, тегирование, принудительный показ и запись файлов `.strm` |
| `magic` | | Пространство имён `__magic__`: сохранённая структура, её строки и перемещение объектов |
| `plex` | | Plex, Jellyfin и Emby: статус, сопоставление и сканирование с защитой |
| `providers` | | Настроенные аккаунты: что умеет каждый, доступен ли он и сколько потратил |
| `usenet` | | Бэкенд NZB: новостные аккаунты, проверки статей, повреждения и кэш статей |
| `clients` | | Эндпоинты SABnzbd, qBittorrent и Stremio, к которым обращаются Sonarr и Radarr |
| `diagnostics` | | Журнал, счётчики байтов, память и горутины |
| `config` | | Чтение конфигурации, поиск расхождений и запись выбранного набора ключей |
| `mount` | | Монтирование rclone: статус, сброс закэшированных списков, перезапуск |
| `system` | | Сведения о сборке, `doctor`, сервис, резервные копии и обновление |

`toolsets: [all]` включает все группы. Имя с префиксом `-` вычитает группу, поэтому `[all, -config, -system]` даёт весь набор без двух групп, которые меняют машину, а не библиотеку. Нераспознанное имя выводит предупреждение при запуске и игнорируется: опечатка не должна отключать эндпоинт.

Инструменты, которые останавливают zurg, управляют его сервисом или перезапускают монтирование, не выделены в отдельную группу. Они находятся в `system` и `mount` и остаются скрытыми, пока не задан `allow_lifecycle`, независимо от того, что указано в `toolsets`.

Небольшая группа `server` (какая это сборка и завершилась ли загрузка библиотеки) всегда регистрируется, что бы ни было указано в `toolsets`. Если её скрыть, клиент не сможет понять, что все остальные ответы сейчас неполные.

## Чего он не будет делать без вашего запроса {#what-it-will-not-do-without-being-asked}

**Подтверждение.** Инструмент, который что-то удаляет, сначала описывает, что он сделает, и возвращает токен. Он выполняет действие, только если его вызвали снова с этим токеном. Токен привязан к плану, поэтому подтверждение нельзя перенести на другой план. Если библиотека изменилась в промежутке, второй вызов снова только описывает действие, а не выполняет его. Токены одноразовые, живут две минуты и не переживают перезапуск.

**`read_only`.** Один переключатель скрывает все инструменты, которые что-то меняют, независимо от того, что написано в `toolsets`. Оператора волнует не то, «какой из этих инструментов пишет», а то, «может ли это сломать мою библиотеку». Такие инструменты убираются из `tools/list`, чтобы клиент не мог выбрать возможность, которую эта конечная точка всё равно не пропустит. Проверка при вызове остаётся как дополнительная защита, на случай если текущая настройка изменится уже после запуска сервера.

**`allow_lifecycle`.** Инструменты, которые останавливают zurg, управляют его сервисом или перезапускают монтирование, скрываются так же, но за отдельным переключателем. Каждый из них может сразу убрать всю библиотеку. Действия с процессом и сервисом не могут сообщить свой результат, потому что могут завершить процесс, который отвечает на вызов.

**Секреты.** Ни один результат инструмента не содержит токен провайдера, API-ключ, пароль новостного сервера, готовую ссылку на CDN или подписанный URL `.strm`. Вывод логов очищается от секретов на выходе. Готовая ссылка работает для любого, у кого она есть, в аккаунте, который её создал. Лог диалога — не место для такой ссылки.

**Размер.** Каждый список ограничен дважды: лимитом элементов на странице и потолком на размер сериализованного результата. Один аккаунт, проверенный на этом, содержит 84,000 релизов. Это около двенадцати мегабайт одних только названий, ещё до того как перечислен хоть один файл. Результат, превышающий потолок, обрезается, и об этом прямо сказано.

## Заметки {#notes}

Эндпоинт наследует базовую аутентификацию дашборда, потому что регистрируется внутри него.
Запрос с другого источника отклоняется: `/mcp` предназначен для локального агента, а не для веб-страницы.
Обратный прокси перед zurg работает. Без этого проверка DNS-rebinding в библиотеке протокола отклоняла бы прокси, который пересылает свой `Host` и при этом обращается к `127.0.0.1`. Поэтому zurg отключает эту проверку и оставляет защиту базовой аутентификации.

`zurg mcp --help` показывает флаги моста. `zurg doctor` проверяет, отвечает ли эндпоинт вообще.
