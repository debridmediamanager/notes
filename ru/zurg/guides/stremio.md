# Дополнение для Stremio {#the-stremio-addon}

zurg умеет отвечать Stremio как аддон. Stremio запрашивает по IMDb id. zurg ищет по вашим Newznab-индексаторам и загружает NZB выбранного релиза в Usenet-бэкенд. Дальше он воспроизводит и восстанавливает его так же, как любой другой релиз zurg. Всё, что воспроизведено таким образом, тоже попадает в библиотеку и появляется в Plex.

## Конфигурация {#configuration}

Аддону нужен NZB-аккаунт, `nzb` или [`torbox_nzb`](../providers/torbox-nzb.md), который отдаёт сами данные, и хотя бы один индексатор. С `torbox_nzb` релиз, который TorBox уже сохранил, начнёт воспроизводиться в пределах времени ожидания аддона, если нет другого NZB-поста в очереди. Некешированный релиз сначала должен докачаться на TorBox, а это дольше, чем плеер обычно ждёт.

```yaml
stremio:
  enabled: true
  # token: ""            # generated and kept in data/stremio-token when empty
  indexers:
    - name: my-indexer
      url: https://indexer.example
      api_key: YOUR_KEY
    - name: second-indexer
      url: https://second-indexer.example
      api_key: YOUR_KEY
      api_path: /api/v1/api   # for an indexer that 404s the default /api
```

Всё это настраивается на странице конфигурации в разделе **Stremio Addon**: переключатель, список индексаторов и лимит результатов. Там же показан адрес аддона с кнопкой копирования. Он строится из адреса, по которому ты открыл дашборд. Именно его и нужно использовать, см. [Установка на другом устройстве](#installing-it-on-another-device).

При запуске zurg пишет адрес аддона в лог:

```
<zurg>/stremio/<token>/manifest.json
```

Вставь его в Stremio (Addons → в поле поиска можно вставить URL). Токен в пути и есть вся авторизация: клиенты Stremio не отправляют собственную авторизацию, поэтому маршруты находятся вне basic auth, как и эндпоинты SABnzbd. Относись к URL как к паролю: ссылки воспроизведения, которые он создаёт, содержат API-ключи твоих индексаторов, а тот, кто знает URL, может потратить твои загрузки (grab) у индексаторов и подключения к новостным серверам.

## Установка на другое устройство {#installing-it-on-another-device}

Stremio принимает дополнение по обычному `http` только на том компьютере,
где запущен сам Stremio. То есть это `http://127.0.0.1` или `http://localhost` на машине с zurg.
Везде в других местах нужен `https`. ТВ, телефон или второй компьютер покажут
**failed to load manifest** для адреса `http://`, даже если они без проблем достучатся до zurg.
Это касается и адреса в локальной сети, и адреса Tailscale. Страница конфигурации
пишет об этом рядом с URL дополнения, если ты открыл её по обычному `http` на таком адресе.

zurg сам `https` не отдаёт. Поставь перед ним что-нибудь, что его отдаёт.
Потом открой страницу конфигурации по адресу `https` и скопируй оттуда URL дополнения.
zurg строит URL дополнения и все ссылки на воспроизведение из того адреса, по которому пришёл каждый запрос.
Настройки публичного URL нет, и `base_url` здесь не используется.
Один zurg может обслуживать и плеер в локальной сети, и удалённый плеер одновременно.

То, что стоит перед zurg, должно передать ему две вещи. Имя берётся из заголовка `Host` или из `X-Forwarded-Host`. Схема берётся из `X-Forwarded-Proto: https`. Без этого заголовка дополнение загрузится, но ссылки на воспроизведение придут с `http://`, и воспроизведение не запустится. Каждый вариант ниже передаёт оба.

Stremio использует два пути. `/stremio/` — это дополнение. `/strm/e/` — сюда плеер получает ссылку на видео, когда ты нажимаешь play. Оба работают без пароля zurg, потому что Stremio не умеет его передавать. Защищает их токен в URL дополнения. Когда выставляешь zurg в интернет, публикуй только эти два пути. Всё остальное — твоя панель и твоя библиотека.

### Tailscale Serve

Самый простой вариант, если на всех устройствах, где запускается Stremio, можно поставить Tailscale. zurg остаётся закрытым от интернета.

1. В админке Tailscale включи MagicDNS и HTTPS certificates.
2. Выполни это на машине с zurg. Если zurg работает не на порту 9999, укажи свой порт.

   ```bash
   tailscale serve --bg 9999
   ```

   В Windows выполни ту же команду в PowerShell, а если она пишет access denied, открой PowerShell от имени администратора. В Linux добавь `sudo` перед командой, если только ты не сделал себя оператором Tailscale (`sudo tailscale set --operator=$USER`). В macOS, если `tailscale` не найден, копия приложения Tailscale лежит здесь: `/Applications/Tailscale.app/Contents/MacOS/Tailscale`.

3. Открой `https://<machine>.<tailnet>.ts.net/config/` и скопируй адрес аддона из карточки **Stremio Addon**.

Tailscale получает сертификат и отправляет оба заголовка. `tailscale serve reset` выключает это снова.

Устройство, которое не может запустить Tailscale, может использовать Tailscale Funnel. Он выставляет тот же адрес в интернет. Публикуй только то, что нужно Stremio.

```bash
tailscale funnel --bg --set-path /stremio http://127.0.0.1:9999/stremio
tailscale funnel --bg --set-path /strm/e http://127.0.0.1:9999/strm/e
```

Страницы конфига по этому адресу нет. Скопируй адрес аддона со страницы, как обычно открываешь её, и замени начало на `https://<machine>.<tailnet>.ts.net`. Tailscale ограничивает пропускную способность Funnel. 4K remux может тормозить.

### Собственный обратный прокси {#your-own-reverse-proxy}

Уже есть реверс-прокси с доменом и сертификатом? Добавь в него zurg.
Caddy сам сохраняет заголовок `Host` и отправляет `X-Forwarded-Proto`.
Так открываются только два пути Stremio и ничего больше.

```
zurg.example.com {
    handle /stremio/* {
        reverse_proxy 127.0.0.1:9999
    }
    handle /strm/e/* {
        reverse_proxy 127.0.0.1:9999
    }
    handle {
        respond 404
    }
}
```

nginx не отправляет ни один из этих заголовков, пока ты сам не попросишь оба.

```nginx
location ~ ^/(stremio|strm/e)/ {
    proxy_pass http://127.0.0.1:9999;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
}
```

Вставь это в блок `server`, который уже слушает 443 порт с твоим сертификатом. `proxy_buffering off` пропускает видеопоток напрямую, а не через буферы nginx.

### Cloudflare Tunnel

Named tunnel даёт zurg адрес с `https` на домене, который у вас есть в Cloudflare, и без открытия порта. Cloudflare сохраняет заголовок `Host` и сам отправляет `X-Forwarded-Proto`. Пропускайте через туннель только пути Stremio в `config.yml` туннеля.

```yaml
ingress:
  - hostname: zurg.example.com
    path: ^/(stremio|strm/e)/
    service: http://127.0.0.1:9999
  - service: http_status:404
```

Сначала два момента. Cloudflare прекращает ждать ответ на запрос через 100 секунд. Первый запуск релиза может занять дольше этого. Нажмите play ещё раз, и он заработает. А условия Cloudflare позволяют ограничивать аккаунты, которые гонят через их сеть много видео без платного плана. Каждое воспроизведение идёт через туннель.

## Что делает воспроизведение {#what-a-play-does}

Выбор потока — это grab: zurg скачивает NZB у индексатора, кладёт его в `nzbs/` (по тем же правилам именования, что и эндпоинт SABnzbd, поэтому релиз, который взяли дважды или который уже взял *arr, находится, а не дублируется), ждёт, пока библиотека его покажет, и перенаправляет плеер на подписанный эндпоинт `/strm/e/`, через который уже проигрывается каждый файл `.strm`: чтение по диапазонам, переключение аккаунтов при сбое, чтение внутренностей RAR/7z.

Первое воспроизведение релиза поэтому занимает больше времени, чем стрим с дебрид-сервиса. NZB нужно скачать и разобрать, а при чтении архива нужно прочитать его содержимое. Обычно это несколько секунд, а для обфусцированного поста, где должен отработать проход по именам, до минуты или двух. Если воспроизведение не успевает за время ожидания, сервер отвечает 503 с Retry-After. Нажмите play ещё раз, и вы попадёте на быстрый путь. Все последующие воспроизведения происходят сразу.

Если релиз появился в библиотеке, но в нём нет ничего пригодного к воспроизведению (обычно это релиз, который уже удалён из спула, или все файлы помечены как битые проверкой на новостном сервере), клик на этом не заканчивается. URL воспроизведения содержит запрос, для которого он был создан, поэтому zurg заново ранжирует релизы тайтла и пробует строки после выбранной, каждую через тот же путь grab-и-list. Первый, который воспроизводится, и становится редиректом для плеера. Перебирается весь ответ, а не только строки, которые были показаны в списке. `max_results` — это сколько человек готов прокрутить, и если бы он ограничивал ещё и восстановление, тайтл, показанный на десятой строке, мог бы пробовать только девять, сколько бы ни нашёл поиск. Строки *после* выбранной стоят намеренно: это то же разрешение, но меньший размер, или разрешение ниже, но никогда не более крупный релиз, который пользователь пропустил. Фолбэк, который сам ещё загружается, отвечает тем же 503, и повторное нажатие play его разрешает: отказанный релиз отклоняется сразу, а фолбэк находится по быстрому пути. Только окончательный отказ идёт дальше по цепочке, 503 никогда не идёт. Каждая попытка тратит запрос к индексатору и оставляет свой релиз в библиотеке, как любой другой grab, поэтому цепочка ограничена бюджетом в 25 секунд и страховочным лимитом в 6 попыток. Бюджет здесь главный, потому что попытки стоят по-разному: релиз, удалённый из спула, отказывает меньше чем за секунду, а тот, который загружается и открывает архив, прежде чем оказаться пустым, может занять почти весь бюджет сам. Когда все перебранные строки отказаны, ответ остаётся прежним 404. Каждый фолбэк пишется в лог на уровне info с указанием отказанного релиза и того, который пробуется следующим.

Измерения проводились 7 сентября 2026 года против трёх других Stremio-аддонов на основе usenet: stremio-addon-findings-2026-09-07.md. Короче говоря, ограничение по количеству на разрешение исправило то, что нашёл прошлый раунд, но охват всё равно упал вдвое. Группе из пяти элементов некуда деться, когда её первая пригодная запись оказывается релизом, который уже удалён из спула. Фолбэк выше — первое исправление из этого раунда. С тех пор группа выросла с пяти до десяти.

## Поведение поиска {#search-behaviour}

- Фильмы ищутся через `t=movie`, эпизоды через `t=tvsearch` с `season`/`ep`. И то и другое ищется по `imdbid`, но голыми цифрами, потому что несколько индексаторов на форму `tt` отвечают нулём результатов.
- Каждый индексатор запрашивается на `search_limit` релизов (по умолчанию 100). Все лимиты ниже выбирают из того, что было запрошено, так что это потолок ответа.
- Индексаторы опрашиваются параллельно. Если один отказал (лимит частоты запросов, мёртвый ключ), он теряет свои результаты, но не весь список. Отказы логируются по каждому индексатору.
- Результаты дедуплицируются по имени релиза, сортируются сначала по разрешению, потом по размеру и обрезаются до `max_results` (по умолчанию 10) **на каждое разрешение**. Лимит считается отдельно для каждого разрешения, потому что сортировка начинается с 2160p: у популярного тайтла UHD-релизов под потолком размера больше, чем любой лимит. Если считать по всему списку, популярный тайтл будет отвечать одними ремуксами, что бы ещё ни нашёл поиск.
- Из каждого разрешения оставляется не самая большая верхушка, а разброс по размерам: равномерно расставленные варианты от самого большого релиза до самого маленького, причём оба конца всегда включены. Если оставить только верхушку, тир 1080p из пяти релизов будет состоять из пяти ремуксов по 19–30 ГБ, а 4-гигабайтный энкод, который телефон или ноутбук проигрывает напрямую, как раз и отсекается лимитом. Замер от 7 сентября 2026 года: из пятнадцати записей zurg для The Shawshank Redemption три были меньше 6 ГБ, при этом на тех же индексаторах нашлось сорок таких релизов. Внутри разрешения список остаётся отсортированным по убыванию размера. Релиз, размер которого индексатор не указал, не имеет места на этой шкале, поэтому он заполняет только то место, которое остаётся после релизов с размером.
- В описании каждого стрима есть имя релиза, его размер, индексатор, который его нашёл, и то, как давно он был опубликован, например `3d`, `126d`, `2y`, если индексатор сообщил дату. Устаревание на новостном сервере было самой частой причиной сбоя воспроизведения в раунде от 7 сентября, а дата публикации — единственный признак, по которому зритель может этого избежать.
- Релизы больше `max_size_gb` отбрасываются до ранжирования, если плеер не тянет ремукс. По умолчанию ограничения нет: разброс выше и так показывает самый маленький релиз каждого разрешения рядом с его ремуксами. Размеры, которые индексатор не указал, сохраняются. Ограничение применяется при отрисовке списка, так что смена потолка работает и для тайтлов из кеша.
- Результаты кешируются на диске (`data/stremio-cache/`, по одному файлу на тайтл), поэтому повторное открытие тайтла не делает запросов к индексаторам. У них часто дневные квоты, а Treasure Maps отказывает примерно после шести быстрых запросов подряд. Срок жизни ответа зависит от того, сколько нашлось: короткий список говорит о том, что загрузки ещё идут или индексатор был недоступен. Один результат живёт час, два живут два часа, до четырёх. Пять и больше — устоявшийся ответ, он живёт `cache_hours` (по умолчанию 24; это единственная настраиваемая ступень). Пустой ответ никогда не кешируется. В конце списка стримов из кеша есть пункт **refresh** с указанием, насколько он старый. Если открыть этот пункт (он открывается в браузере, а не в плеере), кеш этого тайтла очищается, и при повторном открытии тайтла поиск идёт заново. Кеш переживает перезапуски, а истёкшие записи удаляются сами.
- Сезон 0 (спешлы) не ищется, а отклоняется, чтобы не искать неправильно. Покрытие поиска по id зависит от индексатора: релиз, который индексатор находит только текстовым поиском, в списке не появится.
