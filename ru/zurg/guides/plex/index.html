Возможности и функции Plex

Ты запускаешь rex рядом с Plex Media Server или вместо него? В статье Переход с Plex на rex написано, что оставить в zurg, включая твоё монтирование rclone, и какие настройки Plex в zurg нужно удалить.

Конфигурация и хранилище

  • Ключи конфигурации, описанные в config.md/config.example.yml: plex_server_url, plex_token, plex_match_every_mins (по умолчанию 1440), plex_watchlist_enabled, plex_watchlist_check_every_secs (устаревшее написание watchlist.check_every_secs, по умолчанию 60 с), mount_path (обязателен для сопоставления и построения путей сканирования). Настройки, заданные через панель управления, сохраняются прямо в config.yml через писатель конфига (updateConfigFileAtomic).
  • Интервал watchlist откатывается к значению по умолчанию при любом значении 0 или ниже (GetWatchlistCheckEverySecs); plex_match_every_mins откатывается только тогда, когда он точно равен 0 (intOr, internal/config/config.go). Ни то, ни другое нельзя отключить. Панель управления не принимает значения ниже 1 (internal/handlers/dashboard/dashboard.go), а отрицательное plex_match_every_mins в config.yml останавливает zurg при запуске с сообщением is negative; use 0 for the default; оно никогда не выключает сопоставление.
  • Получение из watchlist настраивается блоком watchlist: — enabled, check_every_secs, indexers, max_size_gb, max_season_size_gb и quality (по умолчанию best). Пустой indexers берёт значение из stremio.indexers. Плоские ключи plex_watchlist_enabled, plex_watchlist_check_every_secs и watchlist_quality по-прежнему считаются устаревшими написаниями первого, второго и последнего из этих параметров. См. config.md.
  • mount_path также является префиксом для путей сканирования, которые отправляются в Plex и в управляемое монтирование rclone (config.md, pkg/scan/scanner.go).
  • Хук on_library_update получает каждый изменённый путь как аргументы; вызовы сгруппированы с задержкой 500 мс, дубликаты удаляются, и одновременно выполняется только один вызов. Это позволяет использовать скрипты автоскана Plex (internal/torrent/hooks.go).

Аутентификация и поиск сервера

  • Веб-панель: /plex/auth создаёт PIN-сессию (pkg/plex/auth.go, CreatePlexAuthURL), сохраняет её в pkg/plex/auth_session.go (автоочистка через 10 мин, проверка каждые 5), и опрашивает статус авторизации через /plex/auth/status (PollForAuthToken, 60 попыток с интервалом 5 с, после чего запрос завершается по таймауту).
  • /plex/callback показывает страницу с прогрессом, которая после авторизации вызывает /plex/servers, чтобы получить список серверов, и /plex/server, чтобы выбрать один из них (internal/handlers/dashboard/dashboard.go).
  • Поиск серверов (pkg/plex/auth.go): запрашивает ресурсы Plex с HTTP- и HTTPS-эндпоинтами, отбрасывает relay, если есть прямое подключение, обрабатывает IPv6-адреса и проверяет /identity для каждой записи (проверка TLS отключена). Учитываются только серверы, принадлежащие аккаунту (device.Owned, auth.go) — расшаренные серверы никогда не появляются в списке. Записи, которые не прошли проверку, удаляются из ответа, а не возвращаются с установленным last_error (enrichServersWithIdentity, auth.go).
  • Выбор сервера записывает plex_server_url/plex_token в конфиг, переинициализирует клиент Plex, (пере)запускает планировщик matcher, запускает триггер сопоставления и обновляет кэшированный статус панели (HandlePlexServerSelect, internal/handlers/dashboard/dashboard.go). /plex/logout очищает сохранённые значения и кэш статуса.

Возможности клиента Plex (pkg/plex/client.go)

  • Жизненный цикл соединения: опция отложенного старта (WithDeferredStart), защита ValidateConnection от /identity, аккуратный Close. API для перезапуска нет. RestartAllowed и RestartReason на дашборде определяются по URL сервера (локальный/LAN или удалённый) и нужны только для отображения (internal/handlers/dashboard/plex_status.go:getPlexConnectionDetails).
  • Очередь сканирования: динамическая очередь задач и воркер (common.DynamicJobQueue). ProcessJob делает GET /library/sections/{key}/refresh с заголовками Plex и не больше одного query-параметра path на задачу. Если передать больше одного, запрос сразу отклоняется (client.go). Задача без пути обновляет всю секцию целиком. Ответ 503 превращается в ошибку «сервер занят», а 404 сообщает, что библиотека удалена из Plex. GetJobQueueSize показывает накопившуюся очередь (backlog).
  • Проверка нагрузки и зависаний: CheckServerLoad смотрит /activities и отслеживает прогресс library.update.section для каждого UUID. Изменение прогресса или субтитра считается прогрессом. IsJobStuck помечает застрявшие задачи по librarySectionID, а если его нет, использует Title. GetServerActivitiesDetails создаёт и убирает те же трекеры. Дело в том, что CheckServerLoad работает только пока воркер держит задачу в очереди. Раньше сканирование, которое Plex запускал сам, вообще не получало трекера. Поэтому его нельзя было отметить как зависшее, а прошедшее время на каждом обновлении было нулём. Оба пути хранят историю только для library.update.section. Если отслеживать здесь что-то ещё, статус начнёт мигать из-за очистки воркера.
  • Субтитр в активности — это не тот файл, на котором застряло сканирование. Замер на стенде plex503, 2026-09-15: субтитр library.update.section — это указатель перечисления сканера, и он опережает чтения. Когда маунт отказывал в трёх файлах, субтитр называл четвёртый, который вообще не запрашивался. Заблокированный файл он показывал всего 290 мс из цикла в 56 с. На дашборде это выводится как «Plex reports» и не привязывается к релизу. То, чего на самом деле ждёт сканирование, берётся из отказов zurg (internal/universal/refused_reads.go). Только эта сторона знает правду. Корпус лежит в internal/handlers/dashboard/testdata/plex503-*.
  • Запросы к библиотеке: GetSections (секции фильмов и сериалов с путями), GetSectionItemCount, FindSectionNormalized (сопоставляет путь с путём секции и исправляет префикс под регистр библиотеки), GetAllMediaItemsConcurrent (пакетная параллельная выборка с includeGuids для сбора путей, GUID и IMDB ID) и GetShowLevelIMDBIndex (ID на уровне сериала для секций сериалов, чтобы эпизоды могли их унаследовать).
  • Помощники для метаданных и сопоставления (pkg/plex/match.go): GetMetadataSummary (GET /library/metadata/{ratingKey}), GetMatchCandidates (GET /library/metadata/{ratingKey}/matches?manual=1, с переопределениями title, year и language), LookupMetadataByGUID и LookupRatingKeyByGUID (GET /library/all?guid=…), ApplyManualMatch (PUT /library/metadata/{ratingKey}/match), а также разбор GUID (ExtractIMDBIDFromGUID, ExtractTMDBIDFromGUID, ExtractTVDBIDFromGUID, ExtractAnyIDFromGUIDs; типы MatchResult и MatchSelection).
  • Информация о сервере: GetServerIdentityOnly и GetServerDetails (machine ID и версия; второй ещё и суммирует сессии, транскодирование и трафик), GetStreamingSessions, GetTranscodeSessions, GetServerActivitiesDetails (с пометкой о зависании).
  • История просмотров: GetWatchHistory (GET /status/sessions/history/all), GetMetadataBatch (ключи рейтинга, склеенные через запятую, против /library/metadata) и GetWatchHistoryWithMetadata (pkg/plex/history.go). Они питают статистику в pkg/plex/stats.go.

Интеграция сканера медиа (pkg/scan/scanner.go)

  • Инициализирует клиент Plex, когда заданы mount_path, plex_server_url и plex_token. Повторяет попытку каждые 5s, пока не подключится, и вызывает callback-и OnPlexReconnected.
  • TriggerScan группирует пути по секциям Plex (через FindSectionNormalized) и ставит в очередь одну задачу обновления на каждый путь с префиксом mount_path, логируя прогресс каждые 50. Также поддерживает Jellyfin/Emby, которые идут по негруппированному пути. Путь, который не попал ни в одну секцию, выводит предупреждение только тогда, когда ни один путь из пакета не совпал. В остальных случаях это строка debug, так что торрент, лежащий и в папке библиотеки, и в папке только для zurg (recent, music, …), не вызывает предупреждения.
  • ReinitializePlexClient позволяет обновлениям из панели управления на лету менять серверы и токены.
  • GetQueueSizes показывает глубину очереди Plex для UI/мониторинга.

Сопоставление и синхронизация метаданных (internal/plex/matcher.go, internal/plex/schedule.go)

  • Предусловия: нужны настроенные Plex URL и токен, mount_path и работающий scanner.PlexClient. Иначе функция возвращает явные ошибки.
  • Единственные данные Plex, которые сохраняются в торренте, это PlexRatingKey (на уровне сериала для сериалов) и IMDBID (internal/torrent/torrent_types.go). GUID-ы Plex используются на лету для извлечения ID и для отчётов, но никогда не сохраняются.
  • Сбор данных: берутся все торренты из карты директорий и все элементы Plex через GetAllMediaItemsConcurrent. Перед этим выполняется проход GetShowLevelIMDBIndex, чтобы эпизоды получали IMDB/TVDB/TMDB ID сериала, а не свой ID уровня эпизода. Элементы индексируются по GrandparentRatingKey, если он есть.
  • Шаги синхронизации:
    • Проверить каждый сохранённый rating key по свежезагруженным элементам Plex. Если Plex больше не знает ключ, он очищается вместе с IMDB ID торрента, а торрент ставится в очередь на повторное сопоставление.
    • Сопоставление по пути для торрентов без rating key: buildPlexDirIndex индексирует каждый компонент пути (в нижнем регистре) для каждого файла Plex, и по GetKey торрента выполняется поиск в этом индексе (O(1), побеждает первая запись). Торренты, чьи назначенные директории не совпадают ни с одним путём секции Plex, сначала пропускаются.
    • Дозаполнение IMDB: сначала из уже загруженной пачки (без запросов к API), затем для каждого торрента через GetMetadataSummary (не более 20 одновременно).
    • Находит элементы Plex, к которым не привязан ни один торрент.
    • Отправляет в DMM пары hash+IMDB, которые пользователь задал вручную, но никогда не ID, которые угадал Plex. DMM принимает их без ключа. Если задан dmm_api_key, он передаётся вместе с ними (sendHashImdbPairs → TorrentManager.SendHashImdbPairs, internal/torrent/mediainfo.go).
  • MatchSingleTorrent выполняет тот же поиск по пути для одного торрента. Используется сразу после целевого сканирования. Если у торрента уже есть rating key, ничего не делает.
  • Отчёт: записывает logs/match_report.txt с количеством, несопоставленными торрентами, пропущенными торрентами, элементами Plex без торрентов и совпадениями без IMDB.
  • Планирование (internal/plex/schedule.go): после каждого завершённого запуска обновляется метка времени в data/plex_match_timestamp. При старте StartMatchingJob запускается сразу, только если метка отсутствует или старше plex_match_every_mins. Иначе сначала ждёт оставшееся время. Он слушает ручные триггеры в TorrentManager.PlexMatchTrigger, изменения интервала на лету в ResetPlexMatchTicker, и запускает задачу до трёх раз, если она паникует.
  • Эндпоинт ручного запуска /plex/match-torrents отправляет сигнал в канал триггера и отказывает, пока выполняется запуск. /plex/match-torrents/status показывает, идёт ли сейчас запуск (internal/handlers/utilities.go).

Ручное сопоставление и интерфейс управления (internal/handlers/manage)

  • Фильтры списка торрентов показывают состояния Plex (plex_matched, plex_in_library_not_matched, plex_no_imdb, plex_missing_metadata) для быстрых видов (torrent_list_state.go).
  • Страница ручного сопоставления торрента /manage/{hash}/plex-match:
    • Требует, чтобы у торрента уже был PlexRatingKey (его ставит matcher), иначе страница пишет "torrent is not linked to Plex". resolvePlexRatingKey проверяет этот ключ через GetMetadataSummary, подставляет недостающий IMDB ID из него и, если ключ устарел, заново находит его через LookupRatingKeyByGUID, используя сохранённый у торрента ID tt…/tvdb:///tmdb:// (internal/handlers/manage/handler.go).
    • Запрашивает у Plex варианты ручного сопоставления с необязательными переопределениями названия/года/языка (44 варианта языка, по умолчанию en-US); показывает совпадения с выделением текущего выбора (torrent_matches.go).
    • Применение совпадения (HandleApplyPlexMatch) вызывает ApplyManualMatch, затем заново ищет rating key по выбранному GUID, потому что Plex может его переназначить, обновляет rating key и IMDB торрента (включая необязательный IMDB, который ввёл пользователь), сохраняет изменения и делает редирект с состояниями успеха/ошибки.

Получение по списку просмотра

  • Список просмотра Plex работает как адаптер в internal/acquisition/plex. Он запускается на общем сервисе получения вместе с Seerr. Текущие настройки списка просмотра работают как раньше. Адаптеры также можно настроить в acquisition.sources.
  • Клиент обращается к discover.provider.plex.tv и забирает по 100 элементов за раз. Токен Plex читается заново для каждого запроса, поэтому повторная авторизация применяется без перезапуска адаптера.
  • Общий исполнитель получает фильмы или каждый запланированный сезон из индексаторов Newznab и Torznab и отдаёт предпочтение season packs. При поиске сериалов сначала пробуется TVDB, а потом IMDb, потому что соответствия у индексаторов разные.
  • Прогресс, сроки повторных попыток и подтверждения по каждой серии сохраняются в data/acquisition.json и переживают перезапуски. Старый журнал Plex импортируется автоматически.
  • Удаление из списка происходит после получения всех запланированных целей. Неудачные запросы остаются в списке просмотра и повторяются с постоянной задержкой (backoff). Повтор только для удаления не запускает получение заново. Ограничения читай в Plex watchlist acquisition, а общую конфигурацию источников — в acquisition sources.

Панель и API-эндпоинты (internal/handlers/router.go, internal/handlers/dashboard)

  • Маршруты: /plex/auth, /plex/callback, /plex/auth/status, /plex/servers, /plex/server, /plex/logout, /plex/match-torrents, /plex/match-torrents/status, /plex/scan/{sectionKey}, /plex/scan-all, /plex-stats, /plex-stats/data, /plex-stats/image, /manage/{hash}/plex-match.
  • Дашборд показывает информацию о сервере Plex и его статус через PlexStatusFetcher, который работает по двум таймерам: каждые 30 секунд обновляет сессии стриминга, транскодирование, пропускную способность и активности сервера (GetStreamingSessions/GetTranscodeSessions/GetServerActivitiesDetails); каждые 5 минут делает полное обновление, которое также заново читает идентификацию (GetServerIdentityOnly), разделы библиотеки и количество элементов в каждом разделе. Активности сканирования сверяются со списком торрентов по имени файла, чтобы дашборд мог связать активность с хешем торрента.
  • Эндпоинты сканирования раздела и всех разделов ставят в очередь полное обновление раздела (RefreshSection(key, nil), без пути) для одного или всех разделов; они не трогают STRM-файлы и не запускают побочные эффекты библиотеки (HandlePlexScan/HandlePlexScanAll).

Plex Wrapped (internal/handlers/dashboard/plex_wrapped.go)

  • /plex-stats рендерит 9-слайдовый обзор за год по истории просмотров Plex за последние 12 месяцев; /plex-stats/data отдаёт ту же статистику в виде JSON, а /plex-stats/image создаёт PNG для публикации через headless chromedp (square 1080x1080 по умолчанию, instagram 1080x1920, facebook 1200x630).
  • Статистика запрашивается не чаще одного раза в 24 часа (?refresh=true запускает обновление принудительно), берётся не более 10000 записей истории и кэшируется и в памяти, и на диске в data/plex_wrapped_cache.json, который перечитывается при запуске. Пока идёт запрос, страница показывает состояние загрузки и не блокируется.

Побочные эффекты библиотеки и ссылки на обновление

  • Побочные эффекты для библиотеки срабатывают при изменении назначения директорий, переименованиях, удалениях и восстановлении файлов: TriggerLibrarySideEffects сбрасывает кэш директорий rclone VFS (dircache) для затронутых путей (чтобы медиасерверы не сканировали устаревший список), вызывает MediaScanner.TriggerScan (запускает обновление в Plex) и выполняет пользовательский хук on_library_update (internal/torrent/hooks.go).
  • Конвейер обновления запускает генерацию STRM и побочные эффекты только после завершения инициализации, чтобы не допустить преждевременных сканирований в Plex (internal/torrent/refresh.go).

Инфраструктура и скрипты

  • Пример конфига Nginx для проксирования трафика Plex (nginx/plex.conf).
  • plex_update.sh — эталонный скрипт частичного сканирования для on_library_update: sh plex_update.sh "$@". Положите его рядом с docker-compose.yml, папка которого монтируется в /config, тогда скрипт уже будет внутри контейнера. В Windows хук запускается через PowerShell, а не через /bin/sh (pkg/script/script.go), поэтому этот скрипт там не работает. Вариант для PowerShell показан в разделе Usenet → Укажите Plex на скрипт.
  • integration/plex_integration.sh запускается через make integration-test и make integration-test-media. Если на хосте нет сервера Plex, он громко пропускается, поэтому смотрите на вывод, а не на код выхода. scripts/plex-e2e-test.sh — отдельная проверка воспроизведения, которая читает plex_server_url и plex_token из config.yml.

Рекомендуемые настройки Plex

Настройки Plex по умолчанию рассчитаны на локальные диски, которые всегда на месте и которые можно читать без ограничений. Монтирование zurg устроено иначе: его данные приходят от провайдера по HTTP, и на время переподключения rclone оно может быть ненадолго недоступно. В таких условиях некоторые значения по умолчанию в Plex прямо вредят.

zurg применяет эти настройки при каждом обновлении статуса Plex. До какого предела он доходит, решает plex_settings_policy: off, warn, guard (по умолчанию) или enforce. Список находится в pkg/plex/settings.go (RecommendedSettings), а сама политика в pkg/plex/reconcile.go.

Если сервер не сообщает какую-то настройку, она пропускается, поэтому версия Plex, в которой её нет, не будет помечена как неправильно настроенная.

Девять из шестнадцати значений ниже отличаются от значения Plex по умолчанию. Остальные семь совпадают с ним и служат защитными проверками, а не исправлениями: они срабатывают только если оператор сам их включил. В этих строках в обоих столбцах одно и то же значение, и это не ошибка. Plex по умолчанию ставит GenerateBIFBehavior в never, а сервер, на котором всё измерялось, стоял на scheduled. Plex сообщает своё значение по умолчанию для каждой настройки в /:/prefs, поэтому столбец «Plex ships» ниже берётся с сервера, а не выдумывается (измерено 2026-09-05 на Plex 1.42.2).

Как отключить одну настройку

plex_settings_policy задаётся уровнями, и уровень не всегда отвечает на вопрос, который ты задаёшь. Если у тебя файлы переезжают между папками библиотеки, например при сортировке по тегам, нужно, чтобы Plex сам очищал свою корзину и убирал оставшуюся запись. А guard это отключает. Переход на warn, чтобы вернуть очистку, также отключит защиту по событиям файловой системы. Она на том же уровне, и тебе она не нужна.

plex_settings_ignore перечисляет настройки по отдельности:

plex_settings_policy: guard
plex_settings_ignore:
  - autoEmptyTrash

Этот параметр за тебя ведёт дашборд. На странице конфигурации над настройками Library Trash Sweep есть переключатель Let Plex Empty Its Own Trash. Он добавляет и удаляет autoEmptyTrash здесь и не трогает остальной список. Включение вступает в силу после следующего перезапуска.

Игнорируемая настройка по-прежнему читается и показывается на дашборде и в zurg plex-settings (с отметкой skip), так что ничего не скрыто. Её просто никогда не записывают, не считают проблемой и она не влияет на баннер корзины в дашборде. Идентификаторы сравниваются без учёта регистра. Если id не соответствует ни одной настройке из таблиц ниже, zurg сообщает об этом при запуске, и настройка остаётся под защитой, ведь опечатка не должна работать как отказ.

Игнорирование настройки безопасности делает тебя ответственным за последствия. zurg предупреждает об этом один раз при запуске, а не при каждом обновлении. autoEmptyTrash особенно важна: именно она опустошает библиотеку, когда сканирование натыкается на монтирование, которое на время пропало. Если её игнорировать, задача очистки также переходит обратно к Plex. Подробнее ниже.

Кто очищает корзину

Отключение autoEmptyTrash оставляет задачу незавершённой. Plex получил указание не очищать записи, файлы которых исчезли, а собственное удаление zurg долгое время было необязательным. Поэтому по умолчанию библиотека копила мёртвые записи, и их никто не убирал. Ни одна сторона не ошиблась, но пробел был реальным. С ним сталкиваются, когда файл переезжает в другую папку библиотеки и старая запись остаётся навсегда.

Теперь zurg снова берёт на себя эту задачу. Если plex_trash_sweep_every_mins не задан, очистка корзины удаляет записи каждые 60 минут, но только тогда, когда этим никто другой не занимается. Если Plex сам очищает свою корзину, потому что plex_settings_policy равен off или warn или потому что autoEmptyTrash есть в plex_settings_ignore, zurg не вмешивается и оставляет это Plex. Два сборщика на одной библиотеке означают, что расхождение между ними может обернуться удалением.

Очистка работает намного уже, чем очистка Plex, и именно поэтому её стоит предпочесть. Она удаляет по одной записи за раз, никогда не трогает запись, у которой ещё есть файл, работает только с точкой монтирования, которая доступна в данный момент, и ограничена 50 удалениями и 10% корзины за проход. Записи, по которым у неё нет решения, сначала 14 дней остаются видимыми как сломанные. Для работы также нужен plex_database_path, поэтому очистка запускается только там, где Plex работает на этом же хосте, и где zurg сам запускает монтирование (rclone_enabled с заданным mount_path). zurg читает базу данных программой Plex SQLite, которую устанавливает Plex, и находит её там, куда её кладёт установщик Plex на Linux, macOS и Windows. Поэтому достаточно задать ключ plex_database_path:

plex_database_path: "/var/lib/plexmediaserver/Library/Application Support/Plex Media Server/Plug-in Support/Databases/com.plexapp.plugins.library.db"
 
plex_database_path: "/Users/YOU/Library/Application Support/Plex Media Server/Plug-in Support/Databases/com.plexapp.plugins.library.db"
 
plex_database_path: 'C:\Users\YOU\AppData\Local\Plex Media Server\Plug-in Support\Databases\com.plexapp.plugins.library.db'

Оставьте одинарные кавычки: внутри двойных кавычек YAML воспринимает обратную косую черту как экранирование. Задавайте plex_sqlite_binary только для Plex, установленного в другом месте, например для 32-битного Plex: 'C:\Program Files (x86)\Plex\Plex Media Server\Plex SQLite.exe'.

Замените YOU на имя своего пользователя: zurg не раскрывает ни ~, ни %LOCALAPPDATA%. Очистка сопоставляет пути, которые хранит Plex, с mount_path, и это работает даже с буквой диска, например Z: (pkg/utils/path_within.go).

Чтобы отключить удаление и очищать корзину самостоятельно, укажите plex_trash_sweep_every_mins: 0. Это явный отказ, и он отличается от случая, когда ключ просто не задан.

Этот ключ отключает только собственное удаление zurg. Он не возвращает настройку Plex. При guard zurg всё равно записывает autoEmptyTrash в значение off, поэтому Plex по-прежнему не будет очищать корзину после сканирования, и записи будут копиться без сборщика. Чтобы вернуть эту задачу Plex, используйте переключатель в дашборде или plex_settings_ignore.

Безопасность — исправляется в guard и enforce

Эти настройки теряют данные, а не время, поэтому политика по умолчанию их записывает, а не только предупреждает. Только autoEmptyTrash поставляется с опасным значением. Остальные три уже по умолчанию стоят так, как нужно zurg, и нужны лишь на случай, если оператор что-то включил.

Настройка По умолчанию в Plex Нужно zurg Почему
autoEmptyTrash 1 0 Plex очищает корзину после каждого сканирования. Если во время сканирования монтирование на короткое время станет недоступным для чтения, каждый файл будет выглядеть удалённым, и Plex удалит их навсегда, вместо того чтобы оставить в корзине, откуда они вернулись бы вместе с монтированием.
FSEventLibraryUpdatesEnabled 0 0 Обновления по событиям пропускают то, что здесь на самом деле меняется. Дерево zurg меняется на её стороне, и это не проходит через локальное ядро, поэтому событие не генерируется, и библиотека незаметно устаревает. Те события, что всё-таки приходят, — это записи, сделанные через монтирование, которые попадают туда, пока каталог ещё собирается.
FSEventLibraryPartialScanEnabled 0 0 Частичное сканирование работает по тем же событиям, поэтому срабатывает на записи, идущие через монтирование, то есть именно тогда, когда каталог наполовину записан, и никогда не срабатывает на изменения на удалённой стороне, ради которых сканирование и нужно.
ButlerTaskBackupDatabase 1 1 Ночная резервная копия базы данных — единственное, что восстанавливает библиотеку, которую Plex уже удалил.

Две причины про FSEvent переписаны после замеров на всех платформах, где zurg монтируется. Прежняя формулировка говорила, что FUSE-монтирование «не выдаёт их надёжно, поэтому сканирования запускаются в моменты, о которых никто не просил». Обе половины этого неверны.

Замерено 2026-09-05: на каждой платформе отслеживание велось тем API, которым пользуется её медиасервер, на монтировании rclone, у которого можно было напрямую менять исходный каталог. A — запись, сделанная через монтирование; B — тот же файл появляется на удалённой стороне, как это происходит, когда меняется собственное дерево zurg.

Платформа Монтирование Отслеживание через A: через монтирование B: изменено на удалённой стороне
Linux fuse.rclone inotify CREATE OPEN ATTRIB CLOSE_WRITE событий нет
Docker то же монтирование, пробрасываемое в контейнер через bind mount inotify, внутри контейнера те же четыре, видны в контейнере событий нет
macOS macFUSE FSEvents Created IsFile событий нет
Windows WinFsp ReadDirectoryChangesW Created Changed событий нет

Каждая платформа выдала A, а контрольный замер в том же прогоне на нативной файловой системе (APFS, NTFS) дал те же события, значит, наблюдатели работали. Ни одна платформа не выдала B, хотя файл был виден через монтирование, как только истекал кеш каталога.

Так что режим отказа противоположен заявленному: обновление по событиям срабатывает на записи, идущие через монтирование (импорт из *arr, который приходит в каталог, ещё находящийся в сборке), и никогда не срабатывает на изменения на удалённой стороне, ради которых вообще нужно сканирование. Дело не в том, что события ненадёжны. Просто они сообщают не ту половину того, что происходит на debrid-монтировании.

Пропускная способность — исправляется только в enforce

Каждая из этих настроек заставляет Plex декодировать целые файлы ради результата, который никто не смотрит. На локальном хранилище это безвредно, но через debrid-маунт каждый байт — это запрос к провайдеру, а эти задачи идут по всей библиотеке. Анализ, результат которого виден (превью при перемотке, картинки глав, выравнивание громкости, sonic-анализ), остаётся в taste-уровне ниже, где enforce его не трогает.

Настройка Plex по умолчанию zurg хочет
ButlerTaskDeepMediaAnalysis 1 0
ButlerTaskUpgradeMediaAnalysis 1 0
GenerateAdMarkerBehavior scheduled never
GenerateVADBehavior never never
GenerateIndexFilesDuringAnalysis 0 0
ButlerTaskGenerateMediaIndexFiles 0 0

Вкусы — всегда отчитываются, никогда не исправляются

За каждым из этих значений стоит функция, поэтому zurg говорит, чего стоит каждое значение, и не трогает выбор. Если выключить что-то без спроса, оператор потеряет то, что он видит, а это не решение zurg, как бы ни экономился трафик. Для первых двух более дешёвый вариант сохраняет функцию и переносит работу на окно обслуживания; для остальных выбор стоит между функцией и трафиком.

Настройка Значение Plex по умолчанию Что советует zurg Почему
GenerateIntroMarkerBehavior asap scheduled или never asap декодирует каждый файл сразу, как только он появляется, вне окна обслуживания. scheduled сохраняет кнопку Skip Intro и переносит работу в окно.
GenerateCreditsMarkerBehavior asap scheduled или never То же самое, но для Skip Credits.
GenerateBIFBehavior never never Декодирует всё видео, чтобы собрать полосу изображений для перемотки. Воспроизведению она не нужна.
GenerateChapterThumbBehavior scheduled never Декодирует файл, чтобы вытащить по одному кадру на каждую главу — картинку рядом с каждым пунктом списка глав.
LoudnessAnalysisBehavior scheduled never Полностью декодирует аудио каждого файла, чтобы измерить громкость и выровнять её между треками и фильмами.
MusicAnalysisBehavior scheduled never Декодирует каждый трек. Это много мелких файлов, поэтому именно из-за такого количества запросов аккаунт и попадает под ограничение частоты. Зато получаем анализ звучания: миксы похожих треков и визуализатор.

Окно обслуживания

zurg не трогает ButlerStartHour/ButlerEndHour, потому что не существует часа, который подходил бы всем. Стоит задать его вручную: Plex по умолчанию использует 02:00–05:00, а окно, которое пересекается с часами, когда кто-то смотрит, превращает каждую задачу обслуживания в затор. Всё, что остаётся в bandwidth tier, выполняется внутри этого окна.

Остановка уже запущенного прохода

Изменение настройки останавливает будущие запуски, но не тот, что уже идёт. Plex Media Server перезапускает свои дочерние процессы сканера, так что их завершение ничего не даст:

curl -X DELETE "http://localhost:32400/butler?X-Plex-Token=$TOKEN"
 
curl.exe -X DELETE "http://localhost:32400/butler?X-Plex-Token=$TOKEN"

В Windows PowerShell 5.1 curl — это другое имя для Invoke-WebRequest, так что набери curl.exe.

Сначала задай $TOKEN равным своему Plex-токену: TOKEN=your-token в shell, $TOKEN = 'your-token' в PowerShell.
