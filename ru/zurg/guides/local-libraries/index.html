Локальные дебрид-библиотеки и переносимые zurg-торренты

Локальная библиотека получает своих участников из переносимых файлов .zurgtorrent. Она появляется в обычных каталогах WebDAV, HTTP и провайдера. Импорт файлов, их перечисление и обновление каталога не добавляют торренты и не получают ссылки на загрузку. Воспроизведение получает нужный файл через ваш настроенный аккаунт.

Экспорт библиотеки

Из рабочей директории экспортирующего инстанса:

./zurg --config config.yml export-torrents data --provider realdebrid --output exported/realdebrid
 
.\zurg.exe --config config.yml export-torrents data --provider realdebrid --output exported/realdebrid

--provider — это настроенное имя аккаунта, включая пользовательское имя. Не указывай его, чтобы экспортировать все поддерживаемые копии debrid. Входными данными также может быть один файл runtime-кэша, старая директория dump/ или существующий портативный каталог. Для локальной библиотеки экспортируй её исходную директорию (torrents/<account>), так сохранятся её необязательные ссылки на другие провайдеры.

Экспорт работает офлайн. Перед записью он проверяет все входные данные и конфликты в целевых путях, сообщает о runtime-записях без метаданных выбранных файлов и пропускает их, объединяет релизы по хэшу и записывает <hash>.zurgtorrent. Повторять экспорт с уже существующими одинаковыми файлами безопасно. Если при массовой миграции встречаются некорректные записи старого кэша, --skip-invalid экспортирует корректные записи и сообщает, сколько было пропущено. Без этого флага первая некорректная запись прерывает процесс до того, как что-либо будет записано на диск.

--replace разрешает заменять портативный экспорт с тем же хэшем, но никогда не разрешает перезаписывать runtime-кэш.

Для обмена предназначены только экспортированные файлы. data/*.zurgtorrent остаётся приватным runtime-состоянием. .zurgbackup также содержит учётные данные аккаунтов и является резервной копией инстанса, а не библиотекой для обмена.

Получение библиотеки

Положи экспортированные файлы в torrents/rd-local/, а потом настрой принимающий аккаунт:

providers:
  - name: rd-local
    type: realdebrid
    token: YOUR_OWN_TOKEN
    download_tokens: # Optional bandwidth fallback on another RD account.
      - SECOND_RD_TOKEN
    library:
      source: local
      # Optional; defaults to torrents/<account-name>.
      path: torrents/rd-local

  - name: tb-online
    type: torbox
    token: YOUR_OWN_TORBOX_TOKEN
    # Omitted library block means the provider owns this account's catalog.

На Real-Debrid и AllDebrid download_tokens использует тот же локальный каталог, что и его запись в providers. Второму аккаунту RD выше папка не нужна, и его торрент-библиотека не импортируется. Это резервные учетные данные, которые используются, когда лимит трафика у активного токена загрузки исчерпан; они не заставляют все загрузки идти через второй аккаунт. Если же добавить вторую запись RD в providers, появится отдельный каталог со своей папкой. Все учетные данные остаются в конфиге и исключаются из портативных экспортов.

TorBox тоже принимает download_tokens, но его ротация токенов не сопоставляет сохраненные ID торрентов/файлов с ID на другом аккаунте. Для отдельных аккаунтов TorBox используй отдельные записи в providers, у каждой со своим локальным каталогом.

Аккаунты Premiumize, Offcloud и Debrid-Link тоже могут хранить локальную библиотеку. Ни у одного из них нет портативной ссылки на файл. Поэтому, как и TorBox, каждый при первом воспроизведении добавляет хеш в свой аккаунт и сопоставляет файлы по пути и размеру. Используй одну запись в providers на аккаунт.

Перезапусти после изменения настроек аккаунта. Добавление, замена и удаление файлов подхватываются обычным циклом обновления. Каждая папка сканируется на один уровень вглубь. Пути должны быть разными папками внутри torrents/, чтобы обычные бэкапы их захватывали. Если папка не читается или замена некорректна, сохраняется последняя рабочая запись в памяти, а проблема пишется в лог. После перезапуска некорректный файл нужно исправить, прежде чем он попадет в каталог.

Тот же манифест можно скопировать в локальную папку аккаунта AllDebrid или TorBox. Он содержит идентичность контента, а не имя аккаунта провайдера. Один и тот же хеш у разных аккаунтов показывается один раз, с несколькими источниками, по существующему порядку предпочтения аккаунтов и переключения при сбое. Дубликаты файлов для одного хеша внутри одной папки берутся по первому имени файла в отсортированном порядке; держи один манифест на каждый хеш.

Членство в локальном каталоге сохраняется при удалении из онлайн-библиотеки провайдера. Переименования, теги, IMDb ID и удаления файлов сохраняются обратно в манифесты. Удаление локального релиза удаляет его исходные документы, но не удаляет торренты у провайдера. Удаление релиза, у которого есть онлайн-копии, также удаляет эти онлайн-копии, как и обычное полное удаление релиза.

Локальные аккаунты не являются целями для списков наблюдения, загрузок магнет-ссылок или торрент-файлов. Добавляй записи через импорт манифестов. add_torrents: false по-прежнему позволяет RD/AD активировать существующую общую ссылку, но не дает воспроизведению создавать на стороне провайдера привязку, когда она нужна.

Перенос онлайн-аккаунта в локальную библиотеку

AllDebrid принимает не больше 1000 магнитов на аккаунт, а аккаунты Real-Debrid тоже быстро заполняются. Готовому релизу торрент на аккаунте для проигрывания не нужен. Ссылка Real-Debrid /d/ продолжает работать после удаления торрента, а закрытая ссылка AllDebrid /f/ продолжает работать после удаления магнита. На этом и основан перенос. zurg записывает готовый релиз в локальную библиотеку на том же сервисе, а затем удаляет торрент из онлайн-аккаунта, освобождая его слот. Релиз сохраняет свою папку в маунте и проигрывается по сохранённым ссылкам.

Настрой две записи для одного аккаунта: одну онлайн и одну локальную:

providers:
  - name: ad
    type: alldebrid
    token: YOUR_AD_TOKEN
    library:
      offload_to: ad-local     # the local entry below
      offload_after_mins: 30   # optional, 30 is the default

  - name: ad-local
    type: alldebrid
    token: YOUR_AD_TOKEN       # the same token
    library:
      source: local            # manifests live in torrents/ad-local/

Новые релизы продолжают поступать на ad. После каждого полного списка этого аккаунта и каждые пять минут zurg переносит подходящие релизы по одному. Релиз подходит, когда:

  • Он полностью находится на аккаунте не меньше offload_after_mins, отсчёт идёт с момента, когда этот процесс zurg впервые увидел его полностью загруженным. После перезапуска ожидание начинается заново.
  • У каждого файла есть рабочая ссылка на этом аккаунте, которую может обработать другой аккаунт. Релиз, у которого не хватает ссылки хотя бы для одного файла, остаётся онлайн.
  • Он в порядке, не ремонтируется, и ни один его экземпляр ещё не скачивается. Ни один проход ремонта или клиент загрузки не держит его торрент.
  • Ни одно задание qBittorrent из Sonarr или Radarr его не показывает. Включи Remove Completed Downloads в *arr, чтобы задание удалялось после импорта. Иначе релиз останется онлайн, пока ты сам не удалишь задание.
  • Acquisition не добавил его в последний час.
  • Перенос не меняет ни одну директорию, в которой он лежит, и сохраняет имя его папки. Директория с фильтром provider:, который называет онлайн-аккаунт, его потеряет, поэтому такой релиз остаётся онлайн.

Порядок фиксированный. Манифест <hash>.zurgtorrent сначала записывается в локальную библиотеку, затем релиз попадает в локальную библиотеку, и только после этого торрент удаляется с онлайн-аккаунта. Если манифест не удалось записать, ничего не удаляется. Если удаление не прошло, онлайн-копия остаётся рядом с локальной, и при следующем обновлении видно, есть ли торрент ещё там. Манифест, который уже есть в локальной библиотеке для этого релиза, обновляется на месте, а не записывается дважды. Ссылки онлайн-аккаунта в нём обновляются, его имена и правки следуют за релизом так, как его показывает маунт, а ссылки другого сервиса сохраняются.

Релиз уходит из __ad__ и появляется в __ad-local__. Все остальные директории, включая __all__ и твою собственную, продолжают показывать его под тем же именем. Сканирование медиасервера не запускается, потому что ничего из того, что индексирует медиасервер, не изменилось. Указывай Plex и другие медиасерверы на эти директории, а не на директорию отдельного аккаунта.

Если обе записи идут на одном токене, локальное проигрывание может снова прикрепить релиз к тому же аккаунту (см. ниже), и тогда этот торрент появится в онлайн-списке. zurg никогда не переносит релиз, если его онлайн-торрент является таким прикреплением, и никогда не переносит, пока локальное проигрывание добавляет такое прикрепление, потому что удаление сломало бы проигрывание, которое только что его получило.

Переносить могут только Real-Debrid и AllDebrid. У TorBox, Premiumize, Offcloud и Debrid-Link нет ссылки, которая переживает торрент, поэтому их локальное проигрывание добавляет торрент обратно, и перенос ничего бы не освободил. zurg отказывается принимать offload_to для этих аккаунтов.

Дашборд тоже может перенести один отдельный релиз. На странице релиза в таблице Accounts рядом с каждой копией Real-Debrid или AllDebrid показывается кнопка Move to local library, если существует локальная библиотека того же типа, даже без offload_to. Если релиз пока не может переехать, кнопка неактивна и показывает, почему. На странице конфига в настройках аккаунта есть тот же выбор, а также видно, сколько релизов переехало с момента запуска zurg, и последняя ошибка.

Что содержится в файле

Версионированный JSON-формат имеет format: "zurgtorrent" и числовое version: 1. В нём хранятся инфохеш, названия релизов, временная метка добавления, rename, теги, IMDb ID и пути, размеры и необязательные переименования выбранных файлов. Ссылки необязательны:

Провайдер Переносимая ссылка Воспроизведение
Real-Debrid Канонический 13-символьный https://real-debrid.com/d/... Резолвится с учётными данными получателя и его IP для загрузки.
AllDebrid Заблокированный https://alldebrid.com/f/... Разблокируется с учётными данными получателя.
TorBox Хеш и пути/размеры файлов При первом воспроизведении получает торрент на стороне получателя и сопоставляет файлы по пути и размеру.
Premiumize, Offcloud, Debrid-Link Хеш и пути/размеры файлов При первом воспроизведении добавляет хеш в аккаунт получателя и сопоставляет файлы по пути и размеру.

Имена аккаунтов, учётные данные, ID торрентов и файлов у провайдера, CDN-ссылки, входные URL для MediaInfo, Plex ID, состояние repair и очереди удаления не экспортируются. Импортёр отклоняет неизвестные поля, а также ссылки с учётными данными или неожиданные ссылки на файлы. При проверке манифеста он URL не открывает. Usenet сохраняет свой формат исходников .nzb; кэши NZB во время работы нельзя экспортировать как переносимые торренты.

Воспроизведение и ограничения

Локальное отслеживание меняет то, кто владеет каталогом. Но оно не гарантирует, что провайдер всё ещё хранит файлы и может их отдать. Доступ к аккаунту, разрешённые сетевые адреса, активные слоты, квоты и лимиты запросов по-прежнему действуют.

RD и AD используют общие закреплённые ссылки, если они есть. Манифесты только с хешами и ссылка RD, которую API однозначно помечает как отсутствующую, могут установить контент на аккаунт получателя. TorBox всегда требует привязки к аккаунту и сначала переиспользует подходящий торрент, который уже есть на аккаунте получателя. Добавления используют существующие интервалы провайдера и выполняются по одному на каждый аккаунт. Когда аккаунт сообщает количество слотов или zurg его знает, добавление в заполненный аккаунт отклоняется, и следующий запрос на воспроизведение через минуту попробует снова. AllDebrid, Premiumize и Offcloud не сообщают количество слотов, поэтому добавление выполняется, а заполненный аккаунт его отклоняет. Неоднозначное добавление держится 30 минут перед следующей попыткой. Торрент в состоянии подготовки проверяется только при повторном запросе воспроизведения.

ID получателей и разрешённые нативные дескрипторы файлов хранятся приватно в data/local-torrents/. Эта запись переживает перезапуск и входит в обычные бэкапы. zurg никогда не удаляет эти привязки автоматически: идемпотентное добавление могло вернуть торрент, который получатель уже имел. Выгрузка их тоже не трогает. Ошибки провайдера оставляют локальную запись видимой и откладывают повтор. zurg не запускает фоновое восстановление и не повторяет добавление при каждом сканировании.

Архивные релизы с локальными копиями перечисляют свои исходные тома без автоматической распаковки и фонового анализа. Явный путь внутри архива всё равно может вызвать читалку архивов. Автоматическое определение MediaInfo и предзагрузка следующего файла отключены для записей с локальными копиями.

Миграция со старого дампа

Экспортируйте dump/ командой из инструкции выше, положите результаты в директорию torrents/<name>/ аккаунта-получателя и включите library.source: local.

Отключите load_dumped_torrents после миграции. Старый читатель __dump__, включаемый вручную, остаётся для совместимости; новые локальные библиотеки его не используют. Кэши рантайма без типа аккаунта нужно заново экспортировать из инстанса, который знает их провайдера, прежде чем ими можно будет делиться.

Бэкапы, созданные этой сборкой, используют формат 2, чтобы включать новые постоянные корни. Команда восстановления по-прежнему читает бэкапы формата 1. Старые сборки отказываются работать с форматом 2, а не молча теряют локальную библиотеку.
