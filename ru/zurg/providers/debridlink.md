# Debrid-Link

`type: debridlink`

Список seedbox у [Debrid-Link](https://debrid-link.com/id/diG1t) содержит все файлы. Обновление библиотеки требует одного постраничного обхода, а не отдельного запроса для каждого релиза. Из трёх облачных бэкендов это самый дешёвый вариант для поддержания синхронизации.

## Получите API-ключ {#get-the-api-key}

Войдите и откройте [debrid-link.fr/webapp/apikey](https://debrid-link.fr/webapp/apikey). Сгенерируйте ключ и скопируйте его.

## Настройте его {#configure-it}

```yaml
zurg: v1
providers:
  - type: debridlink
    token: YOUR_DEBRID_LINK_API_KEY
mount_path: "/zurg_mnt/zurg"
```

На свежей установке контейнера просто дайте setup записать это.

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider debridlink
```

Если у вас уже есть `config.yml`, используйте **Add provider** в Dashboard по адресу `http://localhost:9999/config/` или отредактируйте файл. В любом случае перезапустите.

```bash
docker compose restart zurg
```

`DEBRIDLINK_TOKEN` читается командой `zurg setup`, а не запущенным демоном.

## Один учётный данные на запись {#one-credential-per-entry}

Debrid-Link определяет каждый файл по ID, который принадлежит аккаунту, к которому относится список файлов.
Переключаться на второй ключ не на что. `download_tokens` отклоняется, и `strm_link_token`, который отличается от `token`, тоже отклоняется. Второй аккаунт — это вторая запись со своим `name`.

```yaml
providers:
  - type: debridlink
    name: dl-main
    token: FIRST_DEBRID_LINK_API_KEY
  - type: debridlink
    name: dl-second
    token: SECOND_DEBRID_LINK_API_KEY
```

## Что здесь работает {#what-works-here}

Просмотр библиотеки, потоковое чтение, перенаправленное чтение, STRM, добавление magnet-ссылок, загрузка `.torrent` и удаление — всё это работает. Для аккаунта создаётся собственная директория `__debridlink__`.

## Ограничения, которые стоит знать {#limits-worth-knowing}

**20 активных слотов.** Это предел, за которым zurg не даёт добавлять новые.

**8 одновременных API-запросов.** Четыре тома многотомного архива обрабатываются одновременно.

**Контент устаревает.** Релиз, которого уже нет, считается ожидаемым, а не сломанным.

**Проверки кэша нет.** Debrid-Link отключил этот эндпоинт, и zurg его не использует. Добавление только из кэша может подтвердить попадание лишь по самому ответу на добавление. Спросить, есть ли что-то в кэше, до добавления этот бэкенд не может.

zurg сопоставляет коды ошибок сервиса с тем, что делать дальше.

| Код от Debrid-Link | Что делает zurg |
|---|---|
| `badToken` или `badSign` | Сообщает о неверных учётных данных. Исправьте ключ. |
| `floodDetected` | Приостанавливает аккаунт на час. |
| `maxTorrent` `maxData` `maxLink` и их варианты с `Host` | Сообщает об исчерпанной суточной квоте на добавления или трафик. |
| `serverNotAllowed` `maintenanceHost` `maxTransfer` | Считает аккаунт временно недоступным. |
| `badId` | Считает торрент удалённым. |

!!!warning Флуд-отказ стоит часа
`floodDetected` блокирует аккаунт на полный час, а не на минуту. Так и задумано: повторные попытки во время флуд-отказа только приводят к следующему. Перед перезапуском zurg сделайте паузу для того, что его перегружало.
!!!

## Проверьте, что всё работает {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/debridlink/test
ls /zurg_mnt/zurg/__all__/ | head
```

При одном аккаунте его собственная папка не выводится в корневом списке маунта,
поэтому маунт показывает те же файлы в `__all__`.

## Когда что-то идёт не так {#when-it-goes-wrong}

**Ничего не происходит в течение часа.** Это отказ из-за флуда. См. предупреждение выше.

**Загрузки отклоняются, но чтение работает.** Дневная квота на добавления или трафик исчерпана. Она сбрасывается по собственному графику сервиса.

**Добавления проходят успешно, а потом застревают.** Без эндпоинта кэша нет способа заранее узнать, был ли хеш уже в кэше. Добавление без кэша загружается как обычно.
