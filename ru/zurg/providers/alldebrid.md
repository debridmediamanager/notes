# AllDebrid

`type: alldebrid`

[AllDebrid](https://alldebrid.com/?uid=1kk5i&lang=en) — это другой бэкенд, который ротирует учётные данные. Поэтому `download_tokens` и отдельный токен для `.strm` здесь обозначают разное. Списки его файлов берутся не из списка magnet-ссылок, а из собственного эндпоинта. Из-за этого первое сканирование большой библиотеки ощущается иначе.

## Получите API-ключ {#get-the-api-key}

Войди в аккаунт и открой [alldebrid.com/apikeys](https://alldebrid.com/apikeys?uid=1kk5i).
Сгенерируй ключ и скопируй его.

## Настройте его {#configure-it}

```yaml
zurg: v1
providers:
  - type: alldebrid
    token: YOUR_ALLDEBRID_API_KEY
mount_path: "/zurg_mnt/zurg"
```

При свежей установке в контейнер пусть файл создаст setup.

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider alldebrid
```

Если в установке уже есть `config.yml`, используй **Add provider** в Dashboard по адресу `http://localhost:9999/config/` или отредактируй файл. В любом случае перезапусти.

```bash
docker compose restart zurg
```

`ALLDEBRID_TOKEN` читает `zurg setup`, а не запущенный демон. Если просто добавить его в блок `environment:` в compose-файле и запустить контейнер, это ничего не даст.

## Дополнительные ключи, которые использует этот бэкенд {#extra-keys-this-backend-uses}

```yaml
providers:
  - type: alldebrid
    token: PRIMARY_AD_API_KEY
    strm_link_token: AD_KEY_FOR_STRM
    download_tokens:
      - SECOND_AD_API_KEY
```

`download_tokens` — это запасные ключи на том же сервисе. Они подхватывают работу, когда у основного ключа заканчивается лимит трафика. Они используют каталог этой записи, а их собственные библиотеки никогда не импортируются.

`strm_link_token` обрабатывает запросы, которые приходят на `/strm/`, чтобы плеер, открывающий `.strm`, не тратил лимит ключа, на котором работает твой live mount. Если он не задан, используется `token`.

## Первое сканирование заполняется постепенно {#the-first-scan-fills-in-gradually}

AllDebrid v4.1 вынес информацию о файлах из списка магнетов в отдельный эндпоинт. Если просто получить список своих магнетов, zurg не узнает, что внутри. На каждый релиз нужен отдельный запрос.

Хорошая новость в том, что этот запрос нужен **только один раз, навсегда**, а не при каждом перезапуске. Файловое дерево магнета не меняется, как только он становится Ready, поэтому кеш информации zurg на диске для него постоянный. Перед эндпоинтом стоит батчер, который обрабатывает первое холодное сканирование. При первом запуске ты увидишь, как большая библиотека появляется частями, а потом это больше не повторяется.

## Ограничения, которые стоит знать {#limits-worth-knowing}

**Никакого опубликованного лимита на активные магниты нет.** zurg его сам не придумывает. Восстановление (repair) никогда не ждёт места, которого и так не было в дефиците.

**600 запросов в минуту на один ключ.** Это задокументированный бюджет. zurg сбавляет темп до 600 минус 100, чтобы повторные попытки, которые HTTP-клиент делает сам по себе, не превысили настоящий предел пачкой запросов. На практике ограничивающий фактор — конкурентность, и она ограничена 12, чтобы соответствовать задокументированным 12 запросам в секунду.

**33-е соединение с одним сервером доставки получает 429.** Измерено 2026-08-23: открывалось по одному соединению каждые 500 мс, и каждое удерживалось. AllDebrid создаёт новое имя хоста для доставки при каждой разблокировке. Поэтому это ограничение срабатывает, только когда несколько чтений попадают на один и тот же хост. zurg ставит в очередь всё, что сверх 32, вместо того чтобы открывать новое соединение.

**Выбора отдельных файлов нет.** Добавление магнита загружает всё его содержимое, а repair повторно добавляет релиз целиком.

**Контент исчезает сам по себе.** Магниты со временем удаляются из аккаунта, а хостер может удалить и ссылку. Пропавший релиз — ожидаемый результат, а не повреждение. Repair не трогает его, пока вы сами об этом не попросите.

**Сохранённые ссылки не устаревают.** Заблокированные ссылки, записанные для файла, пересоздаются по текущему состоянию магнита. Статус самого магнита и так говорит, есть ли данные. zurg не тратит разблокировку на каждый торрент при каждом холодном сканировании, чтобы узнать то, что статус и так сообщает бесплатно.

## Проверьте, что всё работает {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/alldebrid/test
ls /zurg_mnt/zurg/__all__/ | head
```

При одном аккаунте его собственная папка не выводится в корневом списке монтирования,
поэтому монтирование показывает те же файлы в `__all__`.

## Когда что-то идёт не так {#when-it-goes-wrong}

**`AllDebrid rejected the API key` в логе.** Ключ был отозван или перевыпущен. Получите новый на [alldebrid.com/apikeys](https://alldebrid.com/apikeys?uid=1kk5i) и обновите запись.

**Холодная библиотека появляется медленно.** Так и должно быть. См. раздел выше. Это один запрос на релиз, и он не повторяется.

**Релиз воспроизводится в другом месте маунта, но выдаёт 404 под `__alldebrid__`.** Битость определяется для каждого аккаунта, а эта директория привязывает чтение к одному аккаунту. Какой-то другой аккаунт держит рабочую копию.
