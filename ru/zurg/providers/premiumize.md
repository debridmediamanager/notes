# Premiumize

`type: premiumize`

Premiumize монтирует завершённые загрузки **и** облачные файлы, которые остаются после очистки списка загрузок. Вложенные папки сохраняют свои пути. Библиотека, которую вы организовали на Premiumize, попадает в монтирование в том же виде, в каком вы её оставили.

## Получите API-ключ {#get-the-api-key}

Войдите в аккаунт и откройте [premiumize.me/account](https://www.premiumize.me/account). API-ключ находится на этой странице.

## Настройте его {#configure-it}

```yaml
zurg: v1
providers:
  - type: premiumize
    token: YOUR_PREMIUMIZE_API_KEY
mount_path: "/zurg_mnt/zurg"
```

На свежей установке контейнера пусть это запишет setup.

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider premiumize
```

Если у вас уже есть `config.yml`, используйте **Add provider** в Dashboard по адресу `http://localhost:9999/config/` или отредактируйте файл. В любом случае перезапустите.

```bash
docker compose restart zurg
```

`PREMIUMIZE_TOKEN` читает `zurg setup`, а не работающий демон. Сама по себе переменная в блоке `environment:` compose ничего не делает.

## Один учётный данные на запись {#one-credential-per-entry}

Идентификаторы файлов Premiumize принадлежат аккаунту, который их добавил. Второго ключа для ротации нет. `download_tokens` отклоняется полностью, и так же отклоняется `strm_link_token`, если он отличается от `token`. Второй аккаунт Premiumize — это вторая запись со своим собственным `name`.

```yaml
providers:
  - type: premiumize
    name: pm-main
    token: FIRST_PREMIUMIZE_API_KEY
  - type: premiumize
    name: pm-second
    token: SECOND_PREMIUMIZE_API_KEY
```

Загрузчик на этот счёт явный: он не пропускает такие ключи молча, а отказывается загружать конфиг и называет запись, в которой проблема.

## Что здесь работает {#what-works-here}

Просмотр библиотеки, потоковое чтение, редиректы, STRM, добавление magnet-ссылок и загрузка `.torrent`-файлов, а также удаление всё работает. Для аккаунта создаётся собственная папка `__premiumize__`, как и для любого другого.

## Хэши запоминаются на диске {#hashes-are-remembered-on-disk}

Хэши, которые передаются через zurg, записываются в `data/premiumize/<account>/sources.json` внутри bind-монтирования `/config`. Сопоставление между аккаунтами сохраняется после перезапуска и после очистки списка завершённых передач.

Облачный контент, который вы импортировали другим способом, не имеет записанного хэша. Он всё равно стримится. Восстановить его по хэшу нельзя, и сопоставить его с другим аккаунтом по хэшу тоже нельзя.

!!!warning Удаление передачи удаляет её файлы
Удаление передачи Premiumize через zurg также удаляет файлы, которые принадлежат этой передаче. Это собственное поведение Premiumize, а не то, что zurg добавляет сверху.
!!!

## Ограничения, которые стоит знать {#limits-worth-knowing}

**Лимиты облачного хранилища и fair use — это собственные лимиты аккаунта.** zurg их не повышает
и не обходит.

**8 одновременных API-запросов.** Четыре тома многотомного архива разрешаются
одновременно.

**Контент устаревает.** Релиз, которого уже нет, — ожидаемый результат, а не
ошибка. Repair его не трогает, если вы сами не попросите.

**Список торрентов не содержит подробностей о файлах.** Каждый релиз требует
собственного запроса при первом обращении.

zurg сопоставляет коды ошибок сервиса с тем, что ему нужно сделать дальше.

| Код от Premiumize | Что делает zurg |
|---|---|
| `authentication_failed` | Сообщает о неверных учётных данных. Исправьте ключ. |
| `rate_limit_reached` | Приостанавливает аккаунт на минуту. |
| `account_limit_reached` или `service_limit_reached` | Сообщает об исчерпанном лимите. |
| `service_down` | Считает аккаунт временно недоступным. |
| `not_found` | Считает торрент удалённым. |

## Проверьте, что всё работает {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/premiumize/test
ls /zurg_mnt/zurg/__all__/ | head
```

Если у вас только один аккаунт, его собственная папка не попадает в корневой список монтирования, поэтому монтирование показывает те же файлы в `__all__`.

## Когда что-то идёт не так {#when-it-goes-wrong}

**Все падает с ошибкой учётных данных.** Перегенерируйте ключ на [premiumize.me/account](https://www.premiumize.me/account) и обновите запись.
Учтите, что Premiumize одинаково отвечает и на отсутствующий ключ, и на неверный. Из сообщения не понять, какой именно случай.

**Релиз стримится, но не восстанавливается.** У него нет записанного хеша. Значит, он попал в аккаунт не через zurg. См. выше.

**Чтение останавливается на минуту.** Достигнут лимит запросов, и zurg намеренно приостановил аккаунт. Он возобновится сам.

**Сгенерированные ссылки работают для любого, у кого они есть.** Ссылки доставки и доступ через `.strm` лучше держать в тайне. Квоту, которую они расходуют, получает сам аккаунт.
