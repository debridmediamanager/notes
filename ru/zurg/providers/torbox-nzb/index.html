TorBox hosted Usenet

Пусть TorBox загружает ваши Usenet-релизы для zurg: отправляйте NZB-файлы в аккаунт TorBox Pro и смотрите их без собственного новостного сервера.

type: torbox_nzb

С планом TorBox Pro TorBox берёт на себя часть работы с Usenet. zurg отправляет файлы .nzb из своей директории наблюдения в ваш аккаунт TorBox. TorBox загружает каждый релиз, восстанавливает его и отдаёт как любую другую загрузку TorBox. zurg показывает в маунте то, что TorBox загрузил, рядом со всем остальным. Аккаунт новостного сервера не нужен, и статьи Usenet на вашей машине не декодируются.

Это не новостной сервер TorBox. Это логин для бэкенда nzb, который сам читает статьи. Он описан на странице Usenet. И это не запись torbox. Та показывает ваши торренты, о ней рассказано на странице TorBox.

Что понадобится

  • План TorBox Pro. Более низкий план NZB не поддерживает.

  • Ваш API-ключ TorBox с torbox.app/settings. Это тот же ключ, что используется в записи torbox.

  • Актуальная nightly-сборка zurg. Nightly-сборки доступны только при активном спонсорстве.

  • Обычный хост. zurg+rex на Android, то есть Plex-сервер на телефоне, не поддерживает бэкенд torbox_nzb. На устройстве Android воспроизводите NZB, размещённые на TorBox, через TorBox Cast в DMM или через аддон для Kodi.

Настройте его

Запись принимает token; блока nntp нет. watchlist задать нельзя, потому что аккаунт NZB не может добавлять торренты.

providers:
  - type: torbox_nzb
    token: YOUR_TORBOX_API_KEY

На свежей установке контейнера сначала сохрани свой ключ в ~/zurg/secrets/torbox, а потом дай setup его прочитать.

cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider torbox_nzb \
  --torbox-token-file /config/secrets/torbox

Если у тебя уже есть config.yml, можно также использовать Add provider в Dashboard по адресу http://localhost:9999/config/ и выбрать torbox_nzb. В любом случае перезапусти zurg.

docker compose restart zurg

Как NZB попадают внутрь

Всё, что попадает в запись nzb, приходит сюда одним и тем же способом. Действие DMM «TorBox» — единственный путь, который обходит zurg.

  • Папка наблюдения. Положите файл в nzbs/ рядом с конфигом (~/zurg/nzbs/ на хосте, /config/nzbs/ в контейнере). zurg отправит его в TorBox.
  • Sonarr и Radarr через эндпоинт zurg, совместимый с SABnzbd. См. Sonarr and Radarr for Usenet.
  • Получение. Индексаторы Newznab, DMM Wanted и списки отслеживания добавляют сюда релизы. См. Acquisition.
  • Действие DMM «TorBox» для результата из Usenet отправляет NZB напрямую в TorBox. Релиз тоже появляется в zurg, но zurg не хранит для него NZB, поэтому кнопка repair не может загрузить его повторно, когда TorBox его удалит.

Если TorBox не может получить пост, он сообщается в Sonarr или Radarr как неудачная загрузка. Клиент добавляет релиз в blocklist и ищет снова.

Чем отличается от nzb

  • Нет новостного аккаунта. Здесь нет лимита соединений для настройки и не нужно учитывать retention провайдеров. Что можно скачать из поста, решает собственный spool TorBox.
  • Статьи здесь не декодируются. TorBox скачивает весь релиз целиком. Загрузка статей, восстановление PAR2, кэш статей и проверка статей здесь не нужны; дисковый кэш распакованных архивов при этом по-прежнему работает. Успешность загрузки определяется тем, скачал ли её TorBox.
  • Кэш на 30 дней. Релиз, который кто-то уже скачивал на TorBox, готов сразу. TorBox удаляет релиз через 30 дней после того, как закэшировал его. Кнопка repair на дашборде заново скачивает его, отправляя NZB ещё раз, поэтому файлы держите в nzbs/. zurg никогда не отправляет посты повторно сам, потому что TorBox считает такие загрузки без участия пользователя злоупотреблением.
  • Один слот на каждый NZB в работе. Пост, который TorBox ещё скачивает, занимает один из активных слотов вашего тарифа. Запись torbox с тем же ключом использует те же слоты для своих торрентов.
  • 60 постов в час. TorBox принимает столько новых NZB в час на каждый ключ. Большой объём, например полный nzbs/ при первом запуске, будет обрабатываться несколько часов.

Один аккаунт NZB на каждый экземпляр

Экземпляр принимает либо одну запись nzb, либо одну запись torbox_nzb, но никогда обе сразу. Иначе каждый файл из nzbs/ попадёт в список дважды. Чтобы запустить обе, дайте другому типу собственный экземпляр со своим рабочим каталогом. Если у обоих включён dmm_api_key, отключите источник dmm-wanted в одном из них, иначе каждый титул из Wanted будет загружаться дважды. Любой из вариантов может работать рядом с вашими аккаунтами debrid.

Аддон zurg для Stremio отправляет свой выбор на тот NZB-аккаунт, который есть у экземпляра. С torbox_nzb релиз, который TorBox уже хранит, начинает воспроизводиться в пределах ожидания аддона, если в очереди нет других NZB-запросов. Некэшированный релиз сначала должен полностью загрузиться на TorBox, а это дольше, чем плеер готов ждать.

Проверьте, что всё работает

curl -fsS -X POST http://localhost:9999/api/providers/torbox_nzb/test
ls /zurg_mnt/zurg/__all__/
curl -s http://localhost:9999/http/__torbox_nzb__/ | head

При одном аккаунте его собственная папка не выводится в корневом списке монтирования, поэтому монтирование показывает те же файлы в __all__. Имя каталога соответствует имени записи, которое по умолчанию совпадает с её типом.
