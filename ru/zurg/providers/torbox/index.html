TorBox

Используйте аккаунт TorBox с zurg: получите API-ключ, добавьте его в config.yml и посмотрите, как zurg укладывается в лимиты TorBox.

type: torbox

TorBox — самая дешёвая библиотека, которую zurg держит в синхронизации, и её проще всего замедлить при чтении. Список торрентов уже содержит все файлы. Обновление библиотеки занимает один запрос, а не по одному на каждый торрент. Эндпоинт получения ссылок работает по фиксированной квоте, а не по скорости. Поэтому zurg с ним намеренно аккуратен.

Получите API-ключ

Войдите и откройте torbox.app/settings. API-ключ находится на этой странице.

Бесплатный аккаунт с zurg не работает. TorBox отвечает на каждый запрос к библиотеке бесплатным ключом ошибкой PLAN_RESTRICTED_FEATURE, поэтому zurg не может прочитать содержимое аккаунта. Используйте платный тариф. Если платный тариф истекает, аккаунт так же превращается в бесплатный.

Настройте его

zurg: v1
providers:
  - type: torbox
    token: YOUR_TORBOX_API_KEY
mount_path: "/zurg_mnt/zurg"

При чистой установке контейнера пусть setup сам всё запишет.

cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider torbox

Если у вас уже есть config.yml, используйте Add provider в Dashboard по адресу http://localhost:9999/config/ или отредактируйте файл. В любом случае после этого перезапустите сервис.

docker compose restart zurg
Ключ TorBox в переменных окружения compose сам по себе ничего не делает

TORBOX_TOKEN читает zurg setup, а не запущенный демон. Только TOKEN от Real-Debrid создаёт конфиг при первом запуске. Передайте ключ в контейнер setup или добавьте аккаунт в Dashboard.

Для установки без присмотра укажите setup файл вместо переменной окружения.

docker compose run --rm zurg setup --non-interactive \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider torbox \
  --torbox-token-file /config/secrets/torbox

Два ключа, которые здесь не действуют

download_tokens принимается, но на Real-Debrid не делает того, что должен. Переключение на второй ключ не меняет ID торрентов и файлов. На TorBox эти ID принадлежат аккаунту, который их составил. Для второго аккаунта TorBox нужна отдельная запись со своим name.

providers:
  - type: torbox
    name: tb-main
    token: FIRST_TORBOX_API_KEY
  - type: torbox
    name: tb-second
    token: SECOND_TORBOX_API_KEY

strm_link_token принимается, но не используется. TorBox создаёт URL для загрузки при каждом запросе. Постоянного ключа, к которому мог бы привязаться файл .strm, нет.

Реальный предел — активные слоты

TorBox главное ограничение - это количество торрентов, которые могут одновременно скачиваться или раздаваться. У Real-Debrid это полоса пропускания. У TorBox это слоты.

Plan Active slots
Free 1, но zurg не может использовать бесплатный ключ (см. выше)
Essential 3
Standard 5
Pro 10

zurg читает тариф из аккаунта и ограничивает добавление новых торрентов в зависимости от него. Если аккаунт не получается прочитать, zurg считает, что слотов 3.

Всё остальное, что добавляет торренты, тоже считайте по тому же бюджету слотов. Sonarr и Radarr, которые отправляют торренты через эндпоинт qBittorrent, проверка для восстановления и watchlist тоже занимают эти же слоты.

Ограничения, которые стоит знать

Разрешение ссылок — это бюджет примерно в сотню вызовов, а не скорость. Измерено 2026-08-30. Ответ 429 с Retry-After: 300 пришёл на 100-м накопленном вызове, когда вызовы делались как можно быстрее. Он пришёл на 94-м вызове, когда они шли с интервалом в одну секунду. Блокировка действует на весь аккаунт. Она останавливает весь маунт на пять минут, а не только тот запрос, который её вызвал.

Из этого следуют две вещи, и zurg делает обе сами.

  • Он никогда не разрешает файл, который никто не запрашивал. Другие бэкенды могут заранее подготовить следующую серию. TorBox так не может, потому что медиасервер при анализе библиотеки открывает каждый файл ровно один раз, и каждое такое открытие — холодное.
  • Он разрешает тома многотомного архива строго по одному. Быстрее означало бы несколько раз потратить лимит и купить тома, идущие за сломанным, до того как кто-либо понял, что они не нужны.

60 добавлений без кэша в час. Добавления из кэша вместо этого попадают под поминутный бюджет.

300 запросов в минуту по всем эндпоинтам для одного ключа. zurg держит темп на уровне 300 минус 60, чтобы повторы, которые HTTP-клиент делает сам, не выводили запланированный всплеск за реальный лимит.

21-е соединение к одному CDN-хосту получает 429. Измерено 2026-08-23 так: открывалось одно соединение каждые 500 мс, и каждое удерживалось. Лимит действует на хост, а не на ключ. Распределение чтений по парку TorBox его обходит, а если свалить их на один узел — не обходит. zurg ставит в очередь всё, что сверх 20, вместо того чтобы открывать новое соединение. Так отказ превращается в короткое ожидание на своей стороне.

Контент удаляется по истечении срока хранения тарифа. Торрент, который пропал, — это ожидаемо, а не поломка. Repair его не трогает, если вы явно не запросите обратное.

Выбрать отдельные файлы нельзя. Добавление торрента загружает его целиком, а repair добавляет релиз заново целиком.

Полную картину с источниками см. в разделе Ограничения TorBox.

Выбор региона CDN

tb_cdn_host_preference: "auto"

auto не трогает выбор TorBox. force_location_<region> отдает загрузки из указанного региона. Форсировать можно только те регионы, которые сейчас объявляют узел доставки, и именно их показывает список на Dashboard. Не используйте cdn_host_preference здесь. Этот ключ работает только для Real-Debrid, а его значения — коды местоположений Real-Debrid.

Проверьте, что всё работает

curl -fsS -X POST http://localhost:9999/api/providers/torbox/test
ls /zurg_mnt/zurg/__all__/ | head

Если у вас только один аккаунт, его собственная папка не выводится в корневом списке монтирования, поэтому монтирование показывает те же файлы в __all__.

Когда что-то идёт не так

В логе написано Account <name> refused zurg или постоянно повторяется TorBox rejected the API key. Подписка закончилась, и ключ теперь на бесплатном тарифе. Начиная с nightly 2026.10.11.2240 zurg загружает твои другие аккаунты без него. На карточке аккаунта в дашборде будет написано Refused: the account's plan does not include API access. Его релизы остаются в списке, но не воспроизводятся, и из-за этого ничего не удаляется и не отправляется в корзину. zurg каждые 10 минут снова запрашивает TorBox и подхватывает аккаунт, как только тариф оплачен. На старых nightly вся библиотека не успевала загрузиться, поэтому контент из других аккаунтов тоже переставал показываться. Обнови zurg или продли тариф. Также работает вариант: закомментировать провайдер torbox в config.yml и перезапустить zurg.

Воспроизведение останавливается на пять минут. Лимит requestdl исчерпан, и ошибка 429 действует на весь аккаунт. Значит, что-то запрашивает ссылки больше, чем нужно. Обычная причина: медиасервер сканирует всё монтирование сразу. Укажи ему одну папку, а не все.

Новые добавления перестают приниматься. Либо заняты все активные слоты, либо исчерпан почасовой лимит добавлений. Оба ограничения снимаются сами, и повторные попытки тут не помогут.

В релизе файлов меньше, чем ты ожидаешь. __torbox__ показывает только то, что TorBox реально хранит. Если другой аккаунт держит релиз целиком, остальная часть монтирования всё равно отдаёт его полностью.

Торрент пропал. Это срок хранения, см. выше. zurg не будет добавлять его обратно без твоего участия, потому что повторный поиск расходует лимит аккаунта впустую.
