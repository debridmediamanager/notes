# Offcloud

`type: offcloud`

Offcloud получает файловые дескрипторы через свой эндпоинт cloud explore. Размеры файлов проверяются на сервере доставки, а не берутся из списка на веру. Там, где кэшированные метаданные торрентов можно сопоставить однозначно, они подсказывают пути к папкам.

## Получите API-ключ {#get-the-api-key}

Войдите и откройте [offcloud.com/#/account](https://offcloud.com/#/account). API-ключ находится на этой странице.

## Настройте его {#configure-it}

```yaml
zurg: v1
providers:
  - type: offcloud
    token: YOUR_OFFCLOUD_API_KEY
mount_path: "/zurg_mnt/zurg"
```

На свежей установке контейнера пусть это запишет setup.

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider offcloud
```

Если у вас уже есть `config.yml`, используйте **Add provider** в Dashboard по адресу `http://localhost:9999/config/` или отредактируйте файл. В любом случае перезапустите контейнер.

```bash
docker compose restart zurg
```

`OFFCLOUD_TOKEN` читает `zurg setup`, а не запущенный демон.

## Один учётный данные на запись {#one-credential-per-entry}

Файловые дескрипторы Offcloud принадлежат аккаунту, который их вывел. Второго ключа, на который можно было бы переключиться, нет. `download_tokens` отклоняется, и `strm_link_token`, который отличается от `token`, тоже отклоняется. Второй аккаунт добавляется как вторая запись со своим `name`.

```yaml
providers:
  - type: offcloud
    name: oc-main
    token: FIRST_OFFCLOUD_API_KEY
  - type: offcloud
    name: oc-second
    token: SECOND_OFFCLOUD_API_KEY
```

## Что здесь работает {#what-works-here}

Просмотр библиотеки, потоковое чтение, редиректы, STRM, добавление по magnet и загрузка `.torrent` файлов, а также удаление — всё это работает. Для аккаунта создаётся своя папка `__offcloud__`.

## Ограничения, которые стоит знать {#limits-worth-knowing}

**8 параллельных API-запросов.** Четыре тома многотомного архива обрабатываются одновременно.

**Контент устаревает.** Релиз, которого больше нет, считается нормальным, а не сломанным. Repair его не трогает, если вы сами не попросите.

**Список торрентов не содержит информации о файлах.** Поэтому при первом обращении каждый релиз требует отдельного запроса.

**Неоднозначный список файлов — это ошибка, а не догадка.** Бывает, что кэшированные метаданные торрента нельзя сопоставить ровно с одним релизом. zurg сообщает об этом, вместо того чтобы выбирать пути к папкам, которые могут принадлежать чему-то другому.

**Некорректные магнет-ссылки отсеиваются локально.** До сервиса они не доходят. Плохая магнет-ссылка ничего не стоит.

Словарь ошибок Offcloud довольно скудный. `NOAUTH` — единственный код, с которым zurg может что-то сделать: он означает, что учетные данные отклонены. Всё остальное приходит как отказ без причины.

## Проверьте, что всё работает {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/offcloud/test
ls /zurg_mnt/zurg/__all__/ | head
```

При одном аккаунте его собственная папка не попадает в корневой листинг монтирования,
поэтому монтирование показывает те же файлы в `__all__`.

## Когда что-то идёт не так {#when-it-goes-wrong}

**`NOAUTH` в логе.** Ключ был отозван или перевыпущен. Получите новый на [offcloud.com/#/account](https://offcloud.com/#/account) и обновите запись.

**`API refused request` без других деталей.** Offcloud не сообщил причину. Прежде чем считать, что виноват zurg, проверьте аккаунт в браузере.

**Релиз не показывает папок.** Закэшированные метаданные торрента не удалось сопоставить ровно с одним релизом. Файлы всё равно стримятся, просто они лежат без папок.

**Сгенерированные URL работают у любого, кто их получил.** Ссылки доставки обновляются, когда истекает их кэш или когда чтение делает их недействительными. Квота, которую они расходуют, принадлежит аккаунту. Храните их и доступ к `.strm` в тайне.
