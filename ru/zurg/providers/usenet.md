# Usenet

`type: nzb`

Usenet — это тип провайдера, но не сервис debrid. Здесь нет API-токена и нет удалённой библиотеки. Вы кладёте файлы `.nzb` в каталог наблюдения, а zurg превращает каждый из них в релиз. Статьи загружаются с вашего новостного сервера и декодируются в тот момент, когда плеер запрашивает эти байты.

Эта страница содержит только описание провайдера и особенности Docker. Всё остальное о запуске Usenet на zurg находится в [Usenet with zurg](../guides/usenet.md). Это полное руководство с новостными аккаунтами, NZB, монтированием и Plex. Его стоит прочитать вторым.

## Настройте его {#configure-it}

Токена `token` нет. Запись становится валидной, когда есть блок `nntp` с host.

```yaml
zurg: v1
providers:
  - type: nzb
    nntp:
      host: news.example.com
      port: 563
      tls: true
      username: YOUR_USENET_USERNAME
      password: YOUR_USENET_PASSWORD
      connections: 8
      cache_size_mb: 512
mount_path: "/zurg_mnt/zurg"
```

Укажи в `connections` то, что реально позволяет твой тариф. zurg читает именно с таким количеством, потому что одно соединение даёт лишь часть пропускной способности тарифа. Стриминг использует весь лимит, а не качает по одной статье за раз. Если превысить то, что разрешает тариф, соединения будут отклоняться.

При чистой установке в контейнере setup запросит всё это.

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider nzb
```

Для установки без участия пользователя пароль берётся из файла, а всё остальное из флагов.

```bash
docker compose run --rm zurg setup --non-interactive \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider nzb \
  --nntp-host news.example.com \
  --nntp-username YOUR_USENET_USERNAME \
  --nntp-password-file /config/secrets/nntp \
  --nntp-connections 8
```

По умолчанию `--nntp-tls` равен true, а `--nntp-port` равен 563 с TLS или 119 без него.

Если в установке уже есть `config.yml`, используй **Add provider** в Dashboard по адресу `http://localhost:9999/config/` или отредактируй файл. В любом случае перезапусти.

```bash
docker compose restart zurg
```

## Где лежат NZB в контейнере {#where-the-nzbs-go-in-a-container}

Папка наблюдения — это `nzbs/` рядом с конфигом. То есть `~/zurg/nzbs/` на хосте и `/config/nzbs/` внутри контейнера. Это одна и та же папка. Кладите файлы с хоста.

```bash
mkdir -p ~/zurg/nzbs
cp /path/to/some.nzb ~/zurg/nzbs/
ls /zurg_mnt/zurg/__all__/
```

Если у вас только один аккаунт, его собственная папка `__nzb__` не показывается в корневом списке точки монтирования, поэтому смотрите в `__all__`. Папку наблюдения подхватывают примерно каждые 15 секунд. Она лежит внутри bind-монтирования `./:/config`, поэтому, как и всё остальное, переживёт `docker compose pull` и пересоздание контейнера.

## Правила, специфичные для этого типа {#rules-specific-to-this-type}

- **Только одна включённая запись `nzb`.** Две будут сканировать одну и ту же директорию и дублировать каждый релиз. Больше новостных серверов добавляются в `nntp.servers` этой единственной записи. Там они работают с той же библиотекой, а не с отдельной копией. Запись `nzb` рядом с записью [`torbox_nzb`](torbox-nzb.md) тоже отклоняется по той же причине.
- **`watchlist: true` отклоняется.** Новостной сервер никогда не получает торрент.
- **`add_torrents` игнорируется**, и при запуске выводится предупреждение по той же причине.
- **`download_tokens` и `strm_link_token` ничего не делают.** Здесь нет учётных данных, которые нужно менять.
- **Директория называется `__nzb__`**, потому что имя по умолчанию совпадает с типом. Если хотите, чтобы она называлась `__usenet__`, задайте в записи `name: usenet`.

## Второй новостной сервер стоит больше, чем кажется {#a-second-news-server-is-worth-more-than-it-looks}

Хранение зависит от провайдера. Статья, которая уже пропала на одном сервере, very often ещё лежит на другом. Без второго аккаунта единственный способ восстановить пропавшую статью — это PAR2, а для него нужно прочитать **весь релиз целиком**. Поэтому второй сервер — это разница между загрузкой одной статьи и перечитыванием всего.

Дополнительные аккаунты добавляйте в `nntp.servers` этой записи, а не во вторую запись `nzb`. `priority`, `backup` и `backbone` определяют, кого спрашивать и в каком порядке. Чтение идёт на полной мощности суммарного лимита тех аккаунтов, которые не помечены `backup`. Готовый пример конфига и то, что даёт каждый ключ, описаны в [Usenet с zurg](../guides/usenet.md#more-than-one-usenet-provider).

## Проверьте, что всё работает {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/nzb/test
docker compose logs --tail=100 zurg
ls /zurg_mnt/zurg/__all__/
```

При одном аккаунте его собственная папка не выводится в корневом списке монтирования, поэтому монтирование показывает те же файлы в `__all__`.

Проверка здесь авторизуется на новостном сервере, используя не более одного соединения из существующего пула. Запросить это через API аккаунта нельзя.

## Когда что-то идёт не так {#when-it-goes-wrong}

Два симптома относятся к самой записи провайдера, а не к библиотеке.

**Чтение рвётся, и zurg переходит к одной статье за раз.** `pipeline_depth` выше, чем сервер может выдержать. zurg сам уменьшает значение и выводит предупреждение. Для сервера, который не справляется с несколькими командами одновременно, задайте `1` явно.

**Низкая скорость на канале с высокой задержкой.** Не задавайте `socket_receive_buffer_kb`. Зафиксированный буфер перестаёт подстраивать ядро. В Linux это удерживает окно приёма около 64 KiB и отнимает большую часть скорости аккаунта.

Всё остальное есть в таблице решения проблем на странице [Usenet with zurg](../guides/usenet.md#troubleshooting). Там же описаны отказы подключения, медленный стриминг, провайдер, которого никогда не спрашивают, и правка в Dashboard, из-за которой пропал `nntp.servers`.
