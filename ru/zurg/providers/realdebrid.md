# Real-Debrid

`type: realdebrid`

zurg начинался как сервер для [Real-Debrid](http://real-debrid.com/?id=20476302) и до сих пор знает его лучше всего. Это единственный бэкенд с выбором отдельных файлов, отдельным списком `__downloads__`, выбором CDN-хоста и отдельным токеном для `.strm`.

## Получите API-токен {#get-the-api-token}

Войди в аккаунт и открой [real-debrid.com/apitoken](http://real-debrid.com/?id=20476354).
Токен — это длинная hex-строка. Скопируй её целиком.

!!!warning Сначала отключи автоматический remote traffic
На своей [странице аккаунта](http://real-debrid.com/?id=20476410) убедись, что **Use my
Remote Traffic automatically when needed** снят. Если оставить включенным, он будет тратить твой лимит remote traffic на обычный стриминг, и ты об этом не узнаешь.
!!!

## Настройте его {#configure-it}

```yaml
zurg: v1
providers:
  - type: realdebrid
    token: YOUR_RD_API_TOKEN
mount_path: "/zurg_mnt/zurg"
```

На свежей установке контейнера пусть это за вас сделает установка.

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider realdebrid
```

Если у вас уже есть `config.yml`, откройте Dashboard по адресу `http://localhost:9999/config/` или отредактируйте файл. Затем перезапустите.

```bash
docker compose restart zurg
```

### Единственный провайдер, которого контейнер может получить из переменных окружения {#the-one-provider-a-container-can-seed-from-the-environment}

Real-Debrid — единственный аккаунт, для которого запущенный демон сам создаст конфиг. `TOKEN` или `RD_TOKEN` в блоке `environment:` твоего compose-файла заполняют `config.yml` при запуске, который его создаёт. `MOUNT_PATH` задаёт путь монтирования.

```yaml
    environment:
      - TOKEN=YOUR_RD_API_TOKEN
      - MOUNT_PATH=/zurg_mnt/zurg
```

Оба параметра читаются **только** при первом запуске. Как только файл существует, он становится единственным источником правды. Устаревшая переменная никогда не отменит тихо путь монтирования, который ты задал в Dashboard. При старте выводится предупреждение, если `MOUNT_PATH` игнорируется по этой причине.

## Дополнительные ключи, которые использует этот бэкенд {#extra-keys-this-backend-uses}

```yaml
providers:
  - type: realdebrid
    token: PRIMARY_RD_TOKEN
    strm_link_token: RD_TOKEN_FOR_STRM
    download_tokens:
      - SECOND_RD_TOKEN
      - THIRD_RD_TOKEN
```

`download_tokens` — это запасные API-токены того же сервиса. Они включаются, когда
у активного токена заканчивается лимит трафика. Они используют каталог этой записи,
а их собственные торрент-библиотеки никогда не импортируются.

`strm_link_token` обрабатывает запросы, которые приходят на `/strm/`, чтобы плеер, открывающий
файл `.strm`, не тратил трафик токена, по которому идёт ваш живой монтаж. Если он не задан,
используется `token`.

Оба стоит иметь, потому что Real-Debrid — один из двух бэкендов, которые вообще меняют учётные данные.

## Чем Real-Debrid отличается от остальных {#what-real-debrid-does-that-the-others-do-not}

- **Выбор файлов по отдельности.** Когда добавляешь релиз, можно забрать только часть его файлов. Поэтому `force_select_playable_files` есть за что зацепиться, а repair может сузить работу до сломанных файлов и не перезаливать весь релиз целиком.
- **Второй список с названием downloads.** `__downloads__` в корне монтирования — это список неограниченных ссылок, которого есть только у Real-Debrid. Чтобы очистить его разом, нужна cookie веб-сессии. Поэтому единственный способ сделать это — кнопка на Dashboard. Если у установки нет аккаунта Real-Debrid, ей об этом прямо сообщают, а не показывают ложный успех.
- **Выбор CDN-хоста.** `rd_cdn_host_preference` выбирает между вариантом, который предлагает сам Real-Debrid, его Cloudflare-двойниками и конкретной страной. См. [CDN and host selection](../reference/config.md#cdn--host-selection).
- **Repair.** Ссылка Real-Debrid, привязанная к файлу, может перестать работать, while торрент при этом всё ещё показывает статус healthy. Именно ради этого у zurg есть подсистема repair, и это единственный бэкенд, которому она нужна.

## Ограничения, которые стоит знать {#limits-worth-knowing}

**Два добавления на одном аккаунте должны идти с интервалом в 20 секунд.** Замерено на живом API 2026-08-17. Шесть чистых названий релизов, добавленных с интервалом в десять секунд, были отклонены шесть раз из шести. Те же шесть, но с интервалом в двадцать секунд, были приняты шесть раз из шести. zurg сам выдерживает этот минимум между своими добавлениями.

**Отказ добавления выглядит точно так же, как заблокированное имя файла.** Real-Debrid отвечает на оба случая одинаково: `451 infringing_file`. У ограничителя частоты тоже есть память. Однажды сработав, он продолжает отказывать и через несколько минут затишья. В одной боевой проверке-восстановлении четыре часа ничего не добавлялось, потому что в начале три добавления пришли с разницей меньше тринадцати секунд.

**Некоторые релизы отклоняются только из-за своего названия.** С 14 октября 2026 года таких строк одиннадцать. WEB-DL, WEB.x264 и WEB.H264 срабатывают только в точно таком написании, поэтому web-dl, Web-Dl и сценовое WEB.h264 проходят. WEBRip, BDRip, HDRip, DVDRip, HDTV.x264, HDTV.XviD, BluRay.x264 и p.BluRay.DTS срабатывают в любом регистре. Последней нужна буква p прямо перед ней, как в 1080p.BluRay.DTS. Релиз 2002.BluRay.DTS в порядке. Важен только точный разделитель. WEB.DL, WEB-x264 и BluRay-x264 проходят. Релиз, название которого содержит одну из них, отклоняется на первом же запросе каждый раз, что бы за ним ни стояло. Файл внутри релиза, чьё собственное название подходит под шаблон, принимается, но не стримится. zurg знает эти шаблоны и отсекает такие добавления локально, вместо того чтобы тратить слот добавления и две повторные попытки по шестьдесят секунд на заведомо провальную попытку.

**Вторая копия контента, который уже есть на аккаунте, никогда не скачивается.** Real-Debrid принимает добавление, но ничего для него не загружает. Экземпляр навечно застревает на 0 процентах и 0 сидах.

**Список торрентов не содержит сведений о файлах.** Для каждого торрента нужен отдельный запрос info. Поэтому zurg хранит info-кэш на диске. Холодное сканирование большой библиотеки — самый дорогой случай, и кэш не даёт ему повторяться.

Три ключа регулируют темп работы с API, и значения по умолчанию подходят для обычного аккаунта.

```yaml
api_rate_limit_per_minute: 250
torrents_rate_limit_per_minute: 75
fetch_torrents_page_size: 5000
```

## Проверьте, что всё работает {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/realdebrid/test
ls /zurg_mnt/zurg/__all__/ | head
```

Если у вас только один аккаунт, его собственная папка не отображается в корневом списке монтирования, поэтому монтирование показывает те же файлы в `__all__`.

## Когда что-то идёт не так {#when-it-goes-wrong}

**`RD Permission denied` в логе.** Ключ был отозван или перевыпущен. Получите новый
на [real-debrid.com/apitoken](http://real-debrid.com/?id=20476302) и
обновите запись в Dashboard или в `config.yml`.

**Каждый grab возвращает 451.** Либо имя релиза такое, которое Real-Debrid отказывается принимать вообще, либо добавления пришли слишком часто подряд, и троттлинг ещё действует. Это проходит от паузы, а не от повторных попыток.

**При первом запуске монтирование ничего не показывает.** Большая библиотека загружается некоторое время. `/dav/movies/` отвечает 503, пока загрузка не завершится.

**Ссылки проходят проверку, а затем ничего не отдают.** Включите `use_range_verification`, чтобы zurg проверял с помощью GET с диапазоном в один байт, а не `HEAD`. Некоторые сети и некоторые серверы Real-Debrid неправильно отвечают на `HEAD`.
