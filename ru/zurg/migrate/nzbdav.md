# Миграция с nzbdav на zurg {#migrating-from-nzbdav-to-zurg}

Сначала прочитайте [общую страницу](index.md). Там объясняется защита от мусора и то, почему ваша библиотека попадает в `__magic__`.

Последний релиз nzbdav-dev, v0.6.4, вышел в апреле 2026 года, а вышестоящий репозиторий больше не поддерживается. Этот релиз работает. Миграция нужна, чтобы уйти от неподдерживаемого софта. Торопиться с переключением не нужно.

**Это самая простая из пяти миграций.** Если сравнить с zurg на тех же пяти релизах, дерево nzbdav отличается ровно двумя вещами.

| | |
|---|---|
| zurg добавляет | файл `.nfo` из релиза |
| zurg теряет | 5 par2-томов с хеш-именами внутри обфусцированных релизов |

**Ничего не переименовывается.** Каждое имя файла, которое отдаёт nzbdav, zurg отдаёт под тем же именем и в той же структуре каталогов. Это верно и внутри RAR-архивов. Два сервера совпали по всем 20 файлам в корпусе, которые не являются par2.

!!!warning Никогда не обходите корень WebDAV
Хранилище объектов `.ids` в nzbdav создаёт все 16 hex-потомков на каждом из пяти уровней, независимо от содержимого. Это 16^5, или примерно 1 048 576 каталогов. Указывайте `find`, `du`, `rclone` и любой сканер явно на `/content`, `/nzbs` или `/completed-symlinks`. Никогда не на `/`.
!!!

## Как будет выглядеть ваша библиотека после миграции {#what-your-library-looks-like-afterwards}

**Всё нужно добавить заново**, потому что корень библиотеки переезжает в `__magic__`.
Дешёвого пути нет, и частичного тоже. См. [общую страницу](index.md), почему.

Хорошая новость: миграция с nzbdav — единственная, где **ничего не меняется, кроме префикса**. Каждое имя файла, которое отдаёт zurg, совпадает с тем, что отдавал nzbdav. \*arr, который переимпортирует из `__magic__`, разбирает ровно то, что разбирал раньше. Папка, которую ты организуешь вручную, выглядит так же, как и всегда.

Это верно для любой настройки. В Windows и везде, где Plex читает маунт напрямую, имена файлов идентичны. Если Sonarr и Radarr организуют библиотеку из символических ссылок, то имена файлов уже были их собственными, и источник, который они разбирают, не меняется. Поэтому эта миграция ничего не меняет в том, как читается твоя библиотека. Она меняет только то, где она лежит.

## Какой новый контент появляется {#what-new-content-shows-up}

- Файл `.nfo` внутри RAR-релизов.
- **Sample-клипы** внутри `Sample/`. nzbdav публикует и папку, и клип, и zurg тоже. Это не новость для вас: nzbdav — единственный из четырёх серверов, который делал это и раньше.
- Пустые папки для релизов, у которых сломана цепочка архивов. Для них nzbdav ничего не создавал.
- par2 и sfv перестают быть видимыми.

Ничего из этого не превращается в элемент Plex, кроме sample-клипа, а его nzbdav и так вам показывал. Если раньше это вас не беспокоило, то ничего не меняется.

## Вынесите свои NZB {#get-your-nzbs-out}

zurg читает каталог с файлами `.nzb`, и у nzbdav все твои файлы лежат в
`/nzbs/<category>/`. **Копируй их, а не перемещай.** Если удалить что-то из
`/nzbs/`, задание отменится.

```bash
mkdir -p ~/migration/nzbs
for cat in uncategorized movies tv audio software; do
  rclone copy "nzbdav:/nzbs/$cat" ~/migration/nzbs/ --include '*.nzb'
done
ls ~/migration/nzbs | wc -l
```

Оба сервера называют папку релиза по имени NZB-файла. Значит, базовые имена, которые ты восстановил, должны совпадать с папками, которые отдаёт nzbdav. Проверь это и переименуй те, что разошлись.

```bash
rclone lsf "nzbdav:/content/movies" --dirs-only | sed 's:/$::' | sort > ~/migration/folders-old.txt
ls ~/migration/nzbs | sed 's/\.nzb$//' | sort > ~/migration/stems.txt
diff ~/migration/folders-old.txt ~/migration/stems.txt
```

Стоит проверить два правила именования zurg по этому списку.

- zurg отрезает завершающее `.mkv` или `.mp4` из имени папки. Если какое-то базовое имя так заканчивается, поставь `retain_folder_name_extension: true`.
- Два разных релиза с одинаковым базовым именем получают суффикс ` {shorthash}` на одном из них. Найти такие сейчас можно командой `ls ~/migration/nzbs | sed 's/\.nzb$//' | sort |
  uniq -d`.

## Настройте zurg параллельно {#build-zurg-alongside}

nzbdav всё это время продолжает отдавать файлы.
Скопируйте его блок provider в конфиг zurg.
Дайте zurg отдельную точку монтирования.
Закиньте NZB-файлы и дайте ему просканировать.
Папку watch он проверяет примерно каждые 15 секунд.

```yaml
zurg: v1
providers:
  - type: nzb
    nntp:
      host: news.example.com   # copy from nzbdav's provider settings
      port: 563
      tls: true
      username: USER
      password: PASS
      connections: 30          # your plan's real allowance
rclone_enabled: true
rclone_binary: bin/rclone
mount_path: "/mnt/zurg"
```

```bash
mkdir -p nzbs && cp ~/migration/nzbs/*.nzb nzbs/
./zurg
ls /mnt/zurg/__all__/ | wc -l     # should approach your release count
```

## Переключитесь {#cut-over}

**1. Включите `__magic__`** и перезапустите. Маршруты регистрируются при запуске, поэтому переключатель в дашборде не сработает, пока вы не перезапустите сервис и пространство имён не начнёт отвечать.

```yaml
magic:
  enabled: true
```

**2. Создайте корневые папки.** Они должны лежать в корне `__magic__`, рядом с `__all__`, который zurg держит там сам. Не `__magic__/__all__`, не сам `__magic__` и не корень маунта. Оба \*arr выдают проверку состояния на такие места, а соседние папки её не вызывают.

```bash
mkdir -p /mnt/zurg/__magic__/tv /mnt/zurg/__magic__/movies
ls /mnt/zurg/__magic__/__all__/   # your releases are already listed here
```

`__magic__/__all__` повторяет библиотеку, так что каждый релиз уже на месте до того, как вы что-то начнёте раскладывать.

**3. Разложите файлы.** `mv` внутри `__magic__` только записывает строку и не двигает байты.

```bash
mv "/mnt/zurg/__magic__/__all__/Some.Release.S01E01.1080p/ep1.mkv" \
   "/mnt/zurg/__magic__/tv/The Show/Season 01/S01E01.mkv"
```

**Если Sonarr и Radarr раскладывали вашу старую библиотеку, перенесите её одним скриптом.** Он переименовывает каждый файл, на который ссылается старая библиотека, в новую корневую папку внутри `__magic__`. Каждый файл попадает туда, где его уже ждёт \*arr. Ничего не копируется. Потом вы меняете корневую папку в \*arr, не давая ему ничего переносить. Шаги и сам скрипт описаны на [общей странице](index.md#coming-off-a-symlink-library). Никогда не позволяйте \*arr переносить файлы самостоятельно. Это пересекает границу маунта, то есть превращается в копирование, и скачивает вашу библиотеку заново.

Скрипту нужна функция `zurg_path` для ссылок nzbdav. Сохраните её как `zurg_path.sh` рядом со скриптом и укажите в `OLDMOUNT` место, куда смонтирован nzbdav.

```bash
OLDMOUNT=/mnt/nzbdav            # nzbdav's mount, where the old links point
# The map from each .ids name to its release and file. Built once while nzbdav runs.
[ -s uuid-map.tsv ] || find "$OLDMOUNT/completed-symlinks" -type l | while IFS= read -r l; do
  rel=${l#"$OLDMOUNT"/completed-symlinks/}      # <category>/<release>/<file>
  printf '%s\t%s\n' "$(basename "$(readlink "$l")")" "${rel#*/}"
done | sort -u > uuid-map.tsv
zurg_path() {
  local rel release name videos
  rel=$(awk -F'\t' -v u="$(basename "$1")" '$1==u{print $2; exit}' uuid-map.tsv)
  [ -n "$rel" ] || return
  [ -f "$ZURG/__all__/$rel" ] && { echo "$ZURG/__all__/$rel"; return; }
  # A file under another name. Take the release's one video.
  release=${rel%%/*} name=${rel##*/}
  case "$name" in "$release".*) ;; *) return ;; esac
  videos=$(find "$ZURG/__all__/$release" -type f \( -iname '*.mkv' -o -iname '*.mp4' -o -iname '*.avi' \) ! -ipath '*sample*')
  [ "$(printf '%s\n' "$videos" | grep -c .)" -eq 1 ] && echo "$videos"
}
```

Ссылки nzbdav ведут в его хранилище `.ids`, а у zurg такого нет. Поэтому функция один раз читает дерево `completed-symlinks` в nzbdav, чтобы понять, какому релизу и файлу соответствует каждое имя из `.ids`. Держите nzbdav запущенным, пока скрипт не закончит работу. nzbdav ничего не переименовывает, так что каждое найденное имя — то, что zurg уже отдаёт.

**4. Укажите Plex на созданные корневые папки** — `__magic__/tv` и `__magic__/movies` — и только на них. Никогда не указывайте корень `__magic__`: там лежит вся библиотека в `__magic__/__all__`, и тогда каждый эпизод будет найден дважды. Никогда не указывайте одновременно `__magic__` и папку с фильтром, по той же причине. Убедитесь, что `autoEmptyTrash` равен `0`. Добавьте новое расположение и запустите сканирование. Потом удалите старое. Старое — это путь к библиотеке в \*arr или маунт nzbdav, если Plex читал его напрямую.

**5. Очистите корзину** после того, как выборочно проверите несколько элементов. Статус просмотра переходит по совпадению GUID. Коллекции и выбор постеров не переходят.

Оставьте nzbdav запущенным до этого момента. Он ничего не стоит и служит вам откатом. Когда всё готово, остановите его.

```bash
sudo systemctl stop nzbdav
```

## После миграции {#afterwards}

Сохраните каталог конфигурации nzbdav, пока не выполните стриминг с репрезентативной выборкой. Это единственная другая копия ваших NZB.

Теперь о получении файлов. У zurg есть необязательный [SABnzbd-совместимый эндпоинт](../guides/sonarr-radarr.md), через который Sonarr и Radarr могут забирать релизы. Он заменяет nzbdav как их клиент загрузки. Захват попадает в `__magic__/__all__`, а импорт перемещает его оттуда переименованием. Ничего не копируется.
zurg проверяет каждый захват, прежде чем отметить его как Completed. Он запрашивает у новостных серверов начало и конец каждого файла. Также он скачивает первую статью каждого файла. Это до шестидесяти четырёх статей плюс несколько дополнительных для релиза с небольшим количеством файлов. Некоторые новостные серверы до сих пор сообщают, что статья существует, даже когда её содержимое уже удалено, и это видно только при скачивании. zurg восстанавливает релиз с пропавшими статьями в PAR2-файлах там, где это возможно. Релиз, который восстановить нельзя, получает статус **Failed**. Тогда \*arr добавляет его в блоклист и берёт другой. Проверка — это выборка, а не весь пост. Пост, у которого пропал участок, не затронутый выборкой, всё равно получит статус Completed и провалится на чтении, которое дойдёт до пропуска.
Держите корневые папки \*arr внутри `__magic__`. Корневая папка где-либо ещё получит полную копию каждого импорта. В Docker выделите \*arr один том, который содержит весь маунт zurg. Папка загрузки и корневые папки на двух томах тоже приведут к копированию каждого импорта. См. [один том](../guides/sonarr-radarr.md#one-volume-for-the-download-folder-and-the-root-folders).
