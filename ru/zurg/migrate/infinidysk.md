# Миграция с InfiniDysk на zurg {#migrating-from-infinidysk-to-zurg}

Сначала прочитайте [общую страницу](index.md). Там объясняется trash guard и то, почему ваша библиотека попадает в `__magic__`.

Сравнение с zurg на тех же пяти релизах.

| | |
|---|---|
| zurg добавляет | клип-семпл, `.nfo` |
| zurg теряет | 5 par2-томов с хеш-именами внутри обфусцированных релизов |
| переименовано | **каждый релиз, кроме многофайловых** |

!!!warning Переименование и есть вся миграция
InfiniDysk переименовывает медиафайл релиза в имя NZB-файла, если релиз
состоит из одного payload. В корпусе от 2026-09-01 четыре из пяти стали
`ToyStory5.mkv`, `Obfuscated.mkv`, `FatherBrown.mp4` и
`MandaloriaREMUX.mkv`. Только сезон из десяти серий сохранил имена эпизодов.
Переименование работает на любой глубине. `FatherBrown.mp4` лежит *внутри*
сохранённой директории `Father.Brown.2013.S02E05.HDTV.x264-TLA/`.

zurg сохраняет имя файла от постера. Поэтому имя релиза возвращается, и каждый
релиз из одного payload меняет путь. Это та строка, которую Plex и \*arrs
разбирают на качество, группу и номер эпизода.
!!!

Ещё одно отличие небольшое, но сбивает с толку, если столкнуться с ним впервые. InfiniDysk
создаёт директорию `Sample/` архива и оставляет её **пустой**. zurg кладёт
туда клип-семпл.

Причина переезда не в содержимом. Сборка `cd9b1205` импортировала все пять
релизов эталонного корпуса, включая сезон. Не ждите, что InfiniDysk что-то
выбрасывает. Вы получаете обратно именно имена.

!!!warning Никогда не обходите корень WebDAV
Объектное хранилище `.ids` создаёт все 16 hex-дочерних элементов на каждом из
своих пяти уровней независимо от содержимого. Это 16^5, или примерно
1 048 576 директорий. Указывайте `find`, `du`, `rclone` и любой сканер
явно на `/content`, `/nzbs` или `/completed-symlinks`. Никогда на `/`.
!!!

## Как будет выглядеть ваша библиотека после миграции {#what-your-library-looks-like-afterwards}

**Всё добавляется заново**, потому что корень библиотеки переезжает в `__magic__`. См. [общую страницу](index.md), почему нет более дешёвого пути.

Это миграция, где затраты минимальны, а выигрыш максимальный. Почти все имена файлов становятся лучше. `ToyStory5.mkv` превращается в `Toy.Story.5.2026.1080p.AMZN.WEB-DL.DDP5.1.H.264-KyoGo.mkv`, и \*arr, который переимпортирует из `__magic__`, наконец может вытащить из имени качество, источник, группу и редакцию. Остаются как были только сезонные паки, но они и так читаются правильно.

Перечисли релизы, чьи имена меняются. Их будет большинство.

```bash
ID=/mnt/remote/nzbdav                      # your InfiniDysk mount
find "$ID/content" -mindepth 3 -maxdepth 4 -type f | while IFS= read -r f; do
  rel=$(basename "$(dirname "$f")")
  b=$(basename "$f")
  [ "${b%.*}" = "$rel" ] && echo "RENAMED BY INFINIDYSK: $f"
done
```

`-maxdepth 4` важен, потому что переименование может произойти на один уровень внутри каталога архива.

!!!info Видишь ли ты что-то из этого, зависит от твоей настройки
Если Plex читает маунт напрямую, то имена выше — это то, что меняется в твоей библиотеке. Это касается любой установки на Windows и любой установки на Linux или macOS без symlink-фермы \*arr.

Если Sonarr и Radarr организуют symlink-библиотеку с включённым переименованием, то **твои имена файлов уже их**, и ни одно из имён выше в Plex не появится. Тогда имена показывают, насколько хорошо \*arr парсил исходные данные. Это важно при повторном импорте. См. [общую страницу](index.md).
!!!

## Какой новый контент появляется {#what-new-content-shows-up}

- **Сэмпл-клипы.** Папки `Sample/`, которые у тебя уже есть, перестают быть пустыми. Это единственное, что стоит настроить. Поставь [`only_show_the_biggest_file: true`](../reference/config.md), если не хочешь, чтобы 9 MB сэмпл появлялся как вторая версия эпизода.
- Файл `.nfo` внутри RAR-релизов. С стандартными агентами Plex он никак не работает.
- Пустые папки там, где архивная цепочка сломана. InfiniDysk для них ничего не создал.
- **par2 и sfv перестают быть видны.** Это касается и томов с хеш-именами внутри обфусцированных релизов. У них нет медиа-расширения, поэтому Plex их не будет индексировать. Если какие-то сторонние инструменты обходят эти файлы, они это заметят.

## Вынесите свои NZB {#get-your-nzbs-out}

zurg получает данные из папки с `.nzb` файлами. Там один файл на каждый релиз, а имя файла совпадает с именем папки релиза. WebDAV от InfiniDysk по пути `/nzbs/<category>/` отражает очередь и доступен для чтения.

```bash
mkdir -p ~/recovered-nzbs
rclone copy infinidysk:nzbs ~/recovered-nzbs/ --include '*.nzb'   # scoped to /nzbs, never the root
find ~/recovered-nzbs -name '*.nzb' | wc -l
```

Остаются ли завершённые задания в `/nzbs` после окончания, **не проверено**. Там отражается очередь, а история может быть длиннее очереди. Для всего, чего нет в списке, метаданные NZB, которые InfiniDysk хранит для повторного монтирования, лежат в `{CONFIG_PATH}/blobs/`. Формат blob-файлов **не проверен**, так что перед тем как ему доверять, проверь его.

```bash
for f in "$CONFIG_PATH"/blobs/*; do head -c 32 "$f" | grep -q '<?xml' && echo "NZB: $f"; done
```

Если blob-файлы у тебя не в обычном XML, запасной вариант это история загрузок у твоего индексатора.

Затем создай файл `<release>.nzb` для каждой папки релиза, которая у тебя действительно есть.

```bash
find "$ID/content" -mindepth 2 -maxdepth 2 -type d -printf '%P\n' \
  | awk -F/ '{print $1 "\t" $2}' > releases.tsv
```

NZB, скачанные из `/nzbs/<category>/`, обычно уже имеют правильное имя, ведь от него и берётся имя папки. Стоит сверить список с двумя правилами именования zurg.

- zurg убирает завершающие `.mkv` или `.mp4` из имени папки. Если какая-то папка релиза так заканчивается, установи `retain_folder_name_extension: true`.
- Если два разных релиза имеют одинаковое имя, то к одному из них добавляется суффикс ` {shorthash}`. Найти такие можно командой `cut -f2 releases.tsv | sort | uniq -d`. У InfiniDysk была похожая проблема, но проявлялась иначе: повторный импорт NZB там создавал `<Release> (2)`.

## Настройте zurg параллельно {#build-zurg-alongside}

InfiniDysk продолжает работать без перерывов.

```yaml
zurg: v1
providers:
  - type: nzb
    nntp:
      host: news.example.com   # copy from InfiniDysk's provider settings
      port: 563
      tls: true
      username: USER
      password: PASS
      connections: 30          # your plan's real allowance
enable_repair: true
rclone_enabled: true
rclone_binary: bin/rclone
mount_path: "/mnt/zurg"
```

```bash
mkdir -p nzbs && cp ~/recovered-nzbs/*.nzb nzbs/
./zurg
ls /mnt/zurg/__all__/ | wc -l          # should approach your release count
```

`__all__` содержит все релизы независимо от фильтров по директориям.

## Переключитесь {#cut-over}

**Один путь, какой бы у тебя ни был сейчас. Здесь ничего не перемещает байты.**

**1. Включи `__magic__`** и перезапусти. Маршруты регистрируются при запуске, поэтому переключатель в дашборде сам по себе не поможет: пространство имён начнёт отвечать только после перезапуска.

```yaml
magic:
  enabled: true
```

**2. Создай корневые папки.** Они кладутся в корень `__magic__`, рядом с `__all__`, который zurg там держит. Не `__magic__/__all__`, не сам `__magic__` и не корень монтирования. Оба \*arr выдают health check на такие места, а соседние папки ни один из них не трогают.

```bash
mkdir -p /mnt/zurg/__magic__/tv /mnt/zurg/__magic__/movies
ls /mnt/zurg/__magic__/__all__/   # your releases are already listed here
```

`__magic__/__all__` повторяет библиотеку, поэтому каждый релиз уже есть до того, как ты что-то организуешь.

**3. Организуй.** `mv` внутри `__magic__` только записывает строку и не перемещает байты.

```bash
mv "/mnt/zurg/__magic__/__all__/Some.Release.S01E01.1080p/ep1.mkv" \
   "/mnt/zurg/__magic__/tv/The Show/Season 01/S01E01.mkv"
```

**Если Sonarr и Radarr организовывали твою старую библиотеку, перенеси её одним скриптом.** Он переименовывает каждый файл, на который ссылается старая библиотека, в новую корневую папку под `__magic__`. Каждый файл попадает туда, где его уже ожидает \*arr. Ничего не копируется. Потом переключаешь корневую папку в \*arr, не давая ему ничего переместить. Шаги и сам скрипт — на [общей странице](index.md#coming-off-a-symlink-library). Никогда не позволяй \*arr перемещать файлы самому. Это пересекает границу монтирования, превращается в копирование и заново скачивает твою библиотеку.

Скрипту нужна функция `zurg_path` для ссылок InfiniDysk. Сохрани её как `zurg_path.sh` рядом со скриптом и задай `OLDMOUNT` — путь, куда смонтирован InfiniDysk.

```bash
OLDMOUNT=/mnt/remote/infinidysk # InfiniDysk's mount, where the old links point
# The map from each .ids name to its release and file. Built once while InfiniDysk runs.
[ -s uuid-map.tsv ] || find "$OLDMOUNT/completed-symlinks" -type l | while IFS= read -r l; do
  rel=${l#"$OLDMOUNT"/completed-symlinks/}      # <category>/<release>/<file>
  printf '%s\t%s\n' "$(basename "$(readlink "$l")")" "${rel#*/}"
done | sort -u > uuid-map.tsv
zurg_path() {
  local rel release name videos
  rel=$(awk -F'\t' -v u="$(basename "$1")" '$1==u{print $2; exit}' uuid-map.tsv)
  [ -n "$rel" ] || return
  [ -f "$ZURG/__all__/$rel" ] && { echo "$ZURG/__all__/$rel"; return; }
  # InfiniDysk named a lone video after the release. Take the release's one video.
  release=${rel%%/*} name=${rel##*/}
  case "$name" in "$release".*) ;; *) return ;; esac
  videos=$(find "$ZURG/__all__/$release" -type f \( -iname '*.mkv' -o -iname '*.mp4' -o -iname '*.avi' \) ! -ipath '*sample*')
  [ "$(printf '%s\n' "$videos" | grep -c .)" -eq 1 ] && echo "$videos"
}
```

Ссылки InfiniDysk ведут в его хранилище `.ids`, а у zurg такого нет. Поэтому функция один раз читает дерево `completed-symlinks` от InfiniDysk, чтобы понять, какой релиз и какой файл стоит за каждым именем из `.ids`. Держи InfiniDysk запущенным, пока скрипт не закончит работу. Если InfiniDysk назвал одиночное видео по релизу, функция берёт единственное видео, которое zurg отдаёт в этом релизе. Релиз с несколькими видео никогда не угадывается. Вместо этого выводится `NOT IN ZURG`.

**4. Укажи Plex на корневые папки, которые ты создал** — `__magic__/tv` и `__magic__/movies` — и только на них. Никогда не указывай корень `__magic__`, там весь состав лежит и в `__magic__/__all__`. И никогда не указывай `__magic__` *и* папку фильтра сразу, иначе каждый эпизод найдётся дважды. Убедись, что `autoEmptyTrash` равен `0`. Добавь новое расположение и запусти сканирование. Потом удали старое. Это путь к библиотеке в \*arr или точка монтирования InfiniDysk, если Plex читал её напрямую.

**5. Очисти корзину**, когда выборочно проверишь несколько элементов. Статус просмотра возвращается через совпадение GUID. Коллекции и выбор обложек — нет.

```bash
sudo systemctl stop infinidysk infinidysk-rclone-mount
```

Пока всё не проверено, оставь InfiniDysk запущенным. Он ничего не стоит, и это твой откат. Когда закончишь, останови его.

## После миграции {#afterwards}

Не удаляйте `{CONFIG_PATH}/blobs/` и свой восстановленный набор NZB, пока не проиграете что-нибудь из репрезентативной выборки.

Теперь поговорим о получении контента. У zurg есть необязательный [эндпоинт, совместимый с SABnzbd](../guides/sonarr-radarr.md), через который Sonarr и Radarr могут забирать релизы.
Он заменяет InfiniDysk в роли их клиента загрузки. Забранный релиз попадает в `__magic__/__all__`, а импорт переносит его оттуда переименованием. Ничего не копируется.
zurg проверяет каждый релиз, прежде чем сообщить, что он готов. Он спрашивает новостные серверы о начале и конце каждого файла. Ещё он скачивает первую статью каждого файла. Это до шестидесяти четырёх таких статей, а для релиза с парой файлов — ещё несколько сверху.
Некоторые новостные серверы до сих пор говорят, что статья существует, даже когда её содержимое уже удалено, и это видно только при скачивании.
Где может, zurg восстанавливает релиз с пропавшими статьями через PAR2-файлы.
Если восстановить не получается, релиз получает статус **Failed**. Тогда \*arr добавляет его в блоклист и забирает другой.
Проверка берёт выборку, а не весь пост.
Пост, у которого пропал кусок, до которого выборка не дотянулась, всё равно получит Completed и упадёт на том чтении, которое до этого места доберётся.
Держите корневые папки \*arr внутри `__magic__`. Корневая папка где-либо ещё получает полную копию каждого импорта.
В Docker дайте \*arr один том, в котором лежит всё монтирование zurg. Папка загрузок и корневые папки на двух томах тоже копируют каждый импорт. См. [один том](../guides/sonarr-radarr.md#one-volume-for-the-download-folder-and-the-root-folders).
