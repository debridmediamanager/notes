Миграция с AltMount на zurg

Сначала прочитай общую страницу. Там объясняется защита от мусора и то, почему твоя библиотека попадает в __magic__.

AltMount отдаёт самое чистое дерево из пяти. Ровно один файл на релиз. Никаких миниатюр, реклам, сэмплов и мусора. Миграция поэтому тоже небольшая, потому что там почти не из-за чего спорить.

Сравнение с zurg на тех же пяти релизах.

   
zurg получает лишнее клип-сэмпл, .nfo, thumbnail.jpg, рекламные .url, внутреннюю папку архива, и каждый релиз, который AltMount отклонил
zurg ничего не теряет ничего
переименовано только архивные релизы (RAR)
Переименовывает только путь с архивами

За три независимых прогона на сборке 0614008b обычные одиночные файлы сохранили имя, которое дал постер. Это включает релиз, чьё внутреннее имя отличается от имени NZB, и полностью обфусцированный. Только релиз, который пришлось распаковывать из RAR, получился как <NZB name>.mp4.

Старые сборки AltMount переименовывали больше. Проверь своё дерево, прежде чем доверять списку ниже. Одна команда из раздела «Как выглядит твоя библиотека потом» покажет это за несколько секунд.

Более серьёзная проблема: то, что AltMount никогда не импортировал

AltMount отказывался импортировать 10-серийный сезонный пак в каждом из четырёх запусков. Статьи заранее проверялись и были доступны на новостном сервере.

fast-fail segment check inconclusive: 93 segment(s) remained
unverified after 3 attempts: context deadline exceeded

Проверка не детерминированная. Один и тот же релиз получил 196 непроверенных сегментов, потом 93, потом 76. Она также зависит от размера. Настройка import.segment_sample_percentage: 1 проверяет 1% сегментов, поэтому большому релизу нужно больше STAT-запросов, чтобы уложиться в дедлайн. При повторе на более быстром новостном хосте отказов стало больше, а не меньше. Тот запуск потерял и сезонный пак, и remux на 41 ГБ. Задержка тут ни при чём.

Практическое следствие для тебя такое. Релизы, которые AltMount молча так и не опубликовал, — это те, что добавит zurg. Сейчас у них нет элемента в Plex, поэтому ничего не сохраняется и ничем не рискуешь. Они просто появятся. Если твоя библиотека меньше твоей коллекции NZB, то вот почему.

Если хочешь, чтобы AltMount продолжал импорт во время миграции, попробуй уменьшить segment_sample_percentage. Здесь это не проверялось.

Как будет выглядеть ваша библиотека после миграции

Всё добавляется заново, потому что корень библиотеки переезжает в __magic__. Почему нет более дешёвого пути, см. общую страницу.

По пути меняется немного. Обычные релизы из одного файла сохраняют имя, которое им дал AltMount, так что большая часть библиотеки выглядит так же. Релизы из архивов возвращаются под именем автора раздачи и на один уровень глубже. Для *arr это строго лучше. Имя father.brown.2013.s02e05.hdtv.x264-tla.mp4 содержит качество, источник и группу, которые FatherBrown.mp4 теряет.

Найти релизы из архивов можно так: ищите папку в маунте, внутри которой один файл с таким же именем, как у папки.

AM=/mnt/altmount
for d in "$AM"/*/; do
  r=$(basename "$d")
  for f in "$d"*; do
    b=$(basename "$f")
    [ "${b%.*}" = "$r" ] && echo "RENAMED BY ALTMOUNT: $f"
  done
done
Видите ли вы что-то из этого, зависит от вашей настройки

Если Plex читает маунт напрямую, то имена выше и есть то, что меняется в вашей библиотеке. Это касается всех установок на Windows и любых установок на Linux или macOS без фермы симлинков *arr.

Если Sonarr и Radarr организуют библиотеку из симлинков с включённым переименованием, то ваши имена файлов уже их, и ни одно из имён выше в Plex не появится. Что эти имена тогда говорят, так это насколько хорошо *arr разбирал исходные названия. Это важно при повторном импорте. См. общую страницу.

Какой новый контент появляется

AltMount не публикует ничего из этого, поэтому всё из списка на общей странице относится к вам.

  • Sample clips внутри Sample/. Это единственное, что стоит настроить. Установите only_show_the_biggest_file: true, если не хотите, чтобы 9 MB sample появлялся как вторая версия.
  • thumbnail.jpg, .nfo и .url постера с рекламой. Всё это безвредно.
  • Целые релизы, которые AltMount отклонил, появляются как новые элементы библиотеки.
  • Пустые папки там, где сломана цепочка архивов.

Вынесите свои NZB

AltMount взял под контроль каждый NZB, который вы ему скормили. Оригинал перенесли, а сжатую копию сохранили в <config>/.nzbs/<category>/<queueID>-<name>.nzbz. Соответствие между папкой монтирования и .nzbz есть в файлах .meta внутри <config>/metadata/complete/<Release>/. Это бинарные файлы с сигнатурой AM3, а путь к .nzbz лежит в них обычной строкой.

zurg ждёт один .nzb на релиз, названный по релизу и лежащий плоско в nzbs/. Подпапки он пропускает. Имя папки metadata/complete/<Release> и есть имя папки монтирования, и именно такое имя должен получить файл.

AM=/path/to/altmount/config          # holds altmount.db, .nzbs/, metadata/
OUT=./recovered-nzbs
mkdir -p "$OUT"
for dir in "$AM"/metadata/complete/*/; do
  release=$(basename "$dir")
  meta=$(find "$dir" -maxdepth 1 -name '*.meta' | head -1)
  [ -n "$meta" ] || { echo "NO META: $release" >&2; continue; }
  nzbz=$(strings "$meta" | grep -m1 '\.nzbz$')
  case "$nzbz" in "") echo "NO NZBZ REF: $release" >&2; continue ;;
                  /*) src=$nzbz ;; *) src="$AM/$nzbz" ;; esac
  [ -f "$src" ] || { echo "NZBZ MISSING: $release" >&2; continue; }
  [ -e "$OUT/$release.nzb" ] && { echo "NAME COLLISION: $release" >&2; continue; }
  if zcat "$src" > "$OUT/$release.nzb" 2>/dev/null && grep -q '<nzb' "$OUT/$release.nzb"; then
    echo "OK: $release"
  else
    rm -f "$OUT/$release.nzb"
    echo "NOT A GZIPPED NZB: $release. Use the API export instead" >&2
  fi
done

На проверенной установке v0.3.2 .nzbz оказался gzip-копией импортированного NZB. В исходниках также есть путь zstd-protobuf для этих файлов, так что проверка через zcat и grep тут не паранойя. Всё, что он отвергает, идёт через API. GET /api/files/export-nzb?path=<virtual path> заново собирает точный NZB из хранилища, а POST /api/files/export-batch возвращает ZIP. Для обоих нужен JWT, а не API-ключ.

curl -c jar -s -X POST http://localhost:8585/api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"…"}'
curl -b jar -s -G http://localhost:8585/api/files/export-nzb \
  --data-urlencode "path=/complete/<Release>/<file>" -o "$OUT/<Release>.nzb"

Виртуальные пути берите из вида файлов в UI AltMount или из /api/files/info, а не угадывайте формат. Загрузка называется <queueID>-<name>.nzb. Переименуйте её в <Release>.nzb, чтобы zurg правильно назвал папку.

Одна проверка на адекватность: количество восстановленных .nzb должно совпадать с количеством папок metadata/complete/*/.

Настройте zurg параллельно

AltMount продолжает работать всё время. Запусти zurg на порту 9999. Конфликта с портом 8585 у AltMount нет.

zurg: v1
providers:
  - type: nzb
    nntp:
      host: news.example.com   # copy host/port/TLS/credentials from AltMount
      port: 563
      tls: true
      username: USER
      password: PASS
      connections: 30          # your plan's real allowance
rclone_enabled: true
rclone_binary: bin/rclone
mount_path: "/mnt/zurg"
mkdir -p nzbs && cp recovered-nzbs/*.nzb nzbs/
./zurg
ls /mnt/zurg/__all__/ | wc -l

Папок здесь будет больше, чем было у AltMount. Это как раз класс refused-import, который теперь попадает сюда.

Переключитесь

1. Включите __magic__ и перезапустите. Маршруты регистрируются при старте, поэтому переключателю в дашборде нужен перезапуск, прежде чем пространство имён начнёт отвечать.

magic:
  enabled: true

2. Создайте корневые папки. Они кладутся в корень __magic__, рядом с __all__, который там держит zurg. Не __magic__/__all__, не сам __magic__ и не корень монтирования. Оба *arr выдают проверку состояния для этих путей, а соседние папки ничего не вызывают.

mkdir -p /mnt/zurg/__magic__/tv /mnt/zurg/__magic__/movies
ls /mnt/zurg/__magic__/__all__/   # your releases are already listed here

__magic__/__all__ отражает библиотеку, так что каждый релиз есть на месте ещё до того, как ты что-то раскладываешь.

3. Разложите по папкам. mv внутри __magic__ записывает строку и не двигает байты.

mv "/mnt/zurg/__magic__/__all__/Some.Release.S01E01.1080p/ep1.mkv" \
   "/mnt/zurg/__magic__/tv/The Show/Season 01/S01E01.mkv"

Если Sonarr и Radarr раскладывали твою старую библиотеку, перенеси её одним скриптом. Он переименовывает каждый файл, на который ссылается старая библиотека, в новую корневую папку внутри __magic__. Каждый файл попадает по тому пути, который ждёт *arr. Ничего не копируется. Затем переключаешь корневую папку в *arr, не давая ему ничего перемещать. Шаги и скрипт описаны на общей странице. Никогда не позволяй *arr переносить файлы самому. Это пересекает границу монтирования, превращается в копирование и заново скачивает твою библиотеку.

Скрипту нужна функция zurg_path для ссылок AltMount. Сохрани её как zurg_path.sh рядом со скриптом и укажи в OLDMOUNT путь, куда смонтирован AltMount.

OLDMOUNT=/mnt/altmount          # AltMount's mount, where the old links point
zurg_path() {
  case "$1" in "$OLDMOUNT"/*) ;; *) return ;; esac   # not a link into AltMount
  local name=${1##*/} f videos
  local release; release=$(basename "$(dirname "$1")")
  [ -f "$ZURG/__all__/$release/$name" ] && { echo "$ZURG/__all__/$release/$name"; return; }
  # AltMount named a lone video or an unpacked archive after the release. Take its one video.
  case "$name" in "$release".*) ;; *) return ;; esac
  videos=$(find "$ZURG/__all__/$release" -type f \( -iname '*.mkv' -o -iname '*.mp4' -o -iname '*.avi' \) ! -ipath '*sample*')
  [ "$(printf '%s\n' "$videos" | grep -c .)" -eq 1 ] && echo "$videos"
}

Функция ожидает, что папка релиза находится прямо над файлом в цели каждой ссылки. Точный путь, который используют ссылки AltMount, для этого гайда не проверялся. Сначала запусти readlink для одной ссылки. Если AltMount назвал отдельное видео или распакованный архив по имени релиза, функция берёт единственное видео, которое zurg отдаёт в этом релизе. Релиз с несколькими видео никогда не угадывается, вместо этого выводится NOT IN ZURG.

4. Укажи Plex на корневые папки, которые ты создал, __magic__/tv и __magic__/movies, и только на них. Никогда не указывай корень __magic__, там целиком лежит библиотека в __magic__/__all__. И никогда не указывай __magic__ и папку фильтра сразу, иначе каждый эпизод будет найден дважды. Убедись, что autoEmptyTrash равно 0. Добавь новое расположение и запусти сканирование. Потом удали старое. Это путь библиотеки в *arr или монтирование AltMount, если Plex читал его напрямую.

5. Очисти корзину, когда выборочно проверишь несколько элементов. Состояние просмотра вернётся через совпадение GUID. Коллекции и выбор постеров, увы, нет.

Оставь AltMount запущенным до этого момента. Он ничего не стоит, и это твой откат. Когда закончишь, останови его.

sudo systemctl stop altmount

После миграции

Не выводи AltMount из эксплуатации, пока не проиграешь хотя бы репрезентативную выборку через стриминг. Его каталог конфигурации хранит хранилище .nzbz, и это единственная другая копия твоих NZB.

Теперь про загрузку. У zurg есть необязательная SABnzbd-совместимая точка доступа, через которую Sonarr и Radarr могут брать релизы. Она заменяет AltMount как их клиент загрузки. zurg проверяет каждый взятый релиз, прежде чем сообщить, что он готов. Он спрашивает новостные серверы о начале и конце каждого файла. Также он скачивает первую статью каждого файла. Это до шестидесяти четырёх статей плюс несколько дополнительных для релиза с небольшим количеством файлов. Некоторые новостные серверы до сих пор сообщают, что статья существует, даже после того как её содержимое удалили, и это видно только при скачивании. zurg восстанавливает релиз с пропавшими статьями по его PAR2-файлам, где это возможно. Тот, который восстановить нельзя, получает статус Failed. Тогда *arr добавляет его в чёрный список и берёт другой. Проверка — это выборка, а не весь пост. Пост, у которого пропал участок, до которого выборка не дошла, всё равно получит статус Completed и провалится на чтении, которое попадёт в этот пробел.

Держи корневые папки *arr внутри __magic__. Корневая папка где-либо ещё получит полную копию каждого импорта. В Docker дай *arr один том, который содержит весь маунт zurg. Папка загрузок и корневые папки на двух разных томах тоже создают копию при каждом импорте. См. один том.
