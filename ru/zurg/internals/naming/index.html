zurg naming

Почти все имена, которые показывает zurg, вычисляются на лету и нигде не хранятся. Имя папки релиза, имя файла внутри неё и имя на диске у записи кэша вычисляются заново из торрента при каждом обращении. Ничего не записывается и не читается обратно, потому что сохранённое имя — это ещё одна вещь, которую нужно держать в соответствии с библиотекой, а именно это и ломают ремонт или повторное разрешение NZB.

Исключение — переименование, которое запросил оператор. Оно сохраняется в самом релизе и важнее всех правил вычисления ниже. Правила описаны в разделе 9, а версия для пользователей — в руководстве по переименованию. Всё остальное на этой странице описывает имя, которое релиз получает, когда переименование не задано.

Из этого сразу следует одно важное последствие, поскольку оно является источником большинства неожиданностей для всего, что интегрируется с zurg: папка может поменять имя, хотя ничего её не «переименовывало». Входные данные изменились, значит изменился и результат.

Этот файл содержит правила, а не пороговые значения. Если правило определяется эвристикой, документ называет функцию, которая её определяет, и на этом останавливается. Эти эвристики подобраны по реальным релизам и меняются, поэтому копирование их сюда создало бы ещё одну вещь, которую нужно держать в соответствии. Ссылки на код указаны относительно пакета.

1. Имя папки релиза

internal/torrent/key.go, GetKey / GetKey_Original

Папка внутри __all__/, имя файла .zurgtorrent, ключ, через который идёт каждый поиск, и то, что zurg называет "access key", — это одна и та же строка. Она определяется в таком порядке, и побеждает первое совпадение:

Условие Имя папки
ignore_renames: false, задан Torrent.Rename Torrent.Rename
retain_rd_torrent_name: true Name, без изменений
retain_folder_name_extension: true И Name, без изменений
Name содержит OriginalName  
иначе — оба флага в значениях по умолчанию OriginalName, сначала без
  .mp4, потом без .mkv

retain_rd_torrent_name проверяется первым и полностью перекрывает retain_folder_name_extension. Второй работает только там, где Name содержит OriginalName как подстроку; если не содержит, обрезка всё равно происходит.

Обрезка — это strings.TrimSuffix, вызванный дважды, то есть три правила в одном. Отрезаются только .mp4 и .mkv, так что .avi, .ts, .iso и остальные остаются в имени папки. Регистр важен, поэтому Movie.2019.MKV сохраняет свой .MKV. Два вызова идут последовательно, а не как альтернативы, так что Movie.2019.mkv.mp4 становится Movie.2019. Потом может быть добавлен суффикс — см. раздел 4. Результат — один компонент пути, он никогда не разбивается по /.

УСТАРЕЛО. retain_folder_name_extension и retain_rd_torrent_name устарели и будут удалены. Пока что поведение не меняется, но при установке любого из них при запуске пишется предупреждение. Оба привязывают библиотеку к Name, а аккаунт переписывает его под zurg (раздел 2). Значения по умолчанию привязывают её к тому, что объявил сам торрент, и аккаунт этого не трогает. На инстансе, который стоит перед Sonarr или Radarr (то есть с блоком sabnzbd: или qbittorrent:), значения по умолчанию — единственно правильные, потому что ключ доступа, который меняется после импорта, теряет релиз. ignore_renames не устарел.

2. Откуда берутся Name и OriginalName

Real-Debrid internal/realdebrid/types.go Name = filename, OriginalName = original_filename

TorBox internal/torbox/types.go, wireTorrent.originalName Name = name. OriginalName = единственная директория, в которой лежат все файлы, если она одна. Файлы в корне дерева берут name, кроме случая с одним файлом без папки: у него используется собственное имя.

AllDebrid internal/alldebrid/types.go, originalName То же правило, что и у TorBox, применяется к плоскому списку файлов. Если не сработало, берётся filename из magnet.

NZB internal/nzb/provider.go Name и OriginalName оба равны releaseName, а Hash торрента является id релиза. См. раздел 3.

Поскольку бэкенды дебрид-сервисов берут OriginalName из корневой папки самого торрента, два аккаунта с одинаковым содержимым дают одинаковое имя папки.

Что на самом деле значат два поля Real-Debrid. Проверено 2026-08-27 на тестовом аккаунте примерно с 84k торрентов; 252 из них выборочно просмотрены только на чтение через GET /torrents/info: original_filename во всех случаях было тем именем, которое торрент заявлял сам, то есть названием пака или папки, и никогда именем одного файла.

filename — не то. Оно сводится к базовому имени одного файла, и происходит это ровно тогда, когда в торренте из нескольких файлов выбран один файл: 90 из 112 выборочно просмотренных торрентов такой формы, против 0 из 34 с несколькими, но не всеми выбранными файлами, и 0 из 24 со всеми выбранными. На паке из 221 файла, где выбрана одна серия, original_filename показывало Marvel Cinematic Universe MCU Collection 2008-2023 1080p jZQ, а filename показывало Spider-Man.No.Way.Home.2021.1080p.BluRay.x264...-NOGRP.mkv.

Итак, по умолчанию выдаётся имя пака, а retain_rd_torrent_name: true даёт имя отдельного файла. Поэтому флаг и помечен как устаревший: filename зависит от состояния аккаунта, а ключ доступа — не должен.

3. Именование релизов NZB

internal/nzb/provider.go, releaseName; internal/nzb/parse.go

Id релиза, который также является его Hash, это hex(sha1(lowercase(nzb filename))) — то есть считается от имени файла, а не от содержимого. Поэтому повторное сохранение NZB не отвязывает торрент, построенный из него. Имя папки — это FILENAME без расширения, если только основа имени не похожа на хеш или не превращается в пустую строку после sanitize. В таком случае используется имя из метаданных <head> самого NZB. Приоритет у имени файла, потому что это имя, которое написал индексатор, которое сохранил загрузчик и по которому автоматизация ищет релиз. Индексаторы же часто перепостят релизы, и в блоке метаданных у них может оказаться другая тема. stemLooksJunk, looksLikeHash и sanitizeReleaseName в internal/nzb/parse.go решают все три вопроса. Относись к ним как к чёрному ящику.

4. Три суффикса в именах

Существует три формата суффиксов. Они не связаны между собой.

{xxxxxx} У папки релиза, когда два РАЗНЫХ релиза имеют одно имя: шесть hex-символов из собственного infohash этого релиза. Внутри группы САМЫЙ НОВЫЙ добавленный релиз сохраняет голое имя, а все остальные получают тег. Решается один раз при каждом обновлении проходом, который видит всю библиотеку, и сохраняется как KeySuffixed, поэтому GetKey остаётся чистой функцией от торрента (internal/torrent/key.go, disambiguateNames). Торрент RD и NZB одного и того же релиза здесь — два разных релиза, так как хеш NZB — это sha1 от его имени файла.

(tag).ext У ФАЙЛА, чьё базовое имя повторяется внутри одного релиза, так как zurg сплющивает дерево торрента в одну папку. Тег — это директория, которая уже отличает конфликтующие файлы друг от друга: самый короткий компонент пути, отличающийся в пределах группы, а если такого нет, то шесть hex-символов sha1 от пути файла. Какая глубина подходит и что компонент может переносить в имя файла, определяют dupeTags и sanitizeTag в internal/torrent/dupenames.go; относитесь к ним как к непрозрачным. Группа — это все файлы листинга, выбранные или нет, поэтому файл, который перестал быть выбранным, всё равно разрешается в ключ, под которым был записан. __magic__ — единственное исключение: он показывает настоящее дерево релиза без тегов, потому что там папки и так отличают файлы друг от друга — раздел 8.

_xxxxxxxx У имени файла НА ДИСКЕ, если во входе был любой не-ASCII символ: восемь hex-символов sha256 от этого входа. Раздел 6. Никогда не появляется в смонтированной папке.

5. Имена файлов внутри релиза

internal/torrent/manager.go. VisibleName(key, file) — единственный источник имени, которое показывает монтирование, и имени, по которому должен совпадать поиск: File.Rename, если он есть и ignore_renames равен false, а иначе ключ SelectedFiles, который уже содержит тег из раздела 4. GetFilename вместо этого возвращает filepath.Base(file.Path) и поэтому выбрасывает этот тег. Значит, и отображение, и поиск должны идти через VisibleName, иначе запрос к имени с тегом ничего не найдёт, а N файлов будут делить одно голое имя.

6. Имена файлов на диске

internal/torrent/utils.go, sanitizeFilename — штука непрозрачная, и применяется она ТОЛЬКО к файлам, которые zurg пишет на хост (data/<name>.zurgtorrent и дерево STRM), а то, что отдаёт маунт, она не трогает. Она гораздо агрессивнее всего, что описано выше. Релиз, у которого папка на маунте называется Три богатыря, получает файл кэша, в имени которого идёт набор символов подчёркивания плюс суффикс _xxxxxxxx. Этот суффикс нужен, чтобы имя не совпало со следующим тайтлом на кириллице. Это другое пространство имён, и совпадать с маунтом оно не должно.

7. Содержимое архивов

Релиз, который раздаётся из RAR, ZIP или 7z, показывает содержимое архива, а не его тома, и два правила меняют то, как эти элементы называются.

stripRedundantRoot (internal/universal/rar_streamer.go) удаляет ведущие папки, которые оборачивают весь архив. payloadRenames (internal/universal/deobfuscate.go) показывает единственный обфусцированный основной файл под именем РЕЛИЗА и переносит все записи с тем же базовым именем.

Что считается обфусцированным, решает looksObfuscated в том же файле. Это порт проверки из SABnzbd в zurg: непонятное имя плюс проверки вокруг него. Ничего не переписывается на диске, а archiveName понимает и собственное написание архива.

8. Имена папок

internal/torrent/manager.go, internal/torrent/provider_directories.go

Встроенные и зарезервированные:

__all__          каждый релиз
__unplayable__   релизы, в которых нет ничего, что можно воспроизвести
__dump__         сброшенные торренты
__downloads__    представление загрузок
__magic__        записываемый оверлей, единственный каталог, структура которого
                 хранится, а не вычисляется. Его собственный `__all__` повторяет
                 библиотеку: в нём каждый релиз из `__all__`, но в виде дерева
                 каталогов, которое описывают значения `File.Path` его файлов,
                 а не в плоском виде (`internal/magic/tree.go`). Всё, что лежит
                 рядом с этим зеркалом, — то, что сохранил пользователь.
                 Зеркало вычисляется, поэтому в него ничего нельзя записывать;
                 `MirrorDirectory` в `internal/magic/resolve.go` называет его

int__all__       внутренний индекс хешей

__downloads__ и __magic__ не являются фильтрами, поэтому их добавляют в корневой список вручную, а __magic__ появляется только тогда, когда magic включён. Любое имя, начинающееся с int__, в корневом списке полностью пропускается.

Для каждого аккаунта есть ещё один каталог: "__" + account name + "__", например __realdebrid__, __torbox__, __nzb__. Он строится из блока providers. Этот каталог также определяет, откуда читать: файл, открытый в __torbox__, отдаёт TorBox, даже если другой аккаунт содержит тот же релиз и по порядку в конфиге был бы первым. Аккаунт, имя которого совпало бы с зарезервированным, такого каталога не получает, и zurg выводит предупреждение. Всё остальное в корне — это ключ из блока directories:, без изменений.

9. Переименования пользователем

internal/torrent/rename.go, internal/torrent/rename_bulk.go

Переименование — это просто представление, а не изменение чего-либо в аккаунте debrid. Оно хранится как Torrent.Rename или File.Rename и имеет приоритет над всеми вычислениями выше, пока ignore_renames: true не заставит zurg полностью его игнорировать.

Переименование торрента принимается, только если имя после обрезки пробелов не пустое, не содержит / или \, совпадает со своим filepath.Clean (это также отсекает . и ..) и не конфликтует с существующим ключом доступа, принадлежащим другому хэшу. При применении перестраиваются карты директорий, пишется .zurgtorrent под новым именем и УДАЛЯЕТСЯ файл под старым. Если его оставить, то при перезапуске загрузятся оба, и переименование тихо откатится.

Season fix (/torrents/season-fix/plan и /apply) — это массовое переименование файлов, которое опирается на собственное сопоставление эпизодов в Plex. plan только читает данные и для каждого файла показывает причину пропуска, а apply принимает явный список хэшей, а не флаг «применить ко всем». Дашборд работает с обоими через /season-fix/, там же написаны правила сопоставления и причины пропуска, чтобы оператору было понятно.

10. Последствия для всего, что интегрируется с zurg

Если вы строите путь по имени торрента (ферма симлинков, маппинг удалённых путей, скрипт), вот как это обычно ломается:

  1. Расширение. Отрезаются только .mkv и .mp4, с учётом регистра. Любой другой контейнер сохраняет своё расширение в имени папки.

  2. Переименование. Torrent.Rename важнее производного имени, а собственное переименование торрента в RD меняет Name прямо у вас под ногами.

  3. Хеш-суффикс. Если два разных релиза называются одинаково, у одного из них будет суффикс {a1b2c3}. Какой именно, меняется по мере добавления контента.

  4. Тег дубликата файла. Файл, чей basename повторяется внутри релиза, отдаётся как name (tag).ext, где tag — это компонент директории или хеш пути. filepath.Base(file.Path) этого не воспроизводит.

  5. Переименование архива. Замаскированный payload внутри архива показывается под именем релиза, а не под своим собственным.

  6. Имена NZB берутся из FILENAME у .nzb, а не из чего-либо внутри файла, если только имя файла не хеш. Назовите файл, назовите и папку.

  7. Санитизированные имена файлов на диске — это отдельное пространство имён от имён в маунте, и для релизов с не-ASCII символами они намеренно не совпадают.

Надёжный способ найти релиз — по хешу, а потом спросить у zurg, как он называется. Восстанавливать имя по правилам — значит гадать, и каждое правило выше — это лишний способ ошибиться в догадке.
