# Пустые импорты после отклонённого перемещения {#empty-imports-after-a-refused-move}

Воспроизводил с rclone 1.72.0, union с local-first, полным кэшированием VFS и `File.Move(source, destination)` из .NET 6, который использует Sonarr 4.0.19.2979.

Когда бэкенд отклоняет MOVE, `vfs.File.rename` из rclone оставляет каталог и имя файла указывающими на неудачную цель. Тогда .NET переходит на копирование. При создании целевого файла появляется пустая запись кэша VFS. Открытие источника попадает в ту же запись, поэтому копирование читает EOF и сообщает об успехе. В воспроизведении ожидалось 4096 байт, а получено ноль. Смена кода отказа WebDAV с 409 на 422 результат не изменила.

Патч `scripts/patches/rclone-v1.72.0-rename.patch` восстанавливает исходные каталог и имя, если немедленное переименование не удалось. В него входит upstream-тест регрессии для VFS. Тест монтирования проходит весь путь WebDAV, union, FUSE и .NET с фейковым архивом и без учётных данных провайдера. Вердикт о повреждении вводится, пока байты фикстуры ещё читаются: .NET может успешно скопировать эти байты, но не должен превращать их в пустой файл.

Собери новый бинарник рядом с установленным:

```sh
./scripts/build-rclone-move-fix.sh /absolute/path/to/rclone-fixed
RCLONE_TEST_BIN=/absolute/path/to/rclone-fixed ./integration/magic_move_refusal.sh
```

Сборка фиксирует upstream-коммит `38ab3dd5b1df946aecf5bd085c671c86f46f68eb` (1.72.0). Перед сборкой она запускает тесты переименования VFS. Тест монтирования требует Linux FUSE и Docker либо самодостаточный `DOTNET_MOVE_PROBE_BIN`, собранный из `integration/dotnet-move-probe`. На непатченом бинарнике он намеренно падает. `make integration-test` включает эту проверку. При запуске набора укажи `RCLONE_TEST_BIN` и `RCLONE_BIN` на исправленный бинарник.

Для установки перезапусти монтирование, используя обычные защиты медиасервера, принятые в твоём развёртывании. Предыдущий бинарник сохрани для отката. Существующие пустые файлы в локальном upstream у union переживают перезапуск монтирования. Удаляй только подтверждённо пустые артефакты импорта, а остальные сохраняй. Перезапуск сбрасывает устаревшие узлы VFS, но не восстанавливает отсутствующие статьи Usenet.

Эта правка не отключает запасной вариант с копированием в .NET и не делает повреждённое содержимое читаемым. Проверка доступности в zurg перед завершением SABnzbd и отказанный MOVE остаются отдельными защитами. Выборка доступности не является полной проверкой файла, см. `sabnzbd-client-contract.md`.

Закреплённый патч также содержит исправление алиаса файлов, которое использует встроенный union. При `action_policy: all` операция с файлом может прийти и в local, и в WebDAV. Успешный local Move или Remove вместе с 404 от WebDAV принимается только после свежего поиска, который подтверждает, что источник в неудачном upstream исчез. Операции, где упали все upstream, источник, который всё ещё существует, отсутствующий родительский каталог для назначения, а также другие ошибки I/O или прав остаются ошибками. Итоговый бинарник сообщает `v1.72.0-zurg-rename-sidecar-fix`, чтобы его можно было отличить от исходной сборки с исправлением только VFS.
