# Постоянные кэши чтения {#persistent-read-caches}

Импортированные NZB, записи Real-Debrid, AllDebrid и TorBox сохраняют состояние библиотеки в `data/*.zurgtorrent`. Эти файлы описывают библиотеку. Кэши подготовки чтения и байтов лежат рядом с ними, поэтому изменение или очистка производного кэша не переписывает библиотеку и не теряет теги, названия и привязки к аккаунтам.

## Что переживает перезапуск {#what-survives-a-restart}

| Кэш | Расположение | Что не нужно делать заново |
| --- | --- | --- |
| Манифесты NZB-документов | `data/nzb-manifests/` | Разбор XML без изменений ради имён, размеров, классификации восстановления, паролей и количества сегментов |
| Индексы статей NZB | `data/nzb-index/` | Пересборка ссылок на статьи; используется и в режиме `mmap`, и в режиме `resident` |
| Декодированные статьи Usenet | `data/bytecache/articles/` | Загрузка и yEnc-декодирование уже прочитанной статьи |
| Структуры архивов | `data/archive-layouts/` | Повторное чтение заголовков архивов для восстановления границ томов, вложенных записей и выученных смещений ZIP |
| Распакованные блоки архивов | `data/bytecache/decoded/` | Повторная распаковка для доступа к сохранённым диапазонам байтов после перезапуска или перемотки назад |
| Состояние провайдеров | `data/provider-cache/` | Пересборка окна загрузок RD, которое не изменилось, или повторный запрос свежей таблицы регионов TorBox |
| Ссылки на скачивание | `data/linkcache/` | Повторное получение URL, который всё ещё действителен |

Структуры архивов поддерживают хранимые и сжатые записи RAR/ZIP, вложенные источники, зашифрованные участки и поддерживаемые разделённые архивы. Они хранят ссылки на источники и смещения, а не живые HTTP-читатели. Актуальные URL провайдеров подставляются при восстановлении. Неполные структуры с отсутствующими томами пересобираются из источника. Выученные смещения данных в ZIP сохраняются после первого чтения, и при этом не нужно загружать заголовок для каждой записи во время просмотра каталога.

Манифесты NZB проверяются по размеру исходного файла, времени изменения с точностью до наносекунд и версии парсера. Режим `mmap` сразу восстанавливает метаданные и подключает индекс статей, когда он нужен. Режим `resident` загружает этот индекс в память heap. Режим `reparse` сразу восстанавливает метаданные, но XML всё равно разбирается, когда понадобятся ссылки на статьи. Существующие библиотеки создают манифесты во время первого сканирования с этой версией; сохранение при запуске работает начиная со следующих сканирований и перезапусков.

Параллельные запросы AllDebrid и TorBox для одного и того же непрокэшированного аккаунта/файла теперь используют одно общее разрешение. Отмена одного вызывающего не отменяет разрешение для другого. RD сохраняет прежнее объединение запросов. TorBox при разрешении файла использует уже известные имена и размеры из каталога и не запрашивает эти данные повторно.

Записи с подробной информацией о провайдерах в `data/info/` запоминаются после первого декодирования JSON в рамках процесса. При каждом повторном использовании проверяются идентичность файла, размер и время изменения, и возвращается независимая копия. Файлы библиотеки и подробной информации заменяются атомарно.

## Бюджеты хранилища {#storage-budgets}

Эти необязательные настройки верхнего уровня измеряются в MiB и вступают в силу после перезапуска:

```yaml
nzb_article_disk_cache_mb: 512
archive_decoded_disk_cache_mb: 512
```

По умолчанию каждый кэш занимает 512 MiB на весь инстанс. Ноль отключает кэш, а отрицательные значения считаются нулём. Бюджеты учитывают байты записей, включая контрольные суммы, а не накладные расходы файловой системы на выделение места. Когда приходят новые записи, из кэша вытесняются самые старые неиспользуемые. Если уменьшить бюджет, существующий кэш обрежется при инициализации. При отключении уже существующие файлы остаются, их можно удалить вручную.

Кэш статей дополняет существующий кэш в RAM. Кэш архивов хранит декодированные блоки по 64 KiB и дополняет скользящее окно в RAM размером 64 MiB у каждого декодера. Ни один из кэшей не загружает библиотеку заранее. Чтение за пределами сохранённых декодированных блоков всё равно требует декодирования с начала сжатой записи. VFS-кэш Rclone работает отдельно: он по-прежнему отдаёт полностью закэшированные диапазоны, не заходя в эти пути. При этом эти кэши также ускоряют прямые чтения по HTTP/WebDAV.

Сжатую запись можно декодировать только с начала, поэтому чтение где-то далеко внутри неё означает, что сначала загружается весь архив. zurg держит такое чтение 20 секунд, а затем отвечает `503`, чтобы клиент не остался без ответа. То, до чего дошло декодирование, сохраняется, поэтому плеер, который повторяет перемотку вперёд, с каждым разом продвигается дальше. Чтение, которое отклонено ближе к концу записи, также запускает одно фоновое декодирование этой записи (по одной записи за раз), которое сохраняет последние 8 MiB записи в `data/bytecache/decoded-tails/`. После этого конец файла читается сразу — именно его медиасервер запрашивает, когда анализирует файл. Для этого хранилища выделяется отдельный бюджет такого же размера, что и у `archive_decoded_disk_cache_mb`, и оно отключается вместе с ним.

Производные метаданные растут вместе с библиотекой и не входят в эти бюджеты байтов. Сканирование NZB удаляет манифесты и индексы статей для удалённых документов. Устаревшие версии раскладки архивов можно удалить при остановленном инстансе: они одноразовые и при необходимости пересоздадутся.

## Проверка и восстановление {#validation-and-recovery}

Новые записи метаданных и блоки байтов хранят контрольные суммы. Повреждённые записи и неудачные записи в кэш откатываются к источнику. Записи статей попадают в дисковый кэш только после успешной полной загрузки. Записываются они после того, как статья отдана запросу, который её загрузил, поэтому чтение никогда не ждёт кэш. Если разом приходит больше записей статей, чем можно писать одновременно, лишние записи отбрасываются, а не задерживают чтение. Отброшенная запись загрузится заново, когда она снова понадобится. Идентификатор статьи включает ревизию NZB, конфигурацию сервера, файл и сегмент. Идентификатор архива включает текущие ссылки на источники, размеры, конфигурацию аккаунта, пароль и версию формата. Замена источника NZB тоже делает недействительными раскладки архивов и декодированные байты.

Отпечаток локального источника исходит из того, что при замене меняются размер или время изменения. Намеренно не хэшируем весь XML при каждом запуске. Если при замене сохраняются и размер, и время изменения, связанные производные кэши нужно удалить.

Снимки RD принимаются только для того же токена и настроенного лимита загрузок, не старше одного часа, и только если живая проверка подтверждает самую новую запись и общее количество. Если список изменился, запускается полная сверка. Таблицы регионов TorBox сохраняют прежний срок жизни в шесть часов. Сроки жизни ссылок доставки и обработка сбоев провайдеров не меняются: «тёплая» раскладка открывает полезную нагрузку до того, как подтвердит успех HTTP, поэтому отозванная ссылка может пройти обычный путь разрешения и повтора.

Изменения ссылок доставки запускают объединённую запись на диск примерно через секунду. Повтор через пять минут и сброс при завершении работы остаются. Атомарная замена не даёт читателям увидеть частично записанные записи, но это не гарантия fsync при потере питания. Новые файлы кэша создаются с режимом `0600` в Unix, потому что ссылки и зашифрованные раскладки архивов могут содержать учётные данные или производные ключи. В Windows используются ACL родительской папки вместо битов прав Unix.

## Резервные копии с прогретыми кэшами {#backups-with-warm-caches}

Бэкап по умолчанию сохраняет только основное состояние. Чтобы включить производные кэши и локальный кэш rclone VFS инстанса:

```sh
./zurg backup --include-caches --out warm.zurgbackup
```

Такой бэкап может быть намного больше обычного. Он включает корневые каталоги, перечисленные выше, кэши NZB для именования, размеров и PAR2, а также состояние сетевых тестов. Логи и снимки базы Plex не включаются. Кэши rclone за пределами `data/rclone-cache/` в бэкап не попадают. Если важно согласованное состояние активных кэшей, останови инстанс перед созданием бэкапа.

Восстанавливай с остановленным инстансом командой `./zurg restore-backup warm.zurgbackup`. Бэкапы сохраняют наносекундные временные метки исходных файлов, поэтому неизменённые NZB могут сохранить свои индексы и манифесты. Восстановленные кэши всё равно проходят обычные проверки на валидность и истечение срока. В бэкапах хранятся токены из конфига и закэшированные учётные данные.

## Воспроизводимые проверки {#reproducible-checks}

`BenchmarkParsedDocumentStartup` сравнивает разбор XML с каждым режимом восстановления манифеста на 60 файлах и 30 000 сегментах. `BenchmarkDetailJSONRefresh` сравнивает путь чтения JSON с мемоизированным доступом для записи на 1 000 файлов. Оба бенчмарка работают локально, на прогретой файловой системе. Это не замеры запуска в продакшене от начала до конца.

Замеры выполнены на Apple M3 Pro, по три прогона по 500 мс, 2026-09-05 (медианное значение на операцию):

| Операция | Время | Выделено байт |
| --- | ---: | ---: |
| Разбор NZB XML | 43.49 ms | 20.27 MB |
| Восстановление метаданных в режиме `mmap` | 0.224 ms | 59 KB |
| Восстановление метаданных и резидентного индекса статей | 0.577 ms | 1.79 MB |
| Восстановление метаданных в режиме `reparse` | 0.199 ms | 59 KB |
| Чтение и декодирование записи детальной информации провайдера | 0.538 ms | 784 KB |
| Повторное использование записи детальной информации с проверкой stat и копированием | 0.0084 ms | 59 KB |

В случае декодирования детальной информации перед каждым вызовом очищается новая мемо-память, поэтому в замер входит и её заполнение. Эти цифры сравнивают два текущих пути доступа. Они не оценивают задержку сети и не дают прогноза времени загрузки всей библиотеки.

Регрессионные тесты проверяют повторное использование после перезапуска, повреждение данных, изменения источника, изоляцию аккаунтов, параллельное разрешение, побайтовое совпадение в начале, середине и конце, перемотку назад за пределы окна в RAM и отзыв URL после восстановления структуры.

```sh
go test ./...
go test -race ./internal/debrid ./internal/nzb ./internal/rarstream ./internal/universal ./pkg/cachefile ./pkg/diskcache
go test ./internal/nzb ./internal/torrent -run '^$' -bench 'Benchmark(ParsedDocumentStartup|DetailJSONRefresh)$' -benchmem
make integration-test
```

Целевой интеграционный тест требует документированных тестовых аккаунтов и зависимостей хоста. Пропущенный интеграционный скрипт не подтверждает корректность изменений в кэше.
