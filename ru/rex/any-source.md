# rex со своим приложением {#rex-with-your-own-app}

[rex](https://rex.debridmediamanager.com/ru/) — это медиасервер для официальных приложений Plex, который не хранит никаких файлов. Официальные приложения Plex видят его как обычный сервер Plex. Другая программа, которую на этой странице мы называем **вашим приложением**, сообщает rex, что есть в вашей библиотеке, и отдаёт сами файлы. Когда вы нажимаете «воспроизвести», rex стримит файл прямо из вашего приложения. Ничего заранее не скачивается.

Эта страница проведёт вас от нуля до просмотра фильма, шаг за шагом. Она не привязана к какому-то конкретному приложению. Здесь написано, что rex ожидает от приложения, чтобы вы могли проверить, что ваше приложение это умеет, или написать своё. Для каждого шага сказано, что он делает, зачем нужен и что вы должны увидеть, прежде чем идти дальше.

Четыре вещи, которые стоит знать перед началом:

- **Ваше приложение отдаёт файлы.** rex получает каждый байт из вашего приложения по HTTP или HTTPS, так же как браузер скачивает файл. rex не хранит файлы и не требует диска или монтирования для медиа.
- **Ваше приложение сообщает rex, что у него есть.** Оно отправляет rex список файлов через API ленты rex, а потом все изменения. rex никогда не просматривает папки и ничего не сканирует.
- **Ваше приложение решает, что это за файл.** Оно указывает, фильм это или серия, к какому тайтлу он относится (по id IMDb и TMDB) и, для серии, какой у неё сезон и номер. rex никогда не угадывает по имени файла.
- **Plex описывает контент.** Как только rex подключён к аккаунту Plex, он показывает каждый тайтл с названием, постером, описанием и названиями серий, которые есть в собственных метаданных Plex для этих id. Для того, что никакой агент Plex не знает, ваше приложение называет это само: см. [Создание дополнений для rex](addons.md).

rex бесплатен для личного использования (PolyForm Noncommercial): никакого платного уровня и аккаунта для скачивания не нужно. См. [rex.debridmediamanager.com](https://rex.debridmediamanager.com/ru/).

## Перед началом {#before-you-start}

| Что нужно | Зачем |
|---|---|
| Ночная сборка rex от 2026.10.25 или новее | Шаг 1 скачивает самую свежую |
| Машина, которая всегда включена: Linux (Ubuntu 22.04 или новее), macOS или Windows (64 бит) | rex — это сервер: ваши приложения Plex обращаются к нему каждый раз, когда вы нажимаете Play. Там, где команды отличаются, у шага есть вкладка для каждой системы. [Docker](#run-rex-in-docker) описан ниже, для Linux |
| 1 ГБ оперативной памяти | При 4,062 фильмах и 656 сериалах (34,678 эпизодов) rex использовал меньше 500 МБ при запуске и около 730 МБ во время просмотра библиотеки. Конвертация видео требует больше, а также больше ядер или графического чипа |
| Приложение, которое делает то, что перечислено в [Что должно делать ваше приложение](#what-your-app-must-do) | Оттуда берётся ваша библиотека |
| Ваше приложение отправляет данные с этой машины, из домашней сети или через Tailscale | rex принимает поток только оттуда ([Закройте порт от посторонних](#keep-the-port-private)). Приложение на seedbox или облачном сервере не сможет отправлять данные в rex, если этот сервер не в вашем tailnet; сами файлы при этом можно раздавать откуда угодно, куда может достучаться rex |
| Файлы на дисках этой машины? Что-то, что раздаёт их по HTTP и отправляет в rex | rex никогда не читает диск. [Шаг 2](#step-2-see-it-work-by-hand) делает это вручную для одного файла; в остальных случаях оставьте такие файлы в Plex |
| Usenet? Источник, который его читает, например zurg | rex никогда не общается с провайдером Usenet. zurg — это источник, который общается: см. [rex с zurg](with-zurg.md) |
| Новый аккаунт Plex, созданный специально для rex | rex получает все названия, постеры, описания и названия эпизодов из Plex, как только он [добавлен в аккаунт Plex](#step-3-add-it-to-a-plex-account). До этого названия остаются именами файлов, и постеров нет |

## Что должно уметь ваше приложение {#what-your-app-must-do}

Передайте этот список тому, кто делает ваше приложение. Справочник по API rex находится в [docs/feed-api.md](https://github.com/debridmediamanager/rex/blob/main/docs/feed-api.md).

| Ваше приложение должно | Как | Если этого не сделать |
|---|---|---|
| Отдавать каждый файл по HTTP | `GET <address>/<path>` отдаёт файл. Запросы `Range` делают перемотку быстрой, редиректы обрабатываются. Разрешены basic auth или bearer-токен | Ничего не играет: rex пишет в лог 502 |
| Зарегистрироваться в rex | `PUT /rex/sources/<name>` (буквы, цифры, `-` и `_`) с `{"url": ...}` и, если нужен логин, `"user"` и `"password"` или `"bearer"`. В url их быть не должно. Повторять при каждом запуске | rex негде читать |
| Отправлять все свои файлы | `POST /rex/feed/<name>/items`, по несколько сотен файлов за запрос | rex остаётся пустым |
| Отправлять вывод ffprobe для каждого файла | JSON от `-show_format -show_streams` целиком, как `media_info` | Файл **отложен**: он сохранён, но не показывается, потому что приложения Plex отказываются играть файл без него |
| Указывать, что это за файл | `kind` (`movie`, `episode` или `extra`) и `ids`: `imdb` или `tmdb` фильма или **сериала** (достаточно любого из них), но не эпизода. Для эпизода `season` и `episode` указываются у самого элемента (рядом с `kind`, а не внутри `ids`), с номерами, как их даёт TMDB. `episode_end` для файла, в котором несколько эпизодов | Файл не сопоставлен: фильм называется как его файл, эпизод попадает в сериал, названный по релизу, и нумеруется по порядку в файле |
| Сохранять один и тот же `id` для файла навсегда | Даже если файл переименован | Переименованный файл становится новым тайтлом и теряет историю просмотра |
| Отправлять изменения сразу | Тот же `POST` для новых или изменённых файлов, `DELETE /rex/feed/<name>/items` для удалённых | Библиотека устаревает |
| Время от времени отправлять всю библиотеку целиком | `PUT /rex/feed/<name>/snapshot`. rex удаляет всё, что не указано в снимке | Файлы, которые приложение потеряло из виду, остаются в rex |
| Принимать WebDAV `DELETE` для файла | Когда кто-то удаляет тайтл в приложении Plex, rex сначала просит ваше приложение удалить файл | Тайтл остаётся, а приложение Plex сообщает, что его не удалось удалить |

## Шаг 1. Установите rex {#step-1-install-rex}

**Что делает этот шаг.** Скачивает rex в `~/rex` (`$HOME\rex` в Windows) и запускает его как службу со всем, что нужно для следующих шагов. Следующим шагам перезапуск не нужен, он нужен только для необязательных разделов ниже.

**Зачем это нужно.** С rex общаются твои приложения Plex. Первый запуск создаёт `rex.db`, в котором хранятся твои библиотеки, всё, что присылает приложение, и история просмотров.

На Linux можно вместо этого запустить образ rex в Docker: см. [Запуск rex в Docker](#run-rex-in-docker).

+++ Linux и macOS
```bash
mkdir -p ~/rex && cd ~/rex
TAG=$(curl -fsSL 'https://api.github.com/repos/debridmediamanager/rex/releases?per_page=1' | sed -n 's/.*"tag_name": *"\([^"]*\)".*/\1/p' | head -1)
P=$(uname -s | tr A-Z a-z)-$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')
curl -fL "https://github.com/debridmediamanager/rex/releases/download/$TAG/rex-$TAG-$P.tar.gz" | tar xz --strip-components=1
```
+++ Windows
В PowerShell:

```powershell
New-Item -ItemType Directory -Force $HOME\rex | Out-Null; cd $HOME\rex
$tag = (Invoke-RestMethod 'https://api.github.com/repos/debridmediamanager/rex/releases?per_page=1')[0].tag_name
curl.exe -fLO "https://github.com/debridmediamanager/rex/releases/download/$tag/rex-$tag-windows-amd64.zip"
tar -xf "rex-$tag-windows-amd64.zip" --strip-components=1; Remove-Item "rex-$tag-windows-amd64.zip"
```
+++

Берётся самая свежая сборка rex для твоей машины, обычно nightly.

Узнай LAN IP rex, его адрес в твоей домашней сети. В Linux `hostname -I` выводит несколько адресов: возьми тот, что в домашней сети, а не тот, что начинается с `172.17.` (Docker) или `100.` (Tailscale). На macOS его выводит `ipconfig getifaddr en0` (`en1`, если первая команда ничего не выводит). В Windows `ipconfig` показывает его как **IPv4 Address** в разделе адаптера Wi-Fi или Ethernet. **На этой странице везде написано `192.168.1.20`: подставь вместо него свой адрес.** По этому адресу к rex обращаются приложения Plex, твоё приложение и твои команды.

**Plex Media Server работает на той же машине?** Заверши команду запуска rex ниже параметром `--port 32500` и используй `32500` везде, где в команде или настройке написано `32400`, включая правило брандмауэра Windows. Plex уже занимает порт 32400 и порты, через которые приложения находят серверы, а на любом другом порту rex не трогает их, оставляя Plex. Тогда в твоих приложениях будут два сервера с именем машины: rex, тот, что тебе расшарили, и рядом имя новой учётной записи. Когда rex привяжется к своей учётной записи Plex ([шаг 3](#step-3-add-it-to-a-plex-account)), его можно переименовать: войди в Plex под этой учётной записью, открой в rex **Settings**, **General**, измени **Friendly name** и сохрани, затем перезапусти rex, как описано ниже. Приложения Plex покажут новое имя после перезапуска.

Теперь сделай из него службу:

+++ Linux
Создай `~/.config/systemd/user/rex.service`:

```bash
mkdir -p ~/.config/systemd/user
nano ~/.config/systemd/user/rex.service
```

```ini
[Unit]
Description=rex
After=network-online.target

[Service]
WorkingDirectory=%h/rex
EnvironmentFile=-%h/rex/rex.env
ExecStart=%h/rex/rex
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now rex
sudo loginctl enable-linger "$USER"
journalctl --user -u rex -f
```

**Команда запуска** rex — строка `ExecStart`, а ключи идут в `~/rex/rex.env`, по одному `NAME=value` на строку. После изменений `systemctl --user daemon-reload && systemctl --user restart rex` перезапускает rex. `journalctl --user -u rex -f` показывает его лог. `loginctl enable-linger` не даёт rex остановиться при выходе из системы.
+++ macOS
`run.sh` запускает rex в его папке, а LaunchAgent запускает `run.sh` при входе в систему:

```bash
cp ~/rex/examples/run.sh.example ~/rex/run.sh
mkdir -p ~/Library/LaunchAgents
cat > ~/Library/LaunchAgents/com.rex.plist <<PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.rex</string>
  <key>ProgramArguments</key><array><string>/bin/bash</string><string>$HOME/rex/run.sh</string></array>
  <key>RunAtLoad</key><true/><key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>$HOME/rex/rex.log</string>
  <key>StandardErrorPath</key><string>$HOME/rex/rex.log</string>
</dict></plist>
PLIST
launchctl load ~/Library/LaunchAgents/com.rex.plist
tail -F ~/rex/rex.log
```

**Команда запуска** rex — последняя строка `~/rex/run.sh`, а ключи идут в `~/rex/rex.env`, по одному `NAME=value` на строку. После изменений `launchctl kickstart -k gui/$(id -u)/com.rex` перезапускает rex. `tail -f ~/rex/rex.log` показывает его лог.

rex работает, пока ты вошёл в свою учётную запись на Mac. Если Mac перезагружается сам, включи автоматический вход (**System Settings**, **Users & Groups**). Если включён брандмауэр macOS, разреши rex, когда macOS спросит, или добавь `~/rex/rex` в **Options** брандмауэра.
+++ Windows
Открой PowerShell **от имени администратора** и перейди в папку rex командой `cd $HOME\rex`. Сначала создай `run.cmd`: он запускает rex в его папке и пишет лог в `rex.log`. Блокнот предложит создать файл:

```powershell
notepad run.cmd
```

```bat
@echo off
cd /d "%~dp0"
rex.exe 2>> rex.log
```

Сохрани его. Затем разреши свою сеть через брандмауэр Windows для порта rex и двух портов обнаружения, и запусти rex сейчас и при каждом входе в систему:

```powershell
New-NetFirewallRule -DisplayName rex -Protocol TCP -LocalPort 32400
New-NetFirewallRule -DisplayName "rex discovery" -Protocol UDP -LocalPort 32410,32414
$settings = New-ScheduledTaskSettingsSet -ExecutionTimeLimit 0 -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries
Register-ScheduledTask rex -Action (New-ScheduledTaskAction -Execute "$HOME\rex\run.cmd") -Trigger (New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME) -Settings $settings
Start-ScheduledTask rex; Start-Sleep 3
Get-Content rex.log -Wait
```

**Команда запуска** rex — строка `rex.exe` в `run.cmd`, а ключи идут выше неё, по одной строке `set NAME=value`. После изменений `Stop-Process -Name rex; Start-Sleep 1; Start-ScheduledTask rex` перезапускает rex. `Get-Content $HOME\rex\rex.log -Wait` показывает его лог.

Запустил rex вручную в PowerShell? Тогда его лог есть только в этом окне, без `rex.log`, и после перезагрузки ничто его не запустит. rex хранит базу и привязку к аккаунту в папке, из которой запущен, поэтому rex, запущенный из другой папки, — это новый, непривязанный сервер. Останови его через Ctrl+C и запусти снова из папки rex с теми же флагами или, что лучше, настрой задачу выше.

rex работает, пока ты вошёл в Windows, в собственном окне: не закрывай его. В PowerShell пиши `curl.exe` там, где на этой странице написано `curl`: встроенный `curl` в Windows PowerShell — это другая команда.
+++

**Что ты должен увидеть.** Среди первых строк:

```
INFO    seeded rex.db: an empty library named yourhost, machine=...
INFO    no source yet: a source registers itself once pointed at this server (PUT /rex/sources/{name}, docs/feed-api.md)
INFO    claim state: unclaimed
INFO    rex on http://192.168.1.20:32400  machine=...  items=0  parts=proxy
```

rex называет себя по имени машины, и приложения Plex показывают это имя. `no source yet` — это нормально: ни одно приложение ещё не зарегистрировалось. Оставь лог открытым.

## Шаг 2. Проверьте работу вручную {#step-2-see-it-work-by-hand}

**Что он делает.** Играет роль твоего приложения для одного фильма: поднимает временный файловый сервер и отправляет две команды `curl`.

**Зачем это нужно.** Этот шаг доказывает, что rex работает на твоей машине, ещё до того, как в дело вступает приложение. Если этот шаг работает, а приложение нет, проблема в приложении. Пропусти его, если приложение уже настроено.

Понадобятся `ffprobe`, маленький веб-сервер и один видеофайл. Зарегистрируй папку с файлом в rex под именем `test`, а затем отправь rex файл, указав, что это фильм Sintel (IMDb `tt1727587`, TMDB `45745`), вместе с выводом ffprobe.

+++ Linux and macOS
Установи `ffprobe` и `jq` (`sudo apt install -y ffmpeg jq` на Linux, `brew install ffmpeg jq` на macOS). Положи файл туда, где маленький веб-сервер сможет его раздавать:

```bash
mkdir -p ~/rex-test/movies/Sintel.2010
cp /path/to/any-video.mkv ~/rex-test/movies/Sintel.2010/Sintel.2010.mkv
cd ~/rex-test
python3 -m http.server 8099 --bind 127.0.0.1 &
```

Зарегистрируй его в rex:

```bash
curl -s -X PUT http://192.168.1.20:32400/rex/sources/test \
  -H 'Content-Type: application/json' -d '{"url": "http://127.0.0.1:8099"}'
```

Отправь rex файл:

```bash
P=movies/Sintel.2010/Sintel.2010.mkv
jq -n --arg p "$P" \
  --argjson probe "$(ffprobe -v quiet -print_format json -show_format -show_streams "$P")" \
  '{items: [{id: $p, path: $p, kind: "movie", ids: {imdb: "tt1727587", tmdb: 45745}, media_info: $probe}]}' \
| curl -s -X POST http://192.168.1.20:32400/rex/feed/test/items \
    -H 'Content-Type: application/json' --data-binary @-
```
+++ Windows
Установи `ffprobe` и Python командами `winget install Gyan.FFmpeg` и `winget install Python.Python.3.13`, затем открой новое окно PowerShell. Положи файл туда, где маленький веб-сервер сможет его раздавать:

```powershell
New-Item -ItemType Directory -Force $HOME\rex-test\movies\Sintel.2010 | Out-Null
Copy-Item C:\path\to\any-video.mkv $HOME\rex-test\movies\Sintel.2010\Sintel.2010.mkv
cd $HOME\rex-test
$server = Start-Process py '-m http.server 8099 --bind 127.0.0.1' -WindowStyle Hidden -PassThru
```

Зарегистрируй его в rex:

```powershell
Invoke-RestMethod -Method Put http://192.168.1.20:32400/rex/sources/test -ContentType application/json -Body '{"url": "http://127.0.0.1:8099"}'
```

Отправь rex файл:

```powershell
$p = 'movies/Sintel.2010/Sintel.2010.mkv'
$probe = ffprobe -v quiet -print_format json -show_format -show_streams $p | Out-String | ConvertFrom-Json
$item = @{ id = $p; path = $p; kind = 'movie'; ids = @{ imdb = 'tt1727587'; tmdb = 45745 }; media_info = $probe }
Invoke-RestMethod -Method Post http://192.168.1.20:32400/rex/feed/test/items -ContentType application/json -Body (ConvertTo-Json @{ items = @($item) } -Depth 20)
```

PowerShell показывает ответы rex списками, а не JSON.
+++

**Что ты должен увидеть.** Ответ будет `{"created":1,"updated":0,"held":0,"unchanged":0}`, а лог rex выведет:

```
INFO    FEED identified "Sintel.2010" -> movie tmdb:45745 (placed)
INFO    FEED test upsert: 1 created, 0 updated, 0 held, 0 unchanged, 0 rejected
```

Sintel теперь в **Movies** и воспроизводится с маленького веб-сервера. Ни одно приложение Plex не сможет открыть rex до [шага 3](#step-3-add-it-to-a-plex-account), поэтому этот шаг проверяет только сам фид.

**Уборка.** Перед тем как двигаться дальше, удали за собой: удаление тестового источника убирает всё, что он отправил. На первый запрос придёт ответ с путём `confirm`; отправь `DELETE` на этот путь в течение пяти минут.

+++ Linux and macOS
```bash
curl -s -X DELETE http://192.168.1.20:32400/rex/sources/test
curl -s -X DELETE "http://192.168.1.20:32400/rex/sources/test/confirm/<code from the answer>"
kill %1
```
+++ Windows
```powershell
Invoke-RestMethod -Method Delete http://192.168.1.20:32400/rex/sources/test
Invoke-RestMethod -Method Delete "http://192.168.1.20:32400/rex/sources/test/confirm/<code from the answer>"
Stop-Process -InputObject $server
```
+++

**Если что-то пошло не так.**

- `"held":1`: в `media_info` нет данных или нет потоков. Проверь, что `ffprobe` вывел JSON для этого файла.
- Ответ с `rejected`: файл не является видео по расширению, это семпл, нет `id` или `path`, путь составлен неправильно или другой `id` уже занимает этот путь. Причина каждого случая указана в ответе и в логе rex.
- `404 no such source`: сначала не выполнился `PUT /rex/sources/test`.

## Шаг 3. Добавьте в аккаунт Plex {#step-3-add-it-to-a-plex-account}

**Что это делает.** Регистрирует rex в аккаунте Plex, как настоящий Plex Media Server, и открывает к нему доступ для вашего собственного аккаунта.

**Зачем это нужно.** rex берёт название каждого тайтла, постер, описание и названия эпизодов из метаданных самого Plex, а запрашивать их он может только после того, как попадёт в аккаунт. Всё, что ваше приложение отправляет до привязки, сразу получает имя, как только оно появляется, а Fix Match до этого момента ничего не предлагает. Кроме того, привязка убирает уведомление «unclaimed» и нужна, если вы хотите [использовать rex вне дома](#use-it-outside-your-home-optional).

**Для этого используйте новый аккаунт Plex, а не свой.** rex не делает Plex, и Plex может принять меры против аккаунта, в котором зарегистрирован rex. Держите свой основной аккаунт, с историей просмотров, друзьями и любой подпиской Plex Pass, в стороне: создайте новый бесплатный аккаунт на [plex.tv](https://www.plex.tv) с адресом электронной почты, который вы больше нигде не используете, зарегистрируйте rex на нём и откройте доступ к rex для своего аккаунта. Смотреть вы будете под своим именем, как если бы смотрели сервер друга. Пока этот шаг не выполнен, rex ничего не воспроизводит.

### Зарегистрируйте rex на новом аккаунте {#register-rex-on-the-fresh-account}

1. Войдите в [plex.tv](https://www.plex.tv) **под новым аккаунтом**, откройте [plex.tv/claim](https://www.plex.tv/claim) и скопируйте код. Он истекает примерно через пять минут.
2. На машине с rex (`curl.exe` в Windows):

   ```bash
   curl -X POST "http://192.168.1.20:32400/myplex/claim?token=claim-xxxxxxxxxxxx"
   curl -s http://192.168.1.20:32400/identity
   ```

**Что должно быть.** Вторая команда показывает `claimed="1"`, а в папке rex появляется файл `claim_state.json`. Сохраните этот файл: без него rex придётся привязывать заново, а пока файл на месте, rex не даст привязать себя повторно. Начиная с этого момента названия и постеры тайтлов будут приходить без перезапуска.

**Если нет.**

- Первая команда отвечает `409` с `rex: already claimed`: rex уже привязан к аккаунту Plex.
- Она отвечает `500 Internal Server Error`, а rex пишет в лог `claim exchange failed`: код истёк или уже был использован. Получите новый на [plex.tv/claim](https://www.plex.tv/claim).

### Поделитесь им со своим аккаунтом {#share-it-with-your-own-account}

1. Всё ещё войдя в свежий аккаунт, открой [app.plex.tv](https://app.plex.tv), затем **Settings** (гаечный ключ), **Manage Library Access** и **Grant Library Access**.
2. Введи имя пользователя или email своего аккаунта, выбери сервер rex и обе библиотеки, **Movies** и **TV Shows**, и отправь приглашение.
3. Выйди, войди как **ты сам** и прими приглашение. Оно придёт по email и в app.plex.tv.

![Manage Library Access в настройках app.plex.tv, с кнопкой Grant Library Access](../assets/rex/20-plex-manage-library-access.webp)

![Диалог Grant Library Access с отмеченными Movies и TV Shows сервера rex](../assets/rex/21-plex-grant-library-access.webp)

**Что должно получиться.** Войдя как ты сам, приложения Plex показывают сервер rex рядом с твоими собственными серверами, с обеими библиотеками. История просмотров на rex принадлежит тебе: она хранится отдельно от истории свежего аккаунта. Делись ей так же с любым другим членом семьи.

## Шаг 4. Подключите приложение {#step-4-connect-your-app}

**Что это делает.** Направляет ваше приложение на rex. Приложение регистрируется, отправляет всю свою библиотеку, а затем каждое изменение по мере его появления.

**Почему это важно.** Это единственная связь между ними. У rex нет настройки для вашего приложения: приложение находит rex, а не наоборот.

Укажите в вашем приложении адрес rex: `http://192.168.1.20:32400`. Как его ввести, зависит от приложения.

**Что вы должны увидеть.** В логе rex появится запись с именем, под которым ваше приложение зарегистрировалось:

```
INFO    SOURCES myapp registered at http://192.168.1.20:8080
INFO    SOURCES PUT /rex/sources/myapp -> 200
INFO    FEED myapp upsert: 0 created, 0 updated, 200 held, 0 unchanged, 0 rejected
INFO    FEED identified "Some.Movie.2019.1080p" -> movie tmdb:12345 (placed)
INFO    FEED myapp upsert: 180 created, 0 updated, 20 held, 0 unchanged, 0 rejected
```

rex читает каждый файл по адресу из строки `registered at`, поэтому ваше приложение должно быть доступно по этому адресу. rex выводит эту строку повторно только тогда, когда адрес меняется. Файлы `held` ждут вывода ffprobe и появляются, как только ваше приложение его отправит. Проверить, что rex получил от вашего приложения, можно в любой момент (в Windows — `curl.exe` без `| head -c 600`):

```bash
curl -s http://192.168.1.20:32400/rex/sources                # the apps that registered, and their addresses
curl -s http://192.168.1.20:32400/rex/feed/myapp/items | head -c 600   # what is shown
curl -s http://192.168.1.20:32400/rex/feed/myapp/held  | head -c 600   # what waits for ffprobe output
```

**Если нет.**

- Ничего нет в логе rex: ваше приложение так и не достучалось до rex. Проверьте адрес, который вы указали, и что порт rex открыт между двумя машинами.
- Файлы приходят, но строк `identified` нет: ваше приложение не отправляет `kind` и `ids` (файлы в состоянии held и повторные отправки без изменений тоже ничего не выводят). Такие тайтлы останутся без совпадения, пока приложение их не отправит. Исправить один вручную всё равно можно через **Fix Match** в приложении Plex, вошедшем под новым аккаунтом. Ваш собственный аккаунт, с которым расшарен rex, получит отказ.
- Тайтлы появляются, но ничего не воспроизводится: rex не может достучаться до вашего приложения по адресу из `registered at`. Строка `upstream failed` в разделе [Что делать, если что-то не так](#when-something-is-wrong) как раз это проверяет.

## Шаг 5. Посмотрите что-нибудь {#step-5-watch-something}

**Что это делает.** Открывает rex в приложении Plex так же, как ты открыл бы любой сервер Plex.

**Зачем это нужно.** Ради этого вся настройка и затевалась. Заодно это проверяет последнее звено: что rex читает файл из твоего приложения во время просмотра.

Открой приложение Plex на телефоне, телевизоре или компьютере **в той же домашней сети**. rex появится под именем этого устройства, с **Movies** и **TV Shows**. Выбери фильм и нажми play.

![Приложение Plex с библиотеками Movies и TV Shows сервера rex в боковой панели и сеткой фильмов справа](../assets/rex/10-plex-server-libraries.webp)

Дома больше ничего не нужно: приложения Plex находят rex через собственное локальное обнаружение Plex и подключаются к нему по твоей сети. Для этого устройство должно быть в той же сети, что и rex (не в гостевом Wi-Fi и не в отдельном VLAN). Обнаружение работает по UDP-портам 32410 и 32414, поэтому файервол на машине с rex должен их пропускать (в Windows это делают правила файервола из шага 1). rex отвечает на обнаружение, когда использует порт 32400. Если ты перенёс rex на 32500, потому что Plex работает на той же машине, обнаружением занимается Plex, а приложения находят rex через аккаунт Plex, с [которым он общий](#share-it-with-your-own-account). app.plex.tv в веб-браузере тоже работает дома, по HTTPS-адресу, который [rex-direct](#rex-direct) выдаёт rex после привязки (rex nightly 2026.11.02 или новее). При первом запуске Chrome спросит, может ли app.plex.tv обращаться к устройствам в твоей локальной сети: разреши. `http://192.168.1.20:32400/web` — это не Plex Web: у rex нет собственного веб-приложения, и эта страница лишь показывает, привязан ли rex и где смотреть.

**Что ты должен увидеть.** Постеры, названия и годы, как на любом сервере Plex. Воспроизведение начинается в течение нескольких секунд.

Две вещи, с которыми можешь столкнуться:

- **"yourhost server is unclaimed and not secure".** Приложение Plex так пишет про любой сервер, не привязанный к аккаунту Plex, и rex ничего не проигрывает, пока он не привязан. Сделай [шаг 3](#step-3-add-it-to-a-plex-account).
- **"This server is not powerful enough to convert video".** Если не воспроизводится ни одно название ни на одном устройстве, посмотри в логе rex сразу после нажатия Play: `upstream failed` или `502` там означают, что rex не может достучаться до твоего приложения, и FFmpeg это не исправит. В строке `upstream failed` из [Что делать, если что-то не так](#when-something-is-wrong) написано, что делать. Если не работают только некоторые файлы, часто только в веб-браузере, значит устройство не может проиграть их как есть, часто из-за звука AC3 или DTS. Приложения Plex на телевизорах и телефонах играют большинство файлов без изменений. Чтобы играло всё на всех устройствах, настрой [Конвертацию видео](#converting-video-optional).

**Удаление удаляет в твоём приложении.** Если ты вошёл под отдельным аккаунтом, **Delete** у названия в приложении Plex заставляет rex попросить твоё приложение удалить файл, как написано в [Что должно делать твоё приложение](#what-your-app-must-do). Аккаунты, с которыми rex общий, удалять не могут. Чтобы выключить удаление: в app.plex.tv под отдельным аккаунтом открой **Settings**, затем **Library** сервера rex, **Show Advanced**, сними галочку с **Allow media deletion** и сохрани.

![Настройки Library сервера rex с открытым Show Advanced и обведённым Allow media deletion](../assets/rex/32-plex-allow-media-deletion.webp)

Файл, который удалило твоё приложение, попадает в корзину библиотеки, как и в Plex: он остаётся недоступным, со своей историей просмотров, и возвращается как был, если приложение пришлёт его снова. **Empty Trash** в библиотеке удаляет его окончательно, а **Empty trash automatically after every scan** (Settings, Library), которая выключена, делает это само.

Каждый файл попадает в **Movies** или **TV Shows** по `kind`, который прислало твоё приложение. Файл без него определяется по первой папке: `shows` идёт в TV Shows, всё остальное в Movies.

Чтобы дать папке собственные библиотеки, твоё приложение добавляет `directories` в регистрацию, указывая первую папку в путях файлов и названия библиотек: `{"url": ..., "directories": [{"name": "anime", "shows": "Anime", "movies": "Anime Movies"}]}`. Достаточно одного названия. rex создаёт их, когда приложение регистрируется, и переносит туда то, что уже лежит в этой папке, как есть: историю просмотров, Fix Match и правки. Неправильная запись пропускается и указывается в `ignored` в ответе вместе с причиной. Переименовывай их в приложении Plex как хочешь. Если удалить такую библиотеку, она останется удалённой, а её файлы вернутся в Movies или TV Shows, пока ты не добавишь её снова через **Add Library**, где в списке папок видны папки твоего приложения. Правила описаны в [Библиотеки, которые объявляет источник](https://github.com/debridmediamanager/rex/blob/main/docs/feed-api.md#libraries-a-source-declares).

**Резервная копия.** Сохрани `rex.db` из папки rex (там твоя библиотека, история просмотров и логин твоего приложения, так что держи его в секрете), `claim_state.json` и, когда rex-direct выдаст rex имя, `rex-direct.json` (его ключ сертификата):

+++ Linux и macOS
```bash
sudo apt install -y sqlite3    # once, on Linux; macOS has it
mkdir -p ~/rex-backup
sqlite3 ~/rex/rex.db ".backup $HOME/rex-backup/rex.db"
cp ~/rex/*.json ~/rex-backup/
```
+++ Windows
В Windows нет `sqlite3`, поэтому на время останови rex и скопируй `rex.db` вместе с двумя файлами рядом, имена которых начинаются так же:

```powershell
Stop-Process -Name rex; Start-Sleep 1
New-Item -ItemType Directory -Force $HOME\rex-backup | Out-Null
Copy-Item $HOME\rex\rex.db*, $HOME\rex\*.json $HOME\rex-backup
Start-ScheduledTask rex
```
+++

В Docker файлы лежат в `~/rex/config` и доступны только root. Сделай копию изнутри контейнера командой `docker exec rex sqlite3 /config/rex.db ".backup /config/rex.db.bak"`, затем `mkdir -p ~/rex-backup && sudo cp ~/rex/config/rex.db.bak ~/rex/config/*.json ~/rex-backup/`.

[Восстановление из резервной копии](#restore-a-backup) возвращает их на место.

Готово. Разделы ниже необязательны.

## Использование вне дома (необязательно) {#use-it-outside-your-home-optional}

**Что это делает.** Даёт rex HTTPS-адрес, до которого могут достучаться приложения Plex вне дома, и сообщает об этом plex.tv.

**Почему это важно.** Вне дома app.plex.tv подключается только к HTTPS-адресу, и остальные приложения Plex тоже предпочитают его. Настоящий сервер Plex может переключиться на ретрансляцию Plex, а rex не может, поэтому способ доступа выбираешь ты. Сначала rex нужно [привязать](#step-3-add-it-to-a-plex-account) к аккаунту. Прокси, который смотрит в интернет, должен блокировать `/rex/`: см. [Держи порт закрытым](#keep-the-port-private).

**Plex Pass.** Plex Web воспроизводит вне дома без Plex Pass или Remote Watch Pass на любом из аккаунтов. Другие приложения Plex вне дома не тестировались.

Какой бы вариант ты ни выбрал, всё, что ты смотришь вне дома, уходит через **скорость отдачи** (upload) твоего домашнего соединения. Примерно: при отдаче 20 Мбит/с тянется один 1080p WEB-DL, но не remux.

| Твоя ситуация | Что использовать | Почему |
|---|---|---|
| У роутера есть публичный IP, и ты можешь пробросить порт | **[rex-direct](#rex-direct)** (проще всего) | Включён по умолчанию: один проброс порта. DMM выдаёт rex имя и сертификат и следит, чтобы имя указывало на твой домашний IP |
| Ты можешь установить Tailscale на устройства, с которых смотришь | **[Tailscale serve](#tailscale-serve)** (лучше всего) | На роутере ничего открывать не нужно, работает за любым интернет-соединением. Сертификат продлевается сам, а никто вне твоей tailnet не достучится до rex |
| Устройства без Tailscale (телевизор друга, отель), и у роутера есть публичный IP | **[Caddy](#caddy)** со своим доменом или с бесплатным именем `sslip.io` | Прямое соединение без посредников и бесплатный сертификат, который продлевается сам. Нужно пробросить порт 443 |
| У соединения нет публичного IPv4 (CGNAT или DS-Lite, частое явление у кабельного, мобильного и некоторого оптоволокна), но есть IPv6 | **[rex-direct over IPv6](#rex-direct-over-ipv6)** | Проброса портов и аренды не нужно: открываешь порт 32400 по IPv6. Устройства, с которых смотришь, тоже должны работать с IPv6, а он есть у большинства мобильных сетей |
| У соединения вообще нет публичного IP, или ты смотришь в сетях без IPv6, и устройства без Tailscale | **[Небольшой VPS](#a-small-vps)** | У rex нет ретрансляции и не будет. Арендованный VPS имеет публичный IP, а туннель передаёт всё до rex на полной скорости VPS |

Не рекомендуется:

- **Cloudflare tunnel.** Каждый байт идёт через Cloudflare, который к тому же сбрасывает `Range` при первом чтении файла, поэтому каждый запуск воспроизведения тянет весь файл из твоего приложения.
- **Tailscale Funnel, ngrok и другие хостируемые туннели.** Они ограничивают скорость или месячный объём трафика, а фильм его быстро съедает. Tailscale Funnel к тому же публикует весь rex, включая feed API: любой в интернете мог бы добавлять или удалять что-то в твоей библиотеке.
- **Проброс порта 32400 без rex-direct или собственного сертификата.** Приложения Plex получат обычный HTTP-адрес, который app.plex.tv не принимает.

### rex-direct

rex-direct — это ответ DMM на plex.direct, и он включён по умолчанию. На роутере пробросьте порт 32400 (TCP) на машину с rex. Больше ничего делать не нужно, перезапускать ничего не надо.

После привязки rex получает от DMM два имени: `<hash>.rex-direct.debridmediamanager.com`, которое указывает на ваш домашний публичный IP, и `lan.<hash>.rex-direct.debridmediamanager.com`, которое указывает на LAN IP машины с rex, с сертификатом для обоих. Первый сертификат выпускается несколько минут; в логе rex будет сообщение, что он выпускается, а затем каждое имя появится в строке `rex-direct:`. Новый домашний IP и продление сертификатов подхватываются автоматически. На одном аккаунте Plex можно иметь до десяти имён rex-direct. Дома приложения Plex, включая app.plex.tv, могут использовать имя `lan.`, которое обращается к rex напрямую через вашу сеть, поэтому проброс портов нужен только для доступа вне дома. В app.plex.tv разрешите доступ к устройствам в локальной сети, когда Chrome об этом спросит, иначе будет использовано публичное имя, которому нужен проброс портов. [Что вы должны увидеть](#what-you-should-see) поможет проверить оба имени.

Если ваш роутер пробрасывает на rex другой внешний порт, добавьте ключ `REX_DIRECT_PORT=<that port>`, как показано в [шаге 1](#step-1-install-rex) для вашей системы, и перезапустите rex. Проброс порта не открывает API ленты: см. [Держите порт закрытым](#keep-the-port-private).

### rex-direct через IPv6 {#rex-direct-over-ipv6}

Для подключения без публичного IPv4 (CGNAT или DS-Lite), но с IPv6. Когда DMM подключается к rex по его IPv6-адресу и находит там тот же сервер, он привязывает к этому адресу и имя rex-direct. Нужен rex nightly 2026.11.08 или новее, а в Docker нужен host networking.

Проброс портов для IPv6 не нужен, и маппинг портов тоже не нужен: rex должен использовать один и тот же порт снаружи и внутри, поэтому оставьте `REX_DIRECT_PORT` не заданным. В файрволе роутера разрешите входящие TCP-подключения на порт 32400 к машине с rex по IPv6. rex публикует свой IPv6 через минуту после запуска (или после привязки) и далее каждые 6 часов, поэтому добавьте правило до запуска rex или перезапустите rex после его добавления. Примерно через минуту в логе появятся обе строки с адресами:

```
rex-direct: https://<hash>.rex-direct.debridmediamanager.com:32400 -> <IPv4> and <IPv6>
```

Если строка с `and <IPv6>` не появилась в течение нескольких минут, DMM не смог подключиться к rex по IPv6. Проверьте правило файрвола и то, что rex в Docker использует host networking. В Windows rex публикует временный IPv6-адрес Windows, который система меняет примерно раз в сутки. Чтобы отключить временные адреса, выполните `netsh interface ipv6 set privacy state=disabled` в PowerShell от имени администратора, а затем перезапустите rex, чтобы он опубликовал стабильный адрес. `<IPv4>` в этой строке — общий адрес вашего провайдера, по нему rex не достучаться, поэтому устройствам, с которых вы смотрите, тоже нужен IPv6. Большинство мобильных сетей поддерживают IPv6; гостиничная или офисная сеть только с IPv4 таким способом до rex не дотянется.

### Tailscale serve

Установи [Tailscale](https://tailscale.com/download) на машину с rex и на устройства, с которых будешь смотреть, и войди во всех в один и тот же аккаунт. Затем на машине с rex:

```bash
sudo tailscale serve --bg 32400
```

В Windows запусти это в PowerShell от имени администратора, без `sudo`. На macOS используй [утилиту командной строки](https://tailscale.com/kb/1080/cli) из приложения Tailscale, тоже без `sudo`.

Она выведет адрес, например `https://myhost.tailnet.ts.net`. Передай его rex, добавив `:443`: в конец команды запуска rex из [шага 1](#step-1-install-rex) добавь `--announce-url https://myhost.tailnet.ts.net:443` и перезапусти rex.

Все в твоём tailnet, включая тех, с кем ты делишься этой машиной, могут пользоваться API ленты rex. Делись машиной только с теми, кому доверяешь.

### Caddy

Вам нужно пробросить порт 443 на роутере к машине с rex и получить имя для домашнего IP-адреса:

- **Свой домен:** запись `A`, например `rex.example.com`, которая указывает на ваш домашний IP.
- **Без домена:** используйте `1-2-3-4.sslip.io` с цифрами вашего публичного IP (`curl -s ifconfig.me` его покажет). Если IP меняется, обновляйте имя.

Установите [Caddy](https://caddyserver.com/docs/install) и дайте ему такой Caddyfile (`/etc/caddy/Caddyfile` при установке из пакета для Linux; на macOS и Windows это файл с именем `Caddyfile` в отдельной папке, которую читает `caddy run`, запущенный в этой папке):

```
rex.example.com {
	respond /rex/* 403
	reverse_proxy 192.168.1.20:32400
}
```

`respond /rex/* 403` закрывает API фида от интернета, а ваше приложение всё равно достучится до rex напрямую. Затем перезагрузите Caddy (`sudo systemctl reload caddy` для пакета Linux). На macOS и Windows вместо этого запустите `caddy run` в его папке и держите его запущенным так же, как [шаг 1](#step-1-install-rex) держит rex. На Windows также разрешите TCP-порт 443 в брандмауэре, как в шаге 1 для 32400. Затем добавьте в конец команды запуска rex `--announce-url https://rex.example.com:443` и перезапустите rex.

### Небольшой VPS {#a-small-vps}

Для подключения без публичного IP вообще или когда смотришь из сетей без IPv6: тогда VPS несёт весь трафик вместо [rex-direct через IPv6](#rex-direct-over-ipv6). У rex нет релея и не будет, поэтому арендованный сервер заменяет твой роутер: у него есть публичный IP, а туннель с машины rex доставляет весь трафик до rex. Подойдёт любой VPS с публичным IPv4, это несколько евро в месяц. **Выбирай тариф, месячного трафика которого хватит на то, что ты смотришь вне дома:** каждый байт проходит через него, и тариф с небольшим лимитом трафика быстро закончится.

Нужны IP VPS (`1.2.3.4` ниже), открытые порты 443, 80 и 7000 на нём и длинная случайная строка для туннеля (`openssl rand -hex 32`).

**На VPS** установи [frp](https://github.com/fatedier/frp/releases) (программу `frps`) и [Caddy](https://caddyserver.com/docs/install). Создай `frps.toml`:

```toml
bindPort = 7000
auth.token = "your-long-random-string"
proxyBindAddr = "127.0.0.1"
```

`proxyBindAddr` оставляет конец туннеля на loopback VPS, поэтому интернет достукивается до rex только через Caddy. Создай `/etc/caddy/Caddyfile` с IP VPS как `1-2-3-4.sslip.io` (бесплатное имя, которое всегда указывает на этот IP) или со своим доменом, направленным на него:

```
1-2-3-4.sslip.io {
	respond /rex/* 403
	reverse_proxy 127.0.0.1:32400
}
```

`respond /rex/* 403` закрывает API ленты от интернета. Запусти `frps -c frps.toml` как службу и выполни `sudo systemctl reload caddy`.

**На машине с rex** установи frp тоже (программу `frpc`) и создай `frpc.toml`:

```toml
serverAddr = "1.2.3.4"
serverPort = 7000
auth.token = "your-long-random-string"

[[proxies]]
name = "rex"
type = "tcp"
localIP = "192.168.1.20"
localPort = 32400
remotePort = 32400
```

Запусти как службу: в Linux, например, `~/.config/systemd/user/frpc.service` с `ExecStart=%h/frp/frpc -c %h/frp/frpc.toml` и `Restart=always`; в macOS и Windows запусти `frpc -c frpc.toml` так же, как [шаг 1](#step-1-install-rex) запускает rex. Затем допиши к команде запуска rex `--announce-url https://1-2-3-4.sslip.io:443`, добавь ключ `REX_DIRECT_URL=off` (за CGNAT IPv4 имени rex-direct не достигает rex, поэтому plex.tv не должен его публиковать) и перезапусти rex. app.plex.tv дома теперь тоже идёт через VPS; остальные приложения Plex дома подключаются к rex напрямую.

### Что вы должны увидеть {#what-you-should-see}

```bash
curl -s https://lan.<hash>.rex-direct.debridmediamanager.com:32400/identity
```

показывает короткую XML-страницу с `machineIdentifier` rex на домашнем компьютере; `curl` ничего не показывает, если адрес или его сертификат неверны. Используйте свой адрес: rex записывает его при запуске в виде `rex-direct: https://lan.<hash>.rex-direct.debridmediamanager.com:32400 -> 192.168.1.20 (LAN)` (при `REX_DIRECT_URL=off` такой строки нет). Откройте свой внешний адрес с добавленным `/identity` в браузере телефона при выключенном Wi-Fi: при rex-direct это вторая строка `rex-direct:` из лога rex, а при Tailscale serve это `https://myhost.tailnet.ts.net`, который телефон открывает только при включённом Tailscale. Должна появиться короткая XML-страница без предупреждения о сертификате.

Если телефон не подключается, значит, порт не перенаправлен (или, [через IPv6](#rex-direct-over-ipv6), не пропускается), ваше соединение находится за CGNAT без IPv6, rex доступен только по IPv6, а в сети телефона IPv6 нет, или сертификат rex-direct ещё выпускается (пока это происходит, об этом пишет лог rex).

В логе rex перечислены адреса, которые он объявляет:

```
INFO    heartbeat every 600s for machine ... -> https://myhost.tailnet.ts.net:443,http://192.168.1.20:32400
```

rex выводит это при каждом запуске. Проблемы потом проявляются как `heartbeat failed` или `announced but NOT visible`. В остальном сервер передаёт эти адреса на plex.tv, и приложение Plex вне дома выбирает тот, до которого может достучаться. Если rex пишет `waiting for a claim`, сначала выполните [шаг 3](#step-3-add-it-to-a-plex-account).

## История просмотра с другого сервера Plex (необязательно) {#your-watch-history-from-another-plex-server-optional}

Уже смотрели что-нибудь на другом сервере Plex? Когда ваша библиотека будет в rex, [Перенесите историю просмотров](import-watched.md) скопирует оттуда, что вы смотрели, на каком месте остановились и ваши оценки по звёздочкам. Для каждого человека это делается отдельно.

## Конвертация видео (необязательно) {#converting-video-optional}

**Что это делает.** Позволяет rex конвертировать то, что устройство не может воспроизвести, так же как это делает Plex.

**Зачем это нужно.** Без этого, если устройство не может проиграть файл в исходном виде, появляется сообщение "This server is not powerful enough to convert video". Чаще всего с этим сталкиваются веб-браузеры, например из-за звука AC3 или DTS. Если не работает вообще каждый фильм на каждом устройстве, причина в другом: см. [шаг 5](#step-5-watch-something).

Установите **jellyfin-ffmpeg** 8, а не `ffmpeg`, который предлагает ваша система. Это та сборка, с которой rex тестировался, и единственная, которая конвертирует все файлы Dolby Vision, тонмаппит HDR на графическом чипе и выводит субтитры там же. Другой FFmpeg конвертирует обычное видео, а в логе rex будет написано, чего ему не хватает (в собственном FFmpeg Ubuntu 22.04 к тому же перемотка сбивается на несколько секунд). rex находит его сам.

+++ Linux
Пакет устанавливается в `/usr/lib/jellyfin-ffmpeg` рядом с другими FFmpeg. Первая строка выбирает сборку под вашу систему: есть сборки для Ubuntu 22.04, 24.04 и 26.04 и Debian 12 и 13, для amd64 или arm64. На любой другой системе `curl` выдаст ошибку.

```bash
DEB=jellyfin-ffmpeg8_8.1.3-1-$(. /etc/os-release; echo "$VERSION_CODENAME")_$(dpkg --print-architecture).deb
curl -fLO "https://github.com/jellyfin/jellyfin-ffmpeg/releases/download/v8.1.3-1/$DEB"
sudo apt install -y "./$DEB" && rm "$DEB"
systemctl --user restart rex
```

На другом Linux распакуйте портативную сборку jellyfin-ffmpeg в `~/rex/ffmpeg`, где rex её ищет, и перезапустите rex. Она использует драйвер графики вашей системы, поэтому на старой системе конвертация пойдёт только на процессоре. Где есть пакет, используйте его.

```bash
B=$( [ "$(uname -m)" = aarch64 ] && echo linuxarm64 || echo linux64 )
mkdir -p ~/rex/ffmpeg && curl -fL "https://github.com/jellyfin/jellyfin-ffmpeg/releases/download/v8.1.3-1/jellyfin-ffmpeg_8.1.3-1_portable_${B}-gpl.tar.xz" | tar xJ -C ~/rex/ffmpeg
```

Если у вас графика Intel или AMD, также выполните `sudo usermod -aG render "$USER"` и перезагрузитесь, чтобы служба получила группу. В LXC пробросьте GPU. Чип ускоряет конвертацию; без него rex использует процессор. Если чипа Intel или AMD нет, rex также пробует энкодер карты NVIDIA. На Intel команда `sudo apt install intel-opencl-icd` тоже позволяет конвертировать HDR и Dolby Vision на чипе, примерно в реальном времени для 4K на маломощном Intel. Без неё их конвертирует процессор, а маломощный Intel не справится с 4K в реальном времени.
+++ macOS
Портативная сборка кладётся в `~/rex/ffmpeg`, где rex её ищет:

```bash
B=$( [ "$(uname -m)" = arm64 ] && echo macarm64 || echo mac64 )
mkdir -p ~/rex/ffmpeg && curl -fL "https://github.com/jellyfin/jellyfin-ffmpeg/releases/download/v8.1.3-1/jellyfin-ffmpeg_8.1.3-1_portable_${B}-gpl.tar.xz" | tar xJ -C ~/rex/ffmpeg
launchctl kickstart -k gui/$(id -u)/com.rex
```

На Mac rex всегда конвертирует на процессоре: он не умеет использовать графический чип Mac.
+++ Windows
Портативная сборка кладётся в папку `ffmpeg` внутри папки rex, где rex её ищет:

```powershell
cd $HOME\rex
curl.exe -fLO https://github.com/jellyfin/jellyfin-ffmpeg/releases/download/v8.1.3-1/jellyfin-ffmpeg_8.1.3-1_portable_win64-clang-gpl.zip
Expand-Archive jellyfin-ffmpeg_8.1.3-1_portable_win64-clang-gpl.zip ffmpeg
Remove-Item jellyfin-ffmpeg_8.1.3-1_portable_win64-clang-gpl.zip
Stop-Process -Name rex; Start-Sleep 1; Start-ScheduledTask rex
```

На Windows rex конвертирует на энкодере карты NVIDIA, если она есть, а иначе на процессоре.
+++

**Что вы должны увидеть.** В логе rex будет строка `transcoder:` с названием FFmpeg и найденным железом (`hardware none` означает процессор). `transcoder off` при запуске означает, что ничего не найдено. Файл, который раньше не работал, теперь проигрывается; в логе видно, что было сконвертировано, например `video=copy h264 audio=ac3->aac`.

Субтитры в сконвертированном файле: графические субтитры вшиваются в картинку, а загруженные вами субтитры сохраняются. Plex для Android и iOS также оставляют текстовые субтитры отдельной дорожкой, а в других приложениях их тоже вшивают в картинку. Сконвертированные офлайн-загрузки по-прежнему не содержат текстовых субтитров.

## Субтитры {#subtitles}

**Что это делает.** Поиск субтитров в приложении Plex находит субтитры у провайдера самого Plex, как только rex подключён. rex проверяет выбранные вами субтитры по файлу и исправляет их тайминг, если они идут с опозданием или были сделаны под другую частоту кадров. Если в вашем аккаунте Plex включён показ субтитров и у фильма нет субтитров на вашем языке, rex ищет их до 3 секунд перед началом воспроизведения.

**Зачем это нужно.** Первый результат Plex часто не совпадает с файлом по синхронизации.

![Диалог поиска субтитров Subtitles в приложении Plex, со списком английских результатов для Sintel](../assets/rex/51-plex-search-subtitles.webp)

Ничего настраивать не нужно. rex сверяет субтитр с текстовыми субтитрами самого файла, если они там есть. Файл без них сверяется со звуком в момент нажатия «Play». Для этого нужно настроить [Converting video](#converting-video-optional), и rex читает шесть кусков файла по 90 секунд.

**Что вы должны увидеть.** В логе rex есть строка `SUBTITLE measured` для каждого проверенного субтитра, а когда он его исправил, появляется строка `SUBTITLE applied ... corrected by`.

## Возможности для фильмов и сериалов {#movie-and-tv-capabilities}

Загрузки, определение интро и титров, превью для перемотки и другие функции сервера Plex, которые есть у rex, и их настройки описаны в [руководстве по настройке rex](https://github.com/debridmediamanager/rex/blob/main/docs/setup.md#movie-and-tv-capabilities). Музыка и Live TV приходят из источников, которые их передают ([ограничения rex](https://github.com/debridmediamanager/rex#limits)), например [rex-live-sports](https://github.com/debridmediamanager/rex-live-sports) для живых каналов. DVR нет, так что ничего не записывается. Фото появляются только из источника, который их передаёт ([feed API](https://github.com/debridmediamanager/rex/blob/main/docs/feed-api.md#photos)), например комиксы из zurg. Plex Web их показывает, а Plex для Android библиотеку фото не показывает.

Для воспроизведения через общий debrid-аккаунт оставь режим прокси по умолчанию. Real-Debrid отслеживает публичный IP каждого загрузчика, и если один аккаунт используется с нескольких IP, появляется предупреждение о шаринге, даже когда загрузки проходят успешно. Ссылки на скачивание TorBox содержат полный API-ключ, поэтому при перенаправлении каждый клиент и каждый пользователь общего аккаунта получает доступ, включая удаление. Прочитай [риски перенаправления и настройку](direct-download.md#before-you-start), прежде чем разрешать приложениям загружать файлы напрямую у провайдера.

## Запуск rex в Docker {#run-rex-in-docker}

Эти шаги рассчитаны на машину с Linux. На macOS и Windows Docker Desktop запускает контейнеры внутри виртуальной машины, поэтому сетевой режим host, обнаружение в локальной сети (LAN discovery) и графический чип там не работают так же, как на Linux. Используй шаги выше.

Создай папку, например `~/rex`, и положи в неё такой `compose.yml`:

```yaml
services:
  rex:
    image: ghcr.io/debridmediamanager/rex:nightly
    container_name: rex
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./config:/config
```

- Графический чип Intel или AMD? Добавь `devices: ["/dev/dri:/dev/dri"]`, чтобы rex конвертировал видео на нём.
- `network_mode: host` позволяет приложениям Plex в твоей сети находить rex самостоятельно, а rex — достучаться до твоего приложения по адресу, который он регистрирует, так же, как с самой машины.
- В `./config` попадают `rex.db` и позже `claim_state.json`. Читать их может только root, потому что в `rex.db` хранится логин от твоего приложения.
- Plex Media Server на этой же машине? Добавь `command: --port 32500` и используй `32500` везде, где в команде или настройке указано `32400`.

```bash
docker compose up -d
docker compose logs -f rex
```

Ты должен увидеть те же строки, что и в [шаге 1](#step-1-install-rex). Затем выполни шаги со 2 по 5 как описано выше. Если твоё приложение тоже работает в контейнере, оно должно регистрировать адрес, до которого rex может достучаться с машины, а не адрес, видимый только другим контейнерам.

Обновить можно командой `docker compose pull && docker compose up -d`. В образе уже есть jellyfin-ffmpeg, поэтому для [конвертации видео](#converting-video-optional) нужно только передать графический чип. HTTPS работает так же, как описано выше: Tailscale, Caddy и frp запускаются на самой машине, а `--announce-url ...` добавляется в `command:` файла compose.

## Держите порт закрытым {#keep-the-port-private}

rex не требует пароля для своего feed API. Он отвечает на этот API только с этой машины, из вашей домашней сети (10.x, 172.16-31.x, 192.168.x, 169.254.x и приватные IPv6-адреса) и из Tailscale (100.64-127.x). Всем остальным он отвечает так, будто API вообще нет. Поэтому проброс порта rex для [rex-direct](#rex-direct) или доступ к нему по IPv6 сами по себе не открывают API. Если роутер показывает внешним посетителям свой собственный адрес, они выглядят как локальные, и тогда лента становится доступна из интернета. Поэтому ваше приложение должно отправлять запросы из одной из этих сетей. За домашним роутером подходит и устройство с IPv6-адресом из диапазона вашей домашней сети, так что имя хоста, которое резолвится в IPv6-адрес rex, работает дома. На VPS обращайтесь к rex по адресу из приватной сети. Прокси на машине с rex считает запросы локальными, поэтому держите `/rex/*` заблокированным в любом прокси, который смотрит в интернет, как в примере с [Caddy](#caddy).

## Обновление {#updating}

rex никогда не обновляется сам. Запустите блок загрузки из [шага 1](#step-1-install-rex) ещё раз: он заменит программу и `data/` и не тронет `rex.db`, ваши ключи, `claim_state.json` и `rex-direct.json`. Затем перезапустите rex, как показано в шаге 1. На Windows перед блоком загрузки выполните `Stop-Process -Name rex`, потому что Windows не даёт заменить запущенный `rex.exe`, а после блока выполните `Start-ScheduledTask rex`. Если rex после этого завершается с ошибкой `unrecognized arguments`, удалите из команды запуска rex флаги, которые она называет: в rex их больше нет.

## Позже: восстановление, перенос, удаление {#later-restore-move-remove}

### Восстановление из резервной копии {#restore-a-backup}

Остановите rex, удалите `rex.db` и лежащие рядом с ним `rex.db-wal` и `rex.db-shm`, положите файлы вашей резервной копии в папку rex и запустите rex. Если оставить старый `rex.db-wal` на месте, восстановление откатится.

+++ Linux
```bash
systemctl --user stop rex
rm -f ~/rex/rex.db ~/rex/rex.db-wal ~/rex/rex.db-shm
cp ~/rex-backup/* ~/rex/
systemctl --user start rex
```
+++ macOS
```bash
launchctl unload ~/Library/LaunchAgents/com.rex.plist
rm -f ~/rex/rex.db ~/rex/rex.db-wal ~/rex/rex.db-shm
cp ~/rex-backup/* ~/rex/
launchctl load ~/Library/LaunchAgents/com.rex.plist
```
+++ Windows
```powershell
Stop-Process -Name rex; Start-Sleep 1
Remove-Item $HOME\rex\rex.db*
Copy-Item $HOME\rex-backup\* $HOME\rex
Start-ScheduledTask rex
```
+++ Docker
```bash
cd ~/rex && docker compose down
sudo rm -f config/rex.db config/rex.db-wal config/rex.db-shm
sudo cp ~/rex-backup/rex.db.bak config/rex.db && sudo cp ~/rex-backup/*.json config/
docker compose up -d
```
+++

### Перенос rex на другую машину {#move-rex-to-another-machine}

Сделайте бэкап, как в [шаге 5](#step-5-watch-something), затем окончательно остановите rex на старом компьютере, как это сделано в первом блоке [Remove rex](#remove-rex). На новом выполните [шаг 1](#step-1-install-rex), но скопируйте файлы из бэкапа в папку rex до того, как превращать его в сервис. Для ваших приложений Plex это тот же сервер: он по-прежнему привязан к аккаунту и открыт для общего доступа. Затем:

- Укажите вашему приложению новый LAN IP, как в [шаге 4](#step-4-connect-your-app).
- Перенесите проброс портов на роутере на новый компьютер или правило IPv6-файрвола, прежде чем rex запустится там. Имя rex-direct остаётся прежним и само следует за новым публичным IP. Tailscale serve и Caddy настраиваются заново на новом компьютере.

### Перенос rex на другой аккаунт Plex {#move-rex-to-another-plex-account}

Если аккаунт, к которому привязан rex, потерян или заблокирован, или вы хотите перенести rex на другой аккаунт, создайте новый аккаунт, остановите rex, удалите `claim_state.json` в папке rex, запустите rex и заново выполните [шаг 3](#step-3-add-it-to-a-plex-account): привяжите сервер, а затем снова откройте к нему доступ всем. Если вы ещё можете войти в старый аккаунт, удалите rex и там: в app.plex.tv откройте **Settings**, **Authorized Devices**, выберите фильтр **Servers** и удалите его. Этих двух шагов достаточно, чтобы полностью отвязать rex. У rex нет выхода из аккаунта: запрос Plex на выход (`DELETE /myplex/account`) возвращает 200, но rex остаётся привязанным. Библиотека, Fix Match, правки и имя rex-direct сохраняются, а история просмотров каждого человека вернётся, как только rex снова будет открыт для его аккаунта.

### Какой rex запускать? {#which-rex-do-i-run}

rex не имеет команды version. Дата nightly-сборки указана в названии загрузки (`2026.10.30.0040-nightly`), а у файла программы та же дата: `ls -l ~/rex/rex` (в Windows `(Get-Item $HOME\rex\rex.exe).LastWriteTime`). Версия Plex, которую показывают твои приложения, не относится к rex: rex намеренно сообщает текущую версию Plex Media Server, поэтому приложения считают её актуальной, а **Check for Updates** всегда говорит, что обновление не нужно.

### Удаление rex {#remove-rex}

Полностью остановите rex:

+++ Linux
```bash
systemctl --user disable --now rex && rm ~/.config/systemd/user/rex.service
```
+++ macOS
```bash
launchctl unload ~/Library/LaunchAgents/com.rex.plist && rm ~/Library/LaunchAgents/com.rex.plist
```
+++ Windows
В PowerShell от имени администратора:

```powershell
Unregister-ScheduledTask rex -Confirm:$false; Stop-Process -Name rex
Remove-NetFirewallRule -DisplayName rex, "rex discovery"
```
+++ Docker
```bash
cd ~/rex && docker compose down
```
+++

Затем отключите отправку из приложения в rex. На app.plex.tv, войдя в новый аккаунт, откройте **Settings**, **Authorized Devices**, отфильтруйте по **Servers** и удалите rex. Уберите проброс портов на роутере (или правило файервола для IPv6) и удалите папку rex.

## Если что-то не работает {#when-something-is-wrong}

| Что вы видите | Что делать |
|---|---|
| `/rex/sources` остаётся `{"size":0}` | Ваше приложение не зарегистрировалось. Проверьте адрес, который ему дали, и может ли оно достучаться до порта rex |
| Push отвечает `404 no such source` | Ваше приложение отправило push до регистрации. Сначала оно должно сделать `PUT /rex/sources/<name>` |
| В логе rex строка `held ... no media_info yet` | Ваше приложение отправило файл без вывода ffprobe. Он появится, когда этот вывод придёт |
| Тайтлы показывают имена файлов и без постеров | rex не привязан к аккаунту Plex. Сделайте [шаг 3](#step-3-add-it-to-a-plex-account). Если rex привязали после того, как ваше приложение отправило библиотеку, тайтлы сами получат имена, как только привязка пройдёт |
| Тайтл попал не в тот сериал, или фильм назван именем файла | Ваше приложение не отправило `kind` и `ids` для него или отправило неверные. Исправьте это в приложении или используйте **Fix Match** в приложении Plex, вошедшем в новый аккаунт; Fix Match сохраняется так, как вы его задали |
| Все тайтлы не воспроизводятся на всех устройствах, часто с сообщением "This server is not powerful enough to convert video", а в логе rex сразу после нажатия Play появляется `upstream failed` или `502` (если FFmpeg настроен, то `TRANSCODE ... exited` с отказом соединения или тайм-аутом) | rex не может достучаться до вашего приложения по адресу, который оно зарегистрировало, и FFmpeg это не исправит. `curl -s http://192.168.1.20:32400/rex/sources` показывает этот адрес как `url` вашего приложения. На машине с rex выполните `curl -I` по нему: любой HTTP-ответ, включая `401`, — это нормально; `Failed to connect` значит, что rex не может до него достучаться. Приложение должно регистрировать адрес, который работает с машины rex: адрес `172.` принадлежит контейнеру и доступен rex только с той же Linux-машины. Новые сборки прямо об этом пишут: rex выводит в лог `SOURCES <name>: cannot reach ... from this machine` |
| В логе rex `upstream failed: no source ... configured` | У rex нет регистрации от вашего приложения. Пусть оно зарегистрируется снова: перезапустите его |
| В логе rex `part ... is unavailable upstream` | Ваше приложение ответило 404 на этот файл: сейчас его у него нет |
| Ничего не воспроизводится, 401 или 403 | Ваше приложение отказало в собственном входе. Пусть зарегистрируется снова с текущими данными для входа |
| Снимок отвечает 409 `would remove more than half` | Это защита rex от приложения, которое присылает наполовину загруженную библиотеку. Если удаление действительно нужно, ваше приложение должно отправить весь снимок заново, начиная с части 0, с `"force": true` в последней части. Повторная отправка только последней части отклоняется, а отправка её как отдельного нового снимка с `force` удалит всё, что указали предыдущие части |
| Удаление в приложении Plex не работает, а в логе rex `DELETE refused by the source` | Ваше приложение не принимает `DELETE` для файла. Удалите файл в самом приложении |
| Только некоторые файлы не воспроизводятся с сообщением "This server is not powerful enough to convert video", часто только в веб-браузере | Устройство не может проиграть файл в таком виде. Попробуйте приложение Plex на телевизоре или телефоне либо настройте [Конвертацию видео](#converting-video-optional) |
| Файл Dolby Vision не воспроизводится, а в логе rex `DoVi (Profile 5) color space is not supported` | В rex нет FFmpeg или установлен не jellyfin-ffmpeg. Установите jellyfin-ffmpeg, как показано в [Конвертации видео](#converting-video-optional), и оставьте включённой настройку **Enable HDR tone mapping** (Settings, Transcoder) |
| rex завершается с `cannot bind ...:32400 (another rex or Plex on this port? ...)` | Порт занят другой программой. Если на этой машине работает Plex Media Server, используйте `--port 32500`, как сказано в [шаге 1](#step-1-install-rex). Если это другой rex, например запущенный вручную, остановите его |
| Устройство дома не может подключиться, а в строке rex `heartbeat ... ->` нет `http://192.168.1.20:32400` | rex сообщает частный адрес сети, через которую он выходит в интернет; за VPN или exit node Tailscale это будет не ваша домашняя сеть. Добавьте в конец команды запуска rex ([шаг 1](#step-1-install-rex)) `--announce-url http://192.168.1.20:32400` и перезапустите rex |
| Дома app.plex.tv не достаёт до rex, и адрес `lan.` из [Что вы должны видеть](#what-you-should-see) не отвечает | Некоторые роутеры и DNS-фильтры блокируют публичное имя, которое указывает на домашний адрес (защита от DNS rebinding). Разрешите там `rex-direct.debridmediamanager.com`, как пользователи Plex разрешают `plex.direct` |
| Другой компьютер не может достучаться до rex в Windows, хотя правила брандмауэра из шага 1 есть | Если вы когда-либо нажали **Cancel**, когда Windows спросила, разрешать ли rex, Windows сохранила правило, которое его блокирует, и оно важнее правил для портов. Удалите его в PowerShell от имени администратора: <code>Get-NetFirewallApplicationFilter -Program "$HOME\rex\rex.exe" &#124; Get-NetFirewallRule &#124; Where-Object Action -eq Block &#124; Remove-NetFirewallRule</code> (если rex лежит в другом месте, укажите свой путь) |
| rex нет в приложениях Plex вне дома | Не привязан, или устройство не может достучаться до HTTPS-адреса ([rex-direct по IPv6](#rex-direct-over-ipv6) требует IPv6 в сети этого устройства) |
| rex завершается с `argument --announce-url: '...' is not an http:// or https:// address` | Укажите для `--announce-url` только адрес, например `https://myhost.tailnet.ts.net:443`: без скобок, кавычек или ссылки вокруг него |
| rex останавливается при выходе из системы | В Linux выполните `sudo loginctl enable-linger "$USER"` (шаг 1). В macOS и Windows rex, настроенный по шагу 1, работает, пока вы вошли в систему |
