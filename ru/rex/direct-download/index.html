Приложения скачивают с вашего провайдера

Обычно rex читает каждый фильм из вашего источника и передаёт его в Plex. Если источник возвращает ссылку на файл, например ссылку на скачивание с debrid, rex может передать её Plex. Plex тогда сам скачивает файл, а на машине с rex медиа не хранится.

Это работает, когда Plex может воспроизвести файл напрямую (direct play). Всё, что rex должен конвертировать, по-прежнему проходит через rex или, если вы так выберете, отклоняется.

Протестировано 2026-10-25 с zurg на Real-Debrid, Plezy и Plex for Android на Pixel 6, а также Plex Web в Chrome.

Перед началом

Russian translation, informal "ты" style for software docs. Keeping names, links, and the version number as they are.

Сохраняйте режим прокси по умолчанию для общего доступа к debrid-воспроизведению. Редиректы не безопасный способ делиться одним аккаунтом debrid:

  • Real-Debrid отслеживает публичный IP каждого загрузчика. Использование одного аккаунта с нескольких IP приводит к предупреждению о совместном доступе, даже если CDN успешно отдаёт файл. Держите все обращения к этому аккаунту на одном публичном IP. Если удалённое приложение скачивает напрямую, пока rex или его источник проверяет или конвертирует файл с IP сервера, это нарушает это правило. Успешное воспроизведение не доказывает, что всё безопасно.
  • URL загрузки TorBox содержат полный API-ключ в ?token=. Редирект даёт каждому клиенту и каждому общему пользовательскому аккаунту доступ ко всему, включая удаление, а не только к этому файлу. Логи плеера и история браузера могут сохранить ключ. Не передавайте эти ссылки недоверенным клиентам.

Продолжайте, только если эти риски вас устраивают. Сохранение режима прокси по умолчанию в rex означает, что rex сам следует за редиректами источника, вместо того чтобы передавать ссылку провайдера приложению.

Что бы ты ни выбрал, каждое приложение и каждый человек, с которым ты делишься rex, получает ссылку, которую твой источник выдал rex для того, что они проигрывают, и сервис за этой ссылкой, например твой дебрид-сервис, видит каждого, кто её скачивает.

Шаг 1. Пусть источник выдаёт ссылки

Что это делает. Ваш источник на каждый запрос отвечает ссылкой на файл в другом месте (HTTP-редирект), а не самим файлом.

Почему это важно. rex может передать только ту ссылку, которую ему отдал источник. Если источник отдаёт сам файл, он так и будет идти через rex.

Источник Что делать
rex-stremio Ничего: он отвечает ссылкой, которую дал стрим-аддон. Ссылку, которой нужны свои заголовки, и живой плейлист он по-прежнему отдаёт сам
zurg Включите disable_stream_proxy, описано ниже. У zurg нет ссылки для файла из Usenet, поэтому такие файлы он всегда отдаёт сам
Ваше приложение Ответьте на GET файла кодом 302 или 307 с ссылкой

zurg

Настройка относится к zurg, поэтому всё остальное, что читает zurg (rclone, сервер Plex или Jellyfin на маунте zurg), тоже получает эти ссылки. Подробности есть в справочнике по конфигурации zurg.

Проверьте, есть ли эта настройка в конфиге zurg:

grep -n '^disable_stream_proxy:' ~/zurg/config.yml

Если команда выведет строку, измените её на disable_stream_proxy: true с помощью nano ~/zurg/config.yml. Если ничего не выведется, добавьте её:

printf '\ndisable_stream_proxy: true\n' >> ~/zurg/config.yml
cd ~/zurg && ./zurg service restart

Откройте конфиг zurg командой notepad $HOME\zurg\config.yml. Если в нём есть строка disable_stream_proxy:, измените её на disable_stream_proxy: true. Если строки нет, добавьте её в конец. Сохраните файл и перезапустите zurg:

cd $HOME\zurg; .\zurg.exe service restart

В папке zurg:

sudo grep -n '^disable_stream_proxy:' config.yml

Если команда выведет строку, измените её с помощью sudo nano config.yml. Если нет:

printf '\ndisable_stream_proxy: true\n' | sudo tee -a config.yml >/dev/null
docker compose restart zurg

Что вы должны увидеть. zurg запускается снова как обычно. Фильмы пока воспроизводятся через rex: до шага 2 rex сам проходит по ссылкам.

Шаг 2. Пусть rex передаёт ссылки дальше

Что это делает. rex передаёт приложению ту ссылку, которую дал ваш источник, вместо того чтобы скачивать фильм для него.

Добавьте в конец стартовой команды rex --part-mode redirect (или --part-mode redirect-only), затем перезапустите rex и откройте его лог. Установка rex показывает, где на вашей системе находится стартовая команда, и как перезапустить rex и посмотреть его лог. В Linux строка ExecStart в файле ~/.config/systemd/user/rex.service тогда будет выглядеть так, без всего лишнего:

ExecStart=%h/rex/rex --part-mode redirect

Всё, что уже есть в этой строке, например --port 32500 или --announce-url ..., оставьте как есть.

Что вы должны увидеть. Стартовая строка заканчивается на parts=redirect:

INFO    rex on http://192.168.1.20:32400  machine=...  items=...  parts=redirect

С redirect-only она заканчивается на parts=redirect-only, а чуть выше в логе rex пишет transcoder off: --part-mode redirect-only.

Шаг 3. Запустите что-нибудь

Оставьте лог rex открытым и запустите фильм в Plezy или Plex для Android.

Что вы должны увидеть. Для каждого запроса, который делает приложение, появляется строка с названием сервера вашего провайдера:

INFO    PART 1000010 range=bytes=0- -> 302 to 129-4.download.real-debrid.com

Это значит, что rex перенаправляет приложение на сервер ссылки, в данном случае Real-Debrid. Если строка заканчивается на -> 206 len=..., значит rex отдал сам фильм: см. Если не работает.

Что делает каждое приложение

App redirect redirect-only
Plezy Загрузки от провайдера Загрузки от провайдера
Plex for Android, Original quality Загрузки от провайдера, если rex позволяет воспроизвести файл как есть То же самое
Plex for Android, a lower quality, or audio it cannot play rex конвертирует "Playback Error: This item can't be played right now. Please try again."
Plex Web Воспроизводится через rex "Playback Error: This server is not powerful enough to convert video."

Plex Web вообще не может использовать ссылки Real-Debrid: Real-Debrid помечает свои файлы как загрузки, а не как видео, и браузер отказывается их воспроизводить. При redirect Plex Web незаметно переходит на конвертацию через rex в течение секунды, так что всё продолжает работать. При redirect-only переходить не на что.

В Docker

Если вы следовали инструкции rex в Docker, шаг 2 — это строка command: в разделе rex: файла compose.yml от rex, рядом с image::

    command: --part-mode redirect

Уже есть command: --port 32500? Измените её на command: --port 32500 --part-mode redirect. Затем выполните docker compose up -d в папке rex, и docker compose logs -f rex покажет ту же строку parts=redirect.

Если не работает

Что вы видите Что это значит
rex завершается с invalid choice для --part-mode rex старше 2026.10.26. Обновите его, как описано в разделе «Updating» в документации rex
В логе rex для каждого чтения есть -> 206 len=... Источник всё ещё отдаёт сам файл. В случае zurg в конфиге zurg отсутствует disable_stream_proxy: true, или zurg не был перезапущен после шага 1
-> 206 len=... только для некоторых тайтлов Источник отдаёт их сам: это файлы Usenet из zurg или ссылки rex-stremio, которые rex должен ретранслировать
-> 403: the source answered with the bytes, not a link redirect-only отказывается принимать файл, который источник отдал сам, по тем же причинам, что указаны выше
При воспроизведении фильма нет ни одной строки PART Приложение воспроизводит конвертацию, а не сам файл. Установите для него качество Original

Всё ещё не получается? Задайте вопрос на форуме rex-support в Discord. В разделе Получение помощи написано, что нужно указать.

Возврат назад

Удали --part-mode ... из команды запуска rex (или из строки command: в Docker) и перезапусти rex. Твой источник может продолжать выдавать ссылки: когда настройки rex больше нет, rex сам по ним ходит. Для zurg нужно вернуть disable_stream_proxy в false и перезапустить zurg, тогда он снова сам отдаёт файлы, в том числе для rclone и всего остального, что их читает.
