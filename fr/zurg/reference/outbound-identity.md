# Identité de la requête sortante {#outbound-request-identity}

`user_agent` contrôle le User-Agent HTTP partagé utilisé pour les API des services débrid et les lectures CDN, les recherches Newznab, les téléchargements NZB, OpenSubtitles, les sondages ffprobe, les intégrations de serveurs média, les téléchargements de dépendances, les mises à jour et les exports facultatifs de partage ou de journaux.
L'agent par défaut est un agent de navigateur générique. Vide rétablit cette valeur par défaut. Une valeur personnalisée saisie explicitement est envoyée telle quelle, même si elle identifie l'application.
`omit_user_agent: true` supprime l'en-tête User-Agent des clients HTTP Go et donne à ffprobe un agent vide, en remplaçant la chaîne configurée. Certains services peuvent rejeter les requêtes sans agent. GitHub refuse toutes ces requêtes avec un 403. Les requêtes vers GitHub (`zurg update` et les téléchargements de rclone et ffprobe) gardent donc l'agent configuré, ou l'agent de navigateur générique si aucun n'est défini.

Plex, Jellyfin et Emby exigent aussi des métadonnées de client et d'appareil. Configure-les avec `outbound_client_name`, `outbound_client_id`, `outbound_client_version`, `outbound_device_name`, `outbound_device_id` et `outbound_platform`. Les valeurs par défaut sont respectivement `Media Client`, `media-client`, `1.0`, `Media Client`, `media-client` et `Desktop`.
Plex utilise l'ID du client pour les requêtes d'authentification, d'analyse et de métadonnées. Jellyfin et Emby utilisent l'ID de l'appareil dans leurs métadonnées d'authentification. Les champs ne sont utilisés que lorsque le protocole les prend en charge. Changer les ID peut faire apparaître un autre client ou appareil dans le serveur média.

Tous ces réglages sont disponibles sous Network & Connectivity dans le tableau de bord. Le tableau de bord affiche les valeurs enregistrées, avec les valeurs par défaut résolues. Restart applique les réglages en même temps. L'enregistrement ne modifie pas l'identité en cours d'exécution.
Les valeurs doivent être de l'ASCII imprimable, de 2048 caractères maximum. Les champs client et appareil ne peuvent pas contenir de guillemets ni de barres obliques inverses. Les jetons d'authentification et les noms d'en-têtes du protocole restent inchangés, y compris l'identifiant `X-Zurg-Token` requis par DMM.

Les clients des fournisseurs et des indexeurs suppriment les en-têtes `Referer`, `Origin` et `X-Zurg*` avant d'envoyer les requêtes, y compris lors des redirections. Les redirections ne peuvent donc pas révéler les chemins privés des URL précédentes ni les paramètres de requête de clé API via un Referer. L'authentification, les requêtes de plage, les cookies des fournisseurs et les limites de redirection restent en place. Aucun identifiant de client ou d'appareil de l'application n'est ajouté à ces requêtes.

NNTP envoie `AUTHINFO USER`, `AUTHINFO PASS`, `BODY`, `STAT`, `DATE` et `QUIT` selon les besoins, sans commande d'identification du logiciel. Il n'y a pas d'ID logiciel NNTP à configurer. Les noms d'utilisateur et mots de passe restent dans la configuration NNTP de chaque fournisseur. Les tests TLS et de transcription en clair couvrent l'authentification, l'accès aux articles, le keep-alive et l'arrêt.

Cela limite les identifiants explicites de l'application, mais ne garantit pas l'anonymat. Les services distants voient toujours les identifiants, les adresses IP source, le contenu demandé et le timing. Le comportement TLS et HTTP, les identités personnalisées, les clés API enregistrées par l'application et les schémas d'accès (y compris les liens de test réseau de Real-Debrid) peuvent permettre de corréler les requêtes. Les URL fournies de l'extérieur, les métadonnées torrent, les ID d'articles, les données de partage et le contenu des journaux ou de la configuration exportés ne sont pas réécrits. Les URL de téléchargement des logiciels identifient le logiciel demandé. Les lecteurs externes et les outils lancés séparément utilisent leurs propres réglages.

Les tests de régression au niveau des sockets couvrent les valeurs par défaut, les agents personnalisés ou omis, les redirections, la préservation de l'authentification et les métadonnées du serveur média. Les tests de configuration et du tableau de bord couvrent la validation, les allers-retours YAML et l'application des réglages au redémarrage.
