Which setup should I use?

Find your setup with the interactive questionnaire. Answer a few questions about your player, accounts and hosting to get recommended routes, requirements and setup links. No login needed.

Start with the app you want to watch in. You do not need to install everything. DMM helps you find and choose releases; a provider supplies the files; zurg can turn those files into a shared library; rex presents a library to Plex apps. Several routes skip one or more of those pieces.

This is a map of the supported route families, checked against the projects on 8 November 2026. It includes alternatives outside the stack where they remove a step. It is not a promise that every third-party addon, TV model or combination works. Follow the linked setup guide for your chosen route and its tested limits.

Choose where the files come from

An indexer finds releases. A torrent or NZB describes how to fetch one; it is not the video. A provider supplies the bytes. A player decodes them. Buying access to one of these does not automatically buy the others.

zurg's debrid integrations cover Real-Debrid, AllDebrid, TorBox, Premiumize, Offcloud and Debrid-Link. You can combine accounts in one zurg library. That does not make providers' caches, quotas or file availability identical. A cached badge is useful evidence, not a guarantee that your account can play the file now. See providers.

“Usenet without a Usenet account”: which route?

Choose TorBox hosted NZBs if you want TorBox to do the downloading and repair. In DMM, the TorBox action on Usenet results sends the NZB to that service. In current zurg nightlies, the provider type is torbox_nzb; it also accepts NZBs from the watch directory, acquisition and the SABnzbd-compatible interface. A cache miss must finish downloading on TorBox before it plays. Active downloads share the account's slots with torrents, and retained files can expire. Keep the NZBs for re-fetching; zurg does not promise to re-download expired releases unattended.

Choose direct Usenet if you want zurg to read through your own news accounts, including fallback/block accounts. It uses nzb, with NNTP credentials. A TorBox news-server login also belongs to this route: TorBox NNTP is distinct from its hosted NZB downloader. TorBox's own tools page describes that NNTP offering; its plans describe hosted-service entitlements.

One zurg instance uses either nzb or torbox_nzb, not both. Both own the NZB watch directory. To run both, use separate zurg instances and separate working directories. Either can sit beside torrent-provider accounts. zurg's Stremio addon can submit to the selected NZB backend too; an uncached hosted download may take longer than a playback request waits, so it is not a guarantee of instant play.

Choose DMM → Real-Debrid if the desired end result is a release in your RD library. This is a hosted transfer, with queues and allowances; an uncached job takes time. It does not give Real-Debrid native NNTP support, and it does not mean every debrid provider accepts NZBs. The DMM result and Transfers page show the job's progress.

Easynews adds another choice: its Watch, Download and Cast actions use Easynews's HTTP files. Send to zurg instead places that release's NZB on your sponsor Wanted list for zurg to fetch. The latter needs a configured NZB backend; an Easynews web login in DMM does not configure zurg's news servers.

What about HTTP links?

DMM's TorBox Add dialog accepts direct HTTP(S) download links as web downloads. zurg exposes TorBox web downloads in its __downloads__ directory; do not assume that a file appearing there is also an identified library item sent to rex. Real-Debrid unrestricted/file-hoster downloads can also appear in zurg's __downloads__ directory. DMM's TorBox Cast catalog includes completed web and Usenet downloads as well as torrents. This does not make an arbitrary website page a video: login pages, expiring URLs, DRM and a site's own player can require a different integration.

rex supports streamable HTTP(S) media through its feed API. A source or addon submits the media address and the item’s metadata, and rex makes it available in Plex apps. The HTTP server supplying the bytes can be separate from the program submitting the feed; neither zurg nor a debrid account is required. rex-stremio does that for compatible Stremio addons. Raw magnets and torrent-only streams do not work through it; HLS streams need rex's FFmpeg setup. rex does not identify releases or search filenames to decide what a file is: its source supplies that identity.

Decide how titles get added

Acquisition and playback are separate choices. You can change how a title is requested without replacing the app you watch in.

Press Want, or follow a Trakt/MDBList list DMM Wanted → zurg acquisition Automatic films and new episodes without running Sonarr/Radarr; sponsorship required
Family requests in Seerr/Overseerr/Jellyseerr Seerr through DMM → Wanted → zurg Familiar request UI without an arr server; sponsorship required

Want detailed monitoring and quality profiles in Sonarr/Radarr DMM or your indexers → arr → zurg download-client interface → library Keep arr's decisions and import workflow; more services and path setup
Want to choose only when pressing Play DMM Cast/Kodi, another stream addon, or zurg's Stremio search No need to pre-build a managed library of every title

For the recommended DMM + zurg arr route, DMM is the indexer; zurg is the download client. DMM offers Torznab for torrents and Newznab for Usenet, both requiring active sponsorship. Prowlarr is optional. zurg exposes a qBittorrent-compatible interface for torrents and a SABnzbd-compatible interface for NZBs. Those are interfaces built into zurg; they do not require those two downloader applications alongside it. zurg can also help search for arr.

If you want complete local copies, download/copy the actual files from your provider or zurg, use a player's supported offline-download feature, or keep a conventional downloader and disk-based library. Check download quotas and verify the saved files play without the network. zurg's virtual files, .strm links and local debrid catalogs are not offline copies. A local debrid catalog stores the library's records locally; playback still depends on the provider.

The tradeoffs that matter before installing

Question What changes your choice
Must another machine stay on? Hosted Cast/Kodi routes do not need your own server. zurg, rex, rex-stremio and media-server plugins do need their host while you watch. zurg Android can make the viewing device that host. A rented/managed host changes who runs it, not the underlying route.
Will my TV play the file? WebDAV and addon routes depend on the player's codecs, audio and subtitles. zurg serves bytes; it is not a video transcoder. Plex Media Server, Jellyfin, Emby or rex with FFmpeg can convert when needed, with appropriate hardware and server/app capabilities.
How much disk space? Streaming avoids storing the whole collection. Allow space for databases, artwork, caches and any repair, transcode or offline-download work. “No full download first” does not mean zero disk use.
Who pays for bandwidth? Provider traffic quotas still apply. A server proxy carries playback traffic and uses its outgoing bandwidth; direct playback shifts the connection to the viewer. Library analysis can read remote files too.
Will it work away from home? Hosted addons avoid exposing your own server. Self-hosted services need a securely reachable address; a LAN address alone will not work remotely. See rex remote access and the Stremio HTTPS guidance.
Can family use it simultaneously? Check your provider's IP/concurrency rules and the server's sharing model. Real-Debrid use must stay on one public IP; direct links to different households can violate that even when a central library supplied them. Do not enable redirects without understanding where the downloads originate.
What do I pay for? Keep provider subscriptions, indexer access, DMM sponsorship, hosting and player/server purchases separate. DMM's basic website and rex for personal use are free. Current zurg nightlies and DMM's plugin distribution are sponsor benefits; Wanted and DMM's indexer APIs also need sponsorship. rex-stremio does not require it.
Does a catalog entry guarantee playback? No. Addon catalogs describe titles; cloud files can expire; torrents can lack sources; Usenet articles can be missing. Pick the route whose failure and waiting behavior you are comfortable with.

A compatible server client can also be a third-party app: Infuse connects to Plex, Emby and Jellyfin. Needing Infuse does not by itself mean you need a separate zurg mount; verify the selected plugin and client combination.

Infuse supports WebDAV and other network shares. A .strm file is another way to hand a compatible player such as Kodi a URL. It is not a universal substitute for a mount: check the client, and expect different proxy/failover behavior. Do not choose .strm as the normal Plex Media Server setup.

There is also a legacy free zurg release. It is Real-Debrid-only, with a different configuration format; the current multi-provider, Usenet and Android routes here refer to sponsor nightlies.

rex has its own compatibility boundary. It is an independent server for Plex apps, not Plex Media Server or a Plex plugin. Use its FAQ for tested devices, transcoding, remote use and the fresh-account recommendation. Not every Plex app has been tested, and Plex's services and apps can change. A traditional Plex server can remain alongside rex.

Needs that can change the route

I also need… What to choose or check
Local files and cloud titles together Keep your existing Plex/Jellyfin/Emby server and add the mount or matching plugin. rex can combine multiple feed sources, including an HTTP source for local files; it still needs their metadata.
Automatic subtitle files Player-provided or embedded subtitles may be enough. For an arr workflow, Bazarr with zurg writes local sidecars beside virtual videos. rex also has Search Subtitles without Bazarr.
My watched history when changing servers Read moving from Plex and importing watched state before switching; changing the source does not automatically migrate every app's history.
Share a selection with someone who has their own account DMM hashlists share release choices for others to add to their accounts. They do not transfer your credentials or host playback. Sharing a server is a different route, subject to its sharing and provider rules.
A VPS or remote host with limited bandwidth Check whether the route proxies or redirects playback. rex direct-download settings explain its options; redirects change the downloader's public IP and can expose provider URLs.

Other media and existing setups

  • Music: DMM Music provides Real-Debrid browser playback/downloads. rex music sources feed Plexamp and supported Plex apps. A source can be an addon or zurg configured for music. Do not assume a movie/TV addon supplies music too.
  • Live TV: rex's Live TV route provides channels and a guide in the documented apps. Live channels from rex-stremio instead form a library of channels; that is not the same guide interface. Check source availability. rex does not provide DVR recording.
  • Home videos, recordings and photos: use an existing media server, or a rex source you control. The home-video tutorial shows the latter. zurg can also supply comic books as photos to rex; app support differs.
  • Existing Kodi/Stremio addons: if yours already gives the experience you want, keep it. DMM can be the place you select and manage releases without replacing your player. Addon support for providers, Usenet and HTTP varies; the DMM route is not a compatibility promise for all addons.
  • Another debrid mount/downloader already installed: see migration choices before switching. A working setup does not need another layer solely because it exists.
  • Native apps in development: Usenet TV is not a released app-store setup to recommend here. Yomu TV is a separate reading/audiobook project, not a route for this movie/TV stack. Neither is required for the routes above.

Five common starting points

  1. “I have Stremio and RD.” Start with DMM Cast. Add zurg only when you want a shared library, automation or another consumer that needs it.
  2. “I have TorBox Pro and want the NZBs in that post.” Send the NZB to TorBox through DMM. Use TorBox Cast to watch in Stremio, or zurg's hosted NZB backend to feed your chosen library/player route.
  3. “I already have Jellyfin.” Start with the plugin for your provider. Choose separate zurg when you need its shared filesystem, automation or broader backend capabilities.
  4. “I want Plex apps, no mounts, and my existing addons.” Use rex-stremio with rex. Use zurg as a source instead when the thing you want to expose is your managed debrid/Usenet library. Both sources can feed the same rex.
  5. “I have news accounts and want Sonarr/Radarr.” Use DMM Newznab or your existing indexers, zurg's NZB/SABnzbd route and a playback route from the first table. For permanent local files, choose a normal downloader or explicitly save complete copies; virtual imports alone are not offline files.

Still unsure? Tell us your device/player, accounts you already have, whether a host can stay on, and whether you want on-demand playback or an automatically managed library. Those four answers usually decide the route. Getting help says where to ask.
