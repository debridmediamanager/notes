# هوية الطلب الصادر {#outbound-request-identity}

`user_agent` يتحكم في User-Agent المشترك لطلبات HTTP، سواء لواجهات debrid وقراءات CDN،
وعمليات بحث Newznab، وتنزيلات NZB، وOpenSubtitles، وفحوصات ffprobe، وتكاملات خوادم الوسائط،
وتنزيلات المكتبات، والتحديثات، وخيارات المشاركة وتصدير السجلات الاختيارية.
القيمة الافتراضية هي وكيل متصفح عام. القيمة الفارغة تعيد الافتراضي، أما القيمة المخصصة الصريحة فتُرسل كما كتبتها، حتى لو كانت تعرّف بالتطبيق.
`omit_user_agent: true` يمنع إرسال ترويسة User-Agent في عملاء Go HTTP، ويعطي ffprobe وكيلاً فارغاً، ويتجاوز السلسلة المضبوطة. قد ترفض بعض الخدمات الطلبات التي لا تحمل وكيلاً. GitHub يرفض كل طلب بخطأ 403، لذلك فإن الطلبات الموجهة إلى GitHub (`zurg update` وتنزيلات rclone وffprobe) ما زالت تحمل الوكيل المضبوط، أو وكيل المتصفح العام إذا لم يُضبط أي وكيل.

Plex وJellyfin وEmby تحتاج أيضاً بيانات وصفية للعميل والجهاز. اضبطها عبر `outbound_client_name` و`outbound_client_id` و`outbound_client_version` و`outbound_device_name` و`outbound_device_id` و`outbound_platform`. القيم الافتراضية هي `Media Client` و`media-client` و`1.0` و`Media Client` و`media-client` و`Desktop` على التوالي. يستخدم Plex معرّف العميل للمصادقة وطلبات الفحص والبيانات الوصفية، ويستخدم Jellyfin وEmby معرّف الجهاز في بيانات المصادقة الوصفية. تُستخدم الحقول فقط حيث يدعمها البروتوكول. تغيير المعرّفات قد يظهر كعميل أو جهاز مختلف في خادم الوسائط.

كل هذه الإعدادات متاحة تحت Network & Connectivity في لوحة التحكم. تعرض لوحة التحكم القيم المحفوظة مع حل القيم الافتراضية. إعادة التشغيل تطبّق الإعدادات معاً، والحفظ وحده لا يغيّر الهوية الجارية. يجب أن تكون القيم ASCII قابلة للطباعة، بحد أقصى 2048 حرفاً، ولا يمكن أن تحتوي حقول العميل والجهاز على علامات اقتباس أو شرطات مائلة عكسية. رموز المصادقة وأسماء ترويسات البروتوكول تبقى دون تغيير، بما في ذلك بيانات الاعتماد المطلوبة في DMM وهي `X-Zurg-Token`.

عملاء المزودين والمفهرسات يزيلون ترويسات `Referer` و`Origin` و`X-Zurg*` قبل إرسال الطلبات، بما في ذلك عمليات إعادة التوجيه. إعادة التوجيه لا يمكنها كشف المسارات الخاصة للعناوين السابقة أو معاملات مفاتيح API عبر Referer. تبقى المصادقة وطلبات النطاق (range) وكوكيز المزود وحدود إعادة التوجيه كما هي. لا تُضاف أي معرّفات عميل أو جهاز للتطبيق إلى هذه الطلبات.

يرسل NNTP الأوامر `AUTHINFO USER` و`AUTHINFO PASS` و`BODY` و`STAT` و`DATE` و`QUIT` عند الحاجة، دون أي أمر لتعريف البرنامج. لا يوجد معرّف برنامج NNTP للضبط. تبقى أسماء المستخدمين وكلمات المرور في إعداد NNTP الخاص بكل مزود. تغطي اختبارات TLS والنص العادي المصادقة والوصول إلى المقالات والإبقاء على الاتصال (keep-alive) والإغلاق.

هذا يقلل المعرّفات الصريحة للتطبيق، لكنه لا يوفر إخفاءً للهوية. الخدمات البعيدة ما زالت ترى بيانات الاعتماد وعناوين IP المصدر والمحتوى المطلوب والتوقيت. سلوك TLS وHTTP والهويات المخصصة ومفاتيح API المسجلة من التطبيق وأنماط الوصول (بما فيها روابط اختبار الشبكة في Real-Debrid) قد تساعد في ربط الطلبات ببعضها. الروابط الخارجية وبيانات torrent الوصفية ومعرّفات المقالات وحمولات المشاركة ومحتويات السجلات والإعدادات المصدّرة لا تُعاد كتابتها. روابط تنزيل البرامج تعرّف بالبرنامج المطلوب. المشغّلات الخارجية والأدوات التي تُشغَّل بشكل منفصل تستخدم إعداداتها الخاصة.

اختبارات المقابس (socket) على مستوى منخفض تغطي القيم الافتراضية والوكلاء المخصصين والوكلاء المحذوفين وإعادة التوجيه والمصادقة المحفوظة وبيانات خادم الوسائط الوصفية. اختبارات الإعدادات ولوحة التحكم تغطي التحقق، والتحويل ذهاباً وإياباً مع YAML، وتطبيق الإعدادات عند إعادة التشغيل.
