# نقطة نهاية MCP {#the-mcp-endpoint}

يستطيع zurg الرد على وكيل ذكاء اصطناعي عبر [بروتوكول سياق النموذج (Model Context Protocol)](https://modelcontextprotocol.io):
يسأل العميل عن الأدوات المتاحة، فيصفها zurg، ثم يستدعي الوكيل هذه الأدوات لقراءة المكتبة،
ومعرفة سبب عدم تشغيل إصدار ما، وإصلاحه، أو التحكم في خوادم الوسائط.
هي نفس العمليات التي تعرضها لوحة التحكم وواجهة CLI، لكن على شكل أدوات مُحددة النوع مع مخططات،
وليس على شكل صفحات HTML وإعادة توجيه 303.

نقطة النهاية هذه مُعطّلة افتراضياً. وهي خلف نفس المصادقة الأساسية (basic auth) المستخدمة في لوحة التحكم،
ويرفض zurg تشغيلها نهائياً إذا لم يُضبط اسم مستخدم. فإذا كان الاسم فارغاً، تصبح كل المسارات على الخادم متاحة للجميع،
وهذه الأدوات تحذف الإصدارات.

## الإعدادات {#configuration}

```yaml
mcp:
  enabled: true
```

هذا كل ما تحتاجه للتثبيت العادي. للبقية إعدادات افتراضية تستحق أن تعرفها:

```yaml
mcp:
  enabled: true
  toolsets: [library, releases, repair]   # the default; see below
  read_only: false                        # withhold every tool that changes anything
  allow_unauthenticated: false            # serve /mcp with no username set
  allow_lifecycle: false                  # admit the tools that stop zurg or its mount
  page_limit: 50                          # items a listing returns by default; 500 is the cap
  max_result_kb: 256                      # ceiling on one result; a page over it is trimmed
  session_timeout_mins: 30                # -1 keeps sessions for the life of the process
```

مثل بقية كتل الميزات، يُقرأ هذا الإعداد مرة واحدة عند بدء التشغيل، لذلك أي تغيير فيه يتطلب إعادة تشغيل.

## الاتصال {#connecting}

### عبر HTTP {#over-http}

نقطة النهاية هي `/mcp` على المنفذ المعتاد لـ zurg، وتعمل بروتوكول Streamable HTTP. وجّه العميل إلى `http://<host>:9999/mcp` مع بيانات الدخول الخاصة بلوحة التحكم.

```bash
npx @modelcontextprotocol/inspector
# Transport:  Streamable HTTP
# URL:        http://localhost:9999/mcp
# Header:     Authorization: Basic <base64 of user:password>
```

### عبر stdio {#over-stdio}

العملاء التي لا تتعامل إلا مع stdio تستخدم الأمر الفرعي `zurg mcp`، وهو يربطها بنسخة zurg تعمل بالفعل:

```json
{
  "mcpServers": {
    "zurg": {
      "command": "/path/to/zurg",
      "args": ["mcp"],
      "cwd": "/path/to/your/zurg/directory"
    }
  }
}
```

مجلد العمل (`cwd`) مهم، لأن كل مسار في zurg يُحسب انطلاقاً منه، وهناك يقرأ `zurg mcp` الملف `config.yml` ليأخذ منه المنفذ وبيانات الدخول. ومع هذه الإعدادات لا يحتاج الأمر إلى أي معاملات. الخياران `--username` و`--password` يتجاوزان بيانات الدخول المحلية. أما `--url` المخصص فلا يرث بيانات الدخول من الإعدادات المحلية أبداً، لذا مرّر خياري بيانات الدخول معاً صراحةً إذا كانت تلك النقطة تحتاجها، حتى لا تُرسل كلمة المرور المحلية إلى مضيف آخر بالخطأ.

هو لا يشغّل نسخة ثانية. فالنسخة الثانية من zurg ستحمّل المكتبة كاملة، وستأخذ مجموعة ثانية من فتحات المزوّد على حسابات تُحتسب عليها الاستخدامات، وستتنازع مع الأولى على نقطة التركيب (mount). لذلك يعمل الأمر كأنبوب يصل إلى الخدمة الخلفية (daemon)، ولا يقدم أي شيء إذا كانت الخدمة متوقفة. وتذهب رسائله التشخيصية إلى stderr، لأن stdout يحمل البروتوكول.

قيد واحد: الإشعار الذي يُطلقه الخادم خارج أي استدعاء لا يعبر الجسر. أما أسطر التقدم والسجل التي تُطلق *أثناء* الاستدعاء فتُرسل ضمن الرد الخاص بذلك الاستدعاء وتصل بشكل طبيعي، وهذا يشمل كل ما ترسله zurg.

## مجموعات الأدوات {#toolsets}

| المجموعة | ضمن الافتراضي | ما تغطيه |
|---|:-:|---|
| `library` | نعم | البحث، وقوائم المجلدات، وأعداد الوسوم |
| `releases` | نعم | إصدار واحد بالتفصيل: الملفات، والنسخ لكل حساب، وما يمكنه تقديم كل ملف |
| `repair` | نعم | ما هو معطل، وهل سيصل الإصلاح إليه، وفرض الإصلاح |
| `releases_write` | | الحذف، وإعادة التسمية، والوسم، وفرض العرض، وكتابة ملفات `.strm` |
| `magic` | | مساحة الأسماء `__magic__`: التخطيط المخزّن وصفوفه، ونقل العناصر وتحريكها |
| `plex` | | Plex وJellyfin وEmby: الحالة، والمطابقة، والفحص المحمي |
| `providers` | | الحسابات المُعدّة: ما يستطيع كل منها، وهل يمكن الوصول إليها، وما أنفقته |
| `usenet` | | الواجهة الخلفية لـ NZB: حسابات الأخبار، وفحوصات المقالات، والتلف، وذاكرة المقالات المؤقتة |
| `clients` | | نقاط نهاية SABnzbd وqBittorrent وStremio التي يتحدث معها Sonarr وRadarr |
| `diagnostics` | | السجل، وعدادات البايتات، والذاكرة وgoroutines |
| `config` | | قراءة الإعدادات، وإيجاد الانحراف، وكتابة مجموعة مختارة من المفاتيح |
| `mount` | | تركيب rclone: الحالة، ونسيان قوائم المجلدات المخزّنة مؤقتاً، وإعادة تشغيله |
| `system` | | معلومات البناء، و`doctor`، والخدمة، والنسخ الاحتياطية، والتحديث |

تضم أدوات zurg نحو بضع مئات من الأدوات، وهذا أكثر مما يستطيع العميل التعامل معه بشكل جيد. فبعد حوالي ثمانين أداة، يختار النموذج الأداة الخطأ بتكرار أكبر، وحدها المخططات (schemas) تكلّف عشرات الآلاف من الرموز. لذلك يختار `toolsets` مجموعات، والافتراضي هو مجموعة فرعية عملية بدلاً من كل شيء.

`toolsets: [all]` يفعّل كل المجموعات. الاسم الذي يسبقه `-` يُستثنى، فـ`[all, -config, -system]` تعني السطح الكامل دون المجموعتين اللتين تغيّران الجهاز نفسه لا المكتبة. اسم غير معروف يُنتج تحذيراً عند بدء التشغيل ويُتجاهل: الخطأ الإملائي لا يجب أن يحرم نقطة الوصول من أدواتها.

الأدوات التي توقف zurg أو تتحكم في خدمته أو تعيد تشغيل الـ mount ليست مجموعة مستقلة، بل موجودة ضمن `system` و`mount`، وتبقى محجوبة حتى يتم ضبط `allow_lifecycle`، مهما كانت قيمة `toolsets`.

مجموعة `server` الصغيرة، وهي تخبر بنوع هذا البناء وبما إذا كانت المكتبة قد انتهت من التحميل، تُسجَّل دائماً مهما كانت قيمة `toolsets`. فلو حُجبت، لن يتمكن العميل من معرفة أن كل الإجابات الأخرى ناقصة حالياً.

## ما لن يفعله دون طلب صريح {#what-it-will-not-do-without-being-asked}

**التأكيد.** الأداة التي تحذف شيئاً تصف ما ستفعله وتعيد رمزاً، ولا تنفّذ الفعل إلا إذا استُدعيت مرة أخرى مع ذلك الرمز. الرمز مشتق من الخطة نفسها، لذلك لا يمكن نقل التأكيد إلى خطة مختلفة. إذا تغيّرت المكتبة في الأثناء، يعود الاستدعاء الثاني إلى الوصف بدلاً من التنفيذ. الرموز تُستخدم مرة واحدة فقط، وتبقى صالحة لدقيقتين، ولا تبقى بعد إعادة تشغيل الخادم.

**`read_only`.** مفتاح واحد يخفي كل أداة تغيّر أي شيء، بغض النظر عمّا تقوله `toolsets`. السؤال الذي يطرحه المشغّل فعلاً هو "هل يستطيع هذا أن يكسر مكتبتي؟"، وليس "أيٌّ من هذه الأدوات يكتب؟". هذه الأدوات تُحذف من `tools/list`، فلا يستطيع العميل اختيار قدرة لن يسمح بها هذا الخادم أبداً. وتبقى بوابة التحقق وقت الاستدعاء كطبقة دفاع إضافية، في حال تغيّر الإعداد الحي بعد بناء الخادم.

**`allow_lifecycle`.** الأدوات التي توقف zurg أو تتحكم في خدمته أو تعيد تدوير التركيب تُخفى بالطريقة نفسها خلف مفتاح منفصل. كل واحدة منها قادرة على جعل المكتبة بأكملها تختفي دفعة واحدة، وإجراءات العملية أو الخدمة لا تستطيع الإبلاغ عن نتيجتها بنفسها، لأنها قد تنهي العملية التي تردّ على الاستدعاء.

**الأسرار.** لا تحمل أي نتيجة أداة رمز مزوّد، أو مفتاح API، أو كلمة مرور خادم الأخبار، أو رابط CDN المحلول، أو رابط `.strm` الموقّع. وتُحجب البيانات الحساسة في سجلات الإخراج قبل خروجها. الرابط المحلول يمكن لأي شخص يحمله استخدامه على الحساب الذي أنشأه، ولا مكان لمثل هذا الرابط في سجل المحادثة.

**الحجم.** كل قائمة محدودة بطريقتين: حد لعدد الصفحات، وسقف لحجم النتيجة بعد تسلسلها. حساب واحد اختُبر بهذا يحتوي على 84,000 إصدار، أي نحو اثني عشر ميغابايت من الأسماء فقط قبل أن يُعرض أي ملف. النتيجة التي تتجاوز السقف تُقلَّص، ويُذكر صراحةً أنها قُلِّصت.

## ملاحظات {#notes}

تَرِث نقطة النهاية مصادقة basic auth الخاصة بلوحة التحكم، لأنها مسجّلة داخلها.
يتم رفض طلب cross-origin: فـ`/mcp` مخصص لوكيل محلي، وليس لصفحة ويب.
يعمل وسيط عكسي (reverse proxy) أمام zurg بشكل سليم، لأن فحص DNS-rebinding في مكتبة البروتوكول
يرفض الوسيط الذي يمرّر `Host` الخاص به أثناء الاتصال بـ`127.0.0.1`، لذلك يُعطّل zurg هذا الفحص ويترك البوابة لمصادقة basic auth.

يعرض الأمر `zurg mcp --help` قائمة الخيارات (flags) الخاصة بالجسر. ويتحقق `zurg doctor` مما إذا كانت نقطة النهاية تستجيب أصلاً.
