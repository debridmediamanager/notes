# Offcloud

`type: offcloud`

يحلّ Offcloud معرّفات الملفات عبر نقطة نهاية cloud explore الخاصة به. يتم التحقق من أحجام الملفات مقابل خادم التحميل بدلاً من الاعتماد على ما تعرضه القائمة.
تُستخدم بيانات torrent المخزّنة مؤقتاً لتحديد مسارات المجلدات كلما أمكن مطابقتها بشكل لا لبس فيه.

## الحصول على مفتاح API {#get-the-api-key}

سجّل الدخول وافتح [offcloud.com/#/account](https://offcloud.com/#/account). مفتاح الـ API موجود في تلك الصفحة.

## إعداده {#configure-it}

```yaml
zurg: v1
providers:
  - type: offcloud
    token: YOUR_OFFCLOUD_API_KEY
mount_path: "/zurg_mnt/zurg"
```

عند تثبيت جديد للحاوية، دع الإعداد يكتبه.

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider offcloud
```

في حال وجود ملف `config.yml` بالفعل، استخدم **Add provider** في
Dashboard على `http://localhost:9999/config/` أو عدّل الملف. أعد التشغيل
في كلتا الحالتين.

```bash
docker compose restart zurg
```

يقرأ `zurg setup` المتغيّر `OFFCLOUD_TOKEN`، أما الخدمة قيد التشغيل فلا تقرأه.

## بيانات اعتماد واحدة لكل إدخال {#one-credential-per-entry}

مقابض ملفات Offcloud تابعة للحساب الذي سرد هذه الملفات. ما من مفتاح ثانٍ يمكنك التبديل إليه. يتم رفض `download_tokens`، وكذلك أي `strm_link_token` يختلف عن `token`. إذا أردت حساباً ثانياً، فأضفه كإدخال ثانٍ له `name` خاص به.

```yaml
providers:
  - type: offcloud
    name: oc-main
    token: FIRST_OFFCLOUD_API_KEY
  - type: offcloud
    name: oc-second
    token: SECOND_OFFCLOUD_API_KEY
```

## ما الذي يعمل هنا {#what-works-here}

Library browsing، والقراءة المتدفقة، والقراءة عبر إعادة التوجيه، وملفات STRM، والإضافة عبر magnet، ورفع ملفات `.torrent`، والحذف، كلها تعمل. يحصل الحساب على مجلد `__offcloud__` خاص به.

## حدود تستحق الانتباه {#limits-worth-knowing}

**8 طلبات API متزامنة.** يتم حل أربعة أجزاء من أرشيف متعدد الأجزاء في وقت واحد.

**المحتوى ينتهي صلاحيته.** الإصدار الذي انتهت صلاحيته أمرٌ متوقع وليس عطلًا. لا تقوم عملية الإصلاح بالتعامل معه ما لم تطلب ذلك.

**قائمة التورنتات لا تحتوي على تفاصيل الملفات.** كل إصدار يحتاج إلى استعلام خاص به في المرة الأولى.

**قائمة الملفات الغامضة تُعتبر خطأً وليس تخمينًا.** أحيانًا لا يمكن مطابقة البيانات الوصفية المخزنة مؤقتًا للتورنت مع إصدار واحد فقط. يبلغ zurg عن ذلك بدلًا من اختيار مسارات مجلدات قد تنتمي إلى شيء آخر.

**روابط magnet المعطوبة تُرفض محليًا.** لا تصل أبدًا إلى الخدمة. رابط magnet السيئ لا يكلفك شيئًا.

مفردات الأخطاء في Offcloud محدودة. `NOAUTH` هو الرمز الوحيد الذي يستطيع zurg التصرف بناءً عليه، ويعني أن بيانات الاعتماد قد رُفضت. كل ما عدا ذلك يصل على شكل رفض دون سبب.

## تحقّق من أنه يعمل {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/offcloud/test
ls /zurg_mnt/zurg/__all__/ | head
```

مع حساب واحد فقط، يتم استبعاد مجلده الخاص من قائمة الجذر في الـmount، لذلك يُظهر الـmount نفس الملفات تحت `__all__`.

## عندما تسوء الأمور {#when-it-goes-wrong}

**`NOAUTH` في السجل.** تم إلغاء المفتاح أو إعادة إنشاؤه. احصل على مفتاح جديد من
[offcloud.com/#/account](https://offcloud.com/#/account) وحدّث الإدخال.

**`API refused request` بدون أي تفاصيل أخرى.** لم يذكر Offcloud السبب. تحقق من
حسابك في المتصفح قبل أن تفترض أن zurg هو المشكلة.

**إصدار لا يعرض أي مجلدات.** تعذر مطابقة بيانات التورنت المخزنة مؤقتاً مع
إصدار واحد محدد. الملفات ما زالت تُبث، لكنها تظهر بدون تنظيم في مجلدات.

**روابط التوصيل المُولَّدة تعمل لأي شخص يملكها.** يتم تحديث روابط التوصيل
عند انتهاء صلاحية الذاكرة المؤقتة أو عندما تُبطلها عملية قراءة. الحصة التي تستهلكها
هي حصة حسابك أنت. احتفظ بالروابط وبالوصول عبر `.strm` بشكل خاص.
