# TorBox

`type: torbox`

[TorBox](https://torbox.app/subscription?referral=74ffa560-7381-4a18-adb1-cef97378c670) هو أرخص مكتبة يُبقيها zurg متزامنة، وأسهلها في التقييد عند القراءة منها. قائمة التورنتات فيه تحمل كل الملفات بالفعل. تحديث المكتبة يكلّف طلبًا واحدًا بدلًا من طلب لكل تورنت. نقطة استعلام حلّ الروابط فيه لها حصة ثابتة وليست معدّلًا بالسرعة. لذلك zurg يتعامل معه بحذر متعمّد.

## الحصول على مفتاح API {#get-the-api-key}

سجّل الدخول وافتح [torbox.app/settings](https://torbox.app/settings). مفتاح API
موجود في تلك الصفحة.

**الحساب المجاني لا يعمل مع zurg.** ترد TorBox على كل طلب للمكتبة من مفتاح مجاني
بالرمز `PLAN_RESTRICTED_FEATURE`، فلا يستطيع zurg قراءة ما يحتويه الحساب.
استخدم خطة مدفوعة. والخطة المدفوعة إذا انتهت تتحول إلى خطة مجانية بالطريقة نفسها.

## إعداده {#configure-it}

```yaml
zurg: v1
providers:
  - type: torbox
    token: YOUR_TORBOX_API_KEY
mount_path: "/zurg_mnt/zurg"
```

في تثبيت جديد للحاوية، دع setup يكتب الملف.

```bash
cd ~/zurg
docker compose run --rm zurg setup \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider torbox
```

في تثبيت فيه `config.yml` بالفعل، استخدم **Add provider** في لوحة Dashboard على العنوان `http://localhost:9999/config/`، أو عدّل الملف مباشرة. في الحالتين، أعد التشغيل بعد ذلك.

```bash
docker compose restart zurg
```

!!!warning مفتاح TorBox في متغيرات بيئة compose لا يفعل شيئًا وحده
يقرأ `zurg setup` القيمة `TORBOX_TOKEN`، وليس الخدمة العاملة. فقط `TOKEN` الخاص بـ Real-Debrid يُنشئ الإعداد عند أول تشغيل. مرّر المفتاح إلى حاوية setup، أو أضف الحساب من لوحة Dashboard.
!!!

للتثبيت بدون إشراف، وجّه setup إلى ملف بدلًا من متغير بيئة.

```bash
docker compose run --rm zurg setup --non-interactive \
  --no-service --skip-downloads --mount-path /zurg_mnt/zurg \
  --provider torbox \
  --torbox-token-file /config/secrets/torbox
```

## مفتاحان لا ينطبقان هنا {#two-keys-that-do-not-apply-here}

`download_tokens` مقبولة لكنها لن تعمل كما تعمل على Real-Debrid.
تدوير مفتاح ثانٍ لا يعيد ربط معرّفات التورنت والملفات. على TorBox تنتمي هذه المعرّفات إلى الحساب الذي أدرجها. يحتاج حساب TorBox ثانٍ إلى إدخال خاص به مع `name` خاص به.

```yaml
providers:
  - type: torbox
    name: tb-main
    token: FIRST_TORBOX_API_KEY
  - type: torbox
    name: tb-second
    token: SECOND_TORBOX_API_KEY
```

`strm_link_token` مقبولة لكنها غير مستخدمة. TorBox يُنشئ رابط تنزيل جديداً مع كل طلب. لا يوجد بيانات اعتماد طويلة الأمد يمكن لملف `.strm` أن يتثبّت عليها.

## فتحات النشاط هي الحد الفعلي {#active-slots-are-the-real-ceiling}

أهم قيد في TorBox هو عدد التورنتات التي يمكن تنزيلها أو مشاركتها في الوقت نفسه. أما قيد Real-Debrid فهو عرض النطاق الترددي، وقيد TorBox هو الفتحات.

| الخطة | الفتحات النشطة |
|---|---|
| Free | 1 لكن zurg لا يستطيع استخدام مفتاح مجاني (انظر أعلاه) |
| Essential | 3 |
| Standard | 5 |
| Pro | 10 |

يقرأ zurg الخطة من الحساب ويتحكم في إضافة المزيد من التورنتات بناءً عليها. أي حساب لا يستطيع zurg قراءة خطته يُعامل على أنه 3.

احسب بقية ما يضيف تورنتات ضمن الميزانية نفسها. فـSonarr وRadarr عند الجلب عبر نقطة qBittorrent، وعملية الإصلاح الشامل، وقائمة المراقبة، كلها تستهلك الفتحات نفسها.

## حدود تستحق الانتباه {#limits-worth-knowing}

**حلّ الروابط ميزانية تبلغ نحو مئة استدعاء، وليس معدلًا.**
تم القياس بتاريخ 2026-08-30. ظهر الخطأ 429 مع `Retry-After: 300` عند الاستدعاء التراكمي رقم 100 حين أُرسلت الاستدعاءات بأقصى سرعة ممكنة. وظهر عند الاستدعاء رقم 94 حين وُزّعت بمعدل استدعاء واحد في الثانية. الحظر على مستوى الحساب كله. يوقف التركيب بالكامل لخمس دقائق، لا القراءة التي أدت إليه وحدها.

يترتب على ذلك أمران، ويتولاهما zurg بنفسه.

- لا يحلّ zurg أبدًا ملفًا لم يطلبه أحد. تستطيع الخلفيات الأخرى أن تبدأ مسبقًا بالحلقة التالية، أما TorBox فلا تحتمل هذا التخمين، لأن خادم الوسائط الذي يحلل مكتبة يفتح كل ملف مرة واحدة فقط، وكل فتحة من هذه الفتحات تكون باردة (بلا كاش).
- يحلّ zurg أجزاء الأرشيف متعدد الأجزاء واحدًا تلو الآخر بالتحديد. فالحل الأسرع سيستنزف السقف عدة مرات، ويشتري أجزاء تقع خلف جزء معطوب قبل أن يكتشف أحد أنها غير لازمة.

**60 إضافة غير مخزّنة في الساعة.** أما الإضافات المخزّنة في الكاش فتندرج تحت ميزانية الدقيقة.

**300 طلب في الدقيقة عبر جميع نقاط النهاية لمفتاح واحد.** يضبط zurg سرعته على 300 ناقص 60، حتى لا تدفع المحاولات المتكررة التي يجريها عميل HTTP من تلقاء نفسه الدفعةَ المحسوبة فوق السقف الحقيقي.

**الاتصال الحادي والعشرون بخادم CDN واحد يتلقى خطأ 429.** تم القياس بتاريخ 2026-08-23 بفتح اتصال واحد كل 500 ملّي ثانية والإبقاء عليه مفتوحًا. الحد لكل خادم وليس لكل مفتاح. توزيع القراءات على أسطول TorBox يتجنّب هذا الحد، أما تكديسها على عقدة واحدة فلا يتجنبه. يضع zurg ما يزيد على 20 اتصالًا في طابور بدلًا من الاتصال المباشر، فيتحول الرفض إلى انتظار محلي قصير.

**يُحذف المحتوى بعد فترة الاحتفاظ المحددة في الخطة.** التورنت الذي اختفى أمر متوقع وليس عطلًا. ولا يتعامل الإصلاح معه إلا إذا طلبت ذلك صراحةً.

**لا يوجد اختيار لكل ملف.** إضافة التورنت تجلب كل محتوياته، ويعيد الإصلاح إضافة الإصدار كاملًا.

تجد الصورة الكاملة مع المصادر في [حدود TorBox](torbox-limits.md).

## اختيار منطقة CDN {#choosing-a-cdn-region}

```yaml
tb_cdn_host_preference: "auto"
```

`auto` يترك اختيار TorBox نفسه كما هو. `force_location_<region>` يقدّم التنزيلات من تلك المنطقة. يمكن فرض المناطق التي تعلن حاليًا عن عقدة تسليم فقط، وقائمة الاختيار في Dashboard تعرض هذه المناطق بالضبط. لا تستخدم `cdn_host_preference` هنا. هذا المفتاح خاص بـ Real-Debrid فقط، وقيمه هي رموز مواقع Real-Debrid.

## تحقّق من أنه يعمل {#check-it-worked}

```bash
curl -fsS -X POST http://localhost:9999/api/providers/torbox/test
ls /zurg_mnt/zurg/__all__/ | head
```

مع حساب واحد فقط، يتم استبعاد مجلده الخاص من قائمة الجذر في الـmount، لذلك يُظهر الـmount نفس الملفات تحت `__all__`.

## عندما تسوء الأمور {#when-it-goes-wrong}

**السجل يقول `Account <name> refused zurg` أو يستمر في تكرار `TorBox rejected the API key`.**
انتهت الخطة، وأصبح المفتاح على الخطة المجانية الآن. من إصدار nightly 2026.10.11.2240 فصاعداً، يحمّل zurg حساباتك الأخرى دون هذا الحساب. تظهر بطاقة الحساب في لوحة التحكم بالعبارة `Refused: the account's plan does not include API access`. تبقى إصداراته مدرجة لكنها لا تُشغَّل، ولا يُحذف أو يُنقل إلى سلة المهملات أي شيء بسبب ذلك. يطلب zurg من TorBox مرة أخرى كل 10 دقائق، ويستعيد الحساب بمجرد دفع الخطة. في الإصدارات nightly الأقدم لم تكتمل تحميل المكتبة كلها، لذلك كان المحتوى من حساباتك الأخرى يختفي أيضاً. حدّث zurg أو جدّد الخطة. تعطيل مزوّد `torbox` في `config.yml` بوضع علامة تعليق أمامه، ثم إعادة تشغيل zurg، يعمل أيضاً.

**التشغيل يتوقف لخمس دقائق في كل مرة.** انتهت حصة requestdl، والخطأ 429 يشمل الحساب كله. شيء ما يحلّ روابط أكثر مما يحتاج. عادةً يكون السبب خادم وسائط يفحص المسار المُركَّب كله دفعة واحدة. وجّهه إلى دليل واحد بدلاً من كل الأدلة.

**عمليات الإضافة لم تعد مقبولة.** إما أن كل الفتحات النشطة ممتلئة، أو أن حد الإضافة في الساعة قد استُنفد. يُعاد ضبط الاثنين تلقائياً، ولا تفيد إعادة المحاولة في أي منهما.

**إصدار ما يعرض ملفات أقل مما تتوقع.** يعرض `__torbox__` فقط ما تحتفظ به TorBox فعلاً. إذا كان حساب آخر يحتفظ بالإصدار كاملاً، فبقية المسار المُركَّب ما زالت تقدّم كل ملفاته.

**اختفى تورنت.** بسبب انتهاء مدة الاحتفاظ. انظر أعلاه. لن يعيد zurg إضافته تلقائياً، لأن إعادة اكتشافه تستهلك حصة الحساب دون فائدة.
