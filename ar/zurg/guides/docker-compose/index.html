ملف Docker Compose واحد لـ zurg وPlex وrex

ملف docker-compose.yml واحد تم اختباره يشغّل zurg وPlex Media Server وrex على جهاز Linux واحد، من التثبيت وحتى التشغيل في Plex، مع حلول للأخطاء التي يواجهها الناس.

على جهاز Linux، يمكن لملف docker-compose.yml واحد أن يشغّل zurg وPlex Media Server وrex جنبًا إلى جنب. يعرض zurg مكتبتك كمجلدات تحت /zurg_mnt/zurg، ويقرأ Plex Media Server هذه المجلدات، ويحصل rex على المكتبة نفسها مباشرة من zurg، من دون الحاجة إلى مجلدات. شغّل مُثبِّت zurg عبر Docker مرة واحدة، ثم استبدل ملف docker-compose.yml الخاص به بالملف الموجود أدناه.

تريد Plex Media Server أو rex فقط، وليس الاثنين؟ احذف الخدمة الأخرى من الملف. وإذا لم تستخدم Plex، فاحذف أيضًا سطر command: الخاص بـ rex.

لا يمكن تشغيل هذا على Docker Desktop في Windows أو Mac، لأن مجلدات zurg لن تظهر في Explorer أو Finder، ولن يتمكن rex من الوصول إلى zurg الموجود داخل الجهاز. استخدم بدلًا من ذلك zurg على Windows أو zurg على macOS.

قبل أن تبدأ

  • جهاز Linux يبقى مشغّلاً طوال الوقت. المثبّت يضيف Docker إذا لم يكن موجوداً.
  • رعاية zurg. صورة zurg خاصة. ارعَ المشروع على gatekeeper وسيمنح حسابك على GitHub صلاحية الوصول.
  • مفتاح API الخاص بك من Real-Debrid، أو تسجيل الدخول لخدمة أخرى يدعمها zurg: Your Real-Debrid API token.
  • لخادم Plex Media Server، حساب Plex الخاص بك. أما لـ rex، فأنشئ حساب Plex جديداً خصيصاً له: rex مع zurg يشرح السبب.

1. شغّل مثبّت zurg الخاص بـ Docker

curl -fsSL https://raw.githubusercontent.com/debridmediamanager/zurg-site/main/public/install-docker.sh | bash

يقوم بتثبيت Docker إذا كان غير موجود (وسيسألك أولاً)، ويجهّز /zurg_mnt لمجلدات zurg الآن وبعد كل إعادة تشغيل، ويسجّل دخولك إلى GitHub لسحب صورة zurg، ويكتب ~/zurg/docker-compose.yml، ويطلب منك الخدمات والرمز المميز، ثم يشغّل zurg ويُنفّذ zurg doctor. يقوم إعداد zurg على Docker بالعمل نفسه يدوياً.

ما يجب أن تراه.

ls /zurg_mnt/zurg

يعرض المجلدات __all__ و__downloads__ و__unplayable__ وmovies وshows والملف version.txt.

2. استبدل الملف بالملف الكامل

cd ~/zurg
nano docker-compose.yml

استبدل كل ما فيه بهذا:

services:
  zurg:
    image: ghcr.io/debridmediamanager/zurg:${ZURG_TAG}
    container_name: zurg
    restart: unless-stopped
    devices:
      - /dev/fuse
    cap_add:
      - SYS_ADMIN
    security_opt:
      - apparmor:unconfined
    ports:
      - 9999:9999
    volumes:
      - ./:/config
      - /zurg_mnt:/zurg_mnt:rshared

  plex:
    image: plexinc/pms-docker
    container_name: plex
    restart: unless-stopped
    network_mode: host
    environment:
      - TZ=Europe/London
      - PLEX_CLAIM=
    volumes:
      - ../plex/config:/config
      - ../plex/transcode:/transcode
      - /zurg_mnt:/zurg_mnt:rslave
    depends_on:
      zurg:
        condition: service_healthy

  rex:
    image: ghcr.io/debridmediamanager/rex:nightly
    container_name: rex
    restart: unless-stopped
    network_mode: host
    command: --port 32500
    volumes:
      - ../rex/config:/config
  • zurg هي خدمة المثبّت نفسها، دون تغيير.
  • plex يرى مجلدات zurg في المسار نفسه الذي يستخدمه zurg، أي /zurg_mnt/zurg، لذلك فإن الفحص الذي يطلبه zurg بالاسم يشير إلى مجلد يعرفه Plex. يحافظ rslave على بقاء المجلدات في مكانها عند إعادة تشغيل zurg. ضع منطقتك الزمنية في TZ.
  • PLEX_CLAIM يسجّل دخول Plex Media Server إلى حسابك عند أول تشغيل. سجّل الدخول إلى Plex، ثم افتح plex.tv/claim، وانسخ الرمز والصقه مباشرة بعد علامة =. تنتهي صلاحيته بعد بضع دقائق، لذلك ابدأ تشغيل الحزمة فورا.
  • rex هي الخدمة من rex مع zurg، وتعمل على المنفذ 32500 لأن Plex Media Server يستخدم 32400. ملفاتها تنتهي في ~/rex/config، وهو المكان الذي يبحث فيه rex مع zurg عن ملفاته.

احفظ الملف وشغّل كل شيء:

docker compose up -d
docker compose ps

إذا ظهرت لك الرسالة permission denied عند تشغيل docker، فضع sudo قبل كل أمر docker في هذه الصفحة.

ما الذي يجب أن تراه. ثلاث حاويات: plex وzurg تظهران (healthy)، وrex تظهر Up. تذهب ملفات Plex Media Server الخاصة به إلى ~/plex.

3. أضف مجلدات zurg في Plex

افتح Plex Web على http://<this machine's LAN IP>:32400/web. أضف مكتبة Movies بالمجلد /zurg_mnt/zurg/movies ومكتبة TV Shows بالمجلد /zurg_mnt/zurg/shows، كما يظهر في Real-Debrid في Plex.

حتى يعرف Plex بالمحتوى الجديد، افتح لوحة zurg على http://<this machine's LAN IP>:9999/config/ واضغط Login with Plex تحت Media Server Integration (الخطوة 4 هناك).

4. إعداد rex

اتبع rex مع zurg من D3 إلى D5، واستخدم 32500 بدلًا من 32400 في كل مكان يُذكر فيه. على سبيل المثال، سطر zurg هو rex_url: http://192.168.1.20:32500 مع عنوان IP الخاص بـ rex على الشبكة المحلية. ثم ستعرض تطبيقات Plex الخاصة بك الخادمين معًا: الخطوة 2 من rex مع zurg توضح كيفية التمييز بينهما.

التحديث

cd ~/zurg
docker compose pull
docker compose up -d

يقوم ذلك بتحديث zurg وPlex وrex معًا. وفي الحالة التي يشغّل فيها rex مع zurg الأمر docker compose داخل ~/rex، شغّله هنا داخل ~/zurg مع إضافة rex في نهايته، بحيث يؤثر على rex وحده: docker compose stop rex بدلًا من docker compose down، وdocker compose up -d rex بدلًا من docker compose up -d.

عندما تحدث مشكلة

docker compose logs --tail=100 zurg (أو plex، rex) يعرض آخر ما قالته الحاوية.

ما تراه ما الذي يجب فعله
المثبِّت يقول Host-visible Docker mounts require a Linux host. Use the binary installer on macOS or Windows. أنت على جهاز Mac أو Windows. ثبّت zurg باستخدام مثبّت Windows أو مثبّت macOS بدلاً من ذلك.
Error response from daemon: error from registry: unauthorized عندما يسحب Docker صورة zurg هذا الجهاز غير مسجّل الدخول إلى سجل حزم GitHub بحساب له صلاحية الوصول إلى zurg. ادعم المشروع عبر gatekeeper، ثم شغّل المثبّت مرة أخرى. لتسجيل الدخول يدوياً، راجع إعداد Docker لـ zurg: يحتاج الرمز إلى الصلاحيتين read:packages وrepo.
path /zurg_mnt is mounted on ... but it is not a shared mount المسار /zurg_mnt غير مُشارَك بعد. شغّل sudo mount --bind /zurg_mnt /zurg_mnt ثم sudo mount --make-rshared /zurg_mnt، ثم docker compose up -d. المثبّت يجعل هذا الإعداد دائماً بعد إعادة التشغيل؛ يدوياً، راجع الخطوة 7 من إعداد Docker لـ zurg.
zurg يستمر في إعادة التشغيل، وينتهي سجله بـ Error: config ./config.yml is not valid YAML: yaml: unmarshal errors: وmapping key "..." already defined هذا الإعداد موجود مرتين في ملف إعدادات zurg. شغّل sudo nano ~/zurg/config.yml، واحذف أحد السطرين اللذين تذكرهما الرسالة، ثم احفظ، وشغّل docker compose restart zurg.
سجل zurg يقول Mount verification failed: mount verification timeout: /zurg_mnt/zurg/version.txt not accessible after 60 attempts -- you appear to be running inside Docker, mount a parent directory with rshared propagation مجلدات zurg لم تظهر. تأكد أن سطر الـ volume في zurg هو /zurg_mnt:/zurg_mnt:rshared، أي المجلد الأب وليس /zurg_mnt/zurg، وأن /zurg_mnt مُشارَك (الصف الذي فوق). يحتوي المجلد فارغ على فحوصات إضافية.
مكتبات Plex تصبح فارغة بعد إعادة تشغيل zurg، ويقول docker exec plex ls /zurg_mnt/zurg إن cannot access '/zurg_mnt/zurg': Transport endpoint is not connected سطر الـ volume الخاص بـ Plex ينقصه rslave. يجب أن يكون /zurg_mnt:/zurg_mnt:rslave. صحّحه ثم شغّل docker compose up -d.
rex يتوقف مع rex: cannot bind 0.0.0.0:32400: Address already in use (os error 98) (another rex or Plex on this port? --port picks another) Plex Media Server يستخدم المنفذ 32400 أصلاً. أبقِ command: --port 32500 في rex.
/zurg_mnt/zurg/movies فارغ، أو يقول Input/output error، مباشرة بعد البدء zurg ما زال يقرأ حسابك. يطبع curl http://localhost:9999/ready كلمة ready عندما ينتهي. لا تعيد تشغيل zurg في هذه الأثناء، فذلك يبدأ القراءة من جديد.
العناوين تظهر في rex لكن لا شيء يُشغَّل الصف upstream failed في rex مع zurg، عند وجود مشكلة يفحص ما إذا كان rex يستطيع الوصول إلى zurg.
القرص يمتلئ يحتفظ zurg بنسخة مما تم تشغيله في ~/zurg/data/rclone-cache، حتى 256G افتراضياً. يوضح ما الذي يوجد أين كيفية تحديد الحد الأقصى.

ما زلت عالقاً؟ اسأل في منتدى zurg-support على Discord. يوضح الحصول على المساعدة ما الذي يجب تضمينه.

أسئلة

هل يمكنك مراجعة ملف docker compose الخاص بي؟

لا أرى أي نص سابق في هذه المحادثة لأقارنه به. الرسالة الوحيدة هي ملاحظاتك عن الإعدادات. أرسل النص الذي تريد ترجمته، وسأحافظ على هذه النقاط كما هي:

  • يربط zurg المسار /zurg_mnt بخيار rshared.
  • يربط Plex المسار نفسه /zurg_mnt بخيار rslave.
  • يستخدم rex الصورة ghcr.io/debridmediamanager/rex مع network_mode: host.
  • الخدمة التي اسمها rex وتشغّل plexinc/pms-docker هي خادم Plex Media Server ثانٍ، وليست rex.

هل أحتاج إلى حاوية rclone منفصلة؟

لا. يشغّل zurg برنامج rclone داخل الحاوية الخاصة به، ويضع مكتبتك في /zurg_mnt/zurg بنفسه.

هل يمكنني استخدام Plex Media Server وrex معاً؟

هذا ما يفعله هذا الملف بالضبط. يشغّل Plex Media Server المحتوى من مجلدات zurg، ويشغّل rex المحتوى من zurg مباشرة. وستظهر لك المكتبتان في تطبيقات Plex. إذا لم تكن تريد المكتبتين معًا، فاحتفظ بالواحدة التي تستخدمها فقط.

هل يعمل هذا على NAS؟

تم اختباره على كمبيوتر يعمل بنظام Linux، وليس على NAS. يحتاج المثبّت إلى نافذة طرفية (SSH) مع sudo، وإلى FUSE (/dev/fuse). إذا انتهت الخطوة 1 وظهرت مجلدات zurg داخل /zurg_mnt/zurg، فتابع إلى الخطوة 2.

مع أي إصدارات تم اختبار هذا؟

zurg 2026.11.14.1134-nightly و rex 2026.11.14.1123-nightly و Plex Media Server 1.43.5.11079، بتاريخ 14 نوفمبر 2026.
